# P0 — Scaffold: Implementation Spec

> Executable spec for **rust-engineer**. Zero design decisions are left open:
> where this document says something, do exactly that. If reality contradicts
> this spec (e.g. an rmcp API mismatch), fix per the `Implementation note`
> fallbacks below; if there is no fallback, stop and flag to rust-architect.
> Scope guard: **no Hatari spawning, no fifo, no ripper** in P0.

Authority chain: `PLAN.md` §P0 → `ARCHITECTURE.md` → `decisions.md` (ADR-1, -3,
-5, -7 are the ones P0 touches). This spec expands them; it does not override.

**rmcp 2.2 API:** every rmcp construct used below is verified in
[`docs/plan/rmcp-2.2-notes.md`](rmcp-2.2-notes.md) (read it first; do NOT
re-research the crate). Load-bearing gotcha from those notes:
`Implementation`, `ServerInfo`/`InitializeResult`, `ServerCapabilities` are
`#[non_exhaustive]` — **never struct literals; constructors/builders only.**

## 1. Deliverable in one sentence

A compiling `rmcp` **stdio** MCP server (lib + bin crate `shiraz-mcp`) with the
`thiserror` error taxonomy, the `Addr`/`Offset`/`PluginId` newtypes and
`MemImage` stub, the type-state `Session<Stopped|Running|Paused>` skeleton plus
`AnySession` runtime-dispatch enum behind `tokio::sync::Mutex`, and exactly
**one** MCP tool: `status`.

## 5. Error taxonomy — `src/error.rs`

Complete public API. `Display` strings are **contractual** (tests in §10.1
assert them verbatim).

```rust
use crate::types::PluginId;

/// Crate-wide result alias. All `src/` library code returns this; `anyhow`
/// appears only in `main.rs`.
pub type Result<T> = std::result::Result<T, Error>;

/// The matchable error taxonomy (ADR-1). Categories, not a grab bag:
/// callers branch on the variant, humans read the message.
#[derive(Debug, thiserror::Error)]
pub enum Error {
    /// Session lifecycle misuse or failure (bad state, spawn failure, …).
    #[error("session error: {0}")]
    Session(String),

    /// I/O on the Hatari command fifo or its log. Not `#[from]`: fifo
    /// errors must always carry call-site context.
    #[error("fifo I/O ({context}): {source}")]
    Fifo {
        context: String,
        #[source]
        source: std::io::Error,
    },

    /// The sentinel echo never appeared in the log (ADR-7).
    #[error("timeout after {waited_ms} ms waiting for: {what}")]
    Timeout { what: String, waited_ms: u64 },

    /// Hatari log output did not match the expected shape.
    #[error("parse error ({context}): unexpected input {input:?}")]
    Parse { context: String, input: String },

    /// A ripper plugin failed (not "found nothing" — that is an empty Vec).
    #[error("ripper plugin '{plugin}': {message}")]
    Ripper { plugin: PluginId, message: String },

    /// Uncontextualized I/O at the app fringe. Prefer `Fifo`/`Session` with
    /// context in library code; this `#[from]` exists for `?` at boundaries.
    #[error("I/O error: {0}")]
    Io(#[from] std::io::Error),
}
```

All six variants ship in P0 even though only `Session` is constructed —
they are `pub` in a lib crate, so no dead-code warnings. Do not add variants,
do not add a `#[non_exhaustive]` (in-crate consumers only, we want exhaustive
matches to break loudly when a variant is added).

## 6. Newtypes + `MemImage` stub — `src/types.rs`

All inner fields **private**. No `Deref`, no `From<u32> for Addr`, no
`AsRef<[u8]> for MemImage` — accessors only. Doc-comment every item with the
intent shown.

```rust
use std::fmt;

/// A 68000/Atari-ST bus address. Newtype so raw `u32`s never cross a public
/// signature boundary (PLAN.md conventions).
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Addr(u32);

impl Addr {
    pub const fn new(raw: u32) -> Self;   // impl: Self(raw)
    pub const fn raw(self) -> u32;        // impl: self.0
}

/// Display: ST debugger convention — `$` + UPPERCASE hex, zero-padded to a
/// MINIMUM of 6 digits; values above 0xFF_FFFF print all their digits
/// (never truncated). Given in full because the body IS the contract:
impl fmt::Display for Addr {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "${:06X}", self.0)
    }
}

/// A byte offset into a `MemImage` (or any buffer) — distinct from `Addr`
/// so "position in snapshot" and "bus address" cannot be confused.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Offset(usize);

impl Offset {
    pub const fn new(raw: usize) -> Self; // impl: Self(raw)
    pub const fn raw(self) -> usize;      // impl: self.0
}

/// Stable identifier of a ripper plugin ("degas-pi1", "pack-ice"). Static
/// because plugins are compiled in (ADR-2).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct PluginId(&'static str);

impl PluginId {
    pub const fn new(id: &'static str) -> Self; // impl: Self(id)
    pub const fn as_str(self) -> &'static str;  // impl: self.0
}

impl fmt::Display for PluginId {
    // impl: write the inner str verbatim (no quotes, no prefix)
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result;
}

/// An acquired snapshot of ST RAM (≤ 4 MB). The ripper operates on this,
/// never on the live emulator (ADR-2). P0 ships the shape only; acquisition
/// arrives in P1 (`session/memory.rs`).
#[derive(Debug, Clone)]
pub struct MemImage {
    bytes: Vec<u8>,
    base: Addr,
}

impl MemImage {
    /// Snapshot of `bytes` as seen at bus address `base`.
    pub fn new(bytes: Vec<u8>, base: Addr) -> Self; // impl: Self { bytes, base }
    pub fn bytes(&self) -> &[u8];                   // impl: &self.bytes
    pub const fn base(&self) -> Addr;               // impl: self.base
    pub fn len(&self) -> usize;                     // impl: self.bytes.len()
    pub fn is_empty(&self) -> bool;                 // impl: self.bytes.is_empty()
}
```

(`is_empty` is mandatory: clippy `len_without_is_empty` fires under
`-D warnings` otherwise.)

No `serde`/`schemars` derives on these in P0 — nothing serializes them yet;
P1 adds derives when the first tool carries an `Addr`.

## 7. Type-state Session skeleton

### 7.1 `src/session/state.rs` — verbatim shape

```rust
//! Phantom state markers for the Session FSM (ADR-3).
//! Sealed: outside code can name the states but never add one.

mod sealed {
    pub trait Sealed {}
}

/// Compile-time session state. `NAME` is the wire value `status` reports.
pub trait SessionState: sealed::Sealed + Send + Sync + 'static {
    const NAME: &'static str;
}

/// No Hatari process exists.
#[derive(Debug)]
pub struct Stopped;

/// Hatari is running (emulation advancing).
#[derive(Debug)]
pub struct Running;

/// Hatari is frozen — the freezer-cartridge "freeze then rip" state.
#[derive(Debug)]
pub struct Paused;

impl sealed::Sealed for Stopped {}
impl sealed::Sealed for Running {}
impl sealed::Sealed for Paused {}

impl SessionState for Stopped { const NAME: &'static str = "stopped"; }
impl SessionState for Running { const NAME: &'static str = "running"; }
impl SessionState for Paused  { const NAME: &'static str = "paused";  }
```

(`Booting` from the ARCHITECTURE diagram is **not** a type-state: it is
transient inside P1's `start()` and never observable between calls. Do not
add it.)

### 7.2 `src/session/mod.rs` — `SessionConfig` + `Session<S>`

```rust
pub mod state;
pub use state::{Paused, Running, SessionState, Stopped};

use std::marker::PhantomData;
use std::path::PathBuf;

use crate::error::Error;

/// How to launch Hatari. P0 carries only the binary path; P1 extends this
/// with TOS/harddrive/machine flags (DEBUG.md reference invocation).
#[derive(Debug, Clone)]
pub struct SessionConfig {
    pub hatari_path: PathBuf,
}

impl Default for SessionConfig {
    // Given in full — the default path is contractual:
    fn default() -> Self {
        Self { hatari_path: PathBuf::from("/usr/bin/hatari") }
    }
}

/// A Hatari session in compile-time-known state `S` (ADR-3). Transitions
/// consume `self`; a method that does not exist on a state is a compile
/// error, not a runtime check.
#[derive(Debug)]
pub struct Session<S: SessionState> {
    config: SessionConfig,
    _state: PhantomData<S>,
}

// ---- available in every state ----
impl<S: SessionState> Session<S> {
    /// The state name as reported by the `status` tool.
    pub fn state_name(&self) -> &'static str; // impl: S::NAME
    pub fn config(&self) -> &SessionConfig;   // impl: &self.config
}

// ---- Stopped ----
impl Session<Stopped> {
    /// The only public entry point into the FSM.
    pub fn new(config: SessionConfig) -> Self;
    // impl: Self { config, _state: PhantomData }

    /// Spawn Hatari and gate on the sentinel round-trip (P1). On failure the
    /// session is returned so it is never lost (ADR-3 error shape).
    pub fn start(self) -> Result<Session<Running>, (Session<Stopped>, Error)>;
    // impl (P0 placeholder — EXACTLY this, no todo!()):
    //   Err((self, Error::Session("start is deferred to P1".to_string())))
}

// ---- Running ----
impl Session<Running> {
    /// Freeze emulation (P1: `hatari-stop` via fifo).
    pub fn pause(self) -> Result<Session<Paused>, (Session<Running>, Error)>;
    // impl (P0 placeholder):
    //   Err((self, Error::Session("pause is deferred to P1".to_string())))

    /// Kill + reap Hatari. Infallible by design: P1 does best-effort kill
    /// (RAII `Drop` as last resort) and logs failures — a session must
    /// always be stoppable. Implemented for real in P0 (pure transition).
    pub fn stop(self) -> Session<Stopped>;
    // impl: Session { config: self.config, _state: PhantomData }
}

// ---- Paused ----
impl Session<Paused> {
    /// Unfreeze (P1: `hatari-cont`).
    pub fn resume(self) -> Result<Session<Running>, (Session<Paused>, Error)>;
    // impl (P0 placeholder):
    //   Err((self, Error::Session("resume is deferred to P1".to_string())))

    /// Same contract as `Session<Running>::stop`.
    pub fn stop(self) -> Session<Stopped>;
    // impl: Session { config: self.config, _state: PhantomData }
}
```

Placeholder rules (blocking): the three deferred methods (`start`, `pause`,
`resume`) return **exactly** the `Err((self, Error::Session(...)))` values
shown — the exact message strings `"start is deferred to P1"`,
`"pause is deferred to P1"`, `"resume is deferred to P1"`. Never `todo!()`,
`unimplemented!()`, or `panic!()` (the `[lints.clippy]` denials enforce this).
`stop()` is *not* deferred — its P0 body (drop nothing, carry the config to
`Stopped`) is already its final pure-FSM semantics.

### 7.3 `AnySession` — runtime dispatch (same file, `src/session/mod.rs`)

```rust
/// Runtime-dispatch wrapper for the tool layer (ADR-3): MCP tools cannot
/// know the state at compile time, so they hold this enum behind a
/// `tokio::sync::Mutex` and match. Each arm only exposes what that state's
/// `Session<S>` legally offers — the enum gives dispatch, the type-state
/// gives safety.
#[derive(Debug)]
pub enum AnySession {
    Stopped(Session<Stopped>),
    Running(Session<Running>),
    Paused(Session<Paused>),
}

impl AnySession {
    /// Fresh session in `Stopped`.
    pub fn new(config: SessionConfig) -> Self;
    // impl: AnySession::Stopped(Session::new(config))

    /// "stopped" | "running" | "paused" — delegates to the inner
    /// `state_name()`, never re-derives the string.
    pub fn state_name(&self) -> &'static str;
    // impl: match each arm, call .state_name()

    pub fn config(&self) -> &SessionConfig;
    // impl: match each arm, call .config()
}
```

**Transition pattern (documented now, used from P1):** mutating tools will
`let mut guard = mutex.lock().await;` then move the session out with
`std::mem::replace(&mut *guard, AnySession::new(config_clone))`, run the
consuming transition, and write the result back. P0 must include this as a
doc comment on `AnySession` (so P1 doesn't invent a second pattern), but P0
implements **no** mutating dispatch — `status` only reads.

## 9. Tool layer

### 9.1 `src/tools/mod.rs` — server struct + `ServerHandler`

We need a custom `get_info` (server name `shiraz-mcp`, instructions), so we
use the **explicit** pair from `rmcp-2.2-notes.md`: `#[tool_router]` on the
tools impl (§9.2) + `#[tool_handler]` on our own `ServerHandler` impl — NOT
the `#[tool_router(server_handler)]` shorthand (that auto-emits a default
`ServerHandler`, which would conflict with ours).

```rust
pub mod lifecycle;

use std::sync::Arc;

use rmcp::model::{Implementation, ServerCapabilities, ServerInfo};
use rmcp::{tool_handler, ServerHandler};
use tokio::sync::Mutex;

use crate::session::{AnySession, SessionConfig};

/// The MCP server: thin adapter over the layers (no business logic here —
/// ARCHITECTURE.md `tools/` contract). Single session for v1.
#[derive(Clone)]
pub struct HatariServer {
    session: Arc<Mutex<AnySession>>,
}

impl HatariServer {
    pub fn new(config: SessionConfig) -> Self;
    // impl: Self { session: Arc::new(Mutex::new(AnySession::new(config))) }
}

#[tool_handler]
impl ServerHandler for HatariServer {
    fn get_info(&self) -> ServerInfo {
        // Given in full — the wire identity is contractual. Builders only:
        // these model types are #[non_exhaustive] (rmcp-2.2-notes.md).
        ServerInfo::new(ServerCapabilities::builder().enable_tools().build())
            .with_server_info(Implementation::new(
                "shiraz-mcp",
                env!("CARGO_PKG_VERSION"),
            ))
            .with_instructions(
                "Drives the Hatari Atari ST emulator. P0 scaffold: only \
                 `status` is available; lifecycle/debug/rip tools arrive in \
                 later phases.",
            )
    }
}
```

`#[tool_handler]`'s default router expression is `Self::tool_router()`
(generated by `#[tool_router]` in `lifecycle.rs`), so **no `tool_router`
field is needed** on the struct. Do not use `Implementation::from_build_env()`
— it would report the crate name `shiraz_mcp` (underscore); the wire name is
`shiraz-mcp`.

### 9.2 `src/tools/lifecycle.rs` — the `status` tool

```rust
use rmcp::handler::server::wrapper::Json;
use rmcp::{tool, tool_router, ErrorData as McpError};
use schemars::JsonSchema;
use serde::Serialize;

use super::HatariServer;

/// Wire shape of `status`. Field names are the JSON contract.
#[derive(Debug, Serialize, JsonSchema)]
pub struct StatusOutput {
    /// "stopped" | "running" | "paused"
    pub state: String,
    /// Configured Hatari binary path (not yet validated to exist in P0).
    pub hatari_path: String,
    /// This server's crate version.
    pub version: String,
}

#[tool_router]
impl HatariServer {
    /// Given in full — this is the entire P0 tool surface:
    #[tool(
        name = "status",
        description = "Report emulator session status: current state \
                       (stopped|running|paused), configured Hatari binary \
                       path, and server version."
    )]
    pub async fn status(&self) -> Result<Json<StatusOutput>, McpError> {
        let session = self.session.lock().await;
        Ok(Json(StatusOutput {
            state: session.state_name().to_string(),
            hatari_path: session.config().hatari_path.display().to_string(),
            version: env!("CARGO_PKG_VERSION").to_string(),
        }))
    }
}
```

`status` takes **no parameters** (no `Parameters<..>` argument). It cannot
fail today, but the `Result<Json<T>, McpError>` shape is the standard tool
signature from `rmcp-2.2-notes.md` §Tool registration — every future tool
uses it, so P0 sets the precedent (P1+ maps `crate::error::Error` →
`McpError` at this boundary with a generic message; no internal detail
leakage). Registration is the `#[tool]` attribute inside the
`#[tool_router]` impl block — there is no separate registration call in
`main.rs`; `#[tool_handler]` (§9.1) wires `tools/list` + `tools/call` to
this router. Future phases add one `#[tool_router(router = <name>_router)]`
block per tools file and combine routers with `+` — do not restructure for
that now.

### 10.4 `tests/mcp_handshake.rs` — stdio JSON-RPC integration test

// impl: Command::new(env!("CARGO_BIN_EXE_shiraz-mcp"))

Exact wire exchange (requests verbatim, one line each):

1. Send:
   ```json
   {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"handshake-test","version":"0.0.0"}}}
   ```
   Receive one response; assert: `resp["id"] == 1`,
   `resp["result"]["serverInfo"]["name"] == "shiraz-mcp"`,
   `resp["result"]["serverInfo"]["version"] == env!("CARGO_PKG_VERSION")`,
   `resp["result"]["capabilities"]["tools"]` is present (not `Null`).
   Do **not** assert the returned `protocolVersion` string (server may
   negotiate a different revision).
2. Send (notification — no response expected):
   ```json
   {"jsonrpc":"2.0","method":"notifications/initialized"}
   ```
3. Send:
   ```json
   {"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}
   ```
   Receive; assert: `resp["id"] == 2`, `resp["result"]["tools"]` is an array
   of length **1**, `tools[0]["name"] == "status"`,
   `tools[0]["inputSchema"]["type"] == "object"`.
4. Send:
   ```json
   {"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"status","arguments":{}}}
   ```
   Receive; assert: `resp["id"] == 3`,
   `resp["result"]["structuredContent"]["state"] == "stopped"`,
   `resp["result"]["structuredContent"]["hatari_path"] == "/usr/bin/hatari"`,
   `resp["result"]["structuredContent"]["version"] == env!("CARGO_PKG_VERSION")`.
5. Kill the child (`child.kill().await` — `kill_on_drop` is the backstop).

*Implementation note:* `Json<T>` surfaces as `structuredContent` per the MCP
spec (`rmcp-2.2-notes.md` §Tool registration). If step 4's assertion fails
because rmcp additionally/instead puts the JSON in
`result["content"][0]["text"]`, parse that text as JSON and assert the same
three fields — keep whichever location rmcp actually uses and note it in a
one-line comment in the test. Everything else is fixed.

This test needs no Hatari and no display — it is NOT `#[ignore]`d.
