> Executable spec for **rust-engineer**. Zero design decisions are left open:
> where this document says something, do exactly that. If reality contradicts
> this spec, stop and flag to rust-architect. Scope guard: **no ripper
> changes, no session/FSM changes, no debug-layer changes, no watchpoints, no

`TODO.md` §"Missing RE primitives" → `ARCHITECTURE.md` → `decisions.md`
(ADR-5, ADR-9, ADR-10 are the ones P15 leans on). This spec expands them; it

snapshots; `cheat_scan` itself never changes session state. Implement P15 in
either order relative to P14.

## 1. Deliverable in one sentence

One grouped MCP tool, **`cheat_scan(action = new | filter | list | reset)`**,
implementing the classic Action-Replay variable hunt: `new` snapshots RAM and
seeds a candidate set (all addresses, or narrowed by an initial `eq`/`ne`
predicate, optionally region-bounded); after the agent lets the machine run,
`filter` re-snapshots and keeps only candidates matching a predicate against
the previous snapshot (`changed` / `unchanged` / `increased` / `decreased` /
`eq` / `ne` / `delta`); `list` pages the survivors (address + value) for
hand-off to `write_memory` / `watch` — all diff/compare logic living in a
pure, emulator-free engine (`analyze/`), with the candidate set + last
snapshot held as server state exactly like the rip `ScanStore` (ADR-10), and
results always returned as **count + a capped sample**, never a dump (ADR-5).

The workflow this enables (finding the MJJ scroll cursor, a lives counter, a
timer — with NO disassembly):

```
cheat_scan(action="new", width=4)              # snapshot; ~2M candidates
run_frames(5)   (or resume; …; pause)          # let it run
cheat_scan(action="filter", predicate="changed")   # → 40k candidates
run_frames(5)
cheat_scan(action="filter", predicate="changed")   # → 900
run_frames(50)
cheat_scan(action="filter", predicate="increased") # → 12
cheat_scan(action="list")                          # addr + value each
# → read_memory / watch / write_memory the survivors
```

## 3. Design decisions (already made — do not revisit)

1. **One grouped tool with an `action` param, not four tools.** Precedent:
   `breakpoint` and `state` (P2) group related verbs behind one `action` to
   conserve tool-surface context (ARCHITECTURE.md `tools/` contract). The
   four actions share one input/output schema and one store; four separate
   tools would quadruple schema tokens for zero capability. `rip`'s
   plural-tool shape does not apply — `extract`/`list_ripper_plugins` have
   disjoint schemas; `cheat_scan`'s actions do not.
2. **Candidate set = a flat bitset over snapshot offsets** (`Vec<u64>`, one
   bit per byte offset = start address of a candidate value). For a 4 MiB
   snapshot that is 512 KiB **regardless of candidate count** — the initial
   "all addresses" set (~2–4 M candidates) costs the same as a
   narrowed-to-3 set. A sorted `Vec<u32>` would cost 8–16 MiB at seed time
   and churn on every filter; per-address structs are out of the question
   (ADR-5 thinking applied server-side). Iteration is ascending-by-address
   for free (word walk + `trailing_zeros`), which `list` pagination needs.
3. **Widths are 1/2/4 bytes, big-endian, and word/long candidates are
   even-aligned.** A 68000 word/long access to an odd address raises an
   address-error exception — an odd-address word variable **cannot exist**
   on this machine, so odd starts are excluded at seed time (halves the
   set). Byte width scans every address. Alignment is computed on the
   **absolute bus address** (`base + offset`), not the offset (the engine
   is general even though `acquire` always has base `$0`).
4. **The whole previous snapshot is stored, not per-candidate values.**
   `MemImage` (≤ 4 MiB) + the bitset (≤ 512 KiB) is bounded, simple, and
   makes every predicate O(candidates) with no per-candidate bookkeeping.
   Mirrors ADR-10's "retain one scan's source buffers" trade-off; replaced
   wholesale on every `filter`, dropped on `reset`/`new`.
5. **The diff engine is pure and lives in `analyze/`.** `analyze/` is the
   layer for pure computation over a `MemImage` (disasm, cycles, annotate —
   ARCHITECTURE.md); `cheatscan` reads two snapshots and a bitset, touches
   nothing else, and is fully unit-testable on synthetic byte buffers with
   NO emulator. The tool layer does choreography only: acquire → call pure
   engine → page. Filtering 4 MiB is a single linear pass (< ~10 ms) — run
   it **inline, synchronously**: no `spawn_blocking`, no `rayon` (measured
   class of work; the rip registry uses `spawn_blocking` because plugin
   sweeps are 100× heavier).
6. **`cheat_scan` never changes session state.** Snapshots are valid in
   Running or Paused exactly like `search_memory`/`rip` (ADR-9;
   `session/memory.rs` doc). Paused gives a coherent snapshot; the tool
   description tells the agent to freeze (or use `run_frames`, which ends
   Paused) before `new`/`filter` for deterministic results, but does not
   enforce it — a mid-frame snapshot merely adds noise candidates that the
   next filter removes. This keeps the tool state-neutral and trivially
   composable with P14.
7. **Store shape mirrors `ScanStore` exactly** (ADR-10): a single
   `Option<CheatStore>` in a **std** Mutex on `HatariServer`, locked only
   for brief non-`await` critical sections (the tokio session mutex remains
   the only lock held across `.await`); a `search_id` sequence; stale/no-
   session errors phrased and mapped like `resolve_finding`'s
   (`invalid_params`). `new` replaces any existing search — one search at a
   time, like one rip scan at a time.
8. **`list` is pure over the store** — values come from the **last stored
   snapshot**, no emulator I/O, works even when the session is Stopped.
   "Current" values are one `read_memory` away; `filter` is the operation
   that refreshes. This keeps `list` free (paginate at will, zero
   round-trips) and its meaning exact: "the survivors, as of the last
   snapshot".

## 4. Predicate semantics (exact — this table is the contract)

Values are the **big-endian unsigned** integer of `width` bytes at the
candidate's offset. `old` = value in the stored (previous) snapshot, `new` =
value in the freshly acquired snapshot, `x` = the agent-supplied value.

| Predicate | Keeps candidate iff | Value arg | Valid on |
|---|---|---|---|
| `changed`   | `new != old` | forbidden | filter |
| `unchanged` | `new == old` | forbidden | filter |
| `increased` | `new > old` (**unsigned**) | forbidden | filter |
| `decreased` | `new < old` (**unsigned**) | forbidden | filter |
| `eq`        | `new == x` | required, unsigned, must fit width | new, filter |
| `ne`        | `new != x` | required, unsigned, must fit width | new, filter |
| `delta`     | `(new as i64) − (old as i64) == n` | required, **signed**, `|n|` must fit width | filter |

Pinned consequences (unit-tested in §9.1):

- `increased`/`decreased` do **not** see through wrapping: a word going
  `$FFFF → $0000` is `decreased`, not increased. (Matches every classic
  cheat engine; documented in the tool description.)
- `delta` is exact i64 arithmetic, **no wrapping**: a byte going
  `$FF → $00` matches `delta(-255)`, not `delta(1)`. Documented.
- `delta(0)` is legal and equivalent to `unchanged`.
- On `new`, only `eq`/`ne` are accepted (there is no previous snapshot);
  any other predicate → `invalid_params` (§8). Omitting the predicate on
  `new` seeds **all** aligned addresses in the region.
- On `filter`, `predicate` is **required**.

Value argument grammar (pinned): `$` or `0x`/`0X` prefix ⇒ hex, else
decimal — same prefixes as `Addr::parse` but **without** the 24-bit cap
(values range over the full width: `$FFFFFFFF` is a legal long value).
`delta` additionally accepts one leading `-` before the prefix/digits.
Range checks: `eq`/`ne` value ≤ `0xFF` / `0xFFFF` / `0xFFFF_FFFF` per width;
`delta` `|n|` ≤ the same bound (a byte can change by at most ±255). Violations
→ `invalid_params` naming the width and the bound.

### 5.2 `src/analyze/cheat_set.rs` — `CandidateSet`

```rust
//! Memory-change-scan candidate set (P15): one bit per snapshot byte
//! offset (bit set = a candidate value STARTS there). Fixed 1 bit/byte —
//! 512 KiB for a 4 MiB snapshot regardless of how many candidates remain —
//! with ascending-offset iteration for free. Pure; no emulator, no I/O.

/// Bit `i` ⇔ snapshot offset `i` is a live candidate.
#[derive(Debug, Clone)]
pub struct CandidateSet {
    bits: Vec<u64>,   // ceil(capacity / 64) words
    capacity: usize,  // snapshot length the set was built for
    count: u64,       // maintained by insert/retain — never recomputed by scan
}

impl CandidateSet {
    /// Empty set over a snapshot of `capacity` bytes.
    pub fn new(capacity: usize) -> Self;
    /// Number of live candidates. O(1).
    pub fn count(&self) -> u64;
    /// The snapshot length this set indexes into.
    pub fn capacity(&self) -> usize;
    /// Set bit `off`. No-op if already set. Panics in debug if `off >= capacity`.
    pub fn insert(&mut self, off: usize);
    pub fn contains(&self, off: usize) -> bool;
    /// Clear every candidate for which `keep(offset)` is false. One linear
    /// word walk; per set word, iterate set bits via `trailing_zeros`.
    pub fn retain(&mut self, keep: impl FnMut(usize) -> bool);
    /// Ascending offsets of live candidates.
    pub fn iter(&self) -> impl Iterator<Item = usize> + '_;
}
```

Implementation notes (pinned):

- `iter` = `bits.iter().enumerate().flat_map(word-bit walk)` using
  `trailing_zeros` + clear-lowest-bit (`w &= w - 1`) on a local copy — no
  allocation, no per-empty-word cost beyond the word test.
- `retain` walks the same way, clearing bits in place and decrementing
  `count`. Both loops ≤ 30 lines via a shared private
  `fn for_each_set_bit(word: u64, base: usize, f: impl FnMut(usize))`
  helper if needed.
- No `Deref`, no `Index` — this is not a smart pointer.

### 5.3 `src/analyze/cheatscan.rs` — widths, predicates, seed, filter

```rust
//! The memory-difference search engine (P15): seed a candidate set from
//! one snapshot, then iteratively filter it against snapshot pairs. Pure
//! over `MemImage` + `CandidateSet` — NEVER touches the emulator; fully
//! unit-tested on synthetic buffers. Big-endian values; word/long
//! candidates are even-aligned (a 68000 word access to an odd address is
//! an address error — such a variable cannot exist).

use crate::analyze::cheat_set::CandidateSet;
use crate::types::MemImage;

/// Candidate value width. `repr` chosen so `bytes()` is trivially const.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Width { Byte, Word, Long }

impl Width {
    pub const fn bytes(self) -> usize;          // 1 | 2 | 4
    /// Max unsigned value representable (0xFF / 0xFFFF / 0xFFFF_FFFF).
    pub const fn max_value(self) -> u32;
    /// 1|2|4 → Some(width), else None (wire layer maps None → invalid_params).
    pub const fn from_bytes(n: u32) -> Option<Width>;
}

/// Filter predicates — semantics pinned in §4's table, verbatim.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Predicate {
    Changed, Unchanged, Increased, Decreased,
    Eq(u32), Ne(u32), Delta(i64),
}

/// The only predicates legal at seed time (no previous snapshot exists) —
/// a separate type so "changed on new" is unrepresentable past the wire.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SeedFilter { Eq(u32), Ne(u32) }

/// Big-endian unsigned value of `width` bytes at `off`.
/// Precondition (caller-guaranteed, debug_assert): off + width.bytes() <= bytes.len().
pub fn read_value(bytes: &[u8], off: usize, width: Width) -> u32;

/// Seed a candidate set from `mem`: every offset `o` in
/// `[start_off, end_off)` with `o + width.bytes() <= end_off`, where
/// `mem.base().raw() + o` is even for Word/Long (any parity for Byte),
/// and — if `f` is Some — the §4 seed predicate holds for the value at `o`.
/// `start_off`/`end_off` are snapshot offsets already clamped to
/// `[0, mem.len()]` by the caller (debug_assert both).
pub fn seed(mem: &MemImage, width: Width, f: Option<SeedFilter>,
            start_off: usize, end_off: usize) -> CandidateSet;

/// One narrowing step: drop every candidate that does not satisfy `pred`
/// for (old, new) per §4. Preconditions (caller-validated, debug_assert):
/// old.len() == new.len() == set.capacity(), old.base() == new.base().
pub fn filter(set: &mut CandidateSet, old: &MemImage, new: &MemImage,
              width: Width, pred: Predicate);
```

Implementation notes (pinned):

- `filter` = `set.retain(|o| eval(pred, read_value(old…), read_value(new…)))`
  with a private `fn eval(pred: Predicate, old: u32, new: u32) -> bool`
  that is a 9-arm `match` transcribing §4's table literally. `eval` is
  where every §9.1 predicate test points.
- `seed` = one loop over `start_off..end_off` stepping by 1 (Byte) or
  aligned-evens (Word/Long: start at the first offset whose absolute
  address is even, step 2). Bound: `o + width.bytes() <= end_off`.
- No `Result` anywhere in this file — all inputs are pre-validated by the
  wire layer; contract violations are `debug_assert!`s. Pure functions,
  no hidden state, no I/O (the "power ripper" code-API property from
  `docs/BRAINSTORM.md` — callable in a loop server-side).

## 6. Server state — `CheatStore`

Lives in `cheat_wire.rs` (§7.3), mirroring `ScanStore` in `rip_wire.rs`:

```rust
/// The one in-flight cheat search (ADR-10 pattern: single store, replaced
/// by `new`, cleared by `reset`). `snapshot` is the LAST acquired image —
/// what `filter` compares against and `list` reads values from.
#[derive(Debug)]
pub(crate) struct CheatStore {
    pub search_id: u64,
    pub width: Width,
    /// Narrowing steps applied so far: 0 after `new`, +1 per `filter`.
    pub step: u32,
    pub candidates: CandidateSet,
    pub snapshot: MemImage,
}
```

`HatariServer` (`tools/mod.rs`) gains two fields, declared and constructed
exactly like `last_scan`/`scan_seq` (same comment style, same
`Arc<StdMutex<Option<…>>>` + `Arc<AtomicU64>`):

```rust
/// P15: the in-flight cheat search (candidate set + last snapshot) —
/// std Mutex for brief non-await sections, like `last_scan` (ADR-10).
cheat: Arc<StdMutex<Option<CheatStore>>>,
cheat_seq: Arc<AtomicU64>,
```

Locking discipline (pinned, matches `rip.rs`): acquire the RAM snapshot
under the **tokio** session lock, drop it, then lock the **std** `cheat`
mutex for the pure seed/filter/page work only — never both at once with the
std lock outer, never the std lock across an `.await`. Poison handling:
`unwrap_or_else(PoisonError::into_inner)` (the `store_scan` precedent).

Memory bound (state in the field comment): ≤ 4 MiB snapshot + ≤ 512 KiB
bitset, one search at a time — dropped on `reset`, replaced on `new`.

## 7. Tool layer

### 7.1 Tool surface — one tool, four actions

Parameter validity matrix (pinned — violations are `invalid_params` with a
message naming the offending param and action):

| param | `new` | `filter` | `list` | `reset` |
|---|---|---|---|---|
| `predicate` | optional (`eq`/`ne` only) | **required** (any of §4) | forbidden | forbidden |
| `value` | required iff predicate given | required iff predicate is eq/ne/delta, else forbidden | forbidden | forbidden |
| `width` | optional, 1\|2\|4, default 2 | forbidden ("width is fixed at action=new") | forbidden | forbidden |
| `start` / `end` | optional (region bound) | forbidden | forbidden | forbidden |
| `limit` / `offset` | limit only (sample cap) | limit only (sample cap) | both (pagination) | forbidden |

### 7.2 `src/tools/cheat.rs` — the tool

```rust
// Re-exported for the live test (tests/cheat_live.rs), the mem/mod.rs
// ReadMemoryArgs precedent:
pub use super::cheat_wire::{CandidateOut, CheatScanArgs, CheatScanOutput};

#[tool_router(router = cheat_router, vis = "pub(crate)")]
impl HatariServer {
    #[tool(name = "cheat_scan", description = "…§7.2.1 verbatim…")]
    pub async fn cheat_scan(
        &self,
        Parameters(a): Parameters<CheatScanArgs>,
    ) -> Result<Json<CheatScanOutput>, McpError> { … }
}
```

Method body: parse `action` (`cheat_wire::parse_action`), dispatch to four
private `impl HatariServer` helpers, each ≤ 30 lines:

**`cheat_new(a)`**
1. Validate per §7.1: `width = Width::from_bytes(a.width.unwrap_or(2))`
   else `invalid_params("width must be 1, 2 or 4")`; seed filter =
   `cheat_wire::seed_filter(&a, width)?` (parses predicate+value, §7.3);
   `limit = a.limit.unwrap_or(SAMPLE_DEFAULT).min(SAMPLE_MAX)`.
2. Acquire: lock session (tokio), `state_name`/`process_mut` else
   `wrong_state(name, "running or paused")`, `memory::acquire(proc)`
   (`to_mcp`), drop the session lock. (Identical shape to
   `rip::acquire_snapshot`, minus the out_dir.)
3. Clamp region: reuse the `search_memory` semantics — parse optional
   `start`/`end` with `mem::scan::parse_addr`, clamp both to
   `[mem.base(), base + len]`, convert to offsets; if `start_off >
   end_off`, treat as an empty region (seed returns an empty set), not an
   error (the `window_slice` precedent).
4. `search_id = self.cheat_seq.fetch_add(1, Ordering::Relaxed) + 1`;
   `candidates = analyze::seed(&mem, width, filter, start_off, end_off)`.
5. Build the sample page (offset 0) from `candidates` + `mem` (§7.3
   `page_candidates`), then lock `self.cheat` and replace the store with
   `CheatStore { search_id, width, step: 0, candidates, snapshot: mem }`.
6. Output §7.3 with `action:"new"`, `count`, `prev_count: None`.

**`cheat_filter(a)`**
1. Validate per §7.1; `pred = cheat_wire::predicate(&a, /*width from
   store — see step 3*/)` needs the width, so parse in two phases: reject
   forbidden params first, defer value-range checking to step 3.
2. Acquire a fresh snapshot exactly as `cheat_new` step 2.
3. Lock `self.cheat` (std). `None` →
   `invalid_params("no cheat search in memory: run cheat_scan(action=\"new\") first")`.
   Snapshot geometry check: `new.len() != store.snapshot.len() ||
   new.base() != store.snapshot.base()` →
   `invalid_params("snapshot geometry changed (session restarted with a
   different memory size?) — start a new search with action=\"new\"")`.
   Now parse predicate+value against `store.width` (§4 range checks).
4. `prev_count = store.candidates.count()`;
   `analyze::filter(&mut store.candidates, &store.snapshot, &new,
   store.width, pred)`; `store.snapshot = new`; `store.step += 1`.
5. Page sample (offset 0) from the updated store; output with
   `action:"filter"`, `count`, `prev_count: Some(prev_count)`,
   `predicate: Some(<canonical string>)`.

**`cheat_list(a)`** — no session lock at all (design decision 8):
1. Validate; `limit`/`offset` default `SAMPLE_DEFAULT`/`0`.
2. Lock `self.cheat`; `None` → the same no-search `invalid_params`.
3. Page from the store at `offset`; output `action:"list"`, `count`.

**`cheat_reset(a)`** — no session lock:
1. Validate (no params allowed but the action).
2. Lock `self.cheat`, `guard.take()`; output `action:"reset"`,
   `cleared: Some(bool)` (true iff a store existed), everything else
   absent, `sample` empty.

#### 7.2.1 Tool description (verbatim)

*"Iterative memory-change search over ST RAM — the Action-Replay way to
find a variable (lives, timer, scroll cursor) with NO disassembly.
action=new: snapshot RAM and seed candidates (every byte/word/long start —
words/longs even-aligned — optionally region-bounded with start/end, or
pre-narrowed with predicate eq/ne + value). Then let the machine run
(run_frames, or resume+pause) and action=filter with a predicate vs the
previous snapshot: changed | unchanged | increased | decreased | eq | ne |
delta (value; delta is signed and exact — a byte wrapping $FF→$00 is
delta -255). Repeat until few remain; action=list pages survivors
(address + value from the last snapshot) — hand them to
read_memory/watch/write_memory. Comparisons are big-endian unsigned; width
(1/2/4, default 2) is fixed at action=new. Returns count + a capped sample,
never a dump. Snapshots work Running or Paused; pause (or run_frames, which
ends paused) for frame-exact narrowing. list/reset never touch the
emulator. One search at a time; new replaces it, reset discards it."*

### 7.3 `src/tools/cheat_wire.rs` — wire schema + store + pure helpers

Constants: `pub(crate) const SAMPLE_DEFAULT: u32 = 16;`
`pub(crate) const SAMPLE_MAX: u32 = 64;` (the `search_memory` limits — a
candidate row is the same token weight as a search hit).

```rust
#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
pub struct CheatScanArgs {
    /// "new" (snapshot + seed) | "filter" (re-snapshot + narrow) |
    /// "list" (page survivors) | "reset" (discard the search).
    pub action: String,
    /// filter: changed|unchanged|increased|decreased|eq|ne|delta.
    /// new (optional): eq|ne only.
    pub predicate: Option<String>,
    /// For eq/ne (unsigned) and delta (signed): "$1F40", "0x1f40", "8000",
    /// delta also "-1". Must fit the search width.
    pub value: Option<String>,
    /// Value width in bytes: 1, 2 (default) or 4. action=new only; fixed
    /// for the life of the search.
    pub width: Option<u32>,
    /// Region bound for action=new (default: all RAM). Address forms as
    /// read_memory.
    pub start: Option<String>,
    pub end: Option<String>,
    /// Sample/page size (default 16, max 64).
    pub limit: Option<u32>,
    /// action=list: skip the first N survivors (pagination).
    pub offset: Option<u32>,
}

#[derive(Debug, serde::Serialize, schemars::JsonSchema)]
pub struct CandidateOut {
    /// Bus address, "$0004BA" form.
    pub addr: String,
    /// Value in the LAST snapshot, "$xx"/"$xxxx"/"$xxxxxxxx" (2×width
    /// lowercase hex digits).
    pub value: String,
    /// ST hardware/sysvar names covering [addr, addr+width) — same
    /// enrichment as read_memory.
    pub annotations: Vec<super::mem::types::AnnotationOut>,
}

#[derive(Debug, serde::Serialize, schemars::JsonSchema)]
pub struct CheatScanOutput {
    pub action: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub search_id: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub width: Option<u32>,
    /// Narrowing steps applied so far (0 right after new).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub step: Option<u32>,
    /// Surviving candidates (the headline number).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub count: Option<u64>,
    /// Count before this filter step (filter only).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub prev_count: Option<u64>,
    /// Canonical predicate applied (filter only), e.g. "delta(-1)".
    #[serde(skip_serializing_if = "Option::is_none")]
    pub predicate: Option<String>,
    /// Capped sample of survivors, ascending by address.
    pub sample: Vec<CandidateOut>,
    /// Sample's start position within the survivor list.
    #[serde(skip_serializing_if = "Option::is_none")]
    pub offset: Option<u32>,
    /// More survivors exist past this sample/page.
    pub has_more: bool,
    /// reset only: whether a search existed to clear.
    #[serde(skip_serializing_if = "Option::is_none")]
    pub cleared: Option<bool>,
}
```

| new | search_id, width, step=0, count, sample, offset=0, has_more |

Pure helpers (all `pub(crate)`, all unit-tested in §9.2):

```rust
/// "new"|"filter"|"list"|"reset" (case-sensitive) → enum; else Err(String)
/// for invalid_params ("unknown action 'x': use new|filter|list|reset").
pub(crate) enum Action { New, Filter, List, Reset }
pub(crate) fn parse_action(s: &str) -> Result<Action, String>;

/// §4's value grammar: unsigned ($/0x/decimal, ≤ width.max_value()).
pub(crate) fn parse_value(s: &str, width: Width) -> Result<u32, String>;
/// Signed variant for delta (optional leading '-', |n| ≤ width.max_value()).
pub(crate) fn parse_delta(s: &str, width: Width) -> Result<i64, String>;

/// (predicate, value) args → Predicate, enforcing §4's value rules.
pub(crate) fn predicate(pred: &str, value: Option<&str>, width: Width)
    -> Result<Predicate, String>;
/// new-action variant: eq/ne only, else Err("predicate 'changed' needs a
/// previous snapshot — only eq/ne are valid with action=\"new\"").
pub(crate) fn seed_filter(pred: Option<&str>, value: Option<&str>, width: Width)
    -> Result<Option<SeedFilter>, String>;

/// Canonical predicate echo: "changed", "eq($1f40)", "delta(-1)".
pub(crate) fn predicate_str(p: Predicate) -> String;

/// "$xxxx": lowercase hex zero-padded to 2×width.bytes() digits.
pub(crate) fn format_value(v: u32, width: Width) -> String;

/// One output page: walk `set.iter().skip(offset).take(limit)`, read each
/// value from `snap`, map to CandidateOut (annotations via
/// mem::scan::annotations_for(addr, width.bytes())); has_more = a further
/// `.next()` yields Some. ≤ 30 lines.
pub(crate) fn page_candidates(set: &CandidateSet, snap: &MemImage,
    width: Width, offset: u32, limit: u32) -> (Vec<CandidateOut>, bool);
```

## 10. Token-efficiency invariants (ADR-5 — checked in review)

- No action ever returns more than `SAMPLE_MAX` (64) candidate rows; the
  headline datum is always `count`, a single number.
- `list` pagination is offset-based against a server-held set — paging
  costs zero emulator round-trips and zero re-scans.
- The 4 MiB snapshots never cross the wire in any form; they live and die
  in `CheatStore`.
- The narrowing loop is agent-driven but each step is ONE tool call doing
  the full server-side pass (snapshot + compare + count) — never
  per-address tool calls.

## 13. Proposed ADR — append to `decisions.md`

Number it with the **actual next-free ADR number in `decisions.md` at
implementation time** (≈ADR-27 — the file is at ADR-23 today and P12/P13/P14
append theirs as they land, so do not trust a fixed number; check the file,
then use that number in the title and anywhere this spec's artifacts
reference it). Template:

> ## 2026-07-XX — ADR-NN: cheat_scan — iterative memory-change search over server-held snapshot pairs
>
> **Status:** accepted
> **Context:** The live-patch exercise (docs/live-patching.md §"What was
> missing" item 4) identified the classic Action-Replay "cheat search" as a
> missing RE primitive: find a variable (scroll cursor, lives, timer) by
> snapshot → run → diff, with no disassembly. A naive design would ship
> memory dumps or thousands of addresses to the agent (ADR-5 violation) or
> keep per-address state (unbounded).
> **Decision:** One grouped tool `cheat_scan(action=new|filter|list|reset)`
> (the `breakpoint`/`state` action-param precedent). The engine
> (`analyze/cheatscan.rs` + `cheat_set.rs`) is pure over `MemImage` pairs —
> emulator-free, unit-tested on synthetic buffers. Candidates are a flat
> bitset over snapshot offsets (1 bit/byte start address: ≤512 KiB for
> 4 MiB RAM regardless of survivor count, ascending iteration for free);
> word/long candidates are even-aligned because odd-address 68000 word
> accesses are address errors — such variables cannot exist. Values are
> big-endian unsigned of width 1/2/4 fixed at `new`; predicates are
> changed/unchanged/increased/decreased (unsigned, wrap-blind) and
> eq/ne/delta (delta = exact i64 difference, no wrapping). Server state is
> one `CheatStore` (candidate set + the full last snapshot, ≤4.5 MiB) in a
> std Mutex mirroring the rip `ScanStore` (ADR-10): single search, `new`
> replaces, `reset` clears, stale/no-search → invalid_params. Every result
> is count + a ≤64-row sample (ADR-5); `list` is pure over the store (zero
> emulator I/O, works after `stop`). The tool never changes session state —
> the agent drives run intervals via resume/pause or `run_frames` (P14).
> Filtering runs inline and single-threaded (one linear pass over ≤4 MiB,
> <~10 ms — no spawn_blocking/rayon).
> **Alternatives considered:** four separate tools (schema bloat, against
> the grouped-verb precedent); sorted Vec<u32> candidates (8–16 MiB at seed,
> churn per filter) or per-candidate value records (unbounded bookkeeping)
> vs the fixed bitset; storing per-candidate old values instead of the whole
> snapshot (smaller only after heavy narrowing, more code, loses
> re-predicate flexibility); auto-running the machine inside `filter`
> (couples the tool to the session FSM and P14 — kept state-neutral
> instead); wrapping-aware increased/decreased (guesswork — exact unsigned
> semantics are predictable and match classic cheat engines); allowing
> width change mid-search (candidate alignment/meaning would silently
> shift).
> **Consequences:** "Find the variable" becomes a 4–6-call agent loop with
> a single number per step; survivors hand off directly to
> read_memory/watch/write_memory. Costs: ~4.5 MiB server memory while a
> search is live; one whole-RAM savebin per new/filter (the ADR-9 price,
> already paid by rip/search_memory); snapshots while Running can be
> mid-frame (noise candidates — the next filter removes them; pausing or
> run_frames gives frame-exact steps); same-value rewrites are invisible to
> `changed` (value semantics, as with ADR-15-era watches); one search at a
> time (a second `new` discards the first, exactly like rip scans).

## 14. Explicitly out of scope for P15 (do not "helpfully" add)

- Auto-run between filters (`filter(run_frames=N)`) — composition with
  P14/resume is the design; revisit only with usage evidence.
- Multiple concurrent searches / named searches (single store, ADR-10
  precedent).
- Signed-value or float predicates, bitmask predicates, "fuzzy"/range
  predicates (`between`) — add later as new `Predicate` arms if wanted;
  the enum is the seam.
- Unaligned word/long candidates (impossible variables on a 68000 — §3.3).
- Cross-width re-interpretation of an existing search.
- Undo/history of filter steps (store the snapshots yourself via `state`
  save if needed).
- Watch/write integration inside the tool (survivors hand off to the
  existing `write_memory`/`watch` tools).
- Persisting a search to disk across server restarts.
