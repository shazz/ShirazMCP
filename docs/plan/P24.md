## 1. The corpus (facts verified 2026-07-11, design grounded in a full scan)

P19 stated honestly that the SNDH archive was out of reach. It no longer is:

- **Location (local, gitignored):** `refs/sndh_lf/` — composer directories
  directly under it (`refs/sndh_lf/<Composer>/**/*.sndh`).
- **Contents:** 5,897 `.sndh` files, 678 composer directories, 269 MB.
- **Fetch (document in `refs/README.md`, §8.1):** yearly bundle from
  https://sndh.atari.org/download.php —
  `curl -fLO https://sndh.atari.org/files/sndh2026_lf.zip` (100 MiB,
  Content-Length 105124396, Last-Modified 2026-01-01), unzip so that the
  composer dirs sit directly under `refs/sndh_lf/`. The corpus is
  third-party and large: it must NEVER be committed (`/refs/` is already in
  `.gitignore` — verify, do not re-add).
- **Format:** SNDH v2.2 (spec: https://sndh.atari.org/fileformat.php):
  3×4-byte 68k branches (init/exit/play), ASCII `SNDH` at +12, tag blocks,
  `HDNS` terminator — exactly what `sndh_header.rs` already parses.
- **Packing:** all 5,897 files in the 2026 `_lf` bundle are **plain**
  (zero `ICE!`-packed files — verified by scanning every file). No depack
  step is needed. If a future bundle ships ICE-packed files, the existing
  `pack_ice`/`ice_decode` plugin already handles the format; do not build
  anything for that now.
- **PSG reachability:** 25 files contain no `8800/8802` operand words at
  all (STE-DMA-only tunes); **274 files reach the PSG exclusively via
  24-bit `$FF8800.l` operands** (byte shape `00 FF 88 00`) — the class
  `is_psg` currently rejects (§6).

Every signature, count, and offset below was derived from and verified
against this corpus (a whole-archive scan: per-signature match counts with
per-composer-dir breakdowns, plus a best-match simulation using the final
DB order). The spec cites `file@offset` for each entry; §7's corpus test
re-verifies all of it mechanically, forever.

### 1.1 The wrapper hazard (why frequency alone is disqualifying)

The **most frequent** PSG gadgets corpus-wide (578–884 files each) are NOT
driver code: they are shared rip/convert shims (Grazey/PHF-style wrappers,
recognizable by placeholder operands `DEAD`, `BA55CAFE`, `DEAFFADE` that
the wrapper self-patches at init). A signature mined by raw frequency would
confidently name the *wrapper* across every driver. Consequence, pinned as
methodology (§4): a candidate gadget qualifies only if it is
**group-discriminative** — high coverage inside one driver group, near-zero
outside it.

## 4. Methodology v2 (normative — how these entries were derived, and how the next one gets added)

P19 §4.1 steps 1–8 stand unchanged. P24 adds the **group-discrimination
step** that scale requires, between P19 steps 2 and 3:

2b. **Cluster and discriminate.** Over the whole corpus, collect the
    16-byte window `[i-8, i+8)` around every even-offset `8800/8802` word,
    deduplicated per file. Group files by driver evidence (composer dir
    and/or an in-file banner string). A window qualifies as a gadget
    candidate only if in-group file coverage ≥ 50% AND out-group file count
    ≤ 25 (for heterogeneous groups spanning many driver versions, e.g.
    Mad_Max: coverage ≥ 20%, out ≤ 60 — then verify the out-group hits are
    the *same driver* under other composers before accepting). This step
    automatically rejects the §1.1 wrapper shims, whose out-group counts
    are in the hundreds.

The discovery tooling is deliberately **not shipped** (ADR §9 re-affirms
P19's rejection: an offline, few-times-a-year task that ends in human
decode/labeling anyway). What ships is the *validation* half: the §7 corpus
test, which any future entry must also pass ("add a driver = one entry +
one excerpt test + one line in the corpus histogram").

Confidence bands: P19 §4.2 rubric unchanged. All new entries are
AnchorWindow gadgets; 0.85 = ≥20 literal bytes and ≥2 independent samples,
0.82 = ≥8 literal bytes and ≥2 independent samples.

## 6. The `is_psg` 24-bit fix (`ym_player.rs`)

Today (P19 §9 gap, ADR-35): `is_psg` accepts only
`["$ffff8800", "$ffff8802", "$8800.w", "$8802.w"]`, so `confirm` rejects
every 24-bit access (`move.b …,$FF8800.l`, `lea $FF8800.l,aN` — operand
bytes `00 FF 88 00`). `find_candidates` already yields these hits (the
short-form pass suppresses only `FF FF`-prefixed words), and all observed
24-bit encodings put the opcode ≤ 6 bytes before the operand word, so
`BACKS` needs no change (do NOT extend it; a hypothetical
`move.l #imm.l,$FF8800.l` at back-8 is unattested in all 5,897 files).

Change (2 tokens):

```rust
/// P2-pinned Capstone spellings of the two PSG ports (long, short, and
/// 24-bit absolute forms — the ST decodes $FF8800 and $FFFF8800 alike).
/// // verify live: re-pin against P2.md §6.2 table on any capstone bump.
fn is_psg(ops: &str) -> bool {
    ["$ffff8800", "$ffff8802", "$8800.w", "$8802.w", "$ff8800", "$ff8802"]
        .iter()
        .any(|t| ops.contains(t))
}
```

(`"$ffff8800"` does not contain the substring `"$ff8800"` — no overlap;
the new tokens also cover a `$ff8800.l` spelling by containment.)

**Implementation note (spelling pin):** the fix is only correct if Capstone
spells the 24-bit operand with a `$ff8800` substring. §8.2's
`capstone_spells_24bit_psg` test pins this. If it fails (e.g. Capstone
prints `$00ff8800`), replace the two new tokens with the observed spelling
(still lowercase-hex `contains` tokens), keep the test green, and note the
spelling in the comment — do not loosen to `"8800"` (that would confirm
immediates like `move.w #$8800,d0`).

## 9. `decisions.md` — append (fill date + next-free number, see header)

```markdown
## 2026-MM-DD — ADR-<n>: SNDH-archive-derived YM driver fingerprints; 24-bit PSG anchor fix

**Status:** accepted (extends ADR-16/ADR-35)
**Context:** ADR-35 derived 9 signatures from local sources and named the
SNDH archive (sndh.atari.org) as out of reach; it also flagged that
`ym_player::is_psg` misses 24-bit `lea/move $FF8800.l` operands. The
archive is now fetched locally (refs/sndh_lf, gitignored: 5,897 .sndh /
678 composers / 269 MB, yearly zip, all files plain — no ICE depack
needed). A whole-corpus scan grounded three facts: (1) the archive's most
frequent PSG gadgets are shared rip-wrapper shims (placeholder operands
DEAD/BA55CAFE), so frequency alone would fingerprint the wrapper, not the
driver; (2) 274 files reach the PSG only via 24-bit operands and today
produce no anchor at all; (3) the P19 module-magic TCB entries never occur
in SNDH rips (0/5,897) — driver code and module files need separate
signatures.
**Decision:** (1) Methodology extended (P24.md §4) with a
group-discrimination step: a gadget qualifies only with >=50% in-group file
coverage and <=25 out-group files (deep mode 20%/60 for multi-version
drivers), which mechanically rejects wrapper shims. (2) Eleven new
corpus-cited entries (Quartet, David Whittaker x2, TCB replay code,
Hippel x2, Tim Follin, Jess, Tao, Big Alec, Music Mon), each with
file@offset provenance and a byte-pinned excerpt test; rg-triplex's
hand-assembled encoding is now corpus-verified (Damo/YM_Rucka.sndh) but
stays 0.70 (single binary). Best-match coverage on sndh2026: 1,796/5,897
files (30.5%), per-player counts pinned. (3) `is_psg` gains the 24-bit
spellings ($ff8800/$ff8802 tokens); BACKS unchanged (all attested 24-bit
encodings sit within back-6). (4) The discovery pipeline is NOT shipped
(re-affirming ADR-35: offline, few-times-a-year, ends in human
decode/labeling); the validation half ships as the #[ignore]d
tests/ym_sig_corpus.rs (env SHIRAZMCP_SNDH_CORPUS): provenance pins,
exact best-match histogram, per-driver-dir exclusivity matrix — the
false-positive grep, mechanized and re-runnable.
**Alternatives considered:** committing a miner binary/xtask (rejected:
dead weight between yearly archive drops); frequency-ranked signatures
(rejected: names the Grazey/PHF wrapper across every driver); masking the
hippel-runl $1C displacement and bigalec's 4CD0 register field (rejected:
never observed varying — over-masking buys false positives); raising
rg-triplex to 0.82 (rejected: one binary is not two).
**Consequences:** identify_music names 11 engines instead of 5; Whittaker/
Follin/late-Hippel rips in live RAM become findable at all (the 24-bit
fix). Honest gaps remain and are documented in P24.md §10: ~69% of the
archive (per-composer long tail), Rob Hubbard ST (6 heterogeneous files),
Scavenger (gadgets too generic), Big Alec's other driver builds, Lucas/
ProTracker-STk still absent. Corpus counts are pinned to sndh2026_lf; the
yearly refresh re-pins the histogram. A wrong or dead entry still can only
produce "unknown", never a wrong name — the (\"unknown\", 0.25) contract
is unchanged and its tests pass unmodified.
```
