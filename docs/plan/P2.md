## 1. Deliverable in one sentence

Offline Capstone-M68K disassembly over a `MemImage` (`analyze/disasm.rs`),
static 68000 cycle estimation per the bundled skill tables
(`analyze/cycles/`), a Hatari-profiler driver + save-file parser

## 3. Live-verified Hatari wire formats (pinned)

Captured 2026-07-09 against `hatari --machine ste --memsize 1 --tos
tos162fr.img --harddrive …/MJJ/build --fast-boot on --fast-forward on
--confirm-quit off --cmd-fifo <fifo>` with stdin piped (the ADR-11 spawn

### 3.1 Breakpoint add (`b pc > 0 :once`, either control plane)

```
> b pc > 0 :once
CPU condition breakpoint 1 with 1 condition(s) added:
	pc > 0
-> Break only once, and delete breakpoint afterwards.
```

The index is the 4th whitespace-separated token of the
`CPU condition breakpoint N with …` line. The normalized expression is the
following TAB-indented line, trimmed (`pc > 0`). A rejected condition prints
`ERROR: …` lines instead.

### 3.2 Breakpoint fire + debugger entry (what the log shows on freeze)

```
1. CPU breakpoint condition(s) matched 1 times.
	pc > 0 :once
Removed CPU breakpoint 1:
	pc > 0 :once

----------------------------------------------------------------------
You have entered debug mode. Type c to continue emulation, h for help.
CPU=$d106, VBL=35936, FrameCycles=8680, HBL=16, LineCycles=488, DSP=N/A
0000d106 2742 eec4                move.l d2,(a3,-$113c) == $00041b04 [00000000]
```

The fired expression (with options) is the TAB line after
`N. CPU breakpoint condition(s) matched M times.`. `:once` breakpoints
auto-remove (`Removed CPU breakpoint N:`). A symbols-load attempt
(`Reading symbols…` / `ERROR: symbol table missing…`) may appear between the
banner lines against the MJJ demo (ADR-8) — parsers must tolerate arbitrary
interleaved lines and key on the specific prefixes only.

### 3.3 Breakpoint list / remove / clear

```
> b
No conditional CPU breakpoints.
> b
1 conditional CPU breakpoints:
   1:	pc = $d200 :once
> b 1            (remove by index — not probed with this exact arg, same
                  "Removed CPU breakpoint 1:" line as :once auto-remove)
> b all
Removed CPU breakpoint 1:
	pc = $d200 :once
CPU breakpoints: 0
```

List entry format: `%4d:` + TAB + expression-with-options. `b all` on an
already-empty table: expect `CPU breakpoints: 0` `// verify live` — if the
line is absent when empty, treat "no ERROR line" as success.

### 3.4 Profiler (probed end-to-end while frozen, over stdin)

```
> profile on
Profiling enabled.
> c
Returning to emulation...
Allocated CPU profile buffer (11 MB).
1. CPU breakpoint condition(s) matched 1 times.
	pc = $d106 :once
…
Normal RAM (0-0x100000):
…
- used cycles:
  3940 (86.56% of all areas)
…
> profile save <path>

> profile off

```

Facts pinned live: `profile on` answers `Profiling enabled.`; data collects
from the next continue until the next debugger entry, which auto-prints a
stats summary into the log; `profile save <path>` writes the per-address file

`profile off` answers `Profiling disabled.`. A `stateload` frees profile
buffers (`Freed previous CPU profile buffers.`).

### 3.6 `statesave` / `stateload` (both probed over BOTH control planes)

```
> statesave <path>                     (stdin, frozen — immediate)
INFO : Memory state file saved: <path>

> stateload <path>                     (stdin, frozen — DEFERRED, no output
                                        until `c`; after `c`:)
CPU breakpoints: 0
DSP breakpoints: 0
INFO : Memory state file restored: <path>

> statesave <path>                     (fifo, running — immediate)
INFO : Memory state file saved: <path>
> stateload <path>                     (fifo, running — completes in-loop)
CPU breakpoints: 0
DSP breakpoints: 0
INFO : Memory state file restored: <path>
```

Pinned facts: restore **clears all breakpoints** and **frees profiler data**;
restore from a frozen session is deferred until the next `c` (so the `state`
tool only loads while Running, §8.3); a snapshot saved while frozen restores
to a *running* machine. Failure lines: `Save file open error: …`,
`File open error: …`, `Unable to restore Hatari memory state…` (Hatari
version-locked format). Snapshot size ≈ 220 KiB at 1 MiB RAM.

### 3.7 Live disassembly (`d $from-$to`, fifo while running — probed)

```
> d $aa9a-$aab0
0000aa9a 6100 00ba                bsr.w #$00ba == $0000ab56
0000aa9e 6100 00d8                bsr.w #$00d8 == $0000ab78
```

Line shape: 8-hex-digit address, 1–5 four-hex-digit opcode words, then the

## 5. Session + debug layer: the managed run-to-breakpoint primitive

This section implements the critical ADR-11 follow-up: *"a user-armed
breakpoint that fires without session involvement freezes the machine while
the session still thinks it is Running."* P2 makes the session able to
**deliberately** run to a breakpoint and adopt the resulting freeze.

Protocol insight (from ADR-11's own invariants): stdin writes made after `c`
queue in the pipe until the **next** debugger entry. So: write `c`, then
immediately queue one sentinel probe on stdin. The probe is serviced the
instant a breakpoint fires and re-enters DebugUI — its log echo IS the fire
signal. No polling of emulator state, no new blind sleeps; the existing
`LogTail::read_until` bounds the wait.

### 5.1 `fifo::continue_and_wait` + `HatariProcess::continue_until_break`

`src/session/fifo/mod.rs` — add (next to `debug`):

```rust
/// ADR-11 §run-to-break: write `c` (thaw) then ONE queued sentinel probe.
/// While the machine runs, the probe sits unread in Hatari's stdin pipe;
/// the next debugger entry (a firing breakpoint) consumes and echoes it.
/// The sentinel echo in the log therefore means "a breakpoint fired and
/// the CPU is parked again". Returns the intervening log lines (breakpoint
/// match report, auto profiler stats, …), protocol-stripped.
///
/// Deliberately NOT `read_sentinel_with_retry`: re-writing the probe would
/// queue N copies that all replay at entry. One probe, one full-budget
/// `read_until`. On `Err(Timeout)` the machine is still RUNNING and one
/// stale probe stays queued — harmless by ADR-11 (sentinel echoes are
/// filtered from all collected output).
pub async fn continue_and_wait<W: AsyncWrite + Unpin + Send>(
    stdin: &mut W,
    log: &mut LogTail,
    timeout_ms: u64,
    what: &str,
) -> Result<String> {
    write_line(stdin, "c").await?;
    write_line(stdin, SENTINEL_EXPR).await?;
    let mut collected = Vec::new();
    log.read_until(is_sentinel_line, what, timeout_ms, &mut collected)
        .await?;
    Ok(strip_protocol_lines(collected))
}
```

(Two `write_line` calls are safe here, unlike the fifo batching hazard the
`write_line` doc describes: while frozen, DebugUI reads stdin with `fgets`
line-by-line; after it reads `c` the remaining bytes simply wait in the
pipe.)

`src/session/spawn/control.rs` — add to the existing `impl HatariProcess`:

```rust
/// Run until the next debugger entry (i.e. until an armed breakpoint
/// fires). Precondition: frozen (`ControlChannel::DebugStdin`) — callers
/// arm their breakpoint over stdin first. On Ok the machine is frozen
/// again and `control` stays `DebugStdin`; on `Err(Timeout)` (or any I/O
/// error after `c` was written) the machine is running, so `control`
/// flips to `Fifo` before returning.
pub(crate) async fn continue_until_break(&mut self, timeout_ms: u64) -> Result<String> {
    if !matches!(self.control, ControlChannel::DebugStdin) {
        return Err(crate::error::Error::Session(
            "run_until_break requires a frozen session".to_string(),
        ));
    }
    let what = "breakpoint fire (sentinel probe queued behind c)";
    match fifo::continue_and_wait(&mut self.stdin, &mut self.log, timeout_ms, what).await {
        Ok(output) => Ok(output),
        Err(e) => {
            self.control = ControlChannel::Fifo;
            Err(e)
        }
    }
}
```

### 5.2 `src/session/run.rs` — the type-state wrapper

New file; `session/mod.rs` gains `pub mod run;` and
`pub use run::RunToBreak;`.

```rust
//! ADR-11 §run-to-break: `Session<Paused>` can run the machine until an
//! armed breakpoint fires and adopt the resulting freeze — the managed
//! alternative to hand-arming breakpoints via the raw `debug` tool.

use crate::error::Error;
use crate::session::{Paused, Running, Session};

/// Every arm returns the session in a compile-time-known state — a fired
/// breakpoint can never leave the FSM guessing (the "known state"
/// requirement from ADR-11's limitation note).
#[derive(Debug)]
pub enum RunToBreak {
    /// A breakpoint fired within the budget: frozen at it. `output` holds
    /// the debugger-entry log lines (§3.2 — match report, stats, …).
    Fired(Session<Paused>, String),
    /// Nothing fired: the machine was left RUNNING. Whatever was armed is
    /// still armed — callers own disarming (§8.1 recovery).
    TimedOut(Session<Running>),
    /// Control-plane I/O failed (Hatari almost certainly died). Treated as
    /// Running so `stop` — the only sensible next call — is reachable.
    Broken(Session<Running>, Error),
}

impl Session<Paused> {
    /// `c` + queued sentinel probe; see `HatariProcess::continue_until_break`.
    pub async fn run_until_break(mut self, timeout_ms: u64) -> RunToBreak {
        match self.data.continue_until_break(timeout_ms).await {
            Ok(output) => RunToBreak::Fired(self, output),
            Err(e @ Error::Timeout { .. }) => {
                let _ = e; // timeout detail already logged by read_until
                RunToBreak::TimedOut(Session { config: self.config, data: self.data })
            }
            Err(e) => RunToBreak::Broken(
                Session { config: self.config, data: self.data },
                e,
            ),
        }
    }
}
```

(`Session`'s fields are `pub(crate)`? No — they are private to
`session/mod.rs`. Since `run.rs` is a child module of `session`, place it as
`mod run;` inside `src/session/mod.rs`'s module list exactly like `any.rs`
(`mod any;` + `pub use`): child modules of `session` can construct
`Session { config, data }` only if the fields are visible. They are declared
without `pub` in `mod.rs`, and `any.rs` today only *matches* on sessions.
**Do this:** mark both fields `pub(super)` is wrong (run is a sibling child —
`pub(in crate::session)` is the correct scope). Change in `session/mod.rs`:

```rust
pub struct Session<S: SessionState> {
    pub(in crate::session) config: HatariConfig,
    pub(in crate::session) data: S::Data,
}
```

No external visibility change — `crate::session` children only.)

### 5.4 `src/debug/profile.rs` — profiler driver + save-file parse

```rust
//! Drive Hatari's CPU profiler (`profile on/save/off`) and parse the
//! per-address save file. File format pinned live (P2.md §3.4/§3.5) and
//! fixture-committed (tests/fixtures/hatari_profile.txt).

use std::path::Path;

use crate::debug::DebugChannel;
use crate::error::{Error, Result};
use crate::types::Addr;

/// One profiled address from `profile save`.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct ProfiledAddr {
    pub addr: Addr,
    /// Executed-instruction count at this address.
    pub count: u64,
    /// Measured CPU cycles spent at this address (Hatari core, includes
    /// ST bus rounding/contention as emulated).
    pub cycles: u64,
}

pub async fn profile_on(chan: &mut impl DebugChannel) -> Result<()>;
// impl: out contains "Profiling enabled." else Error::Parse{context:"profile on"}

pub async fn profile_off(chan: &mut impl DebugChannel) -> Result<()>;
// impl: out contains "Profiling disabled." else Error::Parse

pub async fn profile_save(chan: &mut impl DebugChannel, path: &Path) -> Result<()>;
// impl: cmd `profile save {path}`; out contains "CPU addresses." (the
//       "Disassembled N (of active N) CPU addresses." line) else
//       Error::Parse{context:"profile save", input: out}

/// Parse the save file (§3.5). Data line test: first whitespace token is
/// 1..=8 ASCII lowercase-hex chars AND the line contains "% (" AND ends
/// with ')'. Fields: substring between the LAST '(' and the trailing ')',
/// split on ',', trimmed → [count, cycles, i_misses, d_hits]; parse the
/// first two as u64. Lines failing the test are skipped silently (headers,
/// "[...]", caller-graph comments). Returns entries in file order.
pub fn parse_profile_file(contents: &str) -> Vec<ProfiledAddr>;

/// Sum (instructions, cycles) over entries with from <= addr < to.
pub fn sum_range(entries: &[ProfiledAddr], from: Addr, to: Addr) -> (u64, u64);
```

Note the honest semantics `sum_range` gives `profile` (§8.2): measured
cycles cover only addresses **inside [from, to)** — time spent in interrupt
handlers/TOS outside the range is excluded, which is exactly what "cost of
this routine" should mean. Say so in the tool description.

### 6.2 `src/analyze/disasm.rs`

Capstone usage — pinned against `capstone 0.13.0` and verified by a compiled
spike in this repo (output below):

```rust
//! Embedded Capstone M68K disassembly over a `MemImage` (ADR-4): bulk,
//! offline, zero emulator round-trips. Hatari's own `disasm` remains the
//! live path (P2 `disasm` tool, source=live).

use capstone::arch::m68k::ArchMode;
use capstone::arch::BuildsCapstone;
use capstone::Capstone;

use crate::error::{Error, Result};
use crate::types::{Addr, MemImage};

/// Longest 68000 instruction (opcode + 4 extension words + …): 10 bytes.
/// Callers size snapshot windows as `count * MAX_INSN_LEN`.
pub const MAX_INSN_LEN: usize = 10;

/// One decoded instruction. `ops` is Capstone's operand text verbatim
/// (e.g. "#$777, $ffff8240.l"); `bytes` the exact instruction bytes.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Insn {
    pub addr: Addr,
    pub mnemonic: String,
    pub ops: String,
    pub bytes: Vec<u8>,
}

/// Disassemble up to `count` instructions starting at bus address `at`,
/// which must lie inside `mem` and be even (68000 alignment). Capstone
/// never stalls on undecodable words — it emits `dc.w $xxxx` and
/// continues — so the result length is `count` unless the image ends.
pub fn disasm(mem: &MemImage, at: Addr, count: usize) -> Result<Vec<Insn>> { .. }
```

Implementation (exact):

1. `at.raw() % 2 != 0` → `Err(Error::Parse { context: "disasm address".into(), input: at.to_string() })`.
2. `let off = (at.raw() as usize).checked_sub(mem.base().raw() as usize)` —
   `None` or `off >= mem.len()` → same `Error::Parse` with context
   `"disasm range"`.
3. Build per call (construction is microseconds; `Capstone` is not `Sync`,
   so never store it in server state):
   ```rust

       .m68k()
       .mode(ArchMode::M68k000)
       .build()
       .map_err(|e| Error::Parse { context: "capstone build".into(), input: e.to_string() })?;
   ```
4. `let insns = cs.disasm_count(&mem.bytes()[off..], u64::from(at.raw()), count)`
   — map error like step 3 with context `"capstone disasm"`.
5. Map each `capstone::Insn`:
   `addr: Addr::new(i.address() as u32)`,
   `mnemonic: i.mnemonic().unwrap_or("?").to_string()`,
   `ops: i.op_str().unwrap_or("").to_string()`,

## 7. Analyze layer: 68000 static cycle estimation

Authority: the bundled skill table
`.claude/skills/m68000-cycles/reference/68000_execution_cycles.md` — every
constant below is transcribed from it; where it is ambiguous this spec pins
the choice. The estimate is **contention-blind** (no Shifter/MMU stealing)
and must be labelled an estimate everywhere it surfaces.

### 7.1 Model

- `insn_cycles(bytes) -> Option<u32>` returns the RAW table value (base +
  EA cost) for one instruction, decoding sizes/addressing modes from the
  raw big-endian opcode words — no Capstone dependency, unit-testable on
  hand-assembled bytes.
- **ST rounding:** the ST rounds every instruction to a multiple of 4
  clocks (reference: "you need to round all times to multiples of four,
  i.e 10 becomes 12"; confirmed live — `dbf` taken measured 12 where the
  table says 10, `move.w (a4,d2.w),d7` measured 16 where the table says
  14). `round_st(raw) = (raw + 3) & !3`, applied per instruction inside
  `estimate`, NOT inside `insn_cycles` (tests pin raw table values).
- **Branch policy (pinned):** a static straight-line walk assumes
  fall-through — `Bcc` uses the NOT-taken cost (.b 8 / .w 12), `DBcc` uses
  the taken-loop cost 10 (the loop is the common case), unconditionals use
  their only cost (`bra` 10, `bsr` 18). Document this in the
  `CycleEstimate` doc comment.
- **Unknown instructions** (not in §7.4's coverage, or `dc.w` garbage):
  contribute `4` cycles and increment `unknown`. The estimate never errors.

### 7.4 `src/analyze/cycles/decode.rs` — opcode classifier

## 8. Tool layer

### 8.1 `src/tools/managed.rs` — THE managed-breakpoint protocol

This module is the single owner of the freeze/run/recover choreography that
ADR-11 demanded ("P2's breakpoint tool must own this interaction"). It
operates on the `AnySession` guard with the exact `std::mem::replace`
pattern of `lifecycle.rs`, and is used by both `breakpoint(action=set)` and
`profile`.

```rust
//! Managed run-to-breakpoint choreography (ADR-11 §known-limitation,
//! resolved by ADR-15). Owns: freeze if needed → arm :once over stdin →
//! continue + wait for fire → recover to a KNOWN state on every path.
//! Invariant: this module never leaves a session in a state where a
//! breakpoint can fire behind the FSM's back — every exit is either
//! Paused-at-breakpoint, or Running with the managed breakpoint disarmed,
//! or an error that names the one narrow race and its remedy (pause).

use crate::debug::breakpoint as bp;
use crate::error::{Error, Result};
use crate::session::{AnySession, RunToBreak, Session};

/// Outcome the tools serialize.
#[derive(Debug)]
pub(crate) enum Fire {
    /// Frozen at the breakpoint; `pc` read post-freeze; `output` = §3.2
    /// entry block (protocol-stripped).
    Fired { pc: u32, output: String },
    /// Budget elapsed; machine left Running, managed breakpoint disarmed.
    TimedOut,
}

/// Arm `condition` as :once and run until it fires (or `timeout_ms`).
/// Steps (each one pinned):
///  1. If Stopped → Err(Error::Session("no live session")).
///  2. If Running → freeze via the existing pause() transition. Remember
///     `was_running`.
///  3. bp::arm_once(proc, condition) over stdin (session is Paused). On
///     parse/ERROR failure: if was_running, resume(); return the error
///     (initial state restored — arming never half-changes the world).
///  4. session.run_until_break(timeout_ms):
///     - Fired(paused, output):
///         a. pc = debug::evaluate(proc, "pc")?.
///         b. If bp::fired_expression(&output) names a DIFFERENT
///            expression than ours (compare against
///            `format!("{} :once", armed.expression)`), our :once bp is
///            still armed: bp::list → find our expression → bp::remove.
///            (Ours fired ⇒ Hatari already auto-removed it.)
///         c. Guard is set to Paused(session); return Fire::Fired.
///     - TimedOut(running):
///         a. Guard is set to Running(session) FIRST (known state even if
///            disarm fails).
///         b. Disarm over the fifo (list → find our expression, options
///            included, e.g. "pc = $12345 :once" → remove by its CURRENT
///            index). The fifo services `b`/`b N` in the running main
///            loop — no freeze needed (§3.3 probed).
///         c. If any disarm step times out, the breakpoint fired in the
///            microseconds since: return
///            Err(Error::Session("breakpoint fired during timeout \
///            recovery — call pause to adopt the frozen session".into()))
///            — `pause` recovers per ADR-11 (its stdin sentinel succeeds
///            against an already-frozen debugger).
///         d. Else return Fire::TimedOut.
///     - Broken(running, e): guard = Running; return Err(e) (tool text
///       tells the agent to call stop).
pub(crate) async fn run_to_breakpoint(
    guard: &mut AnySession,
    condition: &str,
    timeout_ms: u64,
) -> Result<Fire> { .. }
```

Notes that MUST survive into code comments:

- The queued-fifo hazard shapes step TimedOut(a-c): if the breakpoint fires
  in the race window, the disarm fifo writes queue and replay on resume —
  they are plain `b`-list/`b N` commands, harmless on replay (worst case
  "breakpoint N not found" ERROR text nobody parses). The distinguished
  `Error::Session` message is the agent-facing contract for this window.
- `pause()`'s own freeze breakpoint is `pc > 0 :once` — while frozen it can
  never interact with the managed condition (both are :once, both armed
  from a parked CPU).
- All managed breakpoints are `:once` — P2 has NO detached persistent
  breakpoints by design (out of scope §12); `breakpoint(action=set)` is a
  synchronous run-to-break.

3. Lock session; `process_mut()` or `wrong_state(name, "running or paused")`.
4. Snapshot source: `memory::acquire_range(proc, addr, count as usize *
   disasm::MAX_INSN_LEN)` → `analyze::disasm::disasm(&mem, addr, count)` →
   map to `InsnOut` (fold `track_psg` across the stream, `annotate_ops` per
   insn, `cycles_est = insn_cycles(..).map(round_st)`).
5. Live source: `proc.debug(&format!("d ${:x}-${:x}", addr.raw(),
   addr.raw() + count * 10))` → `parse_live_line` per line → truncate to
   `count` → same annotation enrichment (`cycles_est: None`).
6. `next_addr` = last insn addr + its byte length (snapshot) / last parsed
   addr + word-count×2 (live).

Tool description (verbatim): *"Disassemble 68000 code. source=snapshot
(default) decodes an acquired RAM snapshot with the embedded Capstone —
fast, typed, includes a static cycle estimate per instruction (flagged
estimate: ST bus contention not modelled). source=live asks Hatari's own
debugger (knows effective-address hints). Hardware operand addresses come
back annotated. Default 32 instructions, max 128 — page with next_addr."*

`profile`:
1. Parse `from`/`to`; `from == to` or `to < from` or
   `to - from > PROFILE_MAX_RANGE` → `invalid_params` naming the rule.
2. Lock session. Choreography, in order (each step's failure handling in
   §8.1 / noted):
   a. `managed::run_to_breakpoint(guard, &format!("pc = ${:x}", from.raw()), t)`
      → must end `Fired`; `TimedOut` → `internal_error("never reached
      from…")`. Verify `pc == from.raw()` else `internal_error` naming both
      (a foreign breakpoint fired first; its expression is in the output).
   b. `debug::profile::profile_on(proc)`.
   c. `managed::run_to_breakpoint(guard, &format!("pc = ${:x}", to.raw()), t)`
      → `Fired` + pc check as above. On `TimedOut`: best-effort
      `hatari-debug profile off` over the fifo (machine is Running), then
      `internal_error("never reached to…")`.
   d. `path = work_dir/profile-{profile_seq:04}.txt`;
      `debug::profile::profile_save(proc, &path)`; `profile_off(proc)`.
   e. Read the file (tokio::fs), `parse_profile_file`, `sum_range(from, to)`.
   f. Static leg: `memory::acquire_range(proc, from, (to-from) as usize)` →
      `disasm(&mem, from, usize::MAX/… cap: (to-from)/2)` — decode until
      `next addr >= to` (loop `disasm` pages of 128, or decode
      `count = range/2` once and truncate at `to`; pin: single
      `disasm(&mem, from, (range/2) as usize)` then
      `take_while(insn.addr < to)`) → `cycles::estimate`.
   g. Session is left **Paused at `to`** (the freeze belongs to the agent
      now — resume explicitly). `state: "paused"` in the output.

Tool description (verbatim): *"Measure a routine: runs the machine to
pc=from, enables Hatari's profiler, runs to pc=to, and reports measured
cycles (ground truth incl. emulated bus contention, summed over addresses
inside [from,to) — interrupt time outside the range excluded) alongside a
static table estimate for one straight-line pass. Leaves the session PAUSED
at `to`. vbl_fraction is against the 160256-cycle 50Hz frame. The raw
profiler dump is saved to profile_path."*

## 13. Proposed ADR — append to `decisions.md` as ADR-15 (do NOT renumber)

> ## 2026-07-09 — ADR-15: Managed run-to-breakpoint owns the freeze lifecycle
>
> **Status:** accepted (closes ADR-11's known limitation)
> **Context:** ADR-11 left one hole: a breakpoint armed via raw
> `debug("b …")` fires outside the session FSM — the machine freezes while
> the session believes it is Running, and every fifo call then times out.
> P2's `breakpoint`/`profile` tools need firing breakpoints as a *feature*,
> so the session must be able to run to a breakpoint deliberately and adopt
> the freeze.
> **Decision:** (1) A new primitive exploits ADR-11's own queueing
> invariant: from Paused, write `c` then ONE sentinel probe on stdin — the
> probe sits unread while the machine runs and is echoed the instant a
> breakpoint re-enters DebugUI. `Session<Paused>::run_until_break(timeout)`
> returns a three-state `RunToBreak` (`Fired(Paused)`, `TimedOut(Running)`,
> `Broken(Running)`) so every outcome is a compile-time-known session
> state. (2) All managed breakpoints are `:once` and synchronous: `set` =
> freeze-if-needed → arm over stdin → run → fired ⇒ Paused-at-breakpoint /
> timeout ⇒ disarm over the fifo (list+remove work in the running main
> loop, verified live) and stay Running. Nothing persists armed behind the
> FSM's back. (3) The one unavoidable race — fire between timeout and
> disarm — returns a distinguished error whose remedy is `pause` (ADR-11's
> documented recovery). (4) `profile(from,to)` composes two managed runs
> around Hatari's profiler and parses `profile save`'s file (filesystem as
> intermediate state, ADR-5), ending Paused at `to`. (5) Spawn adds
> `--alert-level fatal`: Hatari alert dialogs are modal and would hang the
> managed flows' error paths (`stateload` version mismatch); log lines are
> unaffected (verified in log.c).
> **Alternatives considered:** a background watcher polling for unmanaged
> freezes (adds a concurrent writer to the control planes ADR-11 carefully
> serialized); detached persistent breakpoints with lazy freeze-detection
> (leaves the FSM lying between fire and detection — the exact hole being
> closed); `:trace`-only breakpoints that never freeze (can't support
