# P8 — Assemble + patch: hot-patch a running/frozen ST without rebuilding: Implementation Spec

> Executable spec for **rust-engineer**. Zero design decisions are left open:
> where this document says something, do exactly that. If reality contradicts
> this spec, use the `Implementation note` / `// verify live` fallbacks; if
> there is no fallback, stop and flag to rust-architect.
> Scope guard: **two new tools only** — `assemble` (68000 source → machine
> code via the external vasm binary) and `patch` (assemble + chunked
> `memwrite` + readback-verify disasm). No PRG building, no linker, no
> symbol-table integration (`symbols prg` untouched), no relocation handling,
> no "undo patch" journal, no multi-region patches, no changes to `session/`,
> `debug/`, `analyze/` behavior (one visibility bump in `tools/analyze.rs`
> and one shared-mapper refactor in `tools/analyze_wire.rs` are the ONLY
> edits to existing P2 files, both pinned in §7), no new registry plugins, no
> edits to the ripper.

Authority chain: `PLAN.md` §P8 → `ARCHITECTURE.md` → `decisions.md` (ADR-1
error taxonomy, ADR-3 type-state session, ADR-4 embedded Capstone, ADR-11
two control planes). P8 **appends ADR-18** (§14 — ADR-17 is P7's boot-sector
work, do not reuse the number). Builds on the exact code as it exists today:

- **Write path:** `debug::write_bytes(chan, addr, bytes)` in
  `src/debug/mod.rs` formats `memwrite $addr xx yy …` and fails on any
  `ERROR` line — `patch` reuses it verbatim, chunked (§6.3). **Implementation
  note (P8, reality-contradicts-spec fix-forward):** the live P8 acceptance
  run (§10.3) found the premise above incomplete — Hatari's `memwrite`
  parses bare value tokens in the debugger's configured `nNumberBase`
  (default **decimal**, `hatari/src/configuration.c`), not hex, so bare
  `xx yy` tokens either error (`fc` → "Bad value 'fc'!") or, worse, silently
  write the wrong byte (`82` parses as decimal 82). Fixed at the source
  (`write_bytes` now emits `$xx $yy …`, each value individually
  `$`-prefixed) since this is a pre-existing P1 defect never live-verified
  (the only prior live coverage, `tests/depack_rescan.rs::packed_pi1_live_rip`,
  is `#[ignore]`d), not a P8 design change — ruling: rust-architect,
  2026-07-09. `write_memory`/`patch` both benefit; no ADR (bug fix within an
  existing pattern, not a technical choice). The tool-level
  cap `WRITE_MAX = 256` lives in `src/tools/mem/types.rs` and is the pinned
  chunk size.
- **Readback path:** `crate::session::memory::acquire_range(proc, addr, len)`
  → `MemImage` (the same call `tools/analyze.rs::snapshot_insns` uses), then
  `crate::analyze::disasm::{disasm, Insn}` (P2, ADR-4) over it. Capstone text
  conventions are P2's pinned table (P2.md §6.2).
- **Tool plumbing:** `HatariServer`, `to_mcp`, `wrong_state`,
  `parse_addr`/`hex_encode` (`src/tools/mem/scan.rs`, already `pub(crate)`),
  the `#[tool_router(router = …, vis = "pub(crate)")]` pattern, and
  `combined_router()` summation in `src/tools/mod.rs`.
- **Error taxonomy:** `src/error.rs` (`thiserror`, matchable categories). P8
  adds exactly one variant (§5.1).

## 0. Verified-live vasm facts (probed 2026-07-09 — normative)

The backend is **vasm 2.0e / M68k backend 2.8 / Motorola syntax 3.19d** at
`$HOME/projects/MJJ/bin/vasm/vasmm68k_mot` — the exact assembler the MJJ
ST demos are built with (dialect match is the point). Every claim below was
verified by running that binary; the golden tests in §10.1 re-verify them.

**Invocation (pinned argv — no shell, ever):**

```
vasmm68k_mot -quiet -Fbin -o <out.bin> [-L <out.lst>] <src.s>
```

| Fact | Verified behavior |
|---|---|
| success | exit 0; `-quiet` suppresses the banner entirely; `<out.bin>` contains the raw bytes |
| golden 1 | source `\torg $70000\n\tmove.w #$777,$ffff8240\n` → **6 bytes** `31 FC 07 77 82 40` (vasm optimizes absolute-long to absolute-short `$8240.w` — sign-extends back to `$FFFF8240` on the 68000) |
| golden 2 | `org $70000` + `loop: move.w #$777,$ffff8240` / `subq.w #1,d0` / `bne.s loop` / `rts` → **12 bytes** `31 FC 07 77 82 40 53 40 66 F6 4E 75` |
| no org | legal; assembles as if `org 0` (PC-relative code is position-free; absolute label math is wrong — hence `assemble`'s optional `org`, `patch`'s forced one) |
| errors | **stderr**, exit 1, **no output file**. Shapes: `error 3007: undefined symbol <bogus_label>` and `error 9 in line 3 of "bad2.s": instruction not supported on selected architecture` followed by a `>`-prefixed source-echo line; fatal: `fatal error 14: could not open </nonexistent/x.lst> for output` + `aborting...` |
| warnings | **stderr**, exit 0, output still written. Shape: `warning 51 in line 2 of "warn.s": instruction has been auto-aligned` + `>`-echo line |
| listing (`-L f`) | sections header, then per-line `00:00070000 31FC07778240 \t     2: loop:\tmove.w #$777,$ffff8240`, then symbol tables |
| ⚠️ multiple `org` | `-Fbin` **zero-pads the gap between sections**: `org $70000` + `org $70100` produced a 258-byte file (`4E71`, 254 zero bytes, `4E75`). A patch built from that would zero everything between the two orgs — this is why user-supplied `org`/`rorg` directives are rejected whenever the server injects its own (§4.2). |

Diagnostics parsing contract (§5.3) is written against exactly these shapes.

## 1. Deliverable in one sentence

Two new grouped tools — `assemble(source, org?, listing?)`, which drives the
external vasm binary (argv-vector subprocess, temp files in a controlled dir,
bounded + sanitized diagnostics returned **as data** so the agent iterates on
assembly errors without MCP-error noise) and returns `{ok, bytes_hex, length,
errors, warnings, listing?}`; and `patch(addr, source)`, which assembles with
`org` forced to `addr`, writes the bytes into emulator RAM through the
existing `debug::write_bytes`/`memwrite` path in 256-byte chunks (Running or
Paused — both control planes already work, ADR-11), reads the region back via
`memory::acquire_range`, byte-compares (`verified`), and returns a Capstone
disassembly of what is actually in RAM — the freezer cartridge's built-in
assembler: test a 68k change in place with no PRG rebuild.

## 3. Build configuration

**No new crate dependencies. No new cargo features.** `tokio` already has the
`process` feature (Hatari spawn uses it); temp files use `std::fs` +
`std::env::temp_dir()`; everything else is `serde`/`schemars`/existing
layers. If you feel the urge to add a crate, stop and flag.

The one new *runtime* dependency is the external `vasmm68k_mot` binary —
resolved at call time (§5.2): env var **`SHIRAZMCP_VASM`** overrides the
default `$HOME/projects/MJJ/bin/vasm/vasmm68k_mot` (a machine-local
default, deliberate — same policy as `HatariConfig::default()`). An absent
binary is a **typed, graceful error** (§5.1), never a panic, and never a
compile-time concern — which is exactly why there is **no cargo feature
flag** for this: a feature would gate no code or crates, only pretend to gate
a runtime binary. ADR-18 records this.

## 4. Normative assembly contract (pinned)

### 4.1 Source preparation

- `SRC_MAX_BYTES = 65_536` (64 KiB). Longer source → rejected before any
  file/process work (`invalid_params` at the tool; the pure check lives in
  `prepare_source`, §5.3).
- When the server supplies an org (always for `patch`; when the `org` param
  is given for `assemble`), it **prepends** one line to the user source:
  `\torg $<hex>\n` (lowercase hex, no leading zeros — `Addr::raw()` formatted
  `{:x}`).
- **Org-conflict rule** (⚠️ load-bearing, §0 padding fact): whenever the
  server injects an org, a user source containing its own `org` or `rorg`
  directive is rejected with the exact message
  `source must not contain org/rorg when org/addr is supplied (vasm -Fbin
  zero-pads between sections)`. With no injected org (`assemble` without the
  `org` param), user `org`/`rorg` is allowed (advanced use; the agent owns
  the consequences).
- Directive detection (`has_org_directive`, pinned tokenizer — §5.3): for
  each line, strip a `;` comment, strip one optional leading `label:` token
  (first whitespace-delimited token ending in `:`), then compare the next
  token case-insensitively to `org` / `rorg`. `*` line comments (column-0
  `*`) are also stripped. No regex crate — plain `str` ops.

### 4.2 vasm execution (SECURITY-pinned)

- `tokio::process::Command::new(vasm_path)` with an **explicit argv vector**
  (§0 invocation). `// SECURITY: never a shell, never string interpolation —
  the source text is file content, not an argument.`
- Temp files live in `std::env::temp_dir().join("shirazmcp-asm")`
  (`create_dir_all` first). Names contain **no user-controlled components**:
  `asm-{pid}-{seq}.s` / `.bin` / `.lst`, where `pid = std::process::id()` and
  `seq` is a module-`static AtomicU64` (naming uniqueness only — not shared
  state; justified in a comment).
- Lifecycle: an RAII guard (`TempAsm`, §5.2) removes all three files in
  `Drop` (best-effort `std::fs::remove_file`, errors ignored — tiny files in
  a temp dir; sync I/O in `Drop` is fine).
- `stdin(Stdio::null())`, `stdout(Stdio::piped())`, `stderr(Stdio::piped())`,
  `kill_on_drop(true)`.
- `VASM_TIMEOUT_MS = 10_000`: `tokio::time::timeout(…,
  child.wait_with_output())`; on elapse, dropping the future kills the child
  (`kill_on_drop`) and the call returns `Error::Assembler { context:
  "timeout", … }`.
- Diagnostics = stdout ⧺ stderr concatenated (verified: everything lands on
  stderr, stdout is defensive), parsed per §5.3, **sanitized** (temp filename
  replaced by `source`, §5.3) and **bounded** before anything reaches the
  model: `DIAG_MAX = 16` lines kept, each truncated to `DIAG_LINE_MAX = 200`
  chars. Raw stderr is never returned.
- `BIN_MAX_BYTES = 65_536`: a larger output file → `Error::Assembler {
  context: "output", message: "assembled output exceeds 64 KiB" }`.

### 4.3 Result semantics (diagnostics are data)

Assembly failures in the **user's source** are not MCP errors — the agent's
core loop is assemble → read errors → fix source → retry, and an
`{ok: false, errors: […]}` payload is one round-trip with no error-channel
noise. The MCP error channel is reserved for **infrastructure** failures:
vasm binary missing, spawn/temp I/O failure, timeout, oversized output
(`Error::Assembler` → `internal_error`) and malformed params
(`invalid_params`). Pinned mapping table in §6.4.

### 4.4 Patch limits

- `PATCH_MAX_BYTES = 4096` (16 chunked `memwrite` round-trips worst case).
  Larger assembled output → `PatchOutput { ok: false, errors:
  ["assembled to N bytes, patch max is 4096"] , … }` (data, not MCP error —
  the source assembled fine).
- Assembled length 0 → `PatchOutput { ok: false, errors: ["assembled to 0
  bytes — nothing to write"], … }`.
- `addr` must be even (68000 instruction alignment) → `invalid_params`
  otherwise (reuse `parse_even_addr`, §7.2).
- Works in **Running or Paused** (both `debug` control planes already
  handle `memwrite`/`savebin`, ADR-11). The tool description warns that
  Running is racy (the CPU can execute half-written code mid-patch) and
  recommends `pause` first; the server does not force it.

## 5. `src/assemble/` — new leaf module

**Placement rationale (record in the module doc):** assembling is
analysis-adjacent but drives a subprocess. `analyze/` is a **pure leaf**
(Capstone over byte slices — no tokio, no I/O) and must stay that way;
`session/` owns exactly one process (Hatari) and its two control planes;
`ripper/` must stay pure. So `assemble/` is a new leaf module depending only
on `crate::error` + `crate::types`, consumed **only** by `tools/`. Layering
becomes: `session` → `debug` → `analyze` → `ripper` → `tools`, with
`assemble` a sibling leaf under `tools` (update the `lib.rs` doc comment,
§7.3). Grep gates in §13 enforce no other layer imports it.

### 5.2 `src/assemble/mod.rs` — the vasm driver

Module doc: "External-assembler driver (ADR-18): shells out to vasm
(`vasmm68k_mot`, the assembler the MJJ demos are built with — dialect match)

```rust
pub mod source;

use std::path::{Path, PathBuf};

use crate::error::{Error, Result};

pub const DEFAULT_VASM: &str = "$HOME/projects/MJJ/bin/vasm/vasmm68k_mot";

/// Outcome of one assembler run. `ok == false` means vasm rejected the
/// SOURCE (errors carry the diagnostics); infrastructure failures are
/// `Error::Assembler` instead.
#[derive(Debug)]
pub struct AsmResult {
    pub ok: bool,
    pub bytes: Vec<u8>,          // empty iff !ok
    pub errors: Vec<String>,     // sanitized + bounded (§5.3)
    pub warnings: Vec<String>,   // sanitized + bounded
    pub listing: Option<String>, // bounded; Some only if requested AND ok
}

/// the spawn error is the single source of truth (avoids TOCTOU).
pub fn vasm_path() -> PathBuf;

/// Drive vasm over an already-prepared source (org injected, size-checked —
/// `source::prepare_source`). `want_listing` adds `-L`.
pub async fn assemble(vasm: &Path, prepared_src: &str, want_listing: bool)
    -> Result<AsmResult>;
```

Private items (all `// impl:` notes — bodies ≤ 30 lines each):

```rust

struct TempAsm { src: PathBuf, bin: PathBuf, lst: PathBuf }

fn build_argv(src: &Path, bin: &Path, lst: Option<&Path>) -> Vec<std::ffi::OsString>;
```

prepared_src)` (map err → `Error::Assembler { context: "temp", .. }`) →
`run_vasm` → `source::parse_diagnostics(&diag, tmp.src file name)` →
`collect_outputs` → `AsmResult { ok: status_ok, bytes, errors, warnings,

### 5.3 `src/assemble/source.rs` — pure prep + diagnostics

Module doc: "Pure text helpers for the vasm driver (§4.1/§4.2 rules): org
injection, org/rorg-conflict detection, source bound, diagnostics
parse/sanitize/bound. No I/O, no subprocess — fully unit-tested without
vasm."

```rust
use crate::types::Addr;

pub const DIAG_MAX: usize = 16;
pub const DIAG_LINE_MAX: usize = 200;
pub const LISTING_MAX_BYTES: usize = 4096;

/// §4.1: size-check, org-conflict-check, org injection. Err is a human
/// message the tool maps to invalid_params.
pub fn prepare_source(source: &str, org: Option<Addr>)
    -> std::result::Result<String, String>;

/// §4.1 pinned tokenizer: any line whose first token (after stripping `;`
/// comments, column-0 `*` comment lines, and one optional `label:` token)
/// is `org`/`rorg`, case-insensitive.
pub fn has_org_directive(source: &str) -> bool;

/// §0 shapes: lines starting with "error" / "fatal error" → errors; lines
/// starting with "warning" → warnings. Each kept line is sanitized (every
/// occurrence of `src_name`, e.g. "asm-1234-7.s", replaced by "source")
/// and truncated to DIAG_LINE_MAX chars; each list capped at DIAG_MAX with
/// a final "… (N more)" entry when truncated. `>`-echo lines are dropped
/// (the error already carries the line number).
pub fn parse_diagnostics(diag_text: &str, src_name: &str)
    -> (Vec<String>, Vec<String>);

/// Truncate to LISTING_MAX_BYTES on a char boundary, appending
/// "\n… (listing truncated)" when cut; sanitize `src_name` → "source".
pub fn bound_listing(text: &str, src_name: &str) -> String;
```

`prepare_source` pinned body: `source.len() > SRC_MAX_BYTES` → `Err("source
exceeds 65536 bytes")`; `org.is_some() && has_org_directive(source)` → the
§4.1 conflict message; `Ok(match org { Some(a) => format!("\torg
${:x}\n{source}", a.raw()), None => source.to_string() })`.

### 6.2 `src/tools/assemble_wire.rs` — wire structs + pure helpers

All args `Deserialize + JsonSchema`, outputs `Serialize + JsonSchema`, doc
comments become schema descriptions (exactly like `rip_wire.rs`):

```rust
pub const PATCH_MAX_BYTES: usize = 4096;
pub const READBACK_MAX_INSNS: usize = 64;

#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
pub struct AssembleArgs {
    /// 68000 source, vasm Motorola syntax (labels, $hex, move.w/.l, dc.b…).
    pub source: String,
    /// Load address for absolute label math ("$70000"). When given, the
    /// source must not contain its own org/rorg. Omit for position-free code.
    pub org: Option<String>,
    /// true → also return the assembler listing (addresses + bytes + source).
    pub listing: Option<bool>,
}

#[derive(Debug, serde::Serialize, schemars::JsonSchema)]
pub struct AssembleOutput {
    /// false = the SOURCE failed to assemble; fix it using `errors` and retry.
    pub ok: bool,
    /// Machine code, contiguous lowercase hex ("" when !ok).
    pub bytes_hex: String,
    /// Byte length of the assembled code.
    pub length: u32,
    pub errors: Vec<String>,
    pub warnings: Vec<String>,
    pub listing: Option<String>,
}

#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
pub struct PatchArgs {
    /// Even target address in ST RAM ("$70000"). org is forced to this.
    pub addr: String,
    /// 68000 source (no org/rorg — the server injects `org addr`).
    pub source: String,
}

#[derive(Debug, serde::Serialize, schemars::JsonSchema)]
pub struct PatchOutput {
    /// assembled AND written AND readback == assembled bytes.
    pub ok: bool,
    /// false = assembly failed (see errors); nothing was written.
    pub assembled: bool,
    /// Readback bytes equal assembled bytes. false after a write means the
    /// destination did not take the bytes (ROM/unmapped) — nothing to retry.
    pub verified: bool,
    pub addr: String,
    /// Bytes written (0 when !assembled).
    pub length: u32,
    /// addr + length — handy for the next patch or a breakpoint.
    pub end_addr: String,

}
```

### 6.3 `patch` flow (pinned, step by step)

```rust
// 1. Validate params — before any work.
let addr = parse_even_addr(&a.addr)?;                       // invalid_params on odd/bad
// 2. Assemble with org forced to addr (NO session lock held — subprocess
//    time must not block other tools).
let prepared = asm::source::prepare_source(&a.source, Some(addr))
    .map_err(|m| McpError::invalid_params(m, None))?;
let r = asm::assemble(&asm::vasm_path(), &prepared, false).await.map_err(to_mcp)?;
if !r.ok { return Ok(Json(PatchOutput::failed_assembly(addr, r.errors, r.warnings))); }
// 3. Size gates (§4.4) — as data, not MCP errors.
if r.bytes.is_empty() || r.bytes.len() > PATCH_MAX_BYTES { /* failed_assembly with the pinned message */ }
// 4. Lock the session; Running or Paused both legal (ADR-11 channels).
let mut guard = self.session.lock().await;
let name = guard.state_name();
let proc = guard.process_mut().ok_or_else(|| wrong_state(name, "running or paused"))?;
// 5. Chunked write through the EXISTING path — debug::write_bytes emits
//    `memwrite $addr xx yy …` and fails on any ERROR line.
write_chunks(proc, addr, &r.bytes).await.map_err(to_mcp)?;
// 6. Readback via the EXISTING snapshot path (same as snapshot disasm).
let mem = crate::session::memory::acquire_range(proc, addr, r.bytes.len())
    .await.map_err(to_mcp)?;
drop(guard);                                                // lock released before decode
// 7. Verify + disassemble what is actually in RAM.
let verified = mem.bytes() == r.bytes.as_slice();
let (readback, readback_truncated) = readback_listing(&mem, addr, r.bytes.len());
// 8. Output: ok = verified; end_addr = Addr::new(addr.raw() + len as u32).
```

`write_chunks` (private, `tools/assemble.rs`, ≤ 12 lines):

```rust
/// Sequential ≤ WRITE_MAX-byte memwrite calls (mirrors the proven
/// write_memory limit — one debugger line per chunk, never a mega-line).
async fn write_chunks(proc: &mut HatariProcess, addr: Addr, bytes: &[u8])
    -> crate::error::Result<()> {
    for (i, chunk) in bytes.chunks(WRITE_MAX).enumerate() {
        let at = Addr::new(addr.raw() + (i * WRITE_MAX) as u32);
        crate::debug::write_bytes(proc, at, chunk).await?;
    }
    Ok(())
}
```

A mid-sequence `memwrite` failure leaves a **partial write** — surfaced as
the MCP error from `write_bytes`; the agent re-patches (idempotent writes).
Do not add rollback (out of scope, §12).

### 6.4 Error mapping (pinned table)

| condition | surface |
|---|---|
| bad/odd `addr`, bad `org`, oversized source, org/rorg conflict | `McpError::invalid_params` (message from `prepare_source`/`parse_even_addr`) |
| vasm binary missing / spawn fail / timeout / temp I/O / bin > 64 KiB | `Error::Assembler` → `to_mcp` → `internal_error` (message names `SHIRAZMCP_VASM`) |
| source fails to assemble | `AssembleOutput { ok: false, errors }` / `PatchOutput { assembled: false, errors }` — **HTTP-200-style data** |
| patch > 4096 bytes / 0 bytes | `PatchOutput { ok: false, errors: [pinned message] }` |
| no session (Stopped) for `patch` | `wrong_state(name, "running or paused")` — `assemble` never checks the session |
| `memwrite` ERROR line / fifo timeout | existing `Error::Parse`/`Timeout` → `internal_error` (unchanged path) |
| readback ≠ assembled | `PatchOutput { ok: false, verified: false }` — data (ROM/unmapped is a fact, not a fault) |

### 6.5 Tool descriptions (pinned verbatim, wrap as the other tools do)

`assemble`: "Assemble Motorola 68000 source (vasm Motorola syntax — the ST
demo toolchain dialect: labels, $hex, dc.b/dc.w, move.w/.l…) to machine
code. No emulator needed. Returns hex bytes + length; assembly errors come
back in `errors` — fix the source and call again. Optional org sets the
load address for absolute label math (the source must not contain its own
org/rorg when org is given). listing=true adds the assembler listing.
Requires the vasm binary (override path with SHIRAZMCP_VASM)."

`patch`: "Hot-patch the ST: assemble 68000 source at addr (org is forced to
addr) and write it into emulator RAM — test a code change in place with no
PRG rebuild. Best used while paused (frozen); running works but the CPU may
execute half-written code mid-patch. After writing, the region is read back
and disassembled (`readback`): verified=true means RAM now holds exactly the
assembled bytes (a ROM or unmapped destination fails verification). Max
4096 bytes per patch."

```rust
/// Map decoded instructions to wire InsnOut (cycle estimate + PSG-aware
/// hardware annotations) and compute the next address. Shared by the
/// disasm tool (snapshot source) and patch readback (P8).
pub(crate) fn insns_out(insns: &[crate::analyze::disasm::Insn], base: Addr)
    -> (Vec<InsnOut>, Addr) {
    let mut psg = None;
    let mut next = base;
    let out = insns.iter().map(|i| {
        psg = track_psg(psg, &i.mnemonic, &i.ops);

        InsnOut { addr: i.addr.to_string(), mnemonic: i.mnemonic.clone(),
                  ops: i.ops.clone(), bytes_hex: hex_encode(&i.bytes),
                  cycles_est: cycles::insn_cycles(&i.bytes).map(cycles::round_st),
                  annotations: annotate_ops(&i.ops, psg) }
    }).collect();
    (out, next)
}
```

## 14. ADR-18 — append to `decisions.md` (verbatim; fill only the date)

```markdown
## 2026-07-XX — ADR-18: Hot-patch via external vasm — argv-only subprocess, diagnostics as data, readback-verified writes

**Status:** accepted
**Context:** P8 adds the freezer cartridge's built-in assembler: freeze the
ST → assemble a 68k snippet → write it into RAM → step/observe → iterate,
with no PRG rebuild. That needs a Motorola-syntax 68000 assembler. Writing
or embedding one in Rust is a project of its own, and no maintained crate
covers the full Motorola directive/operand dialect; meanwhile the exact
assembler the target demos are built with (vasm 2.0e, `vasmm68k_mot`) is on
disk, and dialect identity between "what I build" and "what I hot-patch" is
itself a feature. Shelling out to a binary also crosses two policy lines
that needed explicit treatment: dependency hygiene (an external, unpinned
binary) and subprocess security (never a shell).
**Decision:** (1) Shell out to vasm with `tokio::process::Command` and an
explicit argv vector — `-quiet -Fbin -o <tmp.bin> [-L <tmp.lst>] <tmp.s>` —
never a shell, source passed as temp-file content (controlled dir, RAII
cleanup, no user-controlled path components). Binary path from
`SHIRAZMCP_VASM` with a machine-local default (same policy as
`hatari_path`); an absent/failed binary is a typed `Error::Assembler`
(actionable message naming the env var), never a panic. No cargo feature:
there is no compile-time dependency to gate — runtime degradation is
strictly better than a build matrix. (2) A new leaf module `assemble/`
(driver + pure text helpers): `analyze/` stays a pure synchronous leaf,
`session/` stays Hatari-only, `ripper/` stays pure; only `tools/` imports
`assemble`. (3) Assembly diagnostics are DATA, not MCP errors: `{ok: false,
errors, warnings}` (sanitized — temp names scrubbed — and bounded, 16×200
chars) so the agent's assemble→fix→retry loop costs one round-trip per
iteration; the MCP error channel carries only infrastructure failures.
(4) The server injects `org` (always = addr for `patch`); user `org`/`rorg`
is rejected whenever an org is injected, because `-Fbin` zero-pads between
sections (verified: two orgs 256 bytes apart produced a 258-byte image) — a
silent gap-zeroing patch is the worst possible failure. (5) `patch` reuses
the proven paths end to end: `debug::write_bytes` (`memwrite`) in 256-byte
chunks (the `WRITE_MAX` the memory tools already pin), then
`memory::acquire_range` readback, byte-equality (`verified`) and an
embedded-Capstone disassembly of what RAM actually holds (cycle estimates +
hardware annotations via the shared P2 mapper). Bounds: source 64 KiB,
output 64 KiB, patch 4 KiB, vasm timeout 10 s, readback listing 64 insns.
Patch is legal in Running and Paused (both ADR-11 control planes serve
`memwrite`); Running is documented as racy, Paused is the recommended flow.
**Alternatives considered:** Embedding a Rust 68k assembler — rejected for
now: large surface (Motorola directives, expressions, optimizations), no
maintained crate, and dialect drift versus the toolchain the demos use;
revisit only if the external binary becomes untenable. Hatari's debugger —
has no assembler command, not an option. Returning assembly errors as MCP
errors — rejected: it turns the agent's edit loop into error-channel noise
and hides warnings on success. Accepting user org directives alongside an
injected org — rejected outright (gap-zeroing hazard above). A cargo
feature (`asm`) — rejected: gates nothing at compile time, costs a build
matrix. Streaming source over stdin — vasm reads files, and the temp file
keeps diagnostic line numbers meaningful.
**Consequences:** The 68k edit-compile-test loop runs entirely in place —
freeze, patch, step, observe — with byte-verified writes (a ROM/unmapped
destination is reported as `verified=false`, a fact not a fault). The
system depends on an external binary at runtime only, with graceful typed
degradation and a documented override; goldens pin the exact vasm
invocation and output bytes, so a vasm upgrade that changes behavior fails
loudly in tests. Partial writes on a mid-chunk failure are possible and
documented (re-patch is idempotent); undo/journal, symbol-aware assembly,
and PRG emission are the pinned improvement paths.
```
