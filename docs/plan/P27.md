## 0. Open questions (stated, not silently guessed)

1. **Why did Hatari exit in the original field report?** The report ("broken
   pipe while `status` said paused, only stop/start recovered") is fully
   explained by *an exited Hatari that the FSM never noticed* (§4.1 proves
   EPIPE ⇒ Hatari exited or is in its exit path). What *killed* Hatari that
   day (SDL window close? crash? OOM?) is not determinable from source. The
   fix in §4 is defensive and correct regardless of the trigger; it also
   captures the child's exit status into the error/status note so the next
   occurrence is diagnosable.
2. **Is EPIPE-with-Hatari-still-alive reachable?** Only in a narrow mid-exit
   window (Hatari has run `Control_RemoveFifo()` at `main.c:1091` but the
   process has not been reaped yet) or if a `hatari-option … --cmd-fifo`
   re-parse recreated the fifo (`control.c:545` — we never send that option).
   §4.3 handles both defensively (bounded reopen with a short timeout; never
   more than one retry).
3. **Exact `perror` suffix text** is locale/errno-dependent — handled by
   prefix-matching only (§2.2); never match the full line.

Everything else in this spec is pinned.

## 1. Verified Hatari facts (the wire contract this phase builds on)

All from `/home/matt/projects/hatari/src`:

### 1.1 The EAGAIN spam (Ask A1)

- `Control_CheckUpdates()` (`control.c:424`) does a **non-blocking** `read()`
  on the control fifo (`control.c:435`; the fifo is opened
  `O_RDONLY | O_NONBLOCK` at `control.c:554`) and calls
  `perror("command FIFO read error")` on **every** `bytes < 0`
  (`control.c:437`) — on an idle fifo with a writer attached (ours, always),
  `read()` returns `-1`/`EAGAIN` on **every poll**.
- It is polled from the **main loop**: `Main_EventHandler()` calls
  `Control_CheckUpdates()` once per iteration (`main.c:591`). A long
  `run_frames` therefore deposits dozens of these lines into our log (stderr
  is redirected to `hatari.log` by `build_command`, `boot.rs`), and `LogTail`
  faithfully collects them into tool `output`.
- `perror` emits exactly `command FIFO read error: <strerror(errno)>\n` — the
  prefix is compile-time constant; the suffix is locale/errno text.
- **Noise survey** (grep of `control.c` + `main.c` for unconditional
  `perror`/`fprintf(stderr` on per-iteration paths): the *only* line emitted
  repeatedly on the idle main-loop path is `command FIFO read error`. The
  other `perror`s in `control.c` (`Control socket select() error`,
  `Control socket read error` — socket mode, we use fifo mode; `FIFO
  creation/open error`, `Remove FIFO failed` — one-shot setup/teardown) and
  `main.c:1013`'s `ERROR: …` (the `--alert-level` alert path — **real**
  errors we must NOT filter) do not recur. The noise list therefore has
  **one entry**, in a predicate designed to take more (§2.2).

### 1.2 `hatari-event` (Ask B) — verbatim wire strings

- Dispatch: `Control_ProcessBuffer` (`control.c:336`) splits each
  newline-separated command at the **first space**; `hatari-event <arg>` →
  `Control_InsertEvent(arg)` (`control.c:368-369`).
- `Control_InsertEvent` (`control.c:152`) accepts exactly:
  `doubleclick` (`:154`), `rightdown` (`:158`), `rightup` (`:162`), else
  falls through to `Control_InsertKey` (`control.c:87`).
- `Control_InsertKey` accepts `keypress <key>` (press+release, `:92`),
  `keydown <key>` (`:95`), `keyup <key>` (`:99`).
- `<key>` parsing (`control.c:108-135`):
  - **multi-char** ⇒ scancode via `strtol(key, &endptr, 0)` — rejected if
    trailing garbage or `keycode < 0 || keycode > 255` (`:113`), else
    `IKBD_PressSTKey(keycode, down/up)`. Base 0 means decimal, `0x` hex,
    **and leading-0 octal** — our client-side canonicalization sidesteps the
    octal trap (§3.4).
  - **single char** ⇒ must be `isalnum` (`:125`, error text: *"non-alphanumeric
    character '%c' needs to be given as keycode"*), else
    `Keymap_SimulateCharacter(key[0], down/up)`.
- `Keymap_SimulateCharacter` (`keymap.c:933`) auto-presses **LSHIFT around
  uppercase** characters and routes through the host SDL keymap — so `"A"`
  types a shifted A; layout-odd characters are safer as scancodes.
- Hatari's own help pins **space = 57, enter = 28** (`control.c:179`).
- **Failure signaling:** invalid events print `ERROR: …` to stderr
  (`control.c:105,114,126,169`) and `Control_InsertEvent` returns false; on
  success there is **no output at all** (the success `fprintf` is `#if 0`,
  `control.c:136`).
- **CRITICAL batching fact:** `Control_ProcessBuffer`'s loop is
  `while (ok && cmdend && *cmd)` (`control.c:402`) — **the first failing
  command aborts the rest of the read batch**. A single invalid event can
  silently swallow every command queued behind it in the same `read()`.
  Consequence: validation is 100% client-side; we never send an event Hatari
  could reject (§3.4), and the sentinel-confirm design (§3.6) survives even
  if one slips through (the sentinel retry arrives in a *new* read batch).
- **Frozen Hatari does not service the fifo:** `Control_CheckUpdates` runs
  only in `Main_EventHandler` (`main.c:591`); a CPU parked in DebugUI
  (ADR-11 `ControlChannel::DebugStdin`) never reaches it. Fifo writes made
  while frozen **queue in the pipe buffer and replay on resume** — already
  established, load-bearing behavior in this codebase (`fifo/mod.rs` §2.5
  stray-sentinel filter and `freeze()`'s doc both exist because of it).

### 1.4 The broken pipe (Ask A2) — who can close what

- **Our side** (`spawn/boot.rs` / `spawn/mod.rs`): the fifo write end is ONE
  `tokio::fs::File` opened write-only at spawn (`open_fifo_write`) and held
  for the session's life; Hatari's stdin is ONE `ChildStdin`, same lifetime.
- **Hatari's fifo read end** is closed **only** by `Control_RemoveFifo()`
  (`control.c:515`), whose only callers are: `Control_SetFifo` itself
  (re-configuration, `control.c:545,557` — reachable only via option
  parsing, `options.c:2274`, which we never re-trigger at runtime),
  `main.c:1058` (startup option-parse failure), and **`main.c:1091` — the
  line immediately after `M68000_Start()` returns, i.e. the normal emulator
  exit path**.
- **Hatari's stdin read end** is never closed by Hatari code; it closes when
  the **process exits** (kernel).
- Therefore, pinned: **`EPIPE` on either control plane means Hatari has
  exited or is inside its exit path.** A live Hatari — even one frozen in
  DebugUI — holds both read ends open (a frozen Hatari merely doesn't *read*
  the fifo; an unread non-full pipe accepts writes without error; our
  command volume can't approach the 64 KiB pipe buffer). "Reopen and retry
  into a live-but-slow Hatari" is the wrong mental model; the right fix is
  **death detection + honest state**, with a bounded reopen only for the
  narrow mid-exit/alive window (§0 Q2).
- Why the field report saw it "while paused": `status` (`lifecycle.rs`)
  reports the FSM enum name only — it never probes the child. A dead Hatari
  under a `Paused` FSM keeps answering `paused` forever. That is the
  inconsistency §4.5 closes.
- Note on naming: `Error::Fifo` is the variant for **all** control-plane I/O
  (stdin writes included — `write_line` in `fifo/mod.rs` uses it regardless
  of writer), so the report's "fifo I/O … Broken pipe" does not tell us which
  plane failed. The fix covers both.

## 2. Part 1 — A1: filter Hatari noise lines out of returned output

Smallest change of the phase; land it first.

### 2.1 Where the filter lives (decision + rationale)

**In `strip_protocol_lines` (`src/session/fifo/mod.rs`), via a new predicate
module — NOT in `LogTail` ingestion.** Rationale:

- `LogTail` (`log_tail.rs`) is deliberately semantics-free plumbing (byte
  cursor + marker search). Teaching it which Hatari lines "don't count"
  couples generic tailing to Hatari line semantics and silently affects
  *marker matching* callers (`wait_for_log`, `control_and_wait` match
  needles; today no needle can collide with a noise line, but the coupling
  would have to be re-proven for every future needle).
- `strip_protocol_lines` is already the codebase's single, documented
  output-hygiene point (echoes, blanks, §2.5 stray sentinels) and every
  user-visible output path flows through it: `debug()` (all tools) and
  `continue_and_wait()` (watch / run_frames / breakpoint output). One clause
  there fixes every tool at once, stays a pure function, and unit-tests
  without tokio.
- Ordering bonus: outputs are noise-stripped **before** `cap_output_tail`
  (ADR-28) caps them, so noise can no longer evict real output from the tail
  window.

### 2.2 New file: `src/session/fifo/noise.rs` (~40 non-test lines)

```rust
//! Hatari-side log noise: lines Hatari's main loop emits unconditionally on
//! healthy idle paths, carrying zero information for the agent. Kept as a
//! single documented list — extend here, never inline elsewhere.
//!
//! Survey (P27 §1.1, verified against hatari/src): the only recurring
//! main-loop noise is control.c:437's perror on the non-blocking fifo's
//! EAGAIN — emitted once per Main_EventHandler iteration (main.c:591)
//! whenever the fifo is idle, i.e. constantly while the machine runs.
//! main.c:1013's "ERROR: …" alert lines are REAL errors and must never
//! match here.

/// Line prefixes (perror suffixes are locale/errno text — never match the
/// full line). control.c:437.
const NOISE_PREFIXES: [&str; 1] = ["command FIFO read error"];

/// True for lines that are pure Hatari idle-path noise (§1.1 survey).
pub(crate) fn is_hatari_noise(line: &str) -> bool {
    NOISE_PREFIXES.iter().any(|p| line.starts_with(p))
}
```

`starts_with`, not `contains`: a hypothetical program printing that phrase
mid-line through the emulated console must not be eaten.

## 3. Part 2 — B: the `send_key` tool

New tool, independent of Parts 1 and 4; can land second.

### 3.1 Semantics (decision + rationale)

Chosen: **option (c)+(b) hybrid — always write events to the FIFO; compose
with the managed frame-runner when the caller asks for it.**

- Events go to the **fifo in every state** (`HatariProcess::write_wrapper`
  already always targets `self.fifo`). Running ⇒ serviced within one
  main-loop iteration (§1.2). Paused ⇒ they **queue in the pipe and replay on
  resume** (§1.2, established behavior).
- Optional `frames: u32` arg turns the call into the atomic headless-capture
  primitive: *freeze → queue key(s) → run exactly N frames → freeze* — the
  agent flow is `send_key(keys=["space"], frames=2)` → `screenshot`. This
  reuses the existing ADR-15/ADR-27 machinery **verbatim**
  (`managed::ensure_paused`, `managed::run_to_breakpoint`,
  `frames::vbl_condition`, `frames::default_timeout` — all already
  `pub(crate)`), and is strictly *more* deterministic than option (b)'s
  thaw-send-refreeze (which would run an uncontrolled number of frames).
- Why not (a) (error when paused): it throws away the queue-on-freeze
  behavior we get for free and forces the agent into a
  `resume`/`send_key`/`pause` dance — worse ergonomics for the feature's
  whole point. Why not pure (b): non-deterministic frame count; and we would
  be reimplementing `run_frames` badly. Paused + no `frames` returns
  `queued: true` with an explanatory note — honest, cheap, occasionally
  exactly what you want (stage a key, then `run_frames` yourself).
- **Mouse events exposed too** (`doubleclick`/`rightdown`/`rightup`):
  same wire path (§1.2), zero extra tool surface (they are accepted as `keys`
  entries), and they are the only way to drive GEM double-click/context
  interactions headless. Cost: ~6 lines of parse table.

### 3.2 Key sequence, not single key

`keys: Vec<String>`, **1..=32 entries** (`KEYS_MAX = 32`). Typing a string is
`keys: ["h","e","l","l","o"]` — uppercase handled by Hatari itself (§1.2
LSHIFT wrapping). 32 covers a GEM filename plus navigation with slack; it
also bounds the fifo batch far below both Hatari's 4096-byte read buffer
(`control.c:428`) and the pipe buffer. No separate `text` arg: it would
duplicate the sequence path for an alnum-only subset (Hatari's isalnum gate)
and add a second validation surface for no new capability.

### 3.3 New files

- `src/tools/input.rs` — the tool (router `input_router`), ~170 non-test
  lines.
- `src/tools/input_wire.rs` — pure parsing/validation/wire-building +
  unit tests, ~140 non-test lines.

Register in `src/tools/mod.rs`: `pub mod input;`,
`pub(crate) mod input_wire;`, and `+ Self::input_router()` in

`#[tool_router(router = input_router, vis = "pub(crate)")]` — the generated

### 3.4 `input_wire.rs` — exact contract

```rust
//! Pure key/event parsing for `send_key` — everything here is validated
//! CLIENT-SIDE because Control_ProcessBuffer aborts the whole read batch at
//! the first failing command (control.c:402, P27 §1.2): we must never send
//! an event Hatari could reject.

/// control.c-verbatim wire tokens (ADR-11 §2.1 convention: never build
/// these ad hoc). Sources: control.c:368 (hatari-event), :92/:95/:99
/// (keypress/keydown/keyup), :154/:158/:162 (mouse events).
pub(crate) const EVENT_CMD: &str = "hatari-event";
pub(crate) const ACTION_PRESS: &str = "keypress";
pub(crate) const ACTION_DOWN: &str = "keydown";
pub(crate) const ACTION_UP: &str = "keyup";
pub(crate) const MOUSE_DOUBLECLICK: &str = "doubleclick";
pub(crate) const MOUSE_RIGHTDOWN: &str = "rightdown";
pub(crate) const MOUSE_RIGHTUP: &str = "rightup";

pub(crate) const KEYS_MAX: usize = 32;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Action { Press, Down, Up }

#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) enum KeyEvent {
    /// Single ASCII alphanumeric char — control.c:125 isalnum gate.
    Char(char),
    /// ST scancode 0..=255 — control.c:113 range check.
    Scancode(u8),
    /// One of the three control.c mouse events (complete events; only
    /// valid with Action::Press).
    Mouse(&'static str),
}

pub(crate) fn parse_action(s: Option<&str>) -> Result<Action, String>;
pub(crate) fn parse_key_entry(entry: &str) -> Result<KeyEvent, String>;
/// One wire line per event, e.g. "hatari-event keypress 57".
/// Err if a Mouse event is combined with Down/Up.
pub(crate) fn wire_lines(events: &[KeyEvent], action: Action) -> Result<Vec<String>, String>;
```

`parse_key_entry` rules, in order (each mirrors a pinned Hatari rule — never
narrower in a way that lies, never wider than Hatari accepts):

1. Empty ⇒ `Err`.
2. Exactly one char: ASCII alphanumeric ⇒ `Char` (mirrors `control.c:108/125`
   — single chars are ALWAYS the character path, digits included); any other
   single char ⇒ `Err` quoting Hatari's rule ("non-alphanumeric characters
   must be given as a scancode, e.g. space is 57").
3. Case-insensitive match against §1.3 alias table (incl. the three mouse
   tokens) ⇒ `Scancode`/`Mouse`.
4. `0x`/`0X` prefix ⇒ hex parse; else all-digits ⇒ **decimal** parse, but
   **reject a leading zero with more digits** (`"057"`) — Hatari's
   `strtol(…, 0)` would read it as octal; refuse the ambiguity instead of
   silently re-basing. Parsed value must be `0..=255` (`control.c:113`).
5. Anything else ⇒ `Err` listing the accepted forms.

Canonical emission: scancodes are formatted **decimal, no leading zeros**
(unambiguous for Hatari's base-0 `strtol`); chars are emitted as-is. Wire
shapes: `{EVENT_CMD} {action} {key}` for keys, `{EVENT_CMD} {mouse}` for
mouse events (mouse events carry no action word — `control.c:154-165`).

### 3.5 `input.rs` — args, output, tool

```rust
#[derive(Debug, Deserialize, JsonSchema)]
pub struct SendKeyArgs {
    /// Key sequence, 1..=32 entries. Each entry: a single ASCII
    /// alphanumeric character ("a", "5" — uppercase auto-shifts), an ST
    /// scancode ("57", "0x39"), a named alias (space, enter, esc, f1..f10,
    /// up/down/left/right, help, undo, ...), or a mouse event
    /// (doubleclick, rightdown, rightup).
    pub keys: Vec<String>,
    /// "press" (default; press+release), "down", or "up". Programs that
    /// POLL key state each frame can miss a same-slice press+release: use
    /// down + frames + a second call with up.
    pub action: Option<String>,
    /// Run exactly N VBL frames after injecting (1..=5000) and end PAUSED —
    /// the headless capture flow: send_key(keys, frames) → screenshot.
    /// Omitted: running sessions keep running (keys land within one main-
    /// loop iteration); paused sessions queue the keys (queued=true) until
    /// resume/run_frames.
    pub frames: Option<u32>,
    /// Wait budget for the frames run, ms; default as run_frames.
    pub timeout_ms: Option<u64>,
}

#[derive(Debug, Serialize, JsonSchema)]
pub struct SendKeyOutput {
    /// Canonical events as written, e.g. ["keypress 57"].
    pub sent: Vec<String>,
    /// true iff the session is paused and no frames were requested: events
    /// sit in the fifo and take effect on the next resume/run_frames.
    pub queued: bool,
    pub state: String, // "running" | "paused"
    #[serde(skip_serializing_if = "Option::is_none")]
    pub frames_requested: Option<u32>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub frames_completed: Option<bool>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub pc: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub output: Option<String>, // cap_output_tail'd
}
```

Flow (keep each fn ≤30 lines; split helpers as in `frames.rs`):

1. Validate: `keys` len `1..=KEYS_MAX`; `parse_action`; `parse_key_entry`
   per entry; `wire_lines`. Any failure ⇒ `McpError::invalid_params` with
   the offending entry named. **Nothing is written unless everything
   parses** (§1.2 batch-abort fact).
2. Lock session. `AnySession::Stopped` ⇒ `wrong_state(name, "running or
   paused")`.
3. If `frames: Some(n)`: validate `1..=frames::FRAMES_MAX` (reuse
   `frames.rs` validation shape); `managed::ensure_paused`; read
   `vbl_before` (same `debug::evaluate(proc, "VBL")` as `frames.rs`); write
   each wire line via `proc.write_wrapper(&line)` (queues — machine is
   frozen); `managed::run_to_breakpoint(&mut guard,
   &frames::vbl_condition(vbl_before, n), timeout)`; build output like
   `frames.rs::build_output` (Fired ⇒ `state: "paused"`,
   `frames_completed`, `pc`, `output` = `cap_output_tail`; TimedOut ⇒
   `state: "running"`, `frames_completed: Some(false)`). Scan the fired
   `output` for lines starting `"ERROR: "` (Hatari event rejection, §1.2) —
   if present, return `invalid_params` quoting the line (should be
   unreachable after step 1; belt-and-braces).
4. If `frames: None` and **Running**: write each wire line
   (`proc.write_wrapper`); then ONE confirm round-trip
   `proc.debug("evaluate pc")` — the sentinel echo proves the whole batch
   (events + sentinel) was consumed by `Control_ProcessBuffer`; scan its
   returned output for `"ERROR: "` lines as above. Return `queued: false`,
   `state: "running"`. (If an event DID fail, the batch aborts before the
   sentinel, but `read_sentinel_with_retry` re-writes the sentinel in a new
   read batch — so `debug()` still completes and the ERROR line is in its
   collected output. Design holds either way.)
5. If `frames: None` and **Paused**: write each wire line (queues), return
   `queued: true`, `state: "paused"`, no confirm possible (frozen Hatari
   reads nothing — §1.2).

### 3.6 Why the confirm sentinel matters (do not drop it)

Success is silent (§1.2), so without the round-trip a Running-state
`send_key` returns before Hatari even read the batch, and a failure would be
invisible. The sentinel is the existing, cheap "batch consumed" barrier and
also carries any `ERROR:` line back in its collected output. This mirrors
the `LIVENESS_PROBE` convention (`spawn/control.rs`).

## 4. Part 3 — A2: broken pipe = dead Hatari; detect, classify, tell the truth

Independent of Parts 1-2; land last (it touches the most files). If live
verification stalls, Parts 1-2 still ship.

### 4.1 Failure model (pinned in §1.4)

`EPIPE` on either plane ⇒ Hatari exited or is mid-exit. The FSM cannot see
this today; `status` lies (`paused`) until a human runs `stop`/`start`.

### 4.2 New error variant (`src/error.rs`)

Process death is a real category callers must branch on (retry logic must
NOT retry into it; tools should render it distinctly):

```rust
    /// The Hatari child process is gone — detected when a control-plane
    /// write hit EPIPE and `try_wait` confirmed exit (P27/ADR-<N>).
    #[error("hatari exited ({status}) — session is defunct; call status or stop to reset")]
    ProcessExited { status: String },
```

`status` is `ExitStatus`'s `Display` (e.g. `signal: 11 (SIGSEGV)`) or
`"already reaped"` when a prior probe consumed it. Add the variant to
`to_mcp` (internal_error arm) and a display unit test alongside the others.

### 4.3 New file: `src/session/spawn/recover.rs` (~90 non-test lines)

Precedent: `control.rs` (an `impl HatariProcess` block split out for the
line ceiling). Contents:

```rust
/// True iff `e` is a control-plane write that hit EPIPE.
pub(crate) fn is_broken_pipe(e: &Error) -> bool {
    matches!(e, Error::Fifo { source, .. }
             if source.kind() == std::io::ErrorKind::BrokenPipe)
}

impl HatariProcess {
    /// Non-blocking liveness probe. Some(status) ⇒ the child has exited.
    pub fn exit_status(&mut self) -> Option<std::process::ExitStatus>;
    // = self.child.try_wait().ok().flatten()

    /// After an EPIPE on the FIFO plane: confirm the child is alive
    /// (dead ⇒ Error::ProcessExited, never retry into a corpse), then
    /// reopen the fifo write end ONCE with a short bound. A live Hatari
    /// holds the read end open, so a blocking O_WRONLY open returns
    /// immediately; a mid-exit Hatari has removed the fifo file
    /// (main.c:1091) and the open fails fast — map that to ProcessExited
    /// after a final try_wait.
    pub(super) async fn recover_fifo_epipe(&mut self) -> Result<()>;

    /// After an EPIPE on the STDIN plane: no reopen is possible (a child's
    /// stdin is fixed at spawn). Classify only: brief grace
    /// (STDIN_EPIPE_GRACE = 200 ms) for the mid-exit window, re-probe,
    /// and return Error::ProcessExited (probe hit) or Error::Session
    /// ("hatari stdin broken but process alive — unrecoverable; call
    /// stop") — the latter should be unreachable per §1.4 but must not
    /// panic or loop.
    pub(super) async fn classify_stdin_epipe(&mut self) -> Error;
}
```

`recover_fifo_epipe` reuses `boot::open_fifo_write` but with a pinned
`REOPEN_TIMEOUT_MS: u64 = 1_000` (not `boot_timeout_ms` — this open either
succeeds instantly or never; give `open_fifo_write` an explicit timeout
parameter, updating its two call sites, rather than duplicating it).

### 4.4 Retry-once wiring in `src/session/spawn/mod.rs`

Retry at the **`HatariProcess` level, whole-operation** — `write_line` (the
literal write site) is a free function with no `Child` access, and retrying
mid-sentinel-protocol would corrupt the round-trip. Whole-operation retry is
safe because sentinel values are **per-call unique** (`sentinel.rs`: a
half-finished attempt's stale echo is family-filtered and can never satisfy
the retry's fresh value). The one-`write_all` invariant documented on
`write_line` is untouched — the retry re-enters the same `write_line`.

```rust
pub async fn debug_with_timeout(&mut self, cmd: &str, timeout_ms: u64) -> Result<String> {
    match self.debug_attempt(cmd, timeout_ms).await {   // = today's body
        Err(e) if recover::is_broken_pipe(&e) && matches!(self.control, ControlChannel::Fifo) => {
            self.recover_fifo_epipe().await?;           // ProcessExited if dead
            self.debug_attempt(cmd, timeout_ms).await   // exactly ONE retry
        }
        Err(e) if recover::is_broken_pipe(&e) => Err(self.classify_stdin_epipe().await),
        other => other,
    }
}
```

Apply the same wrap to `write_wrapper` (fifo plane) and, via it,
`control_and_wait` gets the retry for free (its only write goes through
`write_wrapper`). In `control.rs`: change `freeze()`'s `ARM_FREEZE` write
from `fifo::write_wrapper(&mut self.fifo, …)` to `self.write_wrapper(…)`
(gains the retry); in `freeze`/`thaw`/`continue_until_break`, map any
remaining `is_broken_pipe` error (their stdin writes) through
`classify_stdin_epipe` before returning. Never more than one retry on any
path; no loop.

`ControlChannel` needs a read: either make the match above live inside
`spawn/mod.rs` (it already owns `self.control`) — preferred — or add a
`fn on_fifo_plane(&self) -> bool`. Do not export `ControlChannel`.

**Guard rails (all three are hard requirements):** (1) never retry unless
`exit_status()` returned `None`; (2) at most one retry per public call;
(3) the retried operation's error is returned as-is (no second recovery).

### 4.5 `status` tells the truth (`src/tools/lifecycle.rs`)

`status` becomes a liveness probe + reaper:

```rust
pub async fn status(&self) -> Result<Json<StatusOutput>, McpError> {
    let mut guard = self.session.lock().await;
    let note = reap_if_dead(&mut guard);
    Ok(Json(StatusOutput {
        state: guard.state_name().to_string(),
        hatari_path: guard.config().hatari_path.display().to_string(),
        version: env!("CARGO_PKG_VERSION").to_string(),
        note,
    }))
}

/// If the FSM says Running/Paused but the child has exited, reset the
/// session to Stopped and say so. ≤30 lines: probe via process_mut()
/// + exit_status(); on Some(status), mem::replace the guard with
/// AnySession::new(config) (the dead Child is dropped; kill_on_drop on a
/// reaped child is a no-op) and return
/// Some(format!("hatari exited ({status}) while session was {old}; reset to stopped")).
fn reap_if_dead(guard: &mut AnySession) -> Option<String>;
```

`StatusOutput` gains
`#[serde(skip_serializing_if = "Option::is_none")] pub note: Option<String>`
— additive wire change only. Other tools do **not** auto-transition the FSM
on `ProcessExited` (that would smear guard-transition logic across every
tool); the error message itself directs the agent to `status`/`stop`, both
of which recover. Record this trade-off in the ADR.

### ADR draft 1 — Control-plane robustness: noise filtering + EPIPE means a dead Hatari

```markdown
## 2026-07-11 — ADR-<N>: Control-plane robustness — Hatari noise filtered centrally; EPIPE classified as process death

**Status:** accepted
**Context:** (1) Hatari's main loop perror()s "command FIFO read error:
EAGAIN" on every idle poll of its non-blocking control fifo
(control.c:435-438, polled at main.c:591); with stderr redirected to our
log, every long-running tool call returned dozens of noise lines. (2) A
field report showed `fifo I/O … Broken pipe` while `status` claimed
`paused`; source analysis (P27 §1.4) pins EPIPE on either control plane to
an exited/exiting Hatari — Control_RemoveFifo's only runtime caller is the
exit path (main.c:1091) and stdin's read end only closes at process death —
yet the FSM never probed the child, so `status` lied until stop/start.
**Decision:** (1) A single documented noise predicate
(`fifo/noise.rs::is_hatari_noise`, prefix-match only — perror suffixes are
locale text) applied in `strip_protocol_lines`, the existing central
output-hygiene point, so every tool inherits the fix and noise is stripped
before ADR-28's tail cap. (2) A `ProcessExited` error variant; on
control-plane EPIPE, HatariProcess probes `try_wait`: dead ⇒ ProcessExited
(never retried), alive+fifo-plane ⇒ reopen the write end once (1 s bound)
and retry the whole operation exactly once (safe: sentinels are per-call
unique), alive+stdin-plane ⇒ classify only (no reopen possible). (3)
`status` probes liveness and reaps: a dead child under a live-state FSM is
reset to Stopped with an explanatory `note`.
**Alternatives considered:** Filtering in LogTail ingestion (rejected:
couples semantics-free tailing to Hatari line meanings and silently affects
needle-matching callers); patching Hatari (rejected: we drive the user's
binary); retrying EPIPE blindly at the write site (rejected: write_line has
no Child access, mid-protocol retries corrupt sentinel round-trips, and
§1.4 shows EPIPE is almost never transient); auto-transitioning the FSM to
Stopped from every tool on ProcessExited (rejected: smears guard-transition
logic across the tool layer; the error message directs to status/stop,
which recover).
**Consequences:** run_frames/watch output is clean; a crashed Hatari is
detected at the next control-plane write and `status` self-heals to
`stopped` with the exit status preserved for diagnosis; the noise list is
one grep away from extension; the paused-plane EPIPE remains
non-recoverable by design (stdin cannot be reopened) — only honest.
```

### ADR draft 2 — `send_key`

```markdown
## 2026-07-11 — ADR-<N+1>: send_key — IKBD injection over the existing control fifo, composed with the managed frame-runner

**Status:** accepted
**Context:** Headless capture of interactive modes required rebuilding
programs with -D default flags because nothing could press a key. Hatari's
control fifo already accepts `hatari-event keypress/keydown/keyup
<char|scancode>` plus doubleclick/rightdown/rightup
(control.c:87-182); but hatari-event is serviced by Control_CheckUpdates in
the MAIN loop (main.c:591) — a Hatari frozen in DebugUI (ADR-11) queues
fifo writes until resume, and Control_ProcessBuffer aborts a whole read
batch at the first invalid command (control.c:402).
**Decision:** One `send_key` tool (keys: 1..=32 entries — chars, scancodes
0..=255 emitted canonically as decimal, named aliases pinned from keymap.c,
plus the three mouse events; action press/down/up). Validation is 100%
client-side (batch-abort fact). Events always go to the fifo: Running ⇒
serviced within one main-loop iteration, confirmed by one sentinel
round-trip whose output is scanned for Hatari `ERROR:` lines; Paused ⇒
queued (reported `queued: true`). An optional `frames: N` arg composes with
the ADR-15/27 machinery (ensure_paused → queue events → run_to_breakpoint
on VBL+N) into the atomic headless-capture primitive: freeze → inject → run
exactly N frames → freeze → screenshot.
**Alternatives considered:** Erroring when paused (rejected: discards the
free queue-on-freeze behavior and worsens the agent flow); auto
thaw-send-refreeze (rejected: uncontrolled frame count — the frames arg
does it deterministically with existing machinery); a separate `send_text`
tool (rejected: alnum-only subset of the sequence path, second validation
surface, no new capability); exposing mouse events as a separate tool
(rejected: same wire path, three parse-table lines).
**Consequences:** Interactive prototypes are drivable headless with
deterministic capture; press+release lands in one main-loop slice, so
state-polling programs need down/frames/up (documented on the tool); the
single-char path rides the host SDL keymap (uppercase auto-shifts,
layout-odd chars should use scancodes).
```
