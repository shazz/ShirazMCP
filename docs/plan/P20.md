# P20 — STE DMA-PCM sample ripper: `rip_sample` — Implementation Spec

> Executable spec for **rust-engineer**. Zero design decisions are left open:
> where this document says something, do exactly that. If reality contradicts
> this spec, fix per the `Implementation note` fallbacks below; if there is no
> fallback, stop and flag to rust-architect.
> Scope guard: **the decode is pure and the dump is register-driven** — if you
> find yourself writing a RAM *scanner* for headerless PCM, adding a
> `RipPlugin`, resampling audio, or emulating the LMC1992 filters, you have
> left the spec.

Authority chain: this spec → `ARCHITECTURE.md` → `decisions.md` (ADR-5, -9,
-11, -20 are the ones P20 leans on; ADR-33 is the sibling it deliberately
deviates from — §3.4). P8–P17 precedent applies: PLAN.md ends at P7 — this

**rmcp 2.2:** everything used below is already proven in the codebase
(`docs/plan/rmcp-2.2-notes.md`). Patterns to copy: `Json<T>` output —
`record_audio` in `tools/audio.rs`; freeze/gather/thaw choreography —
`tools/machine_state.rs`. Do NOT re-research the crate.

**Why this phase exists:** the DHS "Uhane" demo's music is **STE DMA sound**
— 8-bit signed PCM streamed from RAM by the DMA sound engine at
`$FFFF8900+` — not the YM2149. `identify_music` (YM replay anchors) and
`ym_state` (PSG registers) are structurally blind to it. This closes that
gap: the DMA frame registers point *directly* at the playing sample buffer,
so ripping it is deterministic — read registers, dump `[start, end)`,
convert to WAV. No scanning, no heuristics.

---

## 1. Deliverable in one sentence

One new MCP tool: **`rip_sample`** — read the STE DMA sound registers
(`$FF8901` control, `$FF8903/05/07` frame start, `$FF890F/11/13` frame end,
`$FF8921` mode/rate) under a momentary freeze (ADR-20 pattern), `savebin`
the `[frame_start, frame_end)` bytes, convert the signed 8-bit PCM to a
16-bit WAV on disk via `src/audio/wav.rs`, and return a **path handle** plus
rate/length/stereo/peak facts — with a clean `"none"` status (never an
error) when DMA sound is off or the machine has no DMA sound engine.

### 2.1 The register bank (memory_map.txt + `hatari/src/dmaSnd.c`)

All registers are **byte-wide at odd addresses** (68000 upper/lower byte
convention). ST-relevant bits only — the F030 record/16-bit bits exist but
are out of scope (§3.6).

| Address | Name | Bits we decode |
|---|---|---|
| `$FF8901` | DMA control | bit 0 = **DMA replay on** (play), bit 1 = **loop replay buffer** |
| `$FF8903/05/07` | Frame **start** hi/mid/lo | 24-bit RAM address; hardware ignores bit 0 of lo |
| `$FF8909/0B/0D` | Frame **counter** hi/mid/lo | current DMA fetch address (read-only on real HW) |
| `$FF890F/11/13` | Frame **end** hi/mid/lo | 24-bit, exclusive; bit 0 of lo ignored |
| `$FF8920` | Track control (F030) | not decoded (reads 0 on STE) |
| `$FF8921` | Sound mode | bit 7: 0=stereo 1=**mono**; bits 1-0: rate — `00`=6258 Hz, `01`=12517, `10`=25033, `11`=50066 |

Pinned semantics from `dmaSnd.c` (all verified in source):

- **Rate table** — `DmaSndSampleRates[4] = { 6258, 12517, 25033, 50066 }`
  (dmaSnd.c:216), indexed by `soundMode & 3`.
- **Address latch** — `DmaSnd_StartNewFrame()`:
  `frameStartAddr = (IoMem[0xff8903]<<16) | (IoMem[0xff8905]<<8) |
  (IoMem[0xff8907] & ~1)`; identically for end. **The low bit is forced
  even** — our decode does the same, so `end - start` is always even.
- **Sample format** — signed 8-bit PCM (`(int8_t)STMemory_DMA_ReadByte`,
  the FIFO refill). Stereo interleaves byte pairs: **even address = left,
  odd = right** (memory_map.txt: "high pair the left channel, low pair
  right channel"; Hatari's FIFO pulls even→left).
- **Control** — `nDmaSoundControl = written & 3`; `DMASNDCTRL_PLAY` = bit 0,
  `DMASNDCTRL_PLAYLOOP` = bit 1. In loop mode the engine re-latches
  start/end from IoMem at every end-of-frame (`DmaSnd_EndOfFrameReached` →
  `DmaSnd_StartNewFrame`).
- **Mode write masking** — `DmaSnd_SoundModeCtrl_WriteByte` masks to `0x8f`
  and **writes the masked value back into IoMem**, so the IoMem byte at
  `$FF8921` always equals the authoritative `dma.soundMode`.

### 2.2 What a debugger `m` read actually returns (the load-bearing quirk)

Hatari's debugger memdump (`DebugCpu_MemDump`) reads through
`STMemory_ReadByte` → `STMemory_Read` (stMemory.c:660), which reads the
memory bank's `baseaddr` array **directly — it does NOT dispatch the IoMem
read handlers**. Consequences, per register:

| Register | Debugger `m` returns | Authority |
|---|---|---|
| `$FF8903/05/07`, `$FF890F/11/13` | last value the program wrote | **authoritative** (write handlers are trace-only; the engine latches from these same IoMem bytes) |
| `$FF8921` | `dma.soundMode` | **authoritative** (masked value written back on every write, §2.1) |
| `$FF8901` | last value the program **wrote** | **may be stale**: a one-shot frame that finished clears PLAY only in the internal `nDmaSoundControl` (`DmaSnd_EndOfFrameReached`), NOT in IoMem — a finished one-shot can still read play=1. `// verify live` |
| `$FF8909/0B/0D` | last value latched by the **program's own** bus reads (`DmaSnd_FrameCountHigh_ReadByte` refreshes IoMem only on CPU-dispatched reads) | **informational only** — report it, never branch on it |

The staleness is *acceptable for a ripper*: for looping music (the Uhane
case) play=1 is live truth; for a finished one-shot, stale play=1 at worst
rips the sample that *was* just playing — which is what a freezer-cartridge
user wants anyway. Documented in the output field docs and the ADR.

`info dmasnd` exists in 2.4.1 (registered in `debugInfo.c:663`, format
strings confirmed in the installed binary) but reads the **same raw IoMem**
via `IoMem_ReadByte` (the direct array accessor used *inside* handlers) —
zero accuracy advantage over `m`, and it would need a whole new parser.
Rejected (§3.2).

### 2.3 Reading the block is safe and side-effect-free

`ioMemTabSTE.c:143-167` maps the entire `$FF8900–$FF893F` range on
machine=ste with `IoMem_VoidRead` in the gaps — the table comments read "No
bus error here" throughout. Combined with §2.2 (no handler dispatch on
debugger reads), one `m $ff8900 34` block read is **safe** (no emulated bus
error) and **side-effect-free** (no handler runs, nothing is written).
`// verify live`: one `m $ff8900 34` against a running STE session must
return 48 dump bytes (three 16-byte lines; `debug::read_bytes` truncates
to 34) without any log warning.

On machine=st the range is a bus-error region on real hardware; debugger
reads still can't fault (no dispatch, §2.2) but return garbage — hence the
**machine gate** (§9.3), never a runtime probe.

### 2.4 Frame-address width

The register bytes give 24 bits; real STE DMA wires fewer address lines
(4 MB reach). We do NOT mask beyond `& ~1` on the low byte — the
`end ≤ ram_len` gate (§9.3) is the effective bound, and `ram_len` is ≤ 4 MB
(`HatariConfig::ram_len()`).

## 3. The design decisions (ADR, §13)

1. **Register-driven dump, not a RAM scan.** The DMA frame registers point
   at exactly the buffer being played — deterministic, zero false
   positives. A `RipKind::Sample` detector plugin (scan RAM for "things
   that look like PCM") is **deferred honestly**: headerless signed-8-bit
   PCM has no magic, no structure, and no length field; any heuristic
   (entropy/zero-crossing bands) is a false-positive machine that would
   pollute every `rip` sweep. If a future phase wants it, it is one file +
   one registry line by construction — nothing in P20 blocks it.
2. **One `m $ff8900 34` block read through the existing
   `debug::read_bytes`**, not `info dmasnd`: identical data (§2.2), zero
   new parse code (reuses `parse_memdump`), and one sentinel round-trip.
   The per-register authority/staleness table (§2.2) is the accepted cost
   and is documented on the wire fields.
3. **Momentary freeze, mirroring `machine_state` (ADR-20)** — deliberately
   deviating from `ym_state`'s ADR-33 no-freeze: this tool makes **two
   dependent round-trips** (register read, then a ranged `savebin` of up to
   `end-start` bytes), and a running player re-points `$FF8903/0F` from its
   end-of-frame interrupt (double-buffered digi players do this every
   frame). Freezing makes registers and buffer bytes come from one coherent
   instant. Paused sessions are read in place and stay paused.
4. **Output WAV is 16-bit signed integer PCM, `i16 = i8 × 256`** —
   NOT 8-bit WAV. WAV's 8-bit convention is *unsigned* (offset-128): a
   second sample convention to carry, and our own `wav::read_mono` (P11)
   accepts **PCM16 only**. Upscaling by 256 is lossless, deterministic, and
   makes the ripped file directly consumable by the existing
   `spectrogram(wav_path=…)` tool — the compose-with-P11 guarantee. Stereo
   writes L,R frames in STE interleave order (§2.1).
5. **Dedicated tool, not a `RipPlugin`.** `RipPlugin::scan(&MemImage)` is
   pure over a snapshot; this capability is live-register-driven (needs the
   session + debugger). `rip_sample` is choreography-not-capability in the
   `machine_state` sense: it composes `debug::read_bytes` +
   `analyze::dmasnd` (new, pure) + `session::memory::acquire_range` +
   `audio::wav` (extended) and adds no business logic of its own.
6. **Scope cuts:** Falcon/F030 (crossbar, 16-bit mode, record path) — the
   machine gate returns `"none"` for `falcon`; Microwire volume/tone
   (`$FF8922/24`) — not read, does not affect the sample bytes; `.avr`/raw
   export formats — `extract as=raw` already covers raw bytes generically.
7. **DMA-off / not-playing is a RESULT, not an error** (the `machine_state`
   `skip_reason` precedent): `status: "none"` with a `reason` string. A
   valid-but-stopped buffer reports `"stopped"` and rips only with
   `force=true` (the registers still delimit the last sample played).

## 7. `src/analyze/dmasnd.rs` — pure register decode (NO I/O, NO emulator)

Header: `//! Pure STE DMA-sound register decode (P20) — the $FF8900 block →
play/loop, frame [start,end), mono/stereo and sample rate. Semantics pinned
from hatari/src/dmaSnd.c + the hardware memory map (docs/plan/P20.md §2);
no I/O, no emulator access, the same purity contract as ym.rs.`

```rust
use crate::error::{Error, Result};

/// Base/length of the one debugger block read: $FF8900 ..= $FF8921
/// (34 bytes). The whole range is mapped without bus errors on the STE
/// (ioMemTabSTE.c) and debugger reads dispatch no handlers (§2.2/§2.3).
pub const DMASND_BLOCK_ADDR: u32 = 0x00FF_8900;
pub const DMASND_BLOCK_LEN: usize = 0x22;

/// $FF8921 bits 1-0 → replay rate (dmaSnd.c `DmaSndSampleRates`).
pub const DMA_RATES_HZ: [u32; 4] = [6258, 12517, 25033, 50066];

/// Decoded DMA-sound state. Addresses are 24-bit with the low bit forced
/// even, exactly like Hatari's own latch (§2.1). `frame_counter` is
/// informational only — a debugger read returns the last value the
/// *program* latched, not the live DMA position (§2.2).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct DmaSndState {
    pub control: u8,      // $FF8901 raw
    pub play: bool,       // control bit 0 (may be stale after a one-shot, §2.2)
    pub loop_on: bool,    // control bit 1
    pub frame_start: u32, // $FF8903/05/07, & !1
    pub frame_counter: u32,
    pub frame_end: u32,   // $FF890F/11/13, & !1 (exclusive)
    pub mode: u8,         // $FF8921 raw (Hatari masks writes to 0x8F)
    pub mono: bool,       // mode bit 7 set = mono, clear = stereo
    pub rate_hz: u32,     // DMA_RATES_HZ[mode & 3]
}

impl DmaSndState {
    /// 1 (mono) or 2 (stereo) — the WAV channel count.
    pub fn channels(&self) -> u16 { if self.mono { 1 } else { 2 } }
}

/// Why the `[frame_start, frame_end)` buffer can(not) be ripped.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum BufferCheck {
    Ok { len: usize },
    /// start == end: no buffer programmed (also the reset state, all-zero).
    Empty,
    /// end < start: registers mid-update or garbage.
    Inverted,
    /// end beyond ST RAM — unrippable via savebin.
    OutOfRam { end: u32, ram: usize },
}

/// Block index = bus address − $FF8900 (all data bytes are at odd offsets).
fn addr24(block: &[u8], hi: usize, mid: usize, lo: usize) -> u32 {
    (u32::from(block[hi]) << 16) | (u32::from(block[mid]) << 8) | u32::from(block[lo] & !1)
}

/// Decode the 34-byte $FF8900 block. Err(Parse{context:"dmasnd block"})
/// iff `block.len() < DMASND_BLOCK_LEN` (extra bytes are ignored —
/// read_bytes already truncates).
pub fn decode(block: &[u8]) -> Result<DmaSndState>

/// Pure gate for the extraction plan (§9.3). Order of checks: Empty
/// (start == end) → Inverted (end < start) → OutOfRam (end as usize >
/// ram_len) → Ok { len: (end - start) as usize }.
pub fn check_buffer(s: &DmaSndState, ram_len: usize) -> BufferCheck
```

`decode`, exactly: length gate first; then
`control = block[0x01]`, `play = control & 1 != 0`,
`loop_on = control & 2 != 0`,
`frame_start = addr24(block, 0x03, 0x05, 0x07)`,
`frame_counter = addr24(block, 0x09, 0x0B, 0x0D)`,
`frame_end = addr24(block, 0x0F, 0x11, 0x13)`,
`mode = block[0x21]`, `mono = mode & 0x80 != 0`,
`rate_hz = DMA_RATES_HZ[usize::from(mode & 3)]`.

## 8. `src/audio/wav.rs` — add the writer (MODIFIED)

Append (after `read_mono`'s helpers, before `#[cfg(test)]`):

```rust
/// Write signed 8-bit PCM as a 16-bit integer PCM WAV: each byte is
/// reinterpreted as i8 and upscaled losslessly (`i16::from(s as i8) * 256`)
/// so the file is readable back by `read_mono` (PCM16-only) and thus by the
/// spectrogram tool (P20 §3.4). `channels` must be 1 or 2; stereo input is
/// STE interleave (even byte = left, odd = right — memory_map.txt), written
/// as L,R frames. A trailing odd byte with channels == 2 is rejected (STE
/// frames are words; the hardware cannot produce one).
pub fn write_pcm8(path: &Path, pcm: &[u8], channels: u16, rate: u32) -> Result<()> {
    if !(channels == 1 || channels == 2) || rate == 0 {
        return Err(Error::Parse {
            context: "wav write format".to_string(),
            input: format!("channels {channels}, rate {rate}"),
        });
    }
    if channels == 2 && pcm.len() % 2 != 0 {
        return Err(Error::Parse {
            context: "wav write frames".to_string(),
            input: format!("{} bytes is odd for stereo", pcm.len()),
        });
    }
    let spec = hound::WavSpec {
        channels,
        sample_rate: rate,
        bits_per_sample: 16,
        sample_format: hound::SampleFormat::Int,
    };
    let mut w = hound::WavWriter::create(path, spec).map_err(wav_write_err)?;
    for &b in pcm {
        w.write_sample(i16::from(b as i8) * 256).map_err(wav_write_err)?;
    }
    w.finalize().map_err(wav_write_err)
}

fn wav_write_err(e: hound::Error) -> Error {
    Error::Parse { context: "wav write".to_string(), input: e.to_string() }
}
```

(`b as i8` is the whole signed-PCM reinterpretation — the ST bytes ARE i8
two's complement.) *Implementation note:* `wav.rs` is ~80 non-test lines
today; this adds ~35 — comfortably under 200. If a future rustfmt pass tips
it, split a `wav_write.rs` sibling; do not shrink `read_mono`.

### 9.3 Pure helpers (all unit-tested §11.4)

```rust
/// Machines with the STE DMA sound engine (Config_IsMachineSTE/TT in
/// Hatari terms). Falcon is excluded deliberately — crossbar/16-bit
/// differences, P20 §3.6.
pub(crate) fn has_dma_sound(machine: &str) -> bool {
    matches!(machine.to_ascii_lowercase().as_str(), "ste" | "megaste" | "tt")
}

/// The extraction decision. `extract` = (frame_start, len) iff bytes
/// should be acquired.
pub(crate) struct RipPlan {
    pub(crate) status: &'static str, // "playing" | "stopped" | "none"
    pub(crate) reason: Option<String>,
    pub(crate) extract: Option<(u32, usize)>,
}

/// Pure: machine gate → check_buffer → play/force. Exact mapping:
/// - !has_dma_sound          → none, "machine '<m>' has no STE DMA sound —
///                              start with machine=\"ste\"", no extract
/// - BufferCheck::Empty      → none, "frame start == frame end (<start>) —
///                              no sample buffer programmed", no extract
/// - BufferCheck::Inverted   → none, "frame end <end> is below frame start
///                              <start> — registers mid-update or garbage",
///                              no extract
/// - BufferCheck::OutOfRam   → none, "frame end <end> exceeds ST RAM
///                              (<ram> bytes)", no extract
/// - Ok{len}, play           → playing, None, Some((start, len))
/// - Ok{len}, !play, force   → stopped, None, Some((start, len))
/// - Ok{len}, !play, !force  → stopped, "DMA replay is off — the registers
///                              still delimit the last sample; pass
///                              force=true to rip it", no extract
/// (<start>/<end> rendered via Addr Display, "$030000" style.)
pub(crate) fn plan(machine: &str, s: &DmaSndState, ram_len: usize, force: bool) -> RipPlan

/// Pure assembly: state + plan + optional written-wav facts → output.
/// duration_s = (len / channels) as f64 / rate as f64 (0.0 when no len);
/// hex fields via Addr Display / format!("${:02X}").
pub(crate) struct WavFacts {
    pub(crate) path: String,
    pub(crate) peak: f32,
    pub(crate) silent: bool,
}
pub(crate) fn build_output(
    session: &str,
    momentary: bool,
    s: &DmaSndState,
    p: &RipPlan,
    wav: Option<WavFacts>,
) -> RipSampleOutput
```

`build_output` sets `len_bytes`/`duration_s` from `p.extract` **only when a
WAV was actually written** (`wav.is_some()`); a `stopped`-without-force
result reports the registers (`frame_start`/`frame_end` etc.) but
`len_bytes: 0`, `duration_s: 0.0` — the numbers describe the artifact, the
hex strings describe the hardware. Split into ≤30-line helpers as needed.

## 10. `src/tools/rip_sample.rs` — the tool

Header: `//! P20 rip_sample tool: momentary-freeze read of the STE DMA
sound registers ($FF8900 block) + ranged savebin of [frame_start,
frame_end) + signed-8→PCM16 WAV (audio::wav). Choreography-not-capability
(the machine_state pattern, ADR-20); the wire layer is rip_sample_wire.rs.`

### 10.1 Gather (while frozen/paused)

```rust
use crate::analyze::dmasnd::{self, DMASND_BLOCK_ADDR, DMASND_BLOCK_LEN, DmaSndState};

/// Everything read under the freeze. `pcm` is Some iff plan.extract fired.
pub(crate) struct RawRip {
    pub(crate) state: DmaSndState,
    pub(crate) plan: rip_sample_wire::RipPlan,
    pub(crate) pcm: Option<MemImage>,
}

/// Testability seam (machine_state::read_video precedent): one `m $ff8900
/// 34` through the sentinel-synced channel, decoded pure.
async fn read_dma_block(chan: &mut impl DebugChannel) -> crate::error::Result<DmaSndState> {
    let block = debug::read_bytes(chan, Addr::new(DMASND_BLOCK_ADDR), DMASND_BLOCK_LEN).await?;
    dmasnd::decode(&block)
}

async fn gather(proc: &mut HatariProcess, force: bool) -> crate::error::Result<RawRip> {
    let state = read_dma_block(proc).await?;
    let plan = rip_sample_wire::plan(
        &proc.config().machine, &state, proc.config().ram_len(), force,
    );
    let pcm = match plan.extract {
        Some((start, len)) => {
            Some(memory::acquire_range(proc, Addr::new(start), len).await?)
        }
        None => None,
    };
    Ok(RawRip { state, plan, pcm })
}
```

### 10.2 Freeze choreography — copy `machine_state.rs` mechanically

Duplicate `freeze_gather_thaw` and `take_snapshot` from
`tools/machine_state.rs` with `gather(_, force)` substituted (rename to
`take_rip`, returning `(PathBuf /*work_dir*/, &'static str /*session*/,
bool /*momentary*/, Result<RawRip, McpError>)`). Byte-for-byte the same
state machine: Stopped → `wrong_state(name, "running or paused")`; Paused →
gather in place, stays paused; Running → pause → gather → resume, gather
error wins over resume error (ADR-20), resume failure leaves
`AnySession::Paused` honestly. *Implementation note:* this is deliberate
duplication (third occurrence would justify extraction — flag to
rust-architect if a P21+ tool needs it too; do NOT extract now).

### 10.3 The tool fn

```rust
// `vis = "pub(crate)"`: see lifecycle.rs for the rationale (rmcp-2.2 gotcha).
#[tool_router(router = rip_sample_router, vis = "pub(crate)")]
impl HatariServer {
    #[tool(
        name = "rip_sample",
        description = "Rip the 8-bit PCM sample the STE DMA sound engine is \
playing: reads the $FF8900 frame registers (which point directly at the \
buffer in RAM), dumps [frame_start, frame_end), and writes it as a 16-bit \
WAV — returns the path plus rate (6258/12517/25033/50066 Hz), mono/stereo, \
length and a peak/silent verdict, never audio bytes. A running session is \
momentarily frozen so registers and buffer come from one instant; paused \
sessions are read in place. If DMA sound is off or the machine is not an \
STE, returns status \"none\"/\"stopped\" with a reason (not an error); \
force=true rips a valid-but-stopped buffer. Covers what identify_music/\
ym_state cannot: DMA digi-music is not the YM chip. Compose with \
spectrogram(wav_path=…) to see the sample."
    )]
    pub async fn rip_sample(
        &self,
        Parameters(a): Parameters<RipSampleArgs>,
    ) -> Result<Json<RipSampleOutput>, McpError> {
        let force = a.force.unwrap_or(false);
        let (work_dir, session, momentary, raw) = self.take_rip(force).await?;
        let raw = raw?;
        let wav = match &raw.pcm {
            Some(img) => Some(
                self.write_sample(img.bytes(), &raw.state, a.out_path.as_deref(), &work_dir)
                    .await?,
            ),
            None => None,
        };
        Ok(Json(rip_sample_wire::build_output(
            session, momentary, &raw.state, &raw.plan, wav,
        )))
    }
}
```

### 10.4 Artifact write (after the lock is released)

```rust
impl HatariServer {
    /// Resolve the out path (validate_wav_out, or work_dir/sample-NNNN.wav
    /// from audio_seq), write via audio::wav::write_pcm8, read the facts
    /// back with wav::read_mono (record_audio precedent — the read-back IS
    /// the write verification). Sync hound I/O on a ≤4 MB buffer is
    /// milliseconds (the Capstone/read_mono precedent); the session lock is
    /// already released.
    async fn write_sample(
        &self,
        pcm: &[u8],
        state: &DmaSndState,
        out_path: Option<&str>,
        work_dir: &Path,
    ) -> Result<rip_sample_wire::WavFacts, McpError> {
        let path = match out_path {
            Some(p) => audio_wire::validate_wav_out(p)
                .map_err(|m| McpError::invalid_params(m, None))?,
            None => {
                let n = self.audio_seq.fetch_add(1, Ordering::Relaxed) + 1;
                work_dir.join(format!("sample-{n:04}.wav"))
            }
        };
        crate::audio::wav::write_pcm8(&path, pcm, state.channels(), state.rate_hz)
            .map_err(to_mcp)?;
        let (_, info) = crate::audio::wav::read_mono(&path).map_err(to_mcp)?;
        Ok(rip_sample_wire::WavFacts {
            path: path.display().to_string(),
            peak: info.peak,
            silent: info.peak < audio_wire::SILENT_PEAK,
        })
    }
}
```

For a user-supplied `out_path`, verify the parent directory exists before
writing (`tokio::fs::metadata(parent)`; missing ⇒ invalid_params `"parent
directory does not exist: …"`) — the P11 §10.1 rule, same reason.

*Implementation note:* if `rip_sample.rs` tips 200 non-test lines, move
`write_sample` into a `rip_sample_out.rs` sibling (the `cheat_out.rs`
precedent), not into the wire file (it does I/O; the wire stays pure).

### 10.5 Token-efficiency invariants (ADR-5 — checked in review)

- Sample bytes NEVER appear in any block — the WAV is a path handle.
- One call = one compact JSON. No inline image/audio blocks.
- The rip is resumable state on disk: `spectrogram(wav_path=…)`,
  `record_audio` A/B, or external tools consume the same file without
  touching the emulator again.

**Number:** use the NEXT FREE ADR number in `decisions.md` at

Fill `<n>`, the tool count, and the live-verified facts (§12.1/§11.6)
before committing. Template:

```markdown
## 2026-07-XX — ADR-<n>: rip_sample — STE DMA-PCM ripping is register-driven, momentary-freeze, WAV-out

**Status:** accepted
**Context:** DHS "Uhane"-class demos play digi-music through the STE DMA
sound engine ($FFFF8900+, signed 8-bit PCM streamed from RAM) — invisible
to identify_music (YM replay anchors) and ym_state (PSG registers). The
frame start/end registers point directly at the playing buffer, so
extraction can be deterministic.
**Decision:** A dedicated `rip_sample` tool: one `m $ff8900 34` block read
(debug::read_bytes — debugger reads bypass the IoMem handlers, so the read
is side-effect-free raw-IoMem; start/end and $FF8921 are authoritative
there, $FF8901's play bit can read stale-1 after a finished one-shot, the
frame counter is informational only — pinned from hatari dmaSnd.c/
stMemory.c/ioMemTabSTE.c and verified live), decoded pure in
analyze::dmasnd, then a ranged savebin of [frame_start, frame_end) —
both under a momentary freeze (ADR-20 pattern; deliberately NOT ADR-33's
no-freeze, because this is two dependent round-trips and loop-mode players
re-point the frame registers every end-of-frame interrupt). Output is a
16-bit signed WAV (i16 = i8 × 256, stereo = STE even-left interleave)
written by audio::wav::write_pcm8 so wav::read_mono/spectrogram consume it
directly; the tool returns a path handle + rate/length/stereo/peak facts,
never bytes (ADR-5). DMA-off/no-buffer/wrong-machine are results
(status "none"/"stopped" + reason), never errors; force=true rips a
valid-but-stopped buffer.
**Alternatives considered:** (a) `info dmasnd` — exists in 2.4.1 but reads
the same raw IoMem and needs a new parser: rejected; (b) a RipKind::Sample
RAM-scan plugin — headerless PCM has no signature, a false-positive
machine: deferred honestly, and rip_sample is not a RipPlugin at all
(the plugin contract is pure over MemImage; this needs live registers);
(c) 8-bit WAV output — WAV's 8-bit is unsigned, a second convention and
unreadable by our own PCM16-only reader: rejected; (d) no freeze (ADR-33
style) — wrong, multi-round-trip coherence is the point here.
**Consequences:** the last DHS-"Uhane" gap closes: DMA digi-music is
rippable in one call and composes with spectrogram/record_audio.
analyze gains its second audio-domain decoder (dmasnd); audio::wav gains
its first writer. The freeze choreography is duplicated from machine_state
a second time — a third consumer should extract it. Falcon crossbar
(16-bit, record path) is out of scope; frame-counter readback is
best-effort by emulator design. Live facts: <fill from §11.6: Uhane's
observed rate/mono/frame window>. Tool count: <N> → <N+1>.
```
