## 1. Deliverable in one sentence

One new boot detector `bootsector` (`RipKind::Boot`) that analyzes a 512-byte
sector — computes the big-endian `$1234` executability checksum, decodes the
little-endian DOS BPB, and runs disassembly-based virus-tell heuristics
(vector *writes* to `$426`/`$42a`/`$472…$47e`, self-copy loops, BIOS/XBIOS
disk traps) via P2's `disasm` — classifying the sector as **plain-data /
loader / suspicious** and reporting *tells with a confidence < 1.0, never a
"this IS a virus" verdict*; sourced either from a validated raw `.ST` file
(sector 0) or from the TOS disk buffer (`_dskbufp` at `$4C6`) in a whole-RAM
snapshot; registered with one line in `default_registry()`, surfaced by a
façade tool `bootsector(source: ram|disk, path?)`, and materializable through
the existing `extract` (raw 512 bytes or runnable PRG).

### 4.1 The 512-byte boot sector

`SECTOR_LEN = 512`. All analysis operates on exactly 512 bytes. Layout
(offsets are into the sector):

| Offset | Size | Field | Notes |
|--------|------|-------|-------|
| `$000` | 2 | branch to boot code (`$60xx` bra.s / `$6000` bra.w) | present on bootable sectors |
| `$002` | 6 | OEM / loader string | ASCII |
| `$008` | 3 | disk serial | |
| `$00B` | — | **BPB begins** (little-endian, §4.3) | |
| `$01E` | var | boot loader / virus code (68k) | runs iff checksum == `$1234` |
| `$1FE` | 2 | checksum adjustment word (big-endian) | tunes the total to `$1234` |

### 4.2 The `$1234` executability checksum (big-endian word sum)

```rust
/// Sum of all 256 big-endian 16-bit words, mod 65536. Executable iff == 0x1234.
pub const BOOT_MAGIC_SUM: u16 = 0x1234;

pub fn checksum(sector: &[u8]) -> u16 {
    (0..256).fold(0u16, |sum, i| {
        sum.wrapping_add(u16::from_be_bytes([sector[2 * i], sector[2 * i + 1]]))
    })
}
// executable = checksum(sector) == BOOT_MAGIC_SUM
```

`checksum` requires `sector.len() >= 512`; callers guarantee it (the plugin
only ever calls it on a 512-slice). No panic path is reachable in normal use;
if a future caller passes < 512, that is a bug, not a runtime branch — do NOT
add defensive padding.

### 4.3 The DOS BPB (⚠️ little-endian / Intel order)

Read every multi-byte field with `u16::from_le_bytes` (bytes are stored
low-then-high). Offsets and sizes are **pinned**:

| Offset | Rust read | Field | Struct member |
|--------|-----------|-------|---------------|
| `$00B` | le16 | bytes per sector | `bps: u16` |
| `$00D` | u8 | sectors per cluster | `spc: u8` |
| `$00E` | le16 | reserved sectors | `res: u16` |
| `$010` | u8 | number of FATs | `nfats: u8` |
| `$011` | le16 | root dir entries | `ndirs: u16` |
| `$013` | le16 | total sectors | `nsects: u16` |
| `$015` | u8 | media descriptor | `media: u8` |
| `$016` | le16 | sectors per FAT | `spf: u16` |
| `$018` | le16 | sectors per track | `spt: u16` |
| `$01A` | le16 | sides/heads | `nsides: u16` |
| `$01C` | le16 | hidden sectors | `nhid: u16` |

`$011` and `$013` sit at odd byte offsets — that is correct for the DOS BPB;
read the two bytes directly, do not "fix up" alignment.

**BPB plausibility gate** (`fn bpb_plausible(b: &Bpb) -> bool`, pinned
predicate — this is what keeps a zeroed RAM buffer from being reported):

```
bps in {128,256,512,1024,2048,4096,8192}   // power-of-two sector size
&& spc >= 1 && spc <= 64
&& nfats >= 1 && nfats <= 2
&& nsects >= 1
&& spf >= 1
&& (media == 0 || (0xF0..=0xFF).contains(&media))
```

### 4.4 Classification (three classes, pinned rules)

```rust
pub enum BootClass { PlainData, Loader, Suspicious }
```

Given `executable = checksum == 0x1234` and the tells from §5:

| condition | class |
|---|---|
| `!executable` | `PlainData` (TOS will not run it — a blank/FAT sector) |
| `executable` AND any **strong** tell (vector-write or self-copy) | `Suspicious` |
| `executable` AND no strong tell (loader traps alone are fine) | `Loader` |

A "strong tell" = any `VectorWrite` tell OR the `SelfCopy` tell (§5). A
`DiskTrap` tell alone (BIOS/XBIOS `trap`) does NOT force `Suspicious` — legit
loaders read/write disk too; it is reported as evidence and it raises
`confidence`, but classification stays `Loader` unless a strong tell is
present. This is the deliberate no-false-verdict rule (ADR-17).

## 5. Virus-tell heuristics (disassembly-based, pinned — honest, degrade gracefully)

**Contract, load-bearing:** these are heuristics. The output NEVER asserts
"this is a virus". It reports (a) a `BootClass`, (b) a list of `Tell`s (each an
annotated instruction), and (c) a `confidence: f32` in `[0.0, 0.9]` — capped
below 1.0 on purpose. Any decode failure (odd address, capstone error,
truncated code) yields **zero tells and confidence 0.0**, never an error,
never a panic. Mark the module `// verify live` (real virus corpus not run
here).

### 5.1 Where the boot code starts

TOS runs from `$000`; a `bra` there skips the BPB to the real code. Pin
`fn boot_code_start(sector: &[u8]) -> usize`:

```
w = be16(sector, 0)
if w == 0x6000:              target = 2 + (be16(sector,2) as i16 as isize)   // bra.w
elif w >> 8 == 0x60 and (w & 0xFF) not in {0x00, 0xFF}:
                            target = 2 + ((w & 0xFF) as u8 as i8 as isize)   // bra.s
else:                       target = 0x1E                                    // no branch → code region
if target < 0x1E or target >= 512 or target is odd:  target = 0x1E          // clamp/fallback
return target as usize
```

### 5.2 The tell scan

```rust
pub enum TellKind { VectorWrite, SelfCopy, DiskTrap }

pub struct Tell {
    pub kind: TellKind,
    pub addr: Addr,        // where in the sector the flagged instruction sits
    pub insn: String,      // decoded "mnemonic ops" text (the annotated evidence)
    pub note: &'static str,// human why, e.g. "writes hdv_bpb ($472)"
}

/// Disassemble the boot code and collect tells + confidence. Never errors.
pub fn analyze_code(mem: &MemImage, code_start: usize) -> (Vec<Tell>, f32)
```

`BOOT_INSN_MAX = 256` (512 bytes / 2-byte minimum instruction). Implementation:

1. `let at = Addr::new(mem.base().raw() + code_start as u32);`
2. `let insns = disasm(mem, at, BOOT_INSN_MAX).unwrap_or_default();` — decode
   failure ⇒ empty ⇒ no tells (graceful).
3. Fold the stream into `Vec<Tell>` via the three detectors below.
4. `confidence = (0.25 * strong_tells + 0.10 * disk_traps).min(0.9)` where
   `strong_tells` = count of `VectorWrite` + (`1` if any `SelfCopy` else `0`),
   `disk_traps` = count of `DiskTrap`. `f32`, clamped to `0.9`. Zero tells ⇒
   `0.0`.

### 5.3 `VectorWrite` — the primary tell (writes, not reads)

Watched low-memory vectors (a hooked one is how a boot virus persists /
spreads; authority: `ZR_BLK.S` reads these to *detect* exactly this):

```rust
const WATCHED: &[(u32, &str)] = &[
    (0x426, "resvalid ($426)"), (0x42A, "resvector ($42A)"),
    (0x472, "hdv_bpb ($472)"),  (0x476, "hdv_rw ($476)"),
    (0x47A, "hdv_boot ($47A)"), (0x47E, "hdv_mediach ($47E)"),
    (0x4CE, "vbl_list ($4CE)"),
];
```

An instruction is a `VectorWrite` tell iff **all** of:

- mnemonic starts with `"move"` (covers `move.l/.w`, `movea`), AND
- the **destination** operand (the token after the last `", "`) resolves to a
  watched address. Destination = written-to; a *source* watched-address (as in
  the antivirus `move.l $426.w,d0`) is a **read** and is NOT flagged.

Destination resolution (private helper `dest_addr(ops: &str) -> Option<u32>`,
boot_heur cannot import the tool layer, so implement a tiny local resolver):

```
dst = ops.rsplit_once(", ").map(|(_, d)| d).unwrap_or(ops).trim()
// parse a leading "$hex" (up to 8 hex digits); if it is ".w"-suffixed and
// bit 15 is set, sign-extend to 0xFFFF_0000 before masking; mask to 24 bits.
// e.g. "$42a.w" -> 0x42A ; "$ffff8800.l" -> 0xFF8800 ; "d0" / "(a1)" -> None
return Some(addr & 0x00FF_FFFF)   // else None
```

`note` = the matched WATCHED label. (`$42a` and the hdv vectors are 24-bit ST
bus addresses; the `.w` short form is what real code uses — hence the
sign-extend. This mirrors `analyze_wire::resolve_token_addr`, re-implemented
locally to respect the layering — `ripper` must not depend on `tools`.)

### 5.4 `SelfCopy` — the sector relocates/replicates itself

A block-move loop is the classic "copy myself into resident memory / onto the
next disk" body. Pinned detection over the decoded stream:

- there exists at least one `move.*` instruction whose **source or
  destination** operand text contains a post-increment `)+` (i.e. `(aN)+`),
  **AND**
- there exists at least one `db*` instruction (mnemonic starts with `"db"` —
  `dbra`/`dbf`/`dbcc`) anywhere in the stream.

Emit **one** `SelfCopy` tell, anchored at the first post-increment `move`'s
address, `note = "block-copy loop (self-relocation)"`. (One tell, not one per
instruction — this is a single behavioural signal.)

### 5.5 `DiskTrap` — BIOS/XBIOS entry (weak evidence)

A `trap` instruction to the BIOS (`#13`) or XBIOS (`#14`) vector — the family
that includes `Rwabs`/`Flopwr` (raw disk writes) and `Setexc` (vector
install). Pinned: mnemonic == `"trap"` and `ops` is one of `"#$d"`, `"#13"`,
`"#$e"`, `"#14"` (accept both Capstone hex and decimal spellings; the §9.3
unit test pins whichever the shipped capstone emits — start with the hex forms
and add the decimal forms if a test shows them). One `DiskTrap` tell per such
`trap`, `note = "BIOS/XBIOS trap (possible disk write / vector install)"`.
Weak on its own (§4.4): raises confidence, does not force `Suspicious`.

### 6.1 `src/ripper/plugins/bootsector.rs`

Module doc: "Boot-sector detector (§4, ADR-17): the `$1234` big-endian
executability checksum, the little-endian DOS BPB, and a plain/loader/
suspicious classification. Virus tells live in `boot_heur` (disasm-based; line
budget). Pure over a `MemImage`; works on a 512-byte disk sector (offset 0) or
on the TOS disk buffer inside a whole-RAM snapshot (`_dskbufp` at `$4C6`)."

Public API:

```rust
pub const SECTOR_LEN: usize = 512;
pub const BOOT_MAGIC_SUM: u16 = 0x1234;
/// _dskbufp: big-endian long at $4C6 → bus address of the TOS 1024-byte disk
/// buffer, where the loaded boot sector persists. // verify live.
pub const DSKBUFP: usize = 0x4C6;

pub struct Bpb { /* 11 fields, §4.3 */ }
pub enum BootClass { PlainData, Loader, Suspicious }

/// The full analysis of one 512-byte sector. Recomputed by the tool layer
/// from finding bytes (§8) — the source of structured truth, not the label.
pub struct BootReport {
    pub checksum: u16,
    pub executable: bool,
    pub bpb: Bpb,
    pub bpb_plausible: bool,
    pub class: BootClass,
    pub tells: Vec<crate::ripper::plugins::boot_heur::Tell>,
    pub confidence: f32,
}

/// Analyze a 512-byte sector at offset `off` inside `mem` (mem[off..off+512]
/// must exist). Never errors: a garbage sector yields checksum + implausible
/// BPB + PlainData + no tells.
pub fn analyze_sector(mem: &MemImage, off: usize) -> BootReport;

pub struct BootSector;
impl RipPlugin for BootSector { /* below */ }
```

`checksum`, `decode_bpb`, `bpb_plausible` are pinned in §4.2/§4.3. `class` is
`classify(&report)` per §4.4. Helpers `be16`/`le16` as in `neochrome.rs`/
`sndh_header.rs`.

`analyze_sector` body (≤ 20 lines):

```rust
let s = &mem.bytes()[off..off + SECTOR_LEN];
let checksum = checksum(s);
let executable = checksum == BOOT_MAGIC_SUM;
let bpb = decode_bpb(s);
let bpb_plausible = bpb_plausible(&bpb);
let (tells, confidence) = boot_heur::analyze_code(mem, off + boot_heur::boot_code_start(s));
let class = classify(executable, &tells);
BootReport { checksum, executable, bpb, bpb_plausible, class, tells, confidence }
```

Note: `analyze_code` is handed `mem` and an **absolute** offset (`off +
code_start`) so its `disasm` call addresses the right bytes whether the sector
is at offset 0 (disk) or deep in RAM (the `_dskbufp` window).

`RipPlugin` impl:

```rust
impl RipPlugin for BootSector {
    fn id(&self) -> PluginId { PluginId::new("bootsector") }
    fn kind(&self) -> RipKind { RipKind::Boot }
    fn describe(&self) -> &'static str {
        "Atari ST boot sectors ($1234 checksum + DOS BPB + loader/virus heuristics)"
    }
    fn scan(&self, mem: &MemImage) -> Vec<Finding> {
        candidate_offset(mem)
            .into_iter()
            .filter(|&(off, always)| always || worth_reporting(mem, off))
            .map(|(off, _)| {
                let r = analyze_sector(mem, off);
                Finding::new(self.id(), RipKind::Boot, Offset::new(off), SECTOR_LEN, label(&r))
            })
            .collect()
    }
    // no render_png (boot sectors are not pictures).
}
```

Candidate selection (`fn candidate_offset(mem: &MemImage) -> Option<(usize, bool)>`,
the bool = "report unconditionally"):

- **disk-sector mode** — `mem.len() == SECTOR_LEN`: `Some((0, true))`. The user
  handed us exactly a sector; always analyze and report, even plain data.
- **whole-RAM mode** — `mem.base() == Addr::new(0)` and `mem.len() >= 0x4CA`:
  read `be32(mem.bytes(), DSKBUFP)` → `addr`; `off = addr as usize` (base 0 ⇒
  bus addr == offset); if `off + SECTOR_LEN <= mem.len()` and `off >= 0x800`
  (below `$800` is the TOS vector/variable area, never a real disk buffer) →
  `Some((off, false))`, else `None`. `// verify live: _dskbufp persistence of
  the boot sector post-boot is unverified; None ⇒ clean not-found.`
- otherwise `None`.

`fn worth_reporting(mem, off) -> bool` = `let r = analyze_sector(mem, off); r.executable || r.bpb_plausible` — suppresses zeroed / junk `_dskbufp` windows so a normal `rip` over RAM does not emit boot noise.

`fn label(r: &BootReport) -> String` (human, structured facts recomputed by
the tool — do NOT parse this string):

```
format!("Boot sector: {} (checksum=${:04X}, {}; {} tells)",
        class_str(r.class),           // "plain-data" | "loader" | "suspicious"
        r.checksum,
        if r.executable { "executable" } else { "not executable" },
        r.tells.len())
```

## 7. Disk source — `src/ripper/disk.rs`

Module doc: "Raw `.ST` disk-image source (PLAN §P7): logical sector 0 (first
512 bytes) of a plain sector dump. `.MSA`/`.DIM`/`.STX` are compressed/
containered and OUT OF SCOPE — rejected with a clear error, not misread
(future work). Path is validated against traversal per the security rules."

```rust
use std::path::Path;
use crate::error::{Error, Result};
use crate::ripper::plugins::bootsector::SECTOR_LEN;

/// Read logical sector 0 of a raw `.ST` image. Validates the path first
/// (§7 rules); returns exactly 512 bytes.
pub fn read_boot_sector(path: &Path) -> Result<Vec<u8>>;
```

Pinned validation + read (`// SECURITY: path traversal / unexpected-file
guard`):

1. `let canon = path.canonicalize().map_err(|e| Error::Io(e))?;` — resolves
   `..`/symlinks; a non-existent path errors here.
2. `let meta = std::fs::symlink_metadata(&canon)...;` — must be a **regular
   file** (`meta.is_file()`), else `Error::Parse { context: "disk image",
   input: "<path> is not a regular file" }`. (There is no configured images
   root to escape in P7; validation = canonicalize + regular-file + extension +
   size. **If a base-dir allowlist is ever introduced, enforce
   `canon.is_relative_to(base)` here** — noted for the future reader.)
3. Extension gate (case-insensitive): accept `st` or no extension. Reject
   `msa`/`dim`/`stx`/`zip` with `Error::Parse { context: "disk image", input:
   "compressed/containered image not supported (P7: raw .ST only)" }`. Any
   other extension → same "raw .ST only" error (fail loud, never guess).
4. `let bytes = std::fs::read(&canon)?;` — read whole file.
5. `bytes.len() >= SECTOR_LEN` else `Error::Parse { context: "boot sector",
   input: "file shorter than 512 bytes" }`.
6. `Ok(bytes[..SECTOR_LEN].to_vec())`.

## 8. Tool layer — `bootsector`

### 8.1 `src/tools/bootsector.rs` — tool + summary glue

Module doc: "`bootsector` — analyze a boot sector from a live RAM snapshot
(`source=ram`, via rip(kind=boot) → the TOS `_dskbufp` buffer) or a raw `.ST`
file (`source=disk`, sector 0). A façade like `identify_music` (P6): findings
stay in the last-scan store so `extract(finding_id, as=\"raw\"|\"prg\")` works
immediately after. Structured facts (checksum/BPB/tells) are recomputed from
finding bytes via `bootsector::analyze_sector` — never scraped from the label."

```rust

impl HatariServer {

    pub async fn bootsector(
        &self,
        Parameters(a): Parameters<BootsectorArgs>,
    ) -> Result<Json<BootsectorOutput>, McpError> {
        match validate_source(&a)? {                       // §8.3
            Source::Ram => self.bootsector_ram(a.depth).await,
            Source::Disk(path) => self.bootsector_disk(path).await,
        }
    }
}
```

Tool description (pinned intent, wrap as the other tools do): "Analyze an
Atari ST floppy boot sector: the $1234 executability checksum, the DOS BPB
geometry, and loader-vs-virus heuristics (vector hooks, self-copy loops, disk
traps). source=\"ram\" reads the TOS disk buffer from a running/paused session;
source=\"disk\" reads sector 0 of a raw .ST image at `path`. Heuristic —
reports tells with a confidence, never a certain virus verdict. Pass the
returned finding_id to extract (as=\"raw\" for the 512 bytes, \"prg\" for a
runnable wrap)."

`bootsector_ram` = the identify_music pattern exactly: `self.rip(Parameters(
RipArgs { kind: Some("boot".into()), plugin: None, depth: a.depth, limit:
Some(RIP_MAX_LIMIT), offset: Some(0), scan_id: None }))` → lock `last_scan` →
`boot_summary(&guard, page.scan_id)` → `Json` / `internal_error`. Requires a
running/paused session (the inner `rip` already rejects with the standard
`wrong_state` `invalid_request` — propagate untouched). No boot finding ⇒
`found=false` output (§8.3), NOT an error.

`bootsector_disk(path: PathBuf)` — session-independent (analyzing a file needs
no emulator):

1. `let sector = tokio::task::spawn_blocking(move || crate::ripper::disk::read_boot_sector(&path)).await.map_err(internal)?.map_err(to_mcp)?;`
2. `let mem = MemImage::new(sector, Addr::new(0));`
3. scan via the registry (Boot only, depth 0) in `spawn_blocking`:
   `reg.scan(Arc::new(mem), Some(RipKind::Boot), 0)` — reuse `Arc::clone(&self.registry)`.
4. `let scan_id = self.scan_seq.fetch_add(1, Ordering::Relaxed) + 1;`
5. `let out_dir = std::env::temp_dir().join("shirazmcp-bootsector");` —
   disk-source extracts land here (no session ⇒ no work_dir; deterministic,
   documented). Store: `self.store_scan(scan_id, findings, out_dir)` — reuse
   rip.rs's private `store_scan` (make it `pub(crate)` on `HatariServer` in
   rip.rs if not already; it is currently private — **the only allowed edit to
   rip.rs**: change `fn store_scan` to `pub(crate) fn store_scan`. If you'd
   rather not touch rip.rs, duplicate the 6-line body locally — either is
   acceptable; prefer the visibility bump, note it).
6. lock `last_scan`, `boot_summary(&guard, scan_id)` → `Json`.

Because disk mode is `mem.len() == SECTOR_LEN`, `candidate_offset` returns
`Some((0, true))` → there is **always** exactly one boot finding for a disk
source (even plain data), so `found` is always `true` there.

### 10.1 Builders (top of file, plain `fn`s)

```rust
use shiraz_mcp::ripper::plugins::bootsector::{self, SECTOR_LEN, BOOT_MAGIC_SUM};
// (adjust crate name to the real one in Cargo.toml — check `[package] name`.)

/// Write bytes at `off` into a 512-byte sector.
fn put(s: &mut [u8], off: usize, bytes: &[u8]) { s[off..off + bytes.len()].copy_from_slice(bytes); }

/// Tune word $1FE so the big-endian word-sum becomes exactly $1234.
fn set_checksum(s: &mut [u8]) {
    // sum words 0..=254 (all but $1FE), then adjust = 0x1234 - sum.
    let mut sum = 0u16;
    for i in 0..255 { sum = sum.wrapping_add(u16::from_be_bytes([s[2*i], s[2*i+1]])); }
    let adj = BOOT_MAGIC_SUM.wrapping_sub(sum);
    put(s, 0x1FE, &adj.to_be_bytes());
    assert_eq!(bootsector_checksum(s), BOOT_MAGIC_SUM); // self-check
}

/// A standard-geometry DOS BPB (little-endian), no boot code, NOT executable.
fn plain_fat_sector() -> Vec<u8> {
    let mut s = vec![0u8; SECTOR_LEN];
    put(&mut s, 0x00B, &512u16.to_le_bytes());  s[0x00D] = 2;
    put(&mut s, 0x00E, &1u16.to_le_bytes());    s[0x010] = 2;
    put(&mut s, 0x011, &112u16.to_le_bytes());
    put(&mut s, 0x013, &720u16.to_le_bytes());  s[0x015] = 0xF9;
    put(&mut s, 0x016, &5u16.to_le_bytes());
    put(&mut s, 0x018, &9u16.to_le_bytes());
    put(&mut s, 0x01A, &2u16.to_le_bytes());
    put(&mut s, 0x01C, &0u16.to_le_bytes());
    s  // checksum left un-tuned → not executable (assert this in a test)
}

/// Executable loader: bra.s to $1E, benign code (trap #1 print, rts), checksum tuned.
fn bootable_loader_sector() -> Vec<u8> {
    let mut s = plain_fat_sector();
    put(&mut s, 0x000, &[0x60, 0x1C]);                  // bra.s $1E
    put(&mut s, 0x01E, &[0x4E, 0x71]);                  // nop (stand-in for loader body)
    put(&mut s, 0x020, &[0x4E, 0x75]);                  // rts
    set_checksum(&mut s);
    s
}

/// Executable + writes hdv_bpb ($472) and resvector ($42A) + a self-copy loop.
/// Hand-assembled 68k (verify byte encodings with the §9.2 tests):
///   $1E move.l a0,$472.w        21 C8 04 72
///   $22 move.l a1,$42A.w        23 C9 04 2A
///   $26 move.l (a0)+,(a1)+      22 D8
///   $28 dbra   d0,$26           51 C8 FF FC
///   $2C rts                     4E 75
fn virus_like_sector() -> Vec<u8> {
    let mut s = plain_fat_sector();
    put(&mut s, 0x000, &[0x60, 0x1C]);                  // bra.s $1E
    put(&mut s, 0x01E, &[0x21, 0xC8, 0x04, 0x72]);
    put(&mut s, 0x022, &[0x23, 0xC9, 0x04, 0x2A]);
    put(&mut s, 0x026, &[0x22, 0xD8]);
    put(&mut s, 0x028, &[0x51, 0xC8, 0xFF, 0xFC]);
    put(&mut s, 0x02C, &[0x4E, 0x75]);
    set_checksum(&mut s);
    s
}
```

## 14. ADR-17 — append to `decisions.md` (verbatim; fill only the date)

```markdown
## 2026-07-XX — ADR-17: Boot-sector analysis — $1234 checksum, LE BPB, disasm-based virus tells (heuristics, never a verdict)

**Status:** accepted
**Context:** P7 (final phase) must extract and analyze Atari ST floppy boot
sectors — the historic virus vector. A sector is executable iff its 256
big-endian 16-bit words sum to $1234; it carries a little-endian DOS BPB; and
its 68k boot code is either a benign loader or a self-installing virus. The
same engine must serve two sources (a raw .ST file and a live RAM snapshot)
and must classify safely — a false "this IS a virus" is worse than a hedged
"suspicious, here are the tells".
**Decision:** (1) One `bootsector` detector (RipKind::Boot) over a 512-byte
sector: big-endian word-sum checksum vs $1234 (executability); little-endian
BPB decode with a power-of-two plausibility gate; classification into
plain-data / loader / suspicious. (2) Virus tells come from P2's embedded
disassembler (the pinned-legal ripper→analyze dependency, ADR-16): the primary
tell is a *write* to a watched low-memory vector ($426/$42A resvalid/resvector,
$472..$47E hdv_*, $4CE vbl_list) — distinguished from a *read* (antivirus
behaviour, e.g. ZR_BLK.S), so a defender bootblock classifies as loader, not
suspicious; secondary tells are a self-copy loop (post-increment move + dbra)
and BIOS/XBIOS disk traps (weak — do not force suspicious). Every result
carries tells + a confidence capped at 0.9; any decode failure degrades to no
tells / 0.0 — never an error, never a certain verdict. (3) Two sources feed the
one detector: disk mode is a 512-byte MemImage (always reported); RAM mode
dereferences _dskbufp ($4C6) in a whole-RAM snapshot and reports only a
plausible sector (no zero-buffer noise; _dskbufp persistence is // verify
live). (4) `ripper::disk::read_boot_sector` reads sector 0 of a raw .ST with
canonicalize + regular-file + extension + size validation (.MSA/.DIM rejected,
not misread). (5) The `bootsector` tool is a façade like identify_music: RAM
mode reuses rip(kind=boot); disk mode scans a file-backed MemImage and stores
it, so extract(as=raw|prg) works. Structured facts are recomputed from finding
bytes via analyze_sector; the label stays human. The `tells` field carries the
annotated disasm evidence inline, so extract.rs is untouched.
**Alternatives considered:** A known-virus signature DB (Signum/Ghost/…) —
deferred: needs a curated malware corpus; behaviour heuristics ship first and
never over-claim. A new "annotated disasm" ExtractFormat — rejected: the tells
carry the evidence and the P2 disasm tool covers full listings; keep extract
generic. Executing the sector in a sandbox to follow boot-cracktro loads
(r1pp3r) — large, emulator-coupled; backlog. Scanning all of RAM for any
executable sector — noisy and unfounded; _dskbufp is the one principled RAM
source. Flagging vector *reads* as tells — rejected outright: it would misclass
every antivirus bootblock (false positives are the failure mode we most want to
avoid).
**Consequences:** Boot-sector executability and geometry are exact; virus
detection is honest but heuristic — suspicious is a hedge with evidence and a
sub-1.0 confidence, not an accusation. RAM mode depends on unverified _dskbufp
persistence (// verify live); it degrades to a clean not-found. Only raw .ST is
supported; compressed images fail loud. Disk-source extracts land in a temp
dir when no session is running. Signature-based family naming and the
sandbox-follow rip flow are the pinned improvement paths.
```
