> where this document says something, do exactly that. If reality contradicts
> this spec, use the `Implementation note` / `// verify live` fallbacks; if
> there is no fallback, stop and flag to rust-architect.

**Honest difference from r1pp3r:** r1pp3r restores a *pre-run boot context*
and re-enters the cracktro at its entry point. We restore a *mid-run frozen
instant* and resume at the frozen PC — the Ultimate Ripper model. r1pp3r
contributes the load-bearing mechanics (crash-page trampoline, backward
staging copy, RTE launch, PRG wrapping with patched context fields); the
full-RAM in-place restore and the hardware reinstall sequence are this
phase's own engineering, specified below.

## 1. Deliverable in one sentence

`save_prg(out_path, mode="snapshot")` on a **Paused** session captures full
RAM (ADR-9 savebin), CPU registers, and the reinstallable hardware set
(video/Shifter + palette, YM2149, MFP 68901, STE DMA sound, memory config),
packs the RAM image with a purpose-built in-place-safe codec (SNAP1, §4.3),
prepends a two-stage position-independent 68k restore stub (§5), writes a
single self-contained `.PRG`, and returns compact JSON facts (path, sizes,
entry PC, residue ranges, explicit non-restored list) — never raw bytes.

## 2. The three hard problems — decisions (record in the ADR)

### 2.1 Tool surface: extend `save_prg`, don't add a sibling tool

| Option | Verdict |
|---|---|
| **`save_prg` grows `mode="snapshot"`** | **ships** — ADR-30 explicitly reserved this wire value and P16's tool description promises it ("use the future snapshot mode"). One verb = "persist the frozen machine as a .PRG", mode selects flavour; matches the grouped-verb precedent (`breakpoint`/`state` action params) and keeps the tool surface lean (progressive disclosure). |
| Sibling `save_snapshot_prg` tool | rejected — breaks the published contract, adds a tool for what is one capability with two flavours. |

Output becomes a **`#[serde(untagged)]` two-variant enum** (§8.1): the two
flavours legitimately report different facts; forcing them into one struct
of `Option`s is worse for every consumer.

### 2.2 The RAM-overlap problem (the classic freezer bind)

The emitted `.PRG` loads low in the TPA, but must repaint **all** of RAM
`[0, R)` (`R` = frozen `ram_len`), including the memory it and its restore
code occupy. An uncompressed image can never work: image ≈ `R` bytes plus
its own resident copy cannot fit in `R` bytes of RAM. The design:

1. **Compression is structural, not an optimization.** The RAM image is
   packed with **SNAP1** (§4.3), a zero-run/literal codec whose Rust packer
   *proves in-place decodability at pack time* (§4.4). Typical ST RAM is
   half zeros; a dense 4 MB image that cannot fit is an honest
   `invalid_params` error, not a corrupt snapshot.
2. **Stage the payload flush against the top**: stage-0 (running at the
   GEMDOS load address) copies the packed payload to `[R-P, R)` with a
   *backward* copy (r1pp3r `.cp_bwd`; dest > src always holds, proof in
   §4.5), then jumps to the hole block.
3. **Decode forward, in place**: output sweeps `0 → R`, input is always at
   or ahead of output (packer-verified invariant §4.4); the decode's final
   bytes are a raw tail that copies bytes onto themselves.
4. **The residue ("sacrifice window")**: some code must survive the sweep.
   It lives in the **hole** `[$1C0, $400)` — 68000 exception vectors
   112–255, which no ST(E) hardware source ever raises (MFP uses 64–79 at
   `$100–$13F` under the TOS `VR=$40` convention; traps end at `$BF`), plus
   the system crash page `$380–$3FF` that r1pp3r's trampoline already
   squats (TRAMP_DEST, R1PP3R.S:5703). The packer emits a *skip* over the
   hole; after resume those ≤576 bytes contain stub residue instead of the
   frozen bytes. This is the honest, bounded price of a cartridge-less
   freezer — reported in the JSON output every time.
5. **The RTE frame scratch**: the terminal sequence builds a 6-byte
   exception frame at `[frozen_SSP-6, frozen_SSP)` — memory below the
   supervisor stack pointer is scratch by 68000 convention (any interrupt
   would have pushed there). Also reported.

### 2.3 What is honestly NOT restorable — scoped, not hidden

See §4.2. The output carries a fixed `not_restored` list; the ADR and tool
description state it. A spec that promises a perfect snapshot would be
lying; this one promises "frozen RAM + CPU + programmed hardware registers,
frame-top video phase, period-top timer phase".

### 4.2 NOT restorable — the fixed `not_restored` list (verbatim strings in output)

1. `"video beam position — the restored frame starts at the top (base/res/palette are exact)"`
2. `"MFP timer countdown phase — timers restart at their reload values (period-top)"`
3. `"MFP pending/in-service interrupts (IPRA/B, ISRA/B are clear-only registers)"` — plus a **warning** if any captured IPR/ISR bit was set.
4. `"IKBD controller mode (its own MCU; a frozen program's IKBD commands are not replayed)"`
5. `"in-flight FDC/DMA disk operations"`
6. `"blitter registers and any half-done blit"`
7. `"STE DMA-sound frame position — playback restarts at frame start"`
8. `"STE microwire/LMC1992 volume state"`
9. `"hole $1C0–$3FF contains restore-stub residue instead of frozen bytes"`
10. `"6 bytes below the frozen SSP (RTE frame scratch)"`

Additional **conditional warnings** (computed at capture, §8.3):
- MFP `VR & 0xF0 >= 0x70` → `"MFP vector base overlaps the restore-stub hole — resumed MFP interrupts will crash"`.
- frozen `ISP < 0x10` or `ISP > R` → `"frozen SSP is implausible; the RTE frame write may corrupt live state"`.
- captured IPRA|IPRB|ISRA|ISRB ≠ 0 → `"a hardware interrupt was pending/in-service at the freeze; it is lost"`.
- ROM/TOS note (always): `"snapshot assumes the same TOS/machine config — ROM contents are not captured"`.

### 4.3 The SNAP1 stream format (this project's own codec — both ends in-repo)

Purpose-built: trivial 68k decoder, exact Rust packer, provable in-place
safety. Do not substitute ZX0/anything else — the in-tree ZX0 is a
*depacker* only, and a general LZ packer is out of scope.

All multi-byte values **big-endian**. Stream = sequence of runs:

| Opcode | Layout | Meaning |
|---|---|---|
| `0x00` | `00 len:u24` | zero run: write `len` zero bytes (`len ≥ 1`) |
| `0x01` | `01 len:u24` + `len` bytes | literal run: copy `len` bytes from stream (`len ≥ 1`) |
| `0x02` | `02 len:u24` | skip run: advance output by `len` without writing (the hole) |
| `0x03` | `03` + bytes to end | **raw tail + terminator**: copy stream bytes until output == region end |

Rules (packer-enforced, decoder-assumed):
- runs never have `len == 0`;
- exactly one `0x02` skip (the hole), or zero if the hole is empty;
- stream always ends with `0x03` (possibly with an empty tail only if
  output already == end — then `0x03` is still emitted as terminator);
- `len` fits u24 (region ≤ 4 MB, guaranteed);
- `ZERO_MIN = 16`: zero runs shorter than 16 bytes are folded into
  literals (4-byte header must pay for itself with margin).

### 4.4 The in-place safety rule (the load-bearing correctness argument)

At restore time the payload (`P` bytes) sits at `[R-P, R)`; the decoder
reads input pointer `i` (starts `R-P`) left-to-right and writes output `o`
(starts `0`) left-to-right. A write must never land on **unread** input.
Sufficient conditions, checked per run by `verify_inplace` (§6.2):

- **zero run** of `n`: requires `o + n ≤ i` *before* the run (writes with no reads);
- **literal / raw tail** of `n`: requires `o ≤ i` before the run — then each
  step reads `(i)` before writing `(o)` and both advance by 1, preserving
  `o ≤ i` (the degenerate `o == i` step copies a byte onto itself);
- **skip**: no writes; no condition.

The packer guarantees the invariant constructively: emit greedy runs, then
**extend the raw tail backwards** (absorbing trailing runs into verbatim
tail bytes, which can only add slack) until `verify_inplace` passes. This
terminates: with everything-after-the-hole raw, `i₀ = R - P ≥` hole size
`> 0 ≥ o₀` and the tail preserves `o ≤ i`. If even the fully-raw form
cannot satisfy `P ≤ R - hole_end - stage0_reserve` (§6.2 `Dense` error),
`build_snapshot_prg` fails with an honest message — the machine's RAM is
too dense to self-restore from a same-sized machine.

### 4.5 Memory layout during restore (pin this diagram in stub.s comments)

```
GEMDOS load:      [ basepage | stage0 | fields+hole code | payload(P) ]   at L (low TPA)
after stage-0:
  $000            frozen-to-be, decoder sweeps upward ───────────────►
  $1C0..$400      HOLE: fields + decoder + hw-restore + terminal (copied by stage-0)
  $400..          decoder output (TOS vars, program, screen, …)
  R-P .. R        staged payload (backward-copied; consumed as decode input)
```

Stage-0's backward staging copy is overlap-safe because `dest_start = R-P >
src_start = L + payload_off`: GEMDOS only loads the PRG if it fits below
`_memtop < R`, so `src_end = src_start + P < R ⇒ src_start < R - P`. ∎

## 5. The restore stub — `src/ripper/snapshot/stub.s`

One position-independent blob, assembled once with vasm (`SHIRAZMCP_VASM`,
default `vasmm68k_mot`), committed as `stub.bin`. Layout order is
**normative**: `stage0` code, then `fields` (starts with magic `SNP1`),
then `hole_code`, then label `payload` (end of blob). The hole block copied
to `HOLE_BASE = $1C0` is `[fields, payload)`; PC-relative addressing means
the copy needs no relocation. Hole block must fit `$400 - $1C0 = 576`
bytes (pinned test §10.2); if you cannot fit it, STOP and flag — do not
silently move `HOLE_BASE`.

### 5.2 Complete stub source (normative; assemble with vasm, verify opcodes)

```asm
; ShirazMCP P22 snapshot restore stub.
; Two stages: stage0 runs at the GEMDOS load address (position-independent);
; the hole block [fields..payload) is copied to HOLE_BASE and survives the
; full-RAM decode sweep. Heritage: r1pp3r's preamble/trampoline
; (R1PP3R.S 5253-5748); the crash page $380-$3FC precedent is TRAMP_DEST
; (R1PP3R.S 5703). See docs/plan/P22.md §4.5 for the memory layout.

HOLE_BASE   = $1C0          ; vectors 112..255 + crash page — never raised on ST(E)

; ---------------------------------------------------------------- stage 0
stub_start:
        clr.l   -(a7)               ; Super(0)
        move.w  #$20,-(a7)
        trap    #1
        addq.l  #6,a7

        move.l  $42e.w,d0           ; phystop
        cmp.l   f_region_end(pc),d0
        bcc.s   .fits
        pea     .msg(pc)            ; Cconws("snapshot needs more RAM")
        move.w  #9,-(a7)
        trap    #1
        addq.l  #6,a7
        clr.w   -(a7)               ; Pterm0   // verify live: from supervisor
        trap    #1
.fits:
        move.w  #37,-(a7)           ; Vsync — reduce takeover tearing
        trap    #14
        addq.l  #2,a7

        move.w  #$2700,sr           ; mask everything; no stack use below

        ; copy hole block (fields + code) to HOLE_BASE — fwd copy, no overlap
        lea     fields(pc),a0
        lea     HOLE_BASE.w,a1
        move.w  #(payload-fields)/2-1,d0
.cph:   move.w  (a0)+,(a1)+
        dbf     d0,.cph

        ; stage payload flush against top of frozen RAM: [R-P, R)
        ; backward copy (r1pp3r .cp_bwd) — dest > src always (§4.5)
        lea     payload(pc),a0
        move.l  f_payload_len(pc),d0
        adda.l  d0,a0               ; src end
        movea.l f_region_end(pc),a1 ; dest end = R
.cpp:   move.b  -(a0),-(a1)
        subq.l  #1,d0
        bne.s   .cpp

        jmp     (HOLE_BASE+(hole_code-fields)).w

.msg:   dc.b    13,10,"Snapshot needs more RAM than this machine has.",13,10,0
        even

; ------------------------------------------------------- fields (§5.1)
fields:
f_magic:        dc.b    "SNP1"
f_flags:        dc.w    0
f_region_end:   dc.l    0
f_payload_len:  dc.l    0
f_pc:           dc.l    0
f_sr:           dc.w    0
f_usp:          dc.l    0
f_ssp:          dc.l    0
f_dregs:        ds.l    8
f_aregs:        ds.l    7
f_pal:          ds.w    16
f_video:        ds.b    8           ; basehi,basemid,baselo,linewidth,hscroll,sync,res,memcfg
f_ym:           ds.b    16          ; regs 0-13 + pad
f_mfp:          ds.b    16          ; gpip,aer,ddr,iera,ierb,imra,imrb,vr,tacr,tbcr,tcdcr,tadr,tbdr,tcdr,tddr,pad
f_dmasnd:       ds.b    8           ; control,mode,starthi,startmid,startlo,endhi,endmid,endlo
        even

; ---------------------------------------------- hole code (runs at $1C0+)
; RULES: no stack, no subroutines, PC-relative data only (offsets survive
; the copy because fields+code move together).
hole_code:
        ; ---- SNAP1 decode: input a0 = R-P, output a1 = 0, sweep to R
        movea.l f_region_end(pc),a0
        suba.l  f_payload_len(pc),a0
        suba.l  a1,a1
.op:    moveq   #0,d1
        move.b  (a0)+,d0
        cmpi.b  #3,d0
        beq.s   .tail
        move.b  (a0)+,d1            ; u24 big-endian length
        lsl.l   #8,d1
        move.b  (a0)+,d1
        lsl.l   #8,d1
        move.b  (a0)+,d1
        tst.b   d0
        beq.s   .zero
        cmpi.b  #1,d0
        beq.s   .lit
        adda.l  d1,a1               ; 02 = skip (the hole itself)
        bra.s   .op
.zero:  clr.b   (a1)+
        subq.l  #1,d1
        bne.s   .zero
        bra.s   .op
.lit:   move.b  (a0)+,(a1)+
        subq.l  #1,d1
        bne.s   .lit
        bra.s   .op
.tail:  cmpa.l  f_region_end(pc),a1
        beq.s   .hw
        move.b  (a0)+,(a1)+
        bra.s   .tail

        ; ---- hardware reinstall (order is normative)
.hw:    lea     f_video(pc),a2
        move.b  7(a2),$ffff8001.w   ; memory config
        move.b  (a2),$ffff8201.w    ; video base high
        move.b  1(a2),$ffff8203.w   ; video base mid
        move.w  f_flags(pc),d0
        btst    #0,d0
        beq.s   .nst1
        move.b  2(a2),$ffff820d.w   ; STE base low
        move.b  3(a2),$ffff820f.w   ; STE linewidth
        move.b  4(a2),$ffff8265.w   ; STE hscroll
.nst1:  move.b  5(a2),$ffff820a.w   ; sync (50/60)
        move.b  6(a2),$ffff8260.w   ; resolution
        lea     f_pal(pc),a2        ; 16 palette words
        lea     $ffff8240.w,a3
        moveq   #7,d1
.pal:   move.l  (a2)+,(a3)+
        dbf     d1,.pal

        lea     f_ym(pc),a2         ; YM 0..13 — reg 13 written last (retrigger)
        lea     $ffff8800.w,a3
        moveq   #0,d1
.ym:    move.b  d1,(a3)
        move.b  (a2)+,2(a3)
        addq.b  #1,d1
        cmpi.b  #14,d1
        bne.s   .ym

        ; MFP: stop -> clear -> static regs -> reloads -> control -> IER -> IMR
        clr.b   $fffffa19.w         ; TACR
        clr.b   $fffffa1b.w         ; TBCR
        clr.b   $fffffa1d.w         ; TCDCR
        clr.b   $fffffa07.w         ; IERA=0 (clears pending too)
        clr.b   $fffffa09.w         ; IERB
        clr.b   $fffffa0b.w         ; IPRA
        clr.b   $fffffa0d.w         ; IPRB
        clr.b   $fffffa0f.w         ; ISRA
        clr.b   $fffffa11.w         ; ISRB
        move.b  f_mfp+0(pc),$fffffa01.w   ; GPIP
        move.b  f_mfp+1(pc),$fffffa03.w   ; AER
        move.b  f_mfp+2(pc),$fffffa05.w   ; DDR
        move.b  f_mfp+7(pc),$fffffa17.w   ; VR
        move.b  f_mfp+11(pc),$fffffa1f.w  ; TADR (reload)
        move.b  f_mfp+12(pc),$fffffa21.w  ; TBDR
        move.b  f_mfp+13(pc),$fffffa23.w  ; TCDR
        move.b  f_mfp+14(pc),$fffffa25.w  ; TDDR
        move.b  f_mfp+8(pc),$fffffa19.w   ; TACR (starts timer A)
        move.b  f_mfp+9(pc),$fffffa1b.w   ; TBCR
        move.b  f_mfp+10(pc),$fffffa1d.w  ; TCDCR
        move.b  f_mfp+3(pc),$fffffa07.w   ; IERA
        move.b  f_mfp+4(pc),$fffffa09.w   ; IERB
        move.b  f_mfp+5(pc),$fffffa13.w   ; IMRA
        move.b  f_mfp+6(pc),$fffffa15.w   ; IMRB

        move.w  f_flags(pc),d0      ; STE DMA sound
        btst    #0,d0
        beq.s   .nst2
        clr.b   $ffff8901.w
        move.b  f_dmasnd+2(pc),$ffff8903.w
        move.b  f_dmasnd+3(pc),$ffff8905.w
        move.b  f_dmasnd+4(pc),$ffff8907.w
        move.b  f_dmasnd+5(pc),$ffff890f.w
        move.b  f_dmasnd+6(pc),$ffff8911.w
        move.b  f_dmasnd+7(pc),$ffff8913.w
        move.b  f_dmasnd+1(pc),$ffff8921.w
        move.b  f_dmasnd+0(pc),$ffff8901.w
.nst2:
        ; ---- CPU context + launch (r1pp3r RTE model, R1PP3R.S 5641-5675)
        movea.l f_usp(pc),a0
        move    a0,usp
        movea.l f_ssp(pc),a7
        move.l  f_pc(pc),-(a7)      ; frame: [SSP-6,SSP) = SR.w + PC.l
        move.w  f_sr(pc),-(a7)
        movem.l f_dregs(pc),d0-d7
        movem.l f_aregs(pc),a0-a6
        rte
payload:                            ; Rust appends the SNAP1 stream here
```

Implementation notes for the engineer:
- `abs.w` sign-extension makes `$ffff8201.w`, `$fffffa01.w` etc. hit the
  right 24-bit IO addresses; vasm accepts these forms. If vasm's `-Fbin`
  needs an `org 0` header line, add it — the blob must start at offset 0.
- The decoder is byte-loop simple by design (~2.5 s for 1 MB at 8 MHz);
  do NOT "optimize" it in this phase.
- If frozen SR has S=0, the `rte` pops the user SR and execution continues
  on USP (set beforehand) while SSP correctly ends at `f_ssp` — both modes
  are handled by the same terminal sequence.

### 5.3 Restore ordering (normative summary; mirrors the code above)

1. stage-0: `Super(0)` → phystop check → `Vsync` → `SR=$2700` → hole block
   to `$1C0` → payload backward-copied to `[R-P, R)` → `jmp` hole.
2. hole: decode RAM `0→R` (skip hole) → memcfg → video regs → palette →
   YM 0..13 → MFP (stop, clear, static, reloads, control, IER, IMR) →
   STE DMA sound → USP → SSP frame (SR+PC) → `movem` D/A → `RTE`.

### 5.4 Build + commit workflow for `stub.bin`

1. `vasmm68k_mot -Fbin -o src/ripper/snapshot/stub.bin src/ripper/snapshot/stub.s`
   (use `$SHIRAZMCP_VASM` if set; same binary the `assemble` tool drives).
2. Commit both files. `stub.bin` is embedded via `include_bytes!`.
3. Drift guard (§10.2): a test, **skipped** when the vasm binary is absent
   (P8 `tests/assemble.rs` vasm-gated precedent), reassembles `stub.s` with
   `std::process::Command` and asserts byte equality with the committed bin.

```markdown
## 2026-MM-DD — ADR-NN: save_prg mode=snapshot — freeze the machine into a self-restoring .PRG (SNAP1 + $1C0 hole)

**Status:** accepted
**Context:** ADR-30 shipped save_prg as repatch-only and reserved
mode="snapshot": repatch cannot capture BSS/runtime/hardware state and
needs the original file. The freezer-cartridge save (Ultimate Ripper /

does the restoring.

under one Paused-session lock: full RAM (ADR-9 savebin), cpureg, info ym

IoMem cannot provide), and IoMem blocks for video/memcfg/STE-DMA-sound
(debugger IO reads return last-written values — precisely what a restore
stub must rewrite). Emit = position-independent two-stage 68k stub
(committed stub.bin, vasm source + drift-guard test) + SNAP1-packed RAM
image. SNAP1 is a purpose-built zero-run/literal/skip/raw-tail codec whose
Rust packer PROVES in-place decodability at pack time (payload staged
flush at [R-P,R), forward decode, tail extended until the o≤i invariant
holds) — compression is structural: an uncompressed full-RAM snapshot can
never fit its own machine. Restore order: Super → mask → hole block to
$1C0 → payload staged high (r1pp3r backward copy) → decode 0→R (skipping
the hole) → memcfg/video/palette → YM 0-13 → MFP
(stop→clear→static→reloads→control→IER/IMR) → STE DMA sound → USP → RTE
frame below frozen SSP → movem → RTE at the frozen PC.
**Alternatives considered:** sibling tool (breaks the ADR-30 contract);
uncompressed used-extent capture (cannot restore dense regions, no
integrity story); ZX0 for the payload (in-repo ZX0 is a depacker; writing
an optimal packer is a phase of its own and its in-place delta is subtler
than SNAP1's constructive rule); stub residue below frozen SSP instead of
$1C0 (SSP position is untrusted input; the vector hole is fixed,
r1pp3r-precedented — crash page $380 — and never hardware-raised on ST(E)).
**Consequences:** Residue is bounded and ALWAYS reported: ≤576 bytes at
$1C0..$400 + 6 bytes below frozen SSP. Honest non-restores are a fixed
list in every output (beam position, MFP timer phase + pending interrupts,
IKBD mode, FDC/DMA in flight, blitter, DMA-sound position, microwire).
Programs pointing MFP VR at the hole, or with live data in the crash-page
vectors, resume corrupted — detected where possible and warned. A
too-dense RAM image is an honest error, not a broken file. The stub is a
committed binary artifact: reviewable assembly source + byte-equality
drift test replaces build-time assembly (no vasm needed to build the
crate).
```
