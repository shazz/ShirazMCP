## 4. Normative content (pinned)

### 4.1 Fingerprint-extraction methodology (the repeatable recipe)

This is the procedure that produced every entry in §4.3, written so the next
driver is added the same way. A condensed version goes in the `ym_sig_db.rs`
module doc (§5.2).

1. **Gather labelled samples.** ≥ 1 file *known* to contain the target
   driver's replay code. Binaries (rips, `.SND`, `.BIN`) are preferred;
   assembly source is acceptable but the derived entry must carry a
   `hand-assembled — verify live` marker (encoding mistakes make a dead
   entry, which safely degrades to `"unknown"`; they can never cause a wrong
   name). Two or more independent samples upgrade the confidence band (§4.2).
2. **Locate the PSG write gadget.** Scan each sample for the operand bytes
   `FF FF 88 00` / `FF FF 88 02` (absolute long) and, at even offsets,
   `88 00` / `88 02` (absolute short) — same universe as `ym_player.rs`'s
   anchor. Dump ±16 bytes of context around each hit. Reference snippet
   (run from the corpus root; this exact script derived §4.3):

   ```python
   import pathlib, sys
   for f in pathlib.Path(sys.argv[1]).rglob("*"):
       if not f.is_file(): continue
       d = f.read_bytes()
       for pat in (b"\xff\xff\x88\x00", b"\xff\xff\x88\x02", b"\x88\x00", b"\x88\x02"):
           i = d.find(pat)
           while i != -1:
               if i % 2 == 0 and (len(pat) == 4 or d[i-2:i] != b"\xff\xff"):
                   print(f"{f}@{i:#x}: {d[max(0,i-16):i+16].hex(' ')}")
               i = d.find(pat, i + 1)
   ```
3. **Pick the gadget, decode it.** Choose the shortest instruction run that
   (a) contains a PSG hardware operand and (b) recurs across samples.
   Decode every word (68k reference or `analyze::disasm` on a scratch
   `MemImage`) — you must be able to *name* each word in the provenance
   comment; an undecoded pattern is not a signature.
4. **Mask what relocates or varies.** Per the existing `SigWord` scheme:
   hardware constants (`$FFFF8800`, register numbers, immediates that are
   PSG register values) → `mask 0xFFFF`; relocated address operands and
   pc-displacements → `mask 0x0000`; opcode register fields that differ
   across samples → mask those 3 bits (e.g. `movem.l (aN),…` seen with a4
   and a6 → `value 0x4CD0, mask 0xFFF8`). Never mask a word you haven't
   seen vary or that can't relocate — over-masking buys false positives.
5. **Choose the scope.** Instruction gadget → `AnchorWindow` (it sits inside
   the replay cluster ±512). Module-format data magic → `WholeImage`, and
   only with ≥ 6 literal bytes *including a terminator/guard byte* (the P19
   audit found ASCII words like `QUARTET` in demo scrolltexts — an
   unguarded text magic is a confident-wrong-guess machine).
6. **False-positive check.** Grep the candidate pattern across an unrelated
   slice of the corpus (pictures, packers, other drivers' rips). Zero hits
   outside the labelled samples, or the pattern gets longer.
7. **Assign confidence** from the §4.2 rubric, add the entry to
   `SIGNATURES` in descending-confidence order with the pinned provenance
   comment format:
   `// <id> — <decoded instructions>; source: <path>@<hex offset> (+ N more files)`
8. **Pin the tests** (§6.1): one positive test whose input is a hex excerpt
   *copied from the cited sample* (with path+offset in a comment), and
   coverage by the shared unrelated-code negative test. A signature without
   a corpus-excerpt test does not ship.

### 4.2 Confidence rubric (pinned bands — all 2-decimal `f32` literals, they
round-trip through the `{:.2}` label format)

| band | criteria |
|---|---|
| `0.85` | AnchorWindow gadget, ≥ 20 literal bytes, identical in ≥ 2 independent samples |
| `0.82` | AnchorWindow gadget, ≥ 8 literal bytes, seen in ≥ 2 independent samples |
| `0.80` | WholeImage data magic, ≥ 8 literal bytes incl. terminator, ≥ 2 real module files |
| `0.70` | single-sample or hand-assembled-from-source gadget (`// verify live`) |
| `0.60–0.65` | WholeImage magic with weaker guard or single corpus family |
| ≤ `0.25` | forbidden — nothing in the DB may tie or lose against `CONF_ANCHOR_ONLY` |

**Removed entries (normative, with rationale — record in the ADR):**

- `hippel-code` (`13FC 000D FFFF 8800 13C0/FFF8 FFFF 8802`): invented from
  documented envelope behavior, **never observed in any of the 30+ labelled
  Hippel binaries scanned** — every real Hippel replay uses the `movem`
  blast (sigs 2–4). Keeping it would name *any* driver that writes envelope
  shape `$0D` via long-form `move.b` "Hippel" at 0.70. Honesty over
  coverage: delete.
- `quartet` (`"QUARTET"` ASCII, 0.55): no Quartet/Lucas player or module
  exists in the local corpus, and the literal word `QUARTET` was found in
  unrelated demo scrolltexts (`ASM/Inner Cirle/Decade Demo/russ/redh4.s`,
  `ASM/Awesome/MENU_11/MENU_11.S`) — a demonstrated confident-wrong-guess.
  Delete; Lucas/Quartet moves to the §9 gap list.

### 4.4 Invariants preserved (assert-level, §6 tests them)

- No anchor → no finding; anchor + no signature →
  `("unknown", CONF_ANCHOR_ONLY = 0.25)` — byte-identical labels to P6.
- Every DB confidence `> CONF_ANCHOR_ONLY`, `≤ 0.85`, exact 2-decimal
  literal (label round-trip).
- Best match = highest confidence, tie → first in DB order (unchanged
  matcher); DB is written in descending-confidence order so the tie rule
  stays legible.

## 9. Out of scope / gaps (do not "fix" any of these in P19)

- **Lucas/Quartet** — no player or module in the local corpus; entry
  removed rather than guessed. Needs a real Quartet module/replay sample.
- **David Whittaker / Delta Music / Music Mon / ProTracker STk** — no
  labelled local source. The `Mug UK/SNDIMAGE/*.BIN` rips share only Mug
  UK's rip *wrapper* (identical across different games), so the underlying
  drivers cannot be confidently named — listed, not fabricated.
- **24-bit PSG addressing** (`lea $FF8800.l` → `00 FF 88 00`): real rips
  use it (all six SNDIMAGE binaries); the anchor scan misses it because
  `is_psg` has no `"$ff8800"` token. Engine change → its own phase/ADR.
- **`AN COOL!`** variant and **rg-triplex** encoding: `// verify live`
  markers stay until a matching binary is observed.

  8800 …`, seen in every COSO1 binary at ~+0x3CE): a valid fourth Hippel

  fragments.
