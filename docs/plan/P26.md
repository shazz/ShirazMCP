## 0. Open questions (state honestly; none block implementation)

1. **`symbols <file> …` success line wording** is pinned from v2.4.1 source

   token after `(` — keep that tolerance.)
2. **`symbols free` output** — v2.4.1 prints *nothing* on success
   (symbols.c v2.4.1:890-901 has no success print). §5.1's parser treats

3. **Basepage discovery while Running** — `debug::basepage` is proven live

   (`$4F2`→OSHEADER→`p_run`) are stable TOS globals once a program runs, so
   §7's auto-base runs in either live state. If the live test shows flaky

   discovery once, then error.
4. **vasm `-L` listings can NOT be ingested — LOUD AND FINAL for this

## 2. Verified Hatari v2.4.1 facts (the contract we build on)

All line numbers are the **v2.4.1 tag** unless marked HEAD.

### 2.1 Expression evaluation resolves bare symbol names — no sigil

`evaluate.c` v2.4.1:204-263 (`getValue`), called by `Eval_Expression` for
every non-operator token:

1. scan an identifier: `[_A-Za-z0-9]+`, **max 63 chars** (`char name[64]`);
2. Hatari **variable**? (`Vars_GetVariableValue` — case-insensitive:
   `strcasecmp`, vars.c; includes `TEXT`, `DATA`, `BSS`, `TEXTEnd`,
   `Basepage`, `VBL`, … all "invalid before Desktop is up");
3. `PC` / `SR` special-case (case-insensitive);
4. CPU **register** (`DebugCpu_GetRegisterAddress`);
5. **symbol**: `Symbols_GetCpuAddress(SYMTYPE_ALL, name, &addr)` —
   **TEXT, DATA, BSS and ABS live in ONE namespace**, exact `strcmp` match
   (case-sensitive), binary search by name;
6. else parse as a number in the debugger's default base (**10**).

Consequences we pin:

- `evaluate BlitSphere` prints the **same** `= %… (bin), #… (dec), $… (hex)`
  line as any numeric expression (debugui.c `DebugUI_PrintValue`) — our
  existing `parse_evaluate` (src/debug/parse/values.rs) works unchanged.
- An **unknown** name (e.g. `NoSuchLabel`) falls to the number parser, fails
  (`Invalid value` / `Syntax error` on stderr, no `= %` line) →
  `parse_evaluate` returns `Error::Parse`. Deterministic.
- A name shadowed by a **register/variable** (`a0`, `pc`, `VBL`, `TEXT`)
  resolves to the register/variable, never the symbol. Document, don't fight.
- Symbol names containing `.` or `-` (legal in the file formats) are
  **unreachable from expressions** (identifier scan stops at them). §6.4's
  candidate gate mirrors exactly the reachable set.

### 2.2 The `symbols` debugger command (v2.4.1 surface)

`symbols.c` v2.4.1:783-822 (help), 825-936 (`Symbols_Command`):

```
symbols <name|code|data>                      — list (NO 'find' filter in 2.4.1!)
symbols <prg|free>                            — load from GEMDOS-HD program / free
symbols <filename> [<T offset> [<D offset> <B offset>]]
symbols <autoload|match>                      — toggles
```

- **Offsets** are parsed with `Eval_Expression` (v2.4.1:906) → `$hex`
  accepted, even variable names like `TEXT`. Defaults: T=0; **D and B
  default to the T offset** (v2.4.1:909). We always pass all three
  explicitly (§7).
- **Offsets apply to ASCII files only.** If the file starts with GEMDOS
  magic `0x601A` (`Opt_IsAtariProgram`, options.c v2.4.1:729), the binary
  loader runs instead and the offsets are **ignored**: sections are
  relocated to the **currently running program's basepage** via
  `update_sections` → `DebugInfo_GetTEXT()` (symbols.c v2.4.1:233-263).
  Errors: `ERROR: no valid program basepage!` (no process) and
  `ERROR: given program TEXT section size differs from one in RAM!` (the
  file on disk is not the program that is running).
- `symbols prg` = load from `CurrentProgramPath` — the path Hatari recorded
  on the first `Fopen()` after `Pexec()` **through GEMDOS HD emulation
  only** (symbols.c v2.4.1:727-733). Without GEMDOS HD:
  `ERROR: no program loaded (through GEMDOS HD emu)!` (v2.4.1:916).
  Because our sessions mount `--harddrive`, `CurrentProgramPath` is a
  **host filesystem path** — §7.2 exploits this to build the server-side
  listing store.
- Success line: `Loaded %d symbols (%d TEXT) from '%s'.` (v2.4.1:344).
  Missing table: `ERROR: symbol table missing from the program!`
  (symbols-common.c v2.4.1, `symbols_load_binary`) — already handled as
  `SymbolLoad::NoSymbols` (ADR-8; the committed MJJ build has no table).
- **Binary formats accepted:** DRI/GST (default), MiNT a.out, and (HEAD
  only) ELF. ASCII format: nm-style, §2.4.

### 2.3 THE PAGER HAZARD — `symbols name|code|data` is FORBIDDEN on the wire

`Symbols_Show` v2.4.1:649-695 pages the listing every
`DebugUI_GetPageLines(nSymbolLines, 20)` rows (config default `-1` → readline
terminal size → **20** on a pipe) and then does
`fgets(line, sizeof(line), stdin)` on the prompt
`--- q to exit listing, just enter to continue --- `.

Our stdin is either the frozen-state **control plane** (Paused: the pager
would eat our next sentinel line and corrupt the episode) or a held-open
pipe Hatari never otherwise reads while Running (the pager **blocks the
main loop** until we write — the whole emulator freezes). There is no CLI
option to change `nSymbolLines` (config-file key only, verified across
options.c). **Therefore: the server never sends `symbols name`, `symbols
code`, or `symbols data`. Listing is served from a Rust-side store (§7).**
Add this to the grep-gate family: `grep -rn '"symbols name\|"symbols code\|"symbols data' src/` → no hits.

### 2.4 ASCII ("nm-style") file format — exact v2.4.1 rules our parser mirrors

`symbols_load_ascii` v2.4.1:63-170:

- Line: `sscanf("%x %c %32[0-9A-Za-z_.-]s")` → hex address (bare or `0x`),
  one type char, name of **≤32 chars** from `[0-9A-Za-z_.-]`.
- Types: `T`→TEXT (+T offset); `O`,`R`,`D`→DATA (+D offset); `B`→BSS
  (+B offset); `A`→ABS (no offset); `W`,`V` **skipped** (weak; counted);
  anything else warned + skipped. Case-insensitive (`toupper`).
- Comments: first char `#` or `*`. Blank lines skipped. A non-blank line
  whose first non-space char is not a hex digit **aborts the whole load**
  (`ERROR: line %d doesn't start with an address.`).
- After offsetting: `address > 0xFFFFFF` (24-bit, `bAddressSpace24` default)
  → skipped with a warning, load continues.

### 2.5 DRI/GST symbol table — exact rules for the Rust mirror (§6.3)

`symbols_load_dri` (symbols-common.c v2.4.1:554-690; constants identical in
HEAD:694-855):

- Table location in the PRG file: offset `0x1C + tlen + dlen`; size =
  header `slen` (bytes 14..18). Table type: header bytes 18..22 —
  `0x0` = DRI; MiNT/ELF magics otherwise (§6.3 rejects non-DRI politely).
- Entry: **14 bytes** — 8 name chars, u16 `symid` (BE), u32 `value` (BE).
  `tablesize % 14 != 0` or zero → invalid.
- **GST/HiSoft extension:** `symid & 0x0048` ⇒ the NEXT 14-byte slot is 14
  more name chars (name ≤22). This is what vasm emits for >8-char names.
- Section from `symid & 0xf00`: `0x200`=TEXT, `0x400`=DATA, `0x100`=BSS.
  Else: `(symid & 0xe000) == 0xe000` ⇒ debug symbol, skip;
  `symid & 0x4000` ⇒ ABS (no relocation); anything else warn+skip.
- **Relocation heuristic** (`use_bssdata_offset`): if ANY DATA/BSS symbol's
  raw value `< tlen`, values are TEXT-relative → add the TEXT base to
  everything; otherwise DATA/BSS values are section-relative → add each
  section's own base. TEXT always gets the TEXT base. After relocation, a
  symbol past its section end is skipped with a warning.
- v2.4.1 load opts: `no_obj` (skip `*.[ao]` / `*/*` file names) and
  `no_local` (skip `.L*`) — mirror both in §6.3.

### 2.6 Breakpoint conditions already accept symbol names

`breakcond.c` v2.4.1:706-760 (`BreakCond_ParseValue`): a token starting with
a letter or `_` resolves **Variable → Register → Symbol**
(`BreakCond_ParseSymbol` v2.4.1:448-489 → `Symbols_GetCpuAddress`; direct
values use `SYMTYPE_ALL`, indirect `(name)` uses DATA|BSS only). The symbol
is resolved to a number **at arm time**, but the stored/echoed expression
keeps the NAME verbatim (the tokenizer only normalizes spacing,
v2.4.1 `BreakCond_TokenizeExpression`) — so `managed.rs`'s
`fired_expression`/`disarm_ours` string comparisons keep working for
symbolic conditions exactly as well/badly as for numeric ones (i.e. pass
conditions in the already-normalized `lhs = rhs` single-space form; the
tool description already shows that form). Failure text on unknown name:
`invalid variable/register/symbol name` inside an `ERROR: …` block →
already surfaces as `Error::Parse` via `bp::parse_armed`.

**Consequence: the `breakpoint` tool needs no resolution plumbing at all** —
only a description update and a friendlier arm-failure hint (§8.3).

### 2.7 Autoload — reconciling with `control.rs`

v2.4.1 configuration.c:539: `bSymbolsAutoLoad = true` by default. On every
debugger entry (debugui.c → `Symbols_LoadCurrentProgram`, symbols.c
v2.4.1:751-766) Hatari loads the GEMDOS-HD program's symbol table **iff no
symbols are currently loaded**; they're freed when the program exits. This
is precisely the symbol-table load banner `drain_stdin_entry_text`
(src/session/spawn/control.rs) already drains. Net effect for us: for a
symbol-bearing GEMDOS-HD PRG, **name resolution via `evaluate` and `b` may
already work without any tool call** — `symbols(action="load")` is still
what populates the server-side store and reports counts/bases, and is the
documented path.

## 3. Design (one authority, one store, one seam)

- **Hatari is the ONLY resolution authority.** `resolve_addr` asks Hatari
  (`evaluate <name>`) instead of consulting our store, so a name always
  means what a breakpoint condition would mean — no dual-authority drift
  (autoload, `symbols free` via raw `debug`, program exit all stay
  coherent).
- **The store is for LISTING only** (ADR-5: compact findings, capped, no
  bulk in context; §2.3: Hatari's own listing is unusable over our control
  planes). It is rebuilt on every successful `load` from the same source
  file Hatari read, with the same offset rules, and cleared on `free`/`stop`.
- **Parse-first precedence, pinned:** `Addr::parse` first; only on its
  failure may the string be treated as a symbol. A string that parses as a
  number is NEVER sent to Hatari — `"1234"`, `"$dead"`, `"0xFACE"` keep
  their exact current meaning even if a same-named symbol exists.
  (Hatari's own precedence differs — symbols beat bare numbers there — one
  more reason the helper must gate locally first.)
- Async only where I/O lives: the new debugger wrappers are async over
  `DebugChannel`; the two file parsers (nm-ASCII, DRI) are pure sync
  functions over bytes/strings.

## 5. `src/debug/symbols.rs` — typed debugger wrappers

Same shape as `debug/breakpoint.rs`: generic over `DebugChannel`, no fifo

```rust
use crate::error::{Error, Result};

/// Outcome of a file/prg load incl. the host path Hatari read (from the

#[derive(Debug, Clone, PartialEq, Eq)]

    path: &std::path::Path,

    chan: &mut impl DebugChannel,
    path: &std::path::Path,
```

### 6.2 nm-ASCII parser (pure, in `symbols_wire.rs`)

```rust
/// Mirror of Hatari v2.4.1 symbols_load_ascii (§2.4) so the store matches
/// what Hatari loaded from the SAME file with the SAME offsets.
pub(crate) fn parse_ascii_map(text: &str, offsets: [u32; 3]) -> Result<(Vec<SymEntry>, usize), String>;
```

Rules — implement §2.4 EXACTLY: comment chars `#`/`*`; blank-skip;
first-token-not-hex ⇒ `Err` (whole file rejected, like Hatari); type chars
(case-insensitive) `T`→Text+off[0], `O|R|D`→Data+off[1], `B`→Bss+off[2],
`A`→Abs+0, `W|V`→skip count, other→skip count; name = first ≤32 chars of
`[0-9A-Za-z_.-]` after the type char (longer input: truncate at 32, like
`%32[…]s`); relocated `addr > 0xFF_FFFF` (and not Abs) → skip count.
`u32::wrapping_add` for the offset (Hatari does unsigned C addition).

### 6.3 `src/ripper/prg_symbols.rs` — DRI/GST parser (pure)

Sibling of `prg_file.rs` (same layer, same path-validation caller). Operates
on an already-parsed `PrgFile` — do not re-read the file.

```rust
use crate::ripper::prg_file::{PrgFile, HEADER_LEN};

/// Why a PRG's table couldn't be mirrored (load in Hatari may still work).
#[derive(Debug, PartialEq, Eq)]
pub enum DriError {
    NoTable,                     // slen == 0
    NotDri { tabletype: u32 },   // MiNT a.out / ELF: names resolve, no listing
    Malformed(String),           // size % 14, table past EOF, …
}

/// Parse + relocate per §2.5. `bases` = [text, data, bss] section starts
/// (from basepage discovery — the same numbers Hatari's update_sections
/// uses). Returns entries + skipped count.
pub fn parse_dri(prg: &PrgFile, bases: [u32; 3]) -> Result<(Vec<SymEntry>, usize), DriError>;
```

Implementation constraints (all from §2.5, cite `symbols-common.c
v2.4.1:554-690` in the module doc):

- `tabletype` = BE u32 at file offset 18; `!= 0` ⇒ `NotDri`.
- Table slice: `HEADER_LEN + tlen + dlen ..+ slen`; bounds-check against
  `prg.bytes.len()` ⇒ `Malformed`.
- 14-byte slots; GST extension consumes the following slot (careful at the
  end: extension flagged on the LAST slot ⇒ treat as 8-char name, count as
  skipped-malformed rather than erroring the table).
- Name bytes: NUL-terminate at first 0; must be non-empty after trim, else
  skip.
- Section nibble/debug/ABS exactly per §2.5; `use_bssdata_offset` = any
  DATA/BSS raw value `< tlen` (first pass), then relocate in a second pass;
  post-relocation section-end check (TEXT end = `bases[0]+tlen`, DATA end =
  `bases[1]+dlen`, BSS end = `bases[2]+blen`) skips out-of-range symbols.
- Mirror v2.4.1 ignore options: skip names matching `.L*` (no_local) and
  file names (`*.a`/`*.o`/containing `/`, no_obj).
- `SymEntry`/`SymKind` come from `symbols_wire`? **No** — layering: `ripper`
  must not import `tools`. Define the entry pair in `prg_symbols.rs`
  (`pub struct PrgSymbol { pub addr: u32, pub kind: PrgSymKind, pub name: String }`)
  and let `symbols_wire` convert. Ripper stays leaf-pure.

### 6.4 `src/tools/resolve.rs` — THE seam

```rust
use rmcp::ErrorData as McpError;
use crate::debug::{self, DebugChannel};
use crate::types::Addr;

/// Resolve an agent-supplied address string: numeric forms first
/// ($hex/0xhex/decimal — Addr::parse, 100% unchanged), then, ONLY if that
/// fails AND the string is a plausible Hatari identifier, ask Hatari to
/// evaluate it as a register/variable/symbol name. A string that parses as
/// a number is never reinterpreted as a symbol.
pub(crate) async fn resolve_addr(
    chan: &mut impl DebugChannel,
    s: &str,
) -> Result<Addr, McpError>;

/// resolve_addr + the disasm even-address gate (same message as today's
/// parse_even_addr: "disasm address must be even").
pub(crate) async fn resolve_even_addr(
    chan: &mut impl DebugChannel,
    s: &str,
) -> Result<Addr, McpError>;
```

Algorithm for `resolve_addr` (pin verbatim in a doc comment):

1. `Addr::parse(s)` → `Ok(a)` ⇒ return `Ok(a)`. *(Numbers win. Always.)*
2. `is_symbol_candidate(s)`: first char `[A-Za-z_]`, rest `[A-Za-z0-9_]`,
   length 1..=63 (Hatari's identifier scanner, §2.1). Not a candidate ⇒
   `McpError::invalid_params("not a valid address ($hex, 0xhex or decimal) \
   and not a symbol name: {s}", None)`. *(Leading-digit strings are
   malformed numbers, never symbols — `"12x4"` must not reach Hatari.)*
3. `debug::evaluate(chan, s).await`:
   - `Ok(v)` with `v < Addr::BUS_LEN` ⇒ `Ok(Addr::new(v))`.
   - `Ok(v)` otherwise ⇒ `invalid_params("symbol '{s}' = ${v:x} is outside \
     the 24-bit ST bus", None)`.
   - `Err(_)` ⇒ `invalid_params("'{s}' is neither a number nor a known \
     register/variable/symbol. If it is a label, load the symbol map first: \
     symbols(action=\"load\") for a GEMDOS-HD .PRG with a symbol table \
     (vasm -Ftos default), or symbols(action=\"load\", path=…) for an \
     nm-style .sym file.", None)`.

`is_symbol_candidate` is a private pure fn — unit-test it directly.
Note the one behavior change this implies for the three tools: a malformed
input that today errors instantly now costs one `evaluate` round-trip when
it looks like an identifier. Acceptable; do not "optimize" with a local
store lookup (§3 single-authority).

## 7. The `symbols` MCP tool

### 7.1 Schema (`src/tools/symbols_wire.rs`)

```rust
#[derive(Debug, Deserialize, JsonSchema)]
pub struct SymbolsArgs {
    pub action: SymbolsAction,               // load | list | free
    /// load: host path to an nm-style ASCII map or a .PRG with a DRI/GST
    /// symbol table. Omit to load from the running GEMDOS-HD program.
    pub path: Option<String>,
    /// load(ASCII only): explicit TEXT offset ("$70000"/decimal). Omitting
    /// it selects auto-detection from the GEMDOS basepage. Rejected for
    /// .PRG sources (Hatari relocates those itself).
    pub text_offset: Option<String>,
    /// load(ASCII only): DATA offset; defaults to text_offset when that is
    /// given, else auto-detected.
    pub data_offset: Option<String>,
    /// load(ASCII only): BSS offset; same defaulting as data_offset.
    pub bss_offset: Option<String>,
    /// list: "code" (TEXT, by address) | "data" (DATA/BSS/ABS, by address)
    /// | "all" (default, by name).
    pub kind: Option<SymListKind>,
    /// list: case-insensitive substring filter — the primary interface for
    /// big maps; prefer it over paging.
    pub find: Option<String>,
    /// list: max rows (default 32, cap 128).
    pub limit: Option<u32>,
    /// list: skip this many matches first (pagination cursor).
    pub offset: Option<u32>,
}

#[derive(…)] #[serde(rename_all = "lowercase")]
pub enum SymbolsAction { Load, List, Free }
#[derive(…)] #[serde(rename_all = "lowercase")]
pub enum SymListKind { Code, Data, All }

#[derive(Debug, Serialize, JsonSchema)]
pub struct SymbolsOutput {
    pub action: String,
    /// load: what happened.
    #[serde(skip_serializing_if = "Option::is_none")]
    pub loaded: Option<LoadedOut>,
    /// list: the matching rows (capped).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub symbols: Option<Vec<SymbolOut>>,
    /// list: total matches before limit/offset (so the agent knows to
    /// narrow `find` instead of paging a 4000-symbol table).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub total_matches: Option<usize>,
    pub state: String,                        // session state name
}

#[derive(Debug, Serialize, JsonSchema)]
pub struct LoadedOut {
    pub source: String,                       // "prg:/…" | "file:/…"
    pub total: u32,                           // Hatari's count (authority)
    pub text_symbols: u32,                    // Hatari's TEXT count
    /// Section bases used ("$70000" display form). Auto-detected from the
    /// GEMDOS basepage unless explicit offsets were given.
    pub text_base: String, pub data_base: String, pub bss_base: String,
    pub base_source: String,                  // "basepage" | "explicit" | "hatari"
    /// Server-side mirror for `list` — false + note when the mirror could
    /// not be built (a.out table, unreadable file…). Resolution via names
    /// still works when Hatari loaded the table.
    pub listable: bool,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub note: Option<String>,
}

#[derive(Debug, Serialize, JsonSchema)]
pub struct SymbolOut { pub addr: String, pub kind: SymKind, pub name: String }
```

Caps: `LIST_DEFAULT: u32 = 32`, `LIST_MAX: u32 = 128` (the `disasm`
convention). List is pure over the store: filter (case-insensitive
substring on name) → sort (code/data: by addr over that kind subset; all:
by name) → skip `offset` → take `limit` → `total_matches` = count before
skip/take. Names containing `.`/`-` are listed as-is (they are real
symbols) — no flag; §2.1's reachability caveat goes in the tool
description, not per-row.

### 7.2 Load choreography (`src/tools/symbols.rs`)

Tool description (`#[tool(name = "symbols", description = …)]`), verbatim:

> Register a symbol map so profile/disasm/breakpoint accept label names
> (BlitSphere) instead of addresses. action=load with no path loads the
> running GEMDOS-HD program's own symbol table (vasm -Ftos embeds one
> unless -nosym) — Hatari relocates it to the real load address
> automatically. action=load with path loads an nm-style ASCII map
> ("70000 T main" lines) — the TEXT/DATA/BSS offsets are auto-detected
> from the GEMDOS basepage, or given explicitly via text_offset/… — or a
> symbol-bearing .PRG file. action=list browses the loaded map
> server-side (find= substring filter, capped — narrow with find rather
> than paging); action=free unloads. Symbol names in expressions are
> [A-Za-z0-9_] (names with '.'/'-' load but cannot be referenced).
> Registers/variables (a0, pc, VBL, TEXT) shadow same-named symbols.

`action=load` steps (all under one `self.session.lock().await`; any live
state — the existing `wrong_state(name, "running or paused")` gate via
`guard.process_mut()`):

1. Validate args: `text_offset`/`data_offset`/`bss_offset` present without
   `path` ⇒ `invalid_params("offsets apply to ASCII symbol files — pass \
   path")`. `data_offset`/`bss_offset` without `text_offset` ⇒
   `invalid_params("data/bss offsets require text_offset")`.
2. If `path` given: validate — absolute, exists, regular file (follow the
   `save_prg_wire::validate_paths` read-side precedent). Read the first 2
   bytes: `0x60 0x1A` ⇒ PRG-binary source; else ASCII source. Explicit
   offsets + PRG-binary ⇒ `invalid_params("this file is a GEMDOS program — \
   Hatari relocates its symbol table to the current basepage; offsets \
   apply to ASCII maps only")`.
3. Determine bases:
   - explicit: `parse_addr` each; missing D/B default to the TEXT offset
     value (Hatari's own defaulting, made explicit); `base_source="explicit"`.
   - otherwise: `debug::basepage::current_basepage(proc, proc.config().ram_len())`
     (the `save_prg.rs` call shape) → `[text_base, data_base, bss_base]`,
     `base_source="basepage"`. Map its `Error::Session("no GEMDOS process…")`
     to `invalid_params` with: "no GEMDOS process is running — pass \
     text_offset explicitly, or start the program first".
   - PRG sources don't need bases for HATARI (it self-relocates,
     `base_source="hatari"`), but DO need them for the store mirror: run
     basepage discovery anyway; if it fails, proceed with `listable:false`
     + note (Hatari will fail its own load too if there's truly no
     basepage — its error wins).
4. Send the load (§5): `load_prg` / `load_prg_file` / `load_file`.
   `SymbolLoad::NoSymbols` ⇒ `Ok` output with `loaded.total=0`,
   `listable:false`, note `"program has no symbol table (build without \
   -nosym, or supply an ASCII map via path)"` — NOT an MCP error (ADR-8).
5. Build the store mirror:
   - prg (no path): host path from `SymbolsLoaded::source_path`; if `None`
     or unreadable ⇒ `listable:false` + note, skip mirror.
   - PRG file: `prg_file::read_prg_file` → `prg_symbols::parse_dri(bases)`;
     `DriError::NotDri` ⇒ `listable:false`, note "non-DRI symbol table \
     (a.out/ELF): names resolve, listing unavailable"; other errors ⇒
     `listable:false` + note (Hatari load already succeeded — do not fail).
   - ASCII: `tokio::fs::read_to_string` → `parse_ascii_map(text, bases)`.
6. Store `Some(SymbolStore{…})` (std-Mutex lock, non-await section — the
   `last_scan` discipline) — or `None` on mirror failure.
7. Output per §7.1. `total`/`text_symbols` come from HATARI's Loaded line
   (the authority), not from our mirror.

`action=list`: no session access, no state gate (works even Stopped —
the store outlives a paused inspection session deliberately; state is
reported). Store `None` ⇒ `invalid_request("no symbol map registered — \
run symbols(action=\"load\") first; Hatari-autoloaded symbols are usable \
in expressions but not listable")`.

`action=free`: needs live proc; `debug::symbols::free(proc)` then clear the
store. Output `state` as usual.

### 7.5 `lifecycle.rs` — store lifetime

In `stop`: after the session shutdown succeeds, `*self.symbols.lock() = None;`
(Hatari's table died with the process; a stale mirror must not answer
`list`). `start` needs no change (store can only be Some after a load).
Keep it to those lines; do not refactor lifecycle.

## 8. The three consuming tools

### 8.1 `disasm` (`src/tools/analyze.rs`)

Today: `parse_even_addr(&a.addr)?` before the session lock. Change to:
acquire the lock + `proc` first (unchanged code below it), then
`let addr = resolve_even_addr(proc, &a.addr).await?;`. Delete
`parse_even_addr` **only if** nothing else uses it (grep; `patch` readback
uses its own path — verify). Keep the even-address error message identical.
Description: append "addr accepts a symbol name once a map is loaded
(symbols tool)".

### 8.2 `profile` (`src/tools/analyze_profile.rs`)

Move `from`/`to` resolution after `self.session.lock().await`:

```rust
let mut guard = self.session.lock().await;
let (from, to) = {
    let name = guard.state_name();
    let proc = guard.process_mut().ok_or_else(|| wrong_state(name, "running or paused"))?;
    (resolve_addr(proc, &a.from).await?, resolve_addr(proc, &a.to).await?)
};
validate_range(from, to)?;
```

`run_profile` and everything below is untouched (conditions are still built
numerically: `pc = ${:x}` — the `Fire::Fired { pc }` equality check is
unaffected). `validate_range` unchanged — `to <= from` on two labels gives
the same actionable message. Description + `ProfileArgs` doc comments:
mention label names. Note the wrong-state check now happens before arg
validation (a stopped session reports `wrong_state` rather than
`invalid_params` for garbage args) — acceptable, do not contort the code
to preserve the old ordering.

### 8.3 `breakpoint` (`src/tools/breakpoint.rs`)

NO resolution plumbing (§2.6 — Hatari resolves names in `b` conditions
itself, at arm time). Two changes only:

1. Description: append "Conditions accept symbol names once a map is
   loaded: pc = BlitSphere (symbols tool)."
2. In `breakpoint_set`, wrap the `managed::run_to_breakpoint` error: if it
   is `Error::Parse` and `input` contains `invalid variable/register/symbol
   name`, return `invalid_params` appending " — if this is a label, load \
   the symbol map first: symbols(action=\"load\")" instead of the generic
   `to_mcp` internal error. Small private fn `arm_hint(e: Error) -> McpError`,
   unit-tested.

```markdown
## 2026-07-11 — ADR-42: Symbol-aware addressing — Hatari resolves, the server lists

**Status:** accepted
**Context:** TOS relocates GEMDOS-launched programs, so demo developers
hand-computed label addresses (MCP_TODOS §2). Hatari v2.4.1 already loads
DRI/GST symbol tables (autoload on debugger entry, `symbols prg`/`symbols
<file> [T [D B]]`) and resolves bare names in `evaluate` expressions and
`b` conditions (evaluate.c getValue; breakcond.c ParseValue — both verified
at the v2.4.1 tag). What was missing: an MCP surface, auto-detected section
bases, and label names in tools.
**Decision:** (1) One grouped `symbols` tool (load/list/free). (2) Hatari
is the ONLY name→address authority: `resolve_addr` = `Addr::parse` first
(numbers are never reinterpreted — strict superset of the old behavior),
then `evaluate <name>` on parse failure. (3) Listing is served from a
Rust-side mirror parsed from the same file with the same offset rules —
Hatari's own `symbols name|code|data` is FORBIDDEN on the wire because
v2.4.1's Symbols_Show pages via fgets(stdin) every ~20 rows, which
deadlocks the main loop (Running) or corrupts the stdin control plane
(Paused); new grep-gate. (4) Auto base = existing `debug::basepage`
(ADR-31) feeding explicit `$hex` T/D/B offsets; PRG sources are relocated
by Hatari itself against the same basepage. (5) Blast radius: exactly
profile/disasm/breakpoint take names (breakpoint needed zero plumbing —
Hatari's breakcond resolves at arm time); widening other tools is a
mechanical `parse_addr`→`resolve_addr` swap left for demand. (6) vasm `-L`
listings are NOT ingestible (Hatari accepts nm-ASCII or in-PRG tables
only); vasm -Ftos embeds a DRI table by default, so the primary workflow
needs no extra files.
**Alternatives considered:** resolving from the server-side store (rejected:
dual authority drifts from autoload/free/program-exit); generating a Hatari
config file to raise nSymbolLines and use native listing (rejected: touches
global spawn behavior to work around a listing we can serve better
ourselves); symbol support in all ~15 address-taking tools (rejected:
blast radius, and the seam makes later widening one line per tool).
**Consequences:** label workflows cost one extra `evaluate` round-trip per
name; a name that is also a register/variable (a0, VBL, TEXT) resolves to
the register — documented, matches native debugger behavior; names outside
[A-Za-z0-9_] load but cannot be referenced (Hatari's tokenizer, not ours);
the store must be cleared on stop/free or `list` lies.
```
