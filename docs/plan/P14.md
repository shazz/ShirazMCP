## 1. Deliverable in one sentence

Three RE primitives from the live-patch exercise: a **`watch`** tool that
arms a managed one-shot *value-change* breakpoint on a memory location, runs
until code changes it, and reports the PC (and a best-effort decode of the
writing instruction); an **`xrefs`** tool that statically scans a RAM
snapshot for instructions whose operands reference a target address
(abs.l / abs.w / d16(pc) / d8(pc,ix)); and a **`run_frames`** tool that runs
the machine for exactly N VBL frames (managed breakpoint on Hatari's `VBL`
variable) and leaves it frozen — all three riding the existing ADR-15
managed-breakpoint lifecycle, ending in a compile-time-known session state.

## 3. Pinned Hatari facts (from source; `// verify live` where unprobed)

### 3.1 THE key fact: Hatari has NO bus-access breakpoints — only value conditions

Read `breakcond.c` end to end before implementing. `BreakCond_MatchCpu()` is
called from `DebugCpu_Check()` (`debugcpu.c:1381`), which the CPU core calls
from `do_specialties` (`cpu/newcpu.c:5277`) **between instructions**. Every
condition is a *value* comparison (`BreakCond_GetValue` reads registers,
Hatari variables, or memory *at check time*); there is no hook on the
emulated bus. Consequences that shape this whole phase:

1. **A "write watch" is really a change watch.** The grammar's tracking form
   — identical indirect expressions on both sides with `!` — is the
   mechanism: `BreakCond_CheckTracking` (breakcond.c:1141) detects
   `lvalue == rvalue` with comparison `!`, snapshots the current memory
   value into the right side as a constant, and sets `condition->track`;
   the breakpoint then fires when the value at the address *differs from
   the snapshot*. A write that stores the **same value is invisible**; two
   writes between checks (impossible on the CPU side — checks are
   per-instruction — but possible from DMA/blitter) report only the net
   change.
2. **A read watch is impossible.** Reads change no value; nothing in
   breakcond.c (or debugcpu.c, or the remote-debug path) observes them.
   The `watch` tool therefore accepts **only `on="write"`** (schema-level:
   the enum has one variant), and its description points read questions at
   `xrefs` — the static answer to "who reads this?". Do not fake a read
   watch; do not add an `on="read"` that errors at runtime.
3. **The hit PC is the instruction AFTER the writer.** `DebugCpu_Check`
   runs after the previous instruction completed; at debugger entry the
   reported PC is the *next* instruction to execute. The writing
   instruction is (almost always) the one whose bytes **end at** the
   reported PC — recovered by §6.2's `writer_at` backward decode. Caveat,
   comment it in code: `do_specialties` dispatches pending interrupts
   *before* calling `DebugCpu_Check`, so if an interrupt lands on exactly
   the same boundary the PC is the handler entry and the backscan finds
   nothing / garbage — `writer` is best-effort, `None` is a normal outcome.
4. **Per-instruction cost while armed.** Any active condition breakpoint
   sets `SPCFLAG_DEBUGGER`, so the core calls `DebugCpu_Check` (and one ST
   memory read for the tracked value) after **every instruction**.
   Emulation slows noticeably while a watch is armed; bounded by
   `timeout_ms`, and the managed lifecycle guarantees nothing stays armed
   afterwards. Say so in the tool description.
5. **The debugger itself reads the watched address every instruction**
   (`BreakCond_ReadSTMemory` → `STMemory_ReadWord` etc.). Watching a
   hardware register with read side effects (ACIA data, some MFP/DMA regs)
   perturbs the machine. Palette/video registers are safe. One warning
   sentence in the tool description.
6. **Arm-time validation is Hatari's.** `BreakCond_CheckAddress` rejects
   addresses outside RAM/ROM/IO with an `ERROR:` line — which
   `bp::arm_once`'s existing `parse_armed` already surfaces as
   `Error::Parse`; the tool maps it to `invalid_params` (§8).

### 3.2 Watch wire strings (condition grammar per breakcond.c)

The condition the server sends for `watch(addr, len)` — widths map
`1→b, 2→w, 4→l`:

```
b ($<addr>).w ! ($<addr>).w :once          (len=2 form; .b/.l analogous)
```

Address rendering rule (pinned): addresses `>= $FF0000` are written
sign-extended to 32 bits (`$ffff8240`), lower addresses as bare hex
(`$2d645`) — matching how Hatari's own examples and the P8 assembly goldens
write ST bus addresses. `// verify live` that `($ff8240)` unextended would
also work — we don't rely on it either way.

Expected add echo (P2 §3.1 shape + breakcond.c's tokenizer, which
space-separates every `( ) . & = ! < >` token — trace:
`BreakCond_TokenizeExpression`):

```
> b ($2d645).w ! ($2d645).w :once
CPU condition breakpoint 2 with 1 condition(s) added:
	( $2d645 ) . w ! ( $2d645 ) . w
-> Break only once, and delete breakpoint afterwards.
-> Track value changes, show value(s) when matched.
```

The TAB-indented normalized expression is what `bp::Armed.expression`
captures (existing parser, unchanged — it takes the line after the
`CPU condition breakpoint N …` header and ignores the `->` lines). The exact
normalized spacing is derived from the tokenizer source, `// verify live`
**— confirmed live** (2026-07-10, real `watch($470E8, len 4)` against the
MJJ demo): dot-spaced tokens exactly as pinned, e.g.
`( $470e8 ) . l ! ( $470e8 ) . l :once`. **(amended note)** `-> Track value
changes, show value(s) when matched.` is ARM-ECHO text only — a separate
exchange from the fire block, and `bp::Armed` (by design, unchanged since
P2) discards the raw arm-echo text after parsing index+expression, so this
line is never available inside `watch`'s `output` field; §9.4 item 6's
phrasing ("the arm echo contains... and the fire block contains...") was
correct on this point, but is easy to misread as one block — split out
explicitly here to prevent that.

Fire block (ordering from `BreakCond_MatchConditions` →
`BreakCond_UpdateTracked`, which prints **before** `BreakCond_MatchBreakPoints`
prints the match header — `// verify live` the ordering **— confirmed live**:
the tracking value line prints first, exactly as pinned):

```
  $2d645 = $4d41
2. CPU breakpoint condition(s) matched 1 times.
	( $2d645 ) . w ! ( $2d645 ) . w :once
Removed CPU breakpoint 2:
	( $2d645 ) . w ! ( $2d645 ) . w :once
<debugger entry banner as P2 §3.2>
```

The `  $<addr> = $<newvalue>` track line (breakcond.c:253,
`fprintf("  $%x = $%x\n", …)`, lowercase unpadded hex) is informational —
the tool does **not** parse it (it travels inside `output` for the agent);
old/new values are read directly (§7.1 steps 3/8), which is exact because
both reads happen while the CPU is parked.

`fired_expression` matching in `managed::handle_fired` works unchanged: the
fire TAB line is `armed.expression + " :once"` — the same normalized string
Hatari echoed at add time. No normalization logic is needed server-side.

### 3.3 VBL counting for `run_frames` (vars.c + evaluate.c)

- `vars.c:202` — `{ "VBL", (uint32_t*)&nVBLs, VALUE_TYPE_VAR32, …,
  "number of VBL interrupts" }`: a monotonically increasing u32 frame
  counter, usable in `b` conditions (`BreakCond_ParseVariable` →
  `Vars_ParseVariable`).
- `evaluate.c` `getValue` tries `Vars_GetVariableValue(name, …)` first —
  so **`evaluate VBL` returns the current frame count** through the
  existing `debug::evaluate` wrapper (same `= #N (dec), $n (hex)` output
  shape `parse_evaluate` already handles). `// verify live` **— confirmed
  live** (2026-07-10, `run_frames(3)` then `run_frames(1)` chained against
  the MJJ demo): `vbl_after == vbl_before + frames` exactly on both calls,
  `completed: true`, session ends Paused each time — no amendment needed.
- The frame condition (decimal rvalue — the debugger's default number base
  is decimal, ADR-22): armed while frozen at current count `cur`,

  ```
  b VBL > <cur + n - 1> :once
  ```

  `>` rather than `=` so a hypothetical skipped check can never miss the
  boundary. The condition is checked per instruction once armed; `nVBLs`
  increments once per frame in the VBL interrupt handler, so the fire lands
  on the first instruction boundary after the n-th VBL — **exactly n frames
  after resume**, deterministic in frame count (the frozen PC is wherever
  the CPU was at that boundary; frame-deterministic, not PC-deterministic).
- Expected add echo expression: `VBL > 35938` (normalized, `>` spaced) —
  fits the existing `parse_armed`.

Facts this pins for §6.3:

- **pc-relative operands print the RESOLVED target** (`$20010(pc)` =
  insn addr + 2 + d16), including the indexed form's base
  (`$20012(pc, d0.w)`). No displacement arithmetic is needed at match time —
  only at candidate-generation time (§6.2).
- abs.w prints the **raw unextended 16-bit value** (`$8240.w`, not
  `$ffff8240.w`) — the resolver sign-extends.
- abs.l prints the full stored 32-bit value (`$47250.l`); code that writes
  `$FFFF8240` prints `$ffff8240.l` (P2 §6.2's pinned first row).
- Operands are `", "`-separated — but the pc-indexed form contains `", "`
  *inside* parentheses, so the splitter must be paren-depth-aware (§6.3).
- Immediates print with `#` prefix (`#$deadbeef`) — must not match.

## 4. Design decisions (already made — do not revisit)

1. **`watch` and `run_frames` are separate tools, not `breakpoint` actions.**
   Precedent: `profile` (P2) is also "managed run-to-break plus sugar" and is
   its own tool. Both have typed params (`addr`/`len`, `frames`) and typed
   results (old/new value, writer decode, VBL counts) that would bloat the
   raw-condition `breakpoint` tool's schema; `breakpoint` stays the
   raw-Hatari-syntax surface. `xrefs` is a third tool (pure analysis).
   Total surface: +3 tools, each lean.
2. **`watch` semantics are honest**: it is a *change* watch (§3.1). The tool
   is still named `watch` (the freezer-cartridge verb) but every description
   and field says "value change".
3. **One watched location per call** — width 1/2/4 from `len`. Hatari's
   condition grammar has only `&&` (no OR), so a multi-word range would need
   N independent breakpoints and a generalized disarm choreography; out of
   scope (§11). For "watch this 32-byte palette", watch its first word —
   wholesale rewrites touch it.
4. **`xrefs` covers abs.l, abs.w, d16(pc), d8(pc,ix)** — the addressing
   modes that statically resolve to an address. Register-indirect modes
   (`(a0)`, `d16(a0)`) are dynamically resolved and explicitly out of scope;
   the tool description says "for register-indirect consumers, use watch".
5. **Layering:** `analyze/xrefs.rs` is pure over `MemImage` (unit-testable
   without Hatari, like all of `analyze/`); the tools acquire snapshots via
   `session::memory` and stay choreography-only. `ripper/` untouched.

## 5. `tools/managed.rs` — two additive changes (no behavioral change to existing callers)

### 5.1 `Fire::Fired` gains `ours: bool`

`handle_fired` already computes whether the fired expression was the managed
one (to decide whether to disarm); surface that fact instead of discarding
it — `watch`/`run_frames` need "did MY breakpoint fire, or a foreign one?":

```rust
pub(crate) enum Fire {
    /// Frozen at the breakpoint; `pc` read post-freeze; `output` = the
    /// debugger-entry block (protocol-stripped); `ours` = the fired
    /// expression matched the condition this call armed (false ⇒ a foreign
    /// breakpoint fired first; ours was disarmed).
    Fired { pc: u32, output: String, ours: bool },
    TimedOut,
}
```

In `handle_fired`: compute `let ours = bp::fired_expression(&output)
.as_deref() == Some(ours_str.as_str());` once, branch the disarm on `!ours`,
include it in the variant. `tools/breakpoint.rs::set_output` destructures
`Fire::Fired { pc, output, ours: _ }` (its output schema is unchanged).

### 5.2 `ensure_paused` — freeze-then-re-seat helper

`watch` must read the old value, and `run_frames` the current VBL, *while
frozen and before arming*. Add next to `freeze_if_needed` (which stays
private):

```rust
/// Freeze a Running session and re-seat the guard as Paused (no-op when
/// already Paused; Stopped errors) so a caller can do preparatory frozen
/// reads before a `run_to_breakpoint` — which will then find the session
/// already Paused. Deliberate semantic drift, documented here: because the
/// original Running-ness is forgotten, a subsequent arm failure leaves the
/// session Paused instead of restored-to-Running. Every caller reports the
/// true session state in its output, and `resume` recovers.
pub(super) async fn ensure_paused(guard: &mut AnySession) -> Result<()> {
    let (paused, _was_running) = freeze_if_needed(guard).await?;
    *guard = AnySession::Paused(paused);
    Ok(())
}
```

Both changes keep `managed.rs` under 200 non-test lines (it is 173 today).
No change to `session/`, `debug/breakpoint.rs`, or the fifo layer — the
existing `b`-grammar wrappers and the ADR-15/21 freeze machinery carry P14
as-is (`arm_once` sends arbitrary conditions; `parse_armed`/`parse_list`/
`fired_expression` tolerate the watch/VBL expressions per §3.2/§3.3).

### 6.2 `src/analyze/xrefs.rs` — candidate scan + confirm decode + writer backscan

```rust
//! Static data cross-references over a `MemImage` (P14): which
//! instructions reference a target address via statically-resolvable
//! addressing modes (abs.l / abs.w / d16(pc) / d8(pc,ix)). Pure over
//! `types` + `analyze::disasm` — never touches the emulator. Register-
//! indirect references are invisible to this scan by design (use the
//! watch tool for those).

use crate::analyze::disasm::{self, Insn};
use crate::error::Result;
use crate::types::{Addr, MemImage};
use crate::analyze::xrefs_ops::{classify, resolve_operands, RefAccess, RefMode};

/// Hard cap on candidate extension-word offsets examined per scan — low
/// targets (e.g. $4C6) alias ordinary data everywhere; the cap bounds the
/// confirm-decode cost. Exceeding it sets `candidates_capped`.
pub const XREFS_CANDIDATE_CAP: usize = 4096;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Xref {
    pub insn: Insn,
    /// The resolved operand address that fell inside the target range.
    pub ref_addr: Addr,
    pub mode: RefMode,
    pub access: RefAccess,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct XrefScan {
    /// Sorted by insn addr, deduplicated, truncated to `limit`.
    pub hits: Vec<Xref>,
    /// More hits existed than `limit`.
    pub truncated: bool,
    /// The candidate pass hit XREFS_CANDIDATE_CAP — results may be partial.
    pub candidates_capped: bool,
}

/// Scan `[from, from + len)` of `mem` for instructions referencing any
/// address in `[target, target + target_len)`.
pub fn xrefs(
    mem: &MemImage, target: Addr, target_len: u32,
    from: Addr, len: usize, limit: usize,
) -> Result<XrefScan> { .. }

/// Best-effort identification of the instruction that ENDED at `pc` (the
/// watch tool's "who wrote it": §3.1 fact 3 — the hit PC is the
/// instruction after the writer). `references_target` = its operands
/// resolve into `[target, target + width)`.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct WriterGuess {
    pub insn: Insn,
    pub references_target: bool,
}

pub fn writer_at(mem: &MemImage, pc: Addr, target: Addr, width: u32) -> Option<WriterGuess> { .. }
```

**`xrefs` algorithm (exact):**

1. Clamp the scan window to the image: `start_off = from - mem.base()`
   (reject outside with the same `Error::Parse{context:"xrefs range"}` shape
   `disasm` uses), `end_off = min(start_off + len, mem.len())`.
2. **Candidate pass** — one linear walk over even offsets
   `o in (start_off..end_off).step_by(2)` (extension words of even-aligned
   instructions are even-aligned). Let `t0 = target.raw()`,
   `t1 = t0 + target_len` and `in_range(a) = (t0..t1).contains(&(a & 0xFF_FFFF))`.
   At each `o` push `(o, expected_mode)` candidates:
   - **AbsL** (needs `o + 4 <= end_off`): `w32 = BE u32 at o`; candidate iff
     `(w32 >> 24 == 0x00 || w32 >> 24 == 0xFF) && in_range(w32)` (both the
     `$00047250` and sign-extended `$FFFF8240` spellings of a 24-bit bus
     address).
   - **AbsW**: `w16 = BE u16 at o`; candidate iff
     `in_range(w16 as i16 as i32 as u32)`.
   - **PcDisp**: candidate iff
     `in_range((mem.base().raw() + o as u32).wrapping_add_signed((w16 as i16).into()))`
     — 68000 d16(pc) is relative to the extension word's own address.
   - **PcIdx** (brief extension format gate — bits 10..8 must be 0 on the
     68000): iff `w16 & 0x0700 == 0` and
     `in_range((mem.base().raw() + o as u32).wrapping_add_signed(((w16 & 0xFF) as u8 as i8).into()))`.
   Stop collecting at `XREFS_CANDIDATE_CAP` (set `candidates_capped`).
3. **Confirm pass** — for each candidate `(o, expected)`, try instruction
   starts `o - 2, o - 4, o - 6, o - 8` in that order (nearest first; skip
   starts below offset 0 — image bounds, not window bounds: an instruction
   may begin before `from`). At each start: `disasm(mem, base + start, 1)`
   → one `Insn`; accept iff the decode covers the extension word
   (`start + insn.bytes.len() >= o + ext_width`, ext_width 4 for AbsL else
   2) AND `resolve_operands(&insn)` (§6.3) yields some
   `(ref_addr, mode, op_index)` with `mode == expected` and
   `in_range(ref_addr)`. First accepting start wins; build
   `Xref { insn, ref_addr, mode, access: classify(&insn, op_index, n_ops) }`.
   Nearest-first can, on pathological byte patterns, decode a *suffix* of
   the true instruction that still prints the same operand — the reference
   is still reported, at a slightly-wrong insn addr; accepted limitation
   (same class as ADR-16's candidate−{2,4,6} confirm), comment it.
4. Deduplicate by `insn.addr` (`BTreeMap<u32, Xref>` — keeps sorted order
   for free), truncate to `limit` (set `truncated`), return.

**`writer_at` algorithm (exact):** for `delta in [2, 4, 6, 8, 10]`
(`MAX_INSN_LEN`), `start = pc - delta` (skip if below `mem.base()`):
`disasm(mem, start, 1)`; keep as candidate iff
`start + insn.bytes.len() == pc` (ends exactly at the parked PC). Return the
first candidate (in delta order) whose `resolve_operands` hits
`[target, target + width)` with `references_target = true`; if none
references the target, return the first candidate found with
`references_target = false`; else `None`. (A writer using `(a0)`-style
indirection produces the `false` case — still almost always the right
instruction; an interrupt on the boundary produces `None` or garbage — §3.1
fact 3's caveat, which is why this is labelled a guess.)

Both functions ≤ 30 lines by delegating the candidate pass and the confirm
step to private helpers (`push_candidates(o, …)`, `confirm(o, expected)` —
each ≤ 30 lines).

### 6.3 `src/analyze/xrefs_ops.rs` — operand token resolution (pure, fixture-pinned by §3.4)

```rust
//! Capstone M68K op_str token resolution for xrefs/writer_at. The exact
//! output grammar is pinned in P14.md §3.4 (compiled-spike capture).

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RefMode { AbsL, AbsW, PcDisp, PcIdx }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RefAccess { Read, Write, Ea, Exec }

/// Split an op_str on ", " at parenthesis depth 0 — `$20012(pc, d0.w), a0`
/// is TWO operands.
pub(crate) fn split_operands(ops: &str) -> Vec<&str>;

/// All statically-resolvable address references in one instruction:
/// (24-bit bus address, mode, operand index). Rules — an operand resolves
/// iff it starts with '$' followed by 1..=8 hex digits and then exactly:
///   ".l"          → AbsL,  addr = value & 0xFF_FFFF
///   ".w"          → AbsW,  addr = (value as u16 as i16) sign-extended,
///                          & 0xFF_FFFF        (capstone prints raw 16-bit)
///   "(pc)"        → PcDisp, addr = value & 0xFF_FFFF   (capstone already
///                          resolved the displacement — §3.4)
///   "(pc, …)"     → PcIdx,  addr = printed base & 0xFF_FFFF (runtime
///                          target adds the index register)
/// Anything else — registers, "#$…" immediates, "(a0)"-family — yields
/// nothing.
pub(crate) fn resolve_operands(insn: &Insn) -> Vec<(u32, RefMode, usize)>;

/// Access classification, pinned:
///   mnemonic starts with "lea" or "pea"        → Ea
///   mnemonic (before any '.') is "jsr" or "jmp" → Exec
///   op_index < n_ops - 1                        → Read   (source position)
///   last operand, mnemonic base in
///     {"cmp","cmpa","cmpi","cmpm","btst","tst","chk"} → Read
///   last operand otherwise                      → Write  (includes RMW:
///     addq/clr/bset/asl-mem etc. — "who writes this" is the question)
pub(crate) fn classify(insn: &Insn, op_index: usize, n_ops: usize) -> RefAccess;
```

`mnemonic base` = the substring before the first `'.'` (`move.w` → `move`,
`jsr` → `jsr`). Hex parse via `u32::from_str_radix(.., 16)`; a 9+-digit or
malformed token yields nothing (never an error — resolution is a filter).

### 7.1 `src/tools/watch.rs` — the `watch` tool

```rust
    /// observes VALUES, not bus cycles — this fires when the value CHANGES
    /// (a write of the identical value is invisible; reads are never

pub struct WatchOutput {
    /// Did the watch fire within the budget?
    pub fired: bool,
    /// true = the fired breakpoint was THIS watch; false = a foreign
    /// breakpoint fired first (its report is in `output`; the watch was
    /// disarmed).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub ours: Option<bool>,
    pub addr: String,          // watched address, "$02D645" form
    pub len: u32,

    #[serde(skip_serializing_if = "Option::is_none")]

    /// PC at the freeze = the instruction AFTER the writer (fired only).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub pc: Option<String>,
    /// Best-effort decode of the writing instruction (the one ending at
    /// pc). exact=true ⇒ its operand resolves to the watched address.
    #[serde(skip_serializing_if = "Option::is_none")]
    pub writer: Option<WriterOut>,
    /// Debugger-entry block (fired only), capped like breakpoint's.
    #[serde(skip_serializing_if = "Option::is_none")]
    pub output: Option<String>,
    /// "paused" (fired) | "running" (timeout).
    pub state: String,
}

#[derive(Debug, Serialize, JsonSchema)]
pub struct WriterOut {
    pub addr: String,
    pub mnemonic: String,
    pub ops: String,
    pub bytes_hex: String,
    pub exact: bool,
}
```

(Args/outputs live in `watch_wire.rs` — §7.2; the tool file holds the
choreography.)

Tool method steps (each helper ≤ 30 lines):

1. Validate: `parse_addr` (reuse `tools::mem::scan::parse_addr`);
   `len = args.len.unwrap_or(2)`, must be 1|2|4 else
   `invalid_params("len must be 1, 2 or 4")`; widths 2/4 require even addr
   (`invalid_params("addr must be even for len 2/4")`);
   `addr.raw() + len <= 0x100_0000` else invalid_params. `on` defaults
   `Write` (the only variant — serde handles rejection of others).
2. Lock the session; `managed::ensure_paused(&mut guard)` (maps `Error` per
   §8 — "no live session" → `wrong_state`-equivalent internal mapping as
   managed already produces).
3. Read `old` while frozen: `debug::read_bytes(proc, addr, len)` → BE fold
   to u32 (proc via `guard.process_mut()`; cannot be None post-step 2).
4. Build the condition (`watch_wire::watch_condition(addr, len)` — §7.2)
   and `managed::run_to_breakpoint(&mut guard, &condition, timeout_ms)`.
5. `Fire::TimedOut` → output `{ fired:false, ours:None, old_value,
   state:"running" }` (managed already disarmed; session Running per
   ADR-15 semantics — same as `breakpoint(set)` timing out from Paused).
6. `Fire::Fired { pc, output, ours }`:
7. Read `new` while frozen (same as step 3).
8. Writer backscan: if `pc >= 10`, `memory::acquire_range(proc,
   Addr::new(pc - 10), 10)` → `analyze::writer_at(&mem, Addr::new(pc),
   addr, len)`; any acquisition/decode error → `writer: None` +
   `tracing::warn` (best effort, never fails the call).
9. Output `{ fired:true, ours:Some(ours), old_value, new_value, pc,
   writer, output: cap_output_tail(..), state:"paused" }`. **(amended per
   live run, ADR-28):** NOT `breakpoint_wire::cap_output` — that keeps the
   FIRST ~2 KiB, correct for `breakpoint(set)`'s near-instant conditions
   whose report sits at the head of a short string, but wrong for `watch`
   (and `run_frames`, same shape): a real-time wait accumulates control-
   plane FIFO-poll noise BEFORE the informative match-report block, which
   always arrives at the END of the captured text — head-capping silently
   discards it. `cap_output_tail` (keeps the LAST ~2 KiB, cutting at the
   first newline at-or-after the window start) lives in `watch_wire.rs`
   and is shared by `frames.rs`; `breakpoint_wire::cap_output` is
   untouched (see ADR-28).

Tool description (verbatim): *"Watch a memory location and run until its
VALUE CHANGES (managed one-shot; Hatari observes values not bus cycles — a
write of the same value is invisible, and reads are never observable: use
xrefs for 'who reads this'). Fires ⇒ session ends PAUSED with the PC that
hit — the instruction AFTER the writer — plus a best-effort decode of the
writing instruction; timeout ⇒ watch disarmed, session left RUNNING. This
answers 'which of N copies is live / who updates this?' directly. Emulation
runs slower while armed (per-instruction check). Watching hardware
registers whose reads have side effects (ACIA/MFP data regs) perturbs the
machine; palette/video registers are safe."*

### 7.3 `src/tools/frames.rs` — the `run_frames` tool (tool + wire, one file)

```rust
pub const FRAMES_MAX: u32 = 5_000;

#[derive(Debug, Deserialize, JsonSchema)]
pub struct RunFramesArgs {
    /// VBL frames to run (1..=5000).
    pub frames: u32,
    /// Wait budget, ms. Default 10000 + 40·frames (a 50 Hz frame is 20 ms
    /// at real speed; the default assumes ≤ half speed under an armed
    /// per-instruction check), capped at 600000.
    pub timeout_ms: Option<u64>,
}

#[derive(Debug, Serialize, JsonSchema)]
pub struct RunFramesOutput {
    pub requested: u32,
    /// true iff our VBL breakpoint fired and vbl_after == vbl_before + requested.
    pub completed: bool,
    pub vbl_before: u32,
    /// Absent on timeout (machine left running; the counter keeps moving).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub vbl_after: Option<u32>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub frames_run: Option<u32>,
    /// PC at the freeze (fired only) — frame-deterministic, not
    /// PC-deterministic (wherever the CPU was at the n-th VBL boundary).
    #[serde(skip_serializing_if = "Option::is_none")]
    pub pc: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub output: Option<String>,
    pub state: String,
}

/// "VBL > {cur + n - 1}" — decimal (debugger default base), §3.3.
pub(crate) fn vbl_condition(cur: u32, n: u32) -> String;

pub(crate) fn default_timeout(frames: u32) -> u64; // (10_000 + 40*frames).min(600_000)
```

Tool method steps:

1. `frames` in `1..=FRAMES_MAX` else invalid_params;
   `timeout = args.timeout_ms.unwrap_or_else(|| default_timeout(frames))`.
2. Lock; `managed::ensure_paused(&mut guard)`.
3. `vbl_before = debug::evaluate(proc, "VBL")?`; guard
   `vbl_before as u64 + frames as u64 <= u32::MAX as u64` (absurd but
   checked) else internal_error.
4. `managed::run_to_breakpoint(&mut guard, &vbl_condition(vbl_before, frames), timeout)`.
5. `TimedOut` → `{ completed:false, vbl_before, vbl_after:None, …,
   state:"running" }`.
6. `Fired { pc, output, ours }` → `vbl_after = debug::evaluate(proc, "VBL")?`
   (frozen — stable); `frames_run = vbl_after - vbl_before`;
   `completed = ours && frames_run == frames` (a foreign breakpoint firing
   mid-run yields `completed:false` with the evidence in `output`);
   `state:"paused"`.

Tool description (verbatim): *"Run the machine for exactly N VBL frames
(50 Hz), then freeze — deterministic frame stepping for animated/transient
states (no more poll-and-race to catch a scroller). Arms a managed one-shot
breakpoint on Hatari's VBL frame counter: session ends PAUSED exactly N
frames later (completed=true; pc is wherever the CPU was at that frame
boundary), or RUNNING on timeout with the breakpoint disarmed. Combine with
watch/machine_state/screenshot for reproducible before-after comparisons."*

### 7.4 `src/tools/xrefs.rs` — the `xrefs` tool

Steps:

1. Parse `addr` (`parse_addr`); `target_len = args.target_len.unwrap_or(2)`
   in `1..=64` else invalid_params; `from` = parsed or `Addr::new(0)`;
   `limit = args.limit.unwrap_or(32).min(128)`.
2. Lock; `guard.process_mut()` or `wrong_state(name, "running or paused")`.
   (Paused recommended for a stable snapshot; Running works — document in
   the description, same stance as `rip`.)
3. `mem = memory::acquire(proc)` (whole RAM, one savebin round-trip,
   ADR-9); `len = args.len.map(|l| l as usize).unwrap_or(mem.len())`.
4. `analyze::xrefs(&mem, target, target_len, from, len, limit as usize)` —
   map `Error::Parse` (bad range) to invalid_params, others `to_mcp`.
5. Map hits to `XrefOut` (§7.5); return.

Tool description (verbatim): *"Static data cross-references: scan a RAM
snapshot for instructions whose operands reference a target address —
answers 'what code reads/writes this table?' without running anything.
Covers absolute (abs.l/abs.w) and PC-relative (d16(pc), d8(pc,ix))
addressing; register-indirect consumers (movea.l ptr,a0 / (a0)) are
invisible to static scanning — use watch for those. target_len widens the
target to a range (e.g. 32 for a palette). access: read | write (includes
read-modify-write) | ea (address taken: lea/pea — the pointer escapes,
consider watch) | exec (jsr/jmp). Default 32 hits, max 128."*

## 8. Error mapping (unchanged taxonomy — no new variants)

| Failure | Wire error |
|---|---|
| no live session (`ensure_paused`/lock on Stopped) | `to_mcp(Error::Session)` — internal_error, as managed already produces for `breakpoint(set)` |
| wrong state for `xrefs` (Stopped) | `wrong_state(name, "running or paused")` |
| bad addr / len ∉ {1,2,4} / odd addr with len 2/4 / addr+len > 16 MiB / frames ∉ 1..=5000 / target_len ∉ 1..=64 / scan range outside image | `McpError::invalid_params(msg, None)` |
| Hatari rejected the watch condition (`ERROR:` on arm — unmapped address etc.) | surfaces as `Error::Parse{context:"breakpoint add"}` from `arm_once` → map to `invalid_params` with the ERROR line (match on that context in the watch tool, exactly as `breakpoint(set)` does today — read `tools/breakpoint.rs` first; if it maps via `to_mcp`, do the same for consistency) |
| fired-during-recovery race | managed's distinguished `Error::Session("… call pause to adopt …")` → `to_mcp` (unchanged) |
| writer backscan failure | NOT an error — `writer: None` + `tracing::warn` |
| everything else | `to_mcp` as today |

Session-state outcomes (pin in code comments): `watch`/`run_frames` fired ⇒
**Paused** at the hit; timeout ⇒ **Running**, managed condition disarmed;
arm failure after `ensure_paused` ⇒ **Paused** (§5.2's documented drift);
`xrefs` never changes state. `stateload` still clears all breakpoints
(P2 §3.6) — irrelevant here since nothing persists armed.

> ## 2026-07-10 — ADR-NN: Interactive RE primitives — change-watchpoints, static xrefs, VBL frame-stepping
>
> **Status:** accepted
> **Context:** The live-patch exercise (docs/live-patching.md §"What was
> missing") showed the tool surface forces "disassemble and reason" where a
> freezer cartridge should let you "ask the machine": which of N copies of
> a table is live (chased by hand through an indirect pointer), what code
> touches an address (hand-scanned disassembly), and catching animated
> state (poll-and-race `pause`). Reading Hatari's `breakcond.c` established
> the load-bearing constraint: Hatari has **no bus-access breakpoints** —
> its condition engine compares *values* at instruction boundaries
> (`DebugCpu_Check` in `do_specialties`), so a "write watch" is really a
> value-change watch (`(addr).w ! (addr).w` + tracking), a read watch is
> impossible, and the hit PC is the instruction *after* the writer.
> **Decision:** (1) `watch(addr, len)` = a managed `:once` change-tracking
> breakpoint riding ADR-15's run-to-breakpoint unchanged: ensure-paused →
> read old value frozen → arm → run → freeze reports hit-PC, new value, and
> a best-effort backward decode of the writing instruction (`writer_at`:
> the instruction ending at PC, preferring one whose operand resolves to
> the watched address). Only `on="write"` exists (schema-level); the
> description routes read questions to xrefs. (2) `xrefs(addr)` = pure
> analysis in `analyze/xrefs.rs`: a linear extension-word candidate scan
> (abs.l, abs.w, d16(pc), d8(pc,ix) arithmetic) confirmed by nearest-first
> single-instruction Capstone decodes (the ADR-16 pattern), classified
> read/write/ea/exec — static "who touches this", register-indirect
> consumers documented as invisible. (3) `run_frames(n)` = a managed `:once`
> breakpoint on Hatari's `VBL` frame counter (`b VBL > cur+n-1`), read via
> `evaluate VBL` while frozen — exactly n frames then Paused,
> frame-deterministic. (4) Surface: three separate tools (the `profile`
> precedent — typed params/results, `breakpoint` stays the raw-condition
> surface); `managed::Fire` gains `ours: bool`, and a `ensure_paused`
> helper freezes-then-reseats for pre-arm frozen reads, accepting one
> documented drift: an arm failure after it leaves the session Paused
> rather than restored-to-Running.
> **Alternatives considered:** patching Hatari for true access hooks
> (upstream-scale project; change-tracking answers the actual questions);
> emulating a read watch by single-stepping every instruction server-side
> (orders of magnitude too slow over the fifo); watch as a `breakpoint`
> action (schema bloat on the raw tool, against the profile precedent);
> xrefs by whole-image linear disassembly (stream-desync garbage — the
> candidate+confirm scan is ADR-16's proven shape); frame-stepping by
> polling `evaluate VBL` from Running (the exact poll-and-race the feature
> exists to kill); multi-word watch ranges (Hatari has no OR conditions —
> N-breakpoint choreography deferred).
> **Consequences:** "Which copy is live?" becomes one `watch` call instead
> of disassembly archaeology; same-value writes are invisible and DMA/
> blitter writes coalesce (documented); emulation slows while a watch is
> armed (per-instruction check + debugger memory read, bounded by
> timeout); watching read-side-effect hardware registers perturbs the
> machine (documented warning). xrefs misses register-indirect flow by
> design and can mis-address a hit by a few bytes on pathological suffix
> decodes (accepted, ADR-16 class). run_frames is frame-deterministic but
> not PC-deterministic. Nothing persists armed behind the FSM's back —
> every exit state is compile-time-known, preserving ADR-15's invariant.
