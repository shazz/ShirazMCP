**Why this phase exists:** the DHS "Uhane" demo run produced **45 "Degas
PI1/PI2" false positives** from `rip(kind=picture)` / `find_picture`. The
Degas header is structurally weak — a res word (0/1/2) plus 32 bytes that
pass `plausible_palette` (upper nibbles clear, ≥4 distinct words,
`src/ripper/image/mod.rs:129`) — so any RAM region containing a table of
small big-endian words (sine tables, palettes parked in data segments,
cleared-but-dirtied buffers) matches, and the 32000 bytes behind it decode as
planar noise. Reference decoders are no help here: RECOIL and the
Atari_ST_Sources authorities (`C/Warwick Grigg/C_series.5/DEGAS.C`) identify
Degas files by **filename extension + exact file length** — signals that do
not exist in a RAM scan. We therefore add what a file-based decoder never
needed: a **structural plausibility score over the decoded pixel data**, used
as (a) an accept/reject gate in the Degas detector, (b) a `confidence` value
surfaced on every picture `Finding`, and (c) a rank-and-cap so the agent sees
at most a handful of best-first candidates instead of 45.

---

## 1. Deliverable in one sentence

The Degas detector gates every PI/PC candidate on a **structure score**
computed from the decoded planar data (vertical/horizontal coherence, palette
usage, sampled byte entropy, dominant-color penalty), ranks its survivors by
a new `Finding.confidence: Option<u8>` (0–100) and caps them at 8 per buffer;
NeoChrome findings are annotated (not gated) with the same score; the wire
`FindingOut` carries `confidence` so the agent can compare candidates —
proven by unit scorers on synthetic planar bodies plus a new
`tests/picture_precision.rs` regression that models the Uhane noise and
asserts a planted real picture outranks it.

Facts the design leans on:

- `Degas::scan` walks even offsets, and **skips past accepted hits**
  (`o += (len+1) & !1`) — overlapping duplicates of one picture are already
  impossible. The 45 FPs are *distinct* gate-passing sites, not overlap noise.
- On a **rejected** candidate the walk advances 2 bytes, so gate cost per
  reject matters (§4.6 sizes it).
- `try_pi` already bounds-checks `o + PI_TOTAL <= bytes.len()` before the
  palette gate, so the screen slice `bytes[o+34..o+34+SCREEN_BYTES]` is
  always in bounds when scoring runs.
- Confidence precedent: `ym_player` embeds `confidence=` in the label
  (string, for humans); `bootsector` has a plugin-internal `confidence: f32`.
  Neither is machine-rankable at the `Finding` level — that is what the new
  field adds (ADR §12 states this).
- `Option<u8>` derives `Ord` with `None < Some(_)` — the rank sort exploits
  this (unscored findings sort last).

## 3. Design decisions (summarized; full ADR text in §12)

1. **Score over decoded pixels, in the `image` layer.** New pure module
   `src/ripper/image/score.rs`: functions over `(&[u8], ScreenRes)` only — no
   `Finding`, no engine imports. Keeps `image/` free of `ripper` types
   (current dependency direction preserved).
2. **Gate Degas, annotate NeoChrome, skip MPP.** Degas's header is weak →
   score is a hard gate + confidence. NEO's header is strong (six pinned
   geometry/flag words, ~2⁻⁴⁸ accidental-match) → confidence annotation only,
   no gate (also keeps its zero-body unit fixtures valid). MPP is
   magic-anchored with exact size math → untouched, `confidence: None`.
3. **Rank + cap inside the plugin, not the engine.** `Degas::scan` sorts its
   own findings confidence-descending and truncates to 8. The engine's
   documented ordering guarantee ("detectors in registration order") gains
   one clause: *within* one detector the order is plugin-defined. No global
   re-sort in `rip` — a cross-plugin sort would risk flipping
   `two_pictures_two_findings` on ties and complicate the `FindingId`
   ordering contract for zero benefit (the agent has `confidence` on the
   wire to compare across plugins).
4. **No dedupe pass.** Skip-past-hit already prevents overlapping duplicates;
   the cap absorbs the rest. (TODO.md's "dedupe near-identical offsets" is
   satisfied by these two mechanisms — say so in the ADR.)
5. **Confidence is `Option<u8>` 0–100 on `Finding`**, `None` = plugin doesn't
   score. Builder method `with_confidence`, not a `new` signature change —
   zero churn in the other nine detectors.
6. **No new dependencies.** All metrics are integer histograms + one `log2`.

Signals considered and **rejected** (record in ADR): cross-bitplane
correlation (real discriminating power, but ~4× the cost and hard to pin
thresholds without live data); content-hash dedupe (redundant, §3.4); global
confidence re-sort in the tool layer (§3.3); minimum-entropy gate (a blank
or two-color picture is legitimately near-zero entropy — the *used-colors*
and *dominance* signals handle degenerate bodies instead).

## 4. The scoring algorithm (exact)

All computation is over `screen: &[u8]` = exactly `SCREEN_BYTES` (32000)
interleaved-planar bytes, plus `res: ScreenRes`.

### 4.1 Sampled row metrics (indices)

Decode **25 sampled scanlines** to palette indices:
`step = res.height() as usize / 25` (= 8 for low/med, 16 for high); rows
`(0..height).step_by(step)`. Per row use `row_indices` (§6) — the same
bit-math as `decode_planar`, factored out, so there is exactly one planar
index decoder in the codebase.

From the sampled indices compute:

- `hist: [u32; 16]` — index histogram.
- `used_colors: u8` — count of non-zero histogram buckets.
- `dominance: f32` — `max(hist) / total` (share of the most common index).
- `h_coherence: f32` — over each sampled row, fraction of adjacent pixel
  pairs `(x, x+1)` with equal index (`windows(2)`), pooled across rows.
- `h_excess: f32` = `(h_coherence − 1.0 / (1 << planes) as f32).max(0.0)` —
  coherence **above the random baseline**. Baseline: uniform random planar
  data yields index-equality ≈ 1/2^planes (0.0625 low, 0.25 med, 0.5 high);
  without the subtraction, medium/high-res noise would look "coherent".

### 4.2 Vertical coherence (raw bytes)

```
v_coherence = max(match_ratio(bpl), match_ratio(2*bpl))
match_ratio(stride): fraction of k in (0..SCREEN_BYTES-stride).step_by(53)
                     with screen[k] == screen[k+stride]
```

`bpl = res.bytes_per_line()`. Rationale: real pictures repeat vertically
(flat areas, and 2×2 ordered dither repeats with period 2 lines — hence the
`2*bpl` arm, without which fully-dithered art scores zero). Random bytes
match at ≈ 1/256 ≈ 0.004. Stride 53 is prime and coprime to 160/320/80 — no
phase-lock with the line grid; ~600 samples per arm.

### 4.3 Sampled byte entropy

Shannon entropy in bits/byte over `screen[k]` for
`k in (0..SCREEN_BYTES).step_by(8)` (4000 samples, 256-bucket histogram).
Packed/random data measures ≈ 7.9 at this sample size; real planar screens
almost never exceed ~7.

### 4.4 Gates — `PictureScore::plausible()`

Reject (return `false`) iff ANY of:

| # | Rule | Kills |
|---|---|---|
| G1 | `used_colors < 2` | blank bodies — the classic "cleared VRAM behind a resident palette" FP |
| G2 | `v_coherence < 0.04 && h_excess < 0.05` | planar noise: data with no spatial structure at all (uniform random, most packed streams, code) — `// verify live` both thresholds against the Uhane RAM |
| G3 | `entropy > 7.5 && v_coherence < 0.10` | high-entropy packed data that slips G2 on a borderline h_excess — `// verify live` |

Deliberate asymmetry: there is **no minimum-entropy** and **no maximum
coherence** — a mostly-flat real picture must pass.

### 4.5 Confidence (0–100)

```
s_v   = min(v_coherence / 0.30, 1.0)
s_h   = min(h_excess    / 0.40, 1.0)
s_pal = min(used_colors as f32 / (1 << planes) as f32, 1.0)
blank_penalty = 1.0 - (max(dominance - 0.85, 0.0) / 0.15) * 0.6
confidence = round(100 * (0.40*s_v + 0.30*s_h + 0.30*s_pal) * blank_penalty)
             clamped to 0..=100, as u8
```

Pinned expectations (assert as **ranges** in tests, the formula may be
re-tuned after the live verification):

| Body | plausible | confidence |
|---|---|---|
| `bands` (graphics.rs fixture: 16 stripes, all colors) | yes | ≥ 95 |
| half-0xFF / half-0x00 lines (§9 unit fixture) | yes | 60..=90 (analytic ≈ 74) |
| 2-line checkerboard dither | yes | 30..=60 (v-arm only) |
| all-zero (blank) | **no** (G1) | — |
| uniform random (xorshift) | **no** (G2, G3) | — |
| ~98%-one-color junk | passes gates | ≤ 60 (blank_penalty ×0.4) |

### 4.6 Cost envelope (why no staged gate)

Score cost per candidate ≈ 25 rows × width index-decode + 1200 v-samples +
4000 entropy samples ≈ 20k ops. It runs only on candidates that pass
`plausible_palette`. Evidence from the real run: 45 candidates in a full
RAM scan → sub-millisecond added. Adversarial worst case (RAM full of
sine-table-like small words: every even offset passes the palette gate) is a
few tens of ms per 64 KiB in release — acceptable; do **not** add a staged
cheap-gate or memoization (flagged as premature). Leave one comment in
`score.rs` stating this budget. `// verify live`: whole-RAM Uhane rip stays
under 1 s.

## 6. `src/ripper/image/render.rs` — factor the index decoder (MOD)

Add, and rewrite `decode_planar`'s inner loop to call it (behavior-identical
— the goldens in `tests/graphics.rs` and `render.rs`'s own unit tests are
the proof):

```rust
/// Decode one interleaved scanline to palette indices, appending to `out`.
/// `line` must be exactly `res.bytes_per_line()` bytes — callers slice.
/// The single planar→index bit-math in the codebase; `decode_planar` and
/// `image::score` both build on it.
pub(crate) fn row_indices(line: &[u8], res: ScreenRes, out: &mut Vec<u8>) {
    let planes = res.planes();
    for group in 0..res.width() as usize / 16 {
        let words = group_words(line, group, planes);
        for p in 0..16 {
            let mut idx = 0u8;
            for (pl, w) in words[..planes].iter().enumerate() {
                idx |= (((w >> (15 - p)) & 1) as u8) << pl;
            }
            out.push(idx);
        }
    }
}
```

`decode_planar` keeps its signature and its short-input `Error::Parse`; its
per-row body becomes: clear a reused `Vec<u8>` (allocated once,
`with_capacity(res.width() as usize)`), call `row_indices`, then
`put_pixel(x, y, Rgba(pal.color(idx)))` per index.

`Implementation note:` if the reuse makes `decode_planar` exceed 30 lines,
extract a `fn paint_row(img, y, indices, pal)` helper — do not inline the
bit-math back.

```rust
use super::{render::row_indices, ScreenRes, SCREEN_BYTES};

/// Structural plausibility of 32000 bytes as an ST planar picture (§P21.4).
#[derive(Debug, Clone, Copy)]
pub struct PictureScore {
    /// 0-100 composite (§P21.4.5) — what `Finding.confidence` carries.
    pub confidence: u8,
    /// Distinct palette indices in the sampled rows.
    pub used_colors: u8,
    /// Horizontal index-coherence above the 1/2^planes random baseline.
    pub h_excess: f32,
    /// Byte self-similarity at 1- and 2-line strides (max of the two).
    pub v_coherence: f32,
    /// Sampled Shannon entropy, bits/byte.
    pub entropy: f32,
    /// Share of the most common index (blank-screen detector).
    pub dominance: f32,
}

impl PictureScore {
    /// Accept/reject gates G1-G3 (§P21.4.4). Thresholds carry
    /// `// verify live` markers — tune against the Uhane RAM when the
    /// emulator frees up; keep fixtures in sync if they move.
    pub fn plausible(&self) -> bool { /* the three rules, verbatim §4.4 */ }
}

/// Score `screen` as an interleaved planar picture. None iff shorter than
/// SCREEN_BYTES (callers normally pre-slice; PC callers pass a fresh
/// reinterleaved buffer). Pure; ~20k ops (§P21.4.6).
pub fn score_screen(screen: &[u8], res: ScreenRes) -> Option<PictureScore>
```

### 10.3 `tests/picture_precision.rs` — NEW (the Uhane regression)

Header comment: models the DHS Uhane false-positive shape — a plausible
palette table in RAM followed by non-picture bytes — without needing the
live demo. Deterministic xorshift32 PRNG local to the file; reuse
`common::{make_pi, plant}` and a local `PAL`/`pal_bytes` copy (graphics.rs
precedent). All buffers 0xFF-filled (same straddle rationale as
`pi1_planted_scan_and_golden`). Scans use
`default_registry().scan(mem, Some(RipKind::Picture), 0)`.

Fixture `fn uhane_like(seed: u32) -> Vec<u8>` — 768 KiB, 0xFF fill, 20
planted candidate sites at `4096 + i * 32768` (even), each =
`0u16 res word ++ pal_bytes() ++ body(i)`. (Erratum 2026-07-11: originally
512 KiB with spacing 24576 — but a candidate footprint is 32034 bytes
(`PI_TOTAL`), so sites overlapped by 7458 bytes, contaminating each site's
scored window with the next site's header/body start, and the test-2 plant
at `0x60000` fell inside site 15's accepted-finding skip span
(`0x5B000..0x62DA2`) and was never scanned. Spacing 32768 > 32034
eliminates overlap; 768 KiB fits 20 sites plus the plant.)

- sites 0..8 — `body` = 32000 xorshift bytes (seed+i): **must be rejected**.
- sites 8..14 — zero-heavy junk: 32000 zeros, xorshift byte at every 64th
  position: may pass gates, must rank low.
- sites 14..20 — table-like: first 512 bytes = incrementing BE words
  (`k as u16`), rest 0xFF: may pass, dominance-penalized. (Table kept to 512
  bytes so palette-gate-passing *interior* offsets stay few — the full-size
  variant would be a multi-second debug-mode test for no extra coverage.)

Tests:

1. `noise_only_is_capped_and_low_confidence`: scan `uhane_like(1)` →
   `degas` findings ≤ 8 (`MAX_FINDINGS`); every `degas` finding has
   `confidence < Some(90)`; **no** finding at any of sites 0..8's offsets.
2. `real_picture_outranks_noise`: `uhane_like(2)` + `plant` of
   `make_pi(ScreenRes::Low)` at `0xA8000` → the FIRST `degas` finding in
   the returned order is at offset `0xA8000` with
   `confidence >= Some(95)`; total `degas` findings ≤ 8. (Plant offset is
   past site 19's footprint end `0xA0CA2`, so no site's window or
   accepted-finding skip span can mask it; its own footprint ends at
   `0xAFD22` < 768 KiB.)
3. `packed_like_region_rejected`: 64 KiB buffer, one site with xorshift
   body → zero `degas` findings.
4. `blank_screen_rejected`: 64 KiB, res word + `pal_bytes()` + 32000 zeros
   → zero `degas` findings (G1 — this is the currently-accepted shape that
   P21 exists to kill; today's code finds it: that is the red test proving
   the fix).

*rejected* by the gates (thresholds are conservative estimates), the
assertions still pass (≤ is directional). If test 2's fixture confidence

```markdown
## 2026-07-XX — ADR-<n>: Picture findings are structure-scored, ranked, and capped — the Degas gate stops trusting the header

**Status:** accepted
**Context:** The DHS "Uhane" run returned 45 "Degas PI1/PI2" false positives
from `rip(kind=picture)`. The Degas header is two weak facts (res word 0-2 +
`plausible_palette`'s 32 bytes), which any table of small BE words in RAM
satisfies; the 32000-byte "screen" behind it then decodes as planar noise.
Reference decoders (RECOIL, Atari_ST_Sources DEGAS.C) identify Degas by
filename extension + exact length — signals a RAM scan does not have, so
precision had to come from the pixel data itself.
**Decision:** A pure scorer (`image::score::score_screen`) computes, from 25
sampled scanlines and strided byte samples: used-color count, horizontal
index-coherence above the per-resolution random baseline (1/2^planes),
vertical byte self-similarity at 1- and 2-line strides (the 2-line arm keeps
ordered dither alive), sampled byte entropy, and dominant-color share. Three
gates reject blank bodies, structure-free noise, and high-entropy packed
data; a weighted composite (0-100) lands in a new `Finding.confidence:
Option<u8>` (machine-rankable, unlike the ym-player label precedent) and on
the wire as `FindingOut.confidence`. Degas gates AND scores; NeoChrome only
scores (its six-word geometry gate already carries the precision); MPP is
untouched (magic + exact size math). `rank_and_cap` (finding.rs) orders each
plugin's survivors confidence-descending and caps Degas at 8 per buffer —
ranking stays *inside* the plugin so the engine's registration-order
guarantee and `FindingId` stability are untouched; cross-plugin comparison
happens agent-side via the confidence field. Thresholds (v 0.04/0.10,
h_excess 0.05, entropy 7.5, cap 8) are source-derived estimates marked
`// verify live` — to be tuned against the Uhane RAM once the emulator is
free.
**Alternatives considered:** cross-bitplane correlation (stronger signal,
~4x cost, unpinnable without live data — deferred); global confidence
re-sort in the rip tool (breaks the documented per-registration ordering and
risks tie-flips in existing tests for no agent-visible gain); content-hash
dedupe (redundant — skip-past-hit already prevents overlaps, the cap absorbs
the rest); a minimum-entropy gate (would reject legitimately blank/flat art).
**Consequences:** Blank-screen-behind-a-palette — previously an accepted
finding — is now rejected by design (G1), and the degas unit fixtures grew
structured bodies to match. Real fixtures (bands PI1/PC1, NEO, packed-PI1
recursion across all five depackers) are pinned unregressed by
tests/picture_precision.rs and the existing suites. A pathological RAM full
of palette-like words costs ~20k ops per gate-passing candidate (measured
envelope: 45 candidates on the real run — sub-millisecond); no staged gate
until live data says otherwise. degas.rs split (degas_rle.rs) was a
prerequisite pure move for the 200-line budget.
```
