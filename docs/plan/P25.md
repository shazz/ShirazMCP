## 0. Open questions / unverified assumptions (state, don't guess)

1. **Source tree vs deployed binary.** Every Hatari fact in §1 was read from
   `/home/matt/projects/hatari/src`, which carries **hrdb-fork
   modifications** (`profilecpu.c` contains `hrdb mod` comments at lines
   849, 887, 929). If the `hatari` binary the server actually spawns was
   built from a different tree, the reset semantics in §1.2 could differ
   (upstream Hatari's `Profile_CpuStart` also free+callocs, but the
   prev-cycle carry-over is hrdb-specific). **Mitigation is built into the
   design:** the live test (§10.3) asserts `total_cycles` ≈ 160256 per frame
   for every sampled frame. If counters did NOT reset per continue, totals
   would read ≈ i×160256 and the test fails on frame 2 — the load-bearing
   assumption is machine-checked, not hoped.
2. **50 Hz assumption.** `fits_50hz`/`headroom_pct`/`vbl_fraction` are
   defined against the 160256-cycle 50 Hz PAL frame
   (`analyze::cycles::VBL_CYCLES`, ADR-34 lineage). On a 60 Hz or mono
   machine the per-frame *measurement* stays correct (the window is the VBL
   counter, not a cycle count) but the budget constant misstates headroom.
   Documented in the tool description; not handled in P25.
3. **Foreign debugger traffic mid-window.** `DebugUI_ParseLine` (the
   remote/fifo command path, `debugui.c:1455`) calls
   `DebugCpu_SetDebugging()` — and therefore resets the profile buffer —
   after **every parsed line**. The measurement loop never sends commands
   while the machine runs (all interaction happens frozen inside the
   `DebugUI()` loop, which resets only at exit — §1.2), and the server is
   single-session, so nothing else can inject traffic. If a future phase
   adds concurrent debugger channels, this invariant must be revisited.

## 1. Verified Hatari facts (read from source 2026-07-11 — cite these, never re-guess)

All paths relative to `/home/matt/projects/hatari/src`.

### 1.1 `profile on`/`off` only toggle a flag

`debug/profile.c`, `Profile_Command` (~line 782): `on` executes
`*enabled = true; fprintf(stderr, "Profiling enabled.\n");` — nothing else.
`off` likewise (`"Profiling disabled.\n"`). These are exactly the
confirmation strings `debug/profile.rs::profile_on/profile_off` already
match. Subcommand set (`Profile_Match`, ~line 621): `addresses, callers,
caches, counts, cycles, d-hits, i-misses, loops, off, on, save, stack,
stats, symbols`; save syntax is `profile save <file>`.

### 1.2 THE LOAD-BEARING FACT — counters reset on every debugger EXIT, not on `profile on`

- `Profile_CpuStart()` (`debug/profilecpu.c:874`): if `cpu_profile.enabled`,
  it calls `Profile_CpuFree()` then `memset(&cpu_profile, 0, ...)` and
  `calloc`s a **fresh zeroed per-address data buffer** (lines 895–912). The
  hrdb mod preserves only `prev_cycles`/`prev_family`/`prev_pc` across the
  memset (lines 887–902) so the first instruction after resume is costed
  correctly — the per-address counts/cycles are unconditionally zeroed.
- `Profile_CpuStart()` is called from exactly one place:
  `DebugCpu_SetDebugging()` (`debug/debugcpu.c:1443`), which runs at every
  **debugger exit**: `DebugUI()` main-loop exit after `c`/continue
  (`debug/debugui.c:1321`), script-file re-init (`debugui.c:1428`), and
  per-line in `DebugUI_ParseLine` (`debugui.c:1455`).
- On debugger **entry** (breakpoint fire → `DebugUI()` →
  `DebugCpu_InitSession()`, `debugui.c:1269` → `debugcpu.c:1602`),
  `Profile_CpuStop()` (`profilecpu.c:1390`) finalizes the accumulated data
  (idempotent via the `processed` flag) — data is valid for `profile save`
  for as long as the machine stays frozen.

**Consequence:** with profiling enabled, each continue→break cycle yields a
buffer containing **exactly that window's** counts and cycles. A loop of
1-VBL-frame legs with a `profile save` at each pause gives clean per-frame
samples with **no explicit reset command needed and none available**. The
cumulative-delta fallback (frame_i = total_i − total_{i−1}) is not merely
unnecessary — it would be **wrong**, because data does not survive a
continue. (This is also why the existing `profile` tool works: it has
exactly one continue between `profile on` and `profile save`.)

### 1.3 The profiler counts ALL executed addresses

Buffer size = `(STRamEnd + CART_SIZE + TosSize) / 2` (+TT RAM if any)
(`profilecpu.c:906–912`) — every executed address in ST RAM, cartridge and
TOS ROM is counted, **including interrupt handlers and the vsync idle
spin**. `profile save` dumps every active address (`Profile_CpuSave`,
`profilecpu.c`, via `Profile_CpuShowAddresses(0, end-2, ...)`);
`debug/profile.rs::parse_profile_file` already parses all of them and
`sum_range(entries, from, to)` filters `[from, to)`. The whole-frame total
is simply the fold over **all** entries (§5.1 adds `sum_all`).

### 1.4 Frame-boundary precision

The `VBL > n` breakpoint is a conditional checked per-instruction
(`BreakCond_MatchCpu` in `DebugCpu_Check`, `debugcpu.c:1410`); it fires at
the first instruction boundary after the VBL counter increments. Boundary
jitter is ≤ one instruction and each boundary is defined identically, so
consecutive-window jitter largely cancels; per-frame totals land within a
few hundred cycles of 160256 (§10.3 asserts a ±5000 band to be safe).

## 2. Design thesis (the shape of the tool — committed)

The MCP_TODOS framing ("allow `to < from`", "same start/end PC") treats the
PC range as the *measurement window*. That is the wrong axis. **The
measurement window is TIME — N whole VBL frames. The address range is
purely a FILTER over which executed code counts as "yours".** Then:

- whole-frame cost falls out (the window is a frame, not a PC pair);
- `bsr`'d callees, interrupt handlers, anything inside the extent are
  counted automatically — give it the PRG text extent;
- loop shape / same-entry-exit-PC stop mattering;
- `to < from` evaporates: from/to are an address *extent*, naturally
  `to > from`.

`profile_routine` (rts-depth tracking) is **out of scope** — the extent
filter subsumes its main use ("routine incl. callees" = the extent covering
routine+callees, or just the whole text segment), and true rts-tracking is a
different mechanism (deferred; see §12).

Both numbers are always reported because neither alone is interpretable:
a vsync-locked effect burns ~160256 **total** cycles per frame *by
construction* (the idle spin absorbs whatever the effect leaves over), so
total is a validity check,
not a cost metric; **range** is the cost metric — and if the vsync
wait-spin sits inside `[from,to)`, range degenerates toward total. The tool
description (§4.3) says all of this to the calling agent explicitly.

## 4. The tool

### 4.1 Arguments (`profile_frame_wire.rs`)

```rust
pub const PROFILE_FRAME_MAX: u32 = 200;

#[derive(Debug, Deserialize, JsonSchema)]
pub struct ProfileFrameArgs {
    /// VBL frames to sample (1..=200). One profiler window per frame.
    pub frames: u32,
    /// Optional address-filter extent start (hex like "$af3c" or decimal —
    /// same parser as `profile`). Give with `to` or not at all.
    pub from: Option<String>,
    /// Optional address-filter extent end (exclusive). Cycles at addresses
    /// in [from,to) are reported as range_* ("your code"); everything
    /// executed is always reported as total_*.
    pub to: Option<String>,
    /// Per-frame-leg wait budget, ms. Default 10040
    /// (`frames::default_timeout(1)`).
    pub timeout_ms: Option<u64>,
}
```

Decisions pinned:
- **from/to are OPTIONAL, both-or-neither.** Optional because the no-filter
  call is the valid "what is running / measurement sanity" mode; paired
  because a half-filter is meaningless.
- **No `PROFILE_MAX_RANGE` cap.** That constant exists only to bound
  `profile`'s static-disasm window; `profile_frame` has **no static
  estimate** (§4.4) and the measured path is unbounded. Do not import it.
- **Validation** (`invalid_params` on failure, exact rules):
  - `frames` in `1..=PROFILE_FRAME_MAX` — message
    `"frames must be 1..=200"`.
  - `from`/`to`: both present or both absent — message
    `"from and to must be given together"`.
  - when present: parse via `super::mem::scan::parse_addr` (propagates its
    own error), then `to > from` — message `"to must be greater than from"`
    — and `to.raw() <= 0x40_0000` (4 MiB, max ST RAM) — message
    `"extent must lie within ST RAM (to <= $400000)"`.
- **No `region` arg** — region only parameterizes the static contention
  model, which this tool doesn't have.

### 4.2 Output (`profile_frame_wire.rs`) — exact struct

```rust
#[derive(Debug, Serialize, JsonSchema)]
pub struct ProfileFrameOutput {
    /// Frames requested == frames measured (the tool hard-errors rather
    /// than returning a short/contaminated sample — §7).
    pub frames: u32,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub from: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub to: Option<String>,
    /// Which series fits_50hz/headroom_pct/vbl_fraction/hbl_count are
    /// computed from: "range" when from/to given, else "total". For a
    /// vsync-locked program a "total" basis reads ~0% headroom by
    /// construction — pass an extent to get a meaningful cost.
    pub cost_basis: String,
    /// Whole-frame measured cycles (every executed address: your code,
    /// interrupts, TOS, idle spin). ~160256/frame when displaying at
    /// 50 Hz — a validity check, not a cost metric.
    pub total_cycles_min: u64,
    pub total_cycles_avg: f64,
    pub total_cycles_max: u64,
    /// Cycles at addresses inside [from,to) per frame — "your code".
    /// Present iff from/to given.
    #[serde(skip_serializing_if = "Option::is_none")]
    pub range_cycles_min: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub range_cycles_avg: Option<f64>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub range_cycles_max: Option<u64>,
    /// Per-frame series, index 0 = first sampled frame (≤200 entries;
    /// spot periodic spikes, e.g. every-4th-frame music work).
    pub per_frame_total_cycles: Vec<u64>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub per_frame_range_cycles: Option<Vec<u64>>,
    /// cost_avg / 160256 — average frames-worth of work per frame.
    pub vbl_fraction: f64,
    /// cost_avg / 512 — average scanlines of work per frame.
    pub hbl_count: f64,
    /// max(cost series) <= 160256. WORST case, deliberately: one dropped
    /// frame is a visible glitch, so the average is not the criterion.
    pub fits_50hz: bool,
    /// (160256 - max(cost)) / 160256 * 100. Negative when over budget.
    pub headroom_pct: f64,
    /// 1-based index of the max-cost frame.
    pub worst_frame: u32,
    /// Raw profiler dump of the worst frame — disassemble/`profile`-drill
    /// here for hot spots (ADR-5: bulk stays on disk).
    pub worst_frame_path: String,
    /// Directory holding all N per-frame dumps (frame-0001.txt …).
    pub profile_dir: String,
    /// Always "paused" on success — frozen at the last frame boundary.
    pub state: String,
}
```

Definitions (pin exactly):
- **cost series** = `per_frame_range_cycles` when the extent was given,
  else `per_frame_total_cycles`.
- `fits_50hz = max(cost) <= u64::from(cycles::VBL_CYCLES)`.
- `headroom_pct = (f64::from(VBL_CYCLES) - max_cost as f64)
  / f64::from(VBL_CYCLES) * 100.0` — may be negative; do not clamp.
- `vbl_fraction = cycles::vbl_fraction_f(cost_avg)`;
  `hbl_count = cycles::hbl_count_f(cost_avg)` (§5.2).
- `worst_frame` = 1-based argmax of the cost series, first index on ties;
  `worst_frame_path = profile_dir.join(format!("frame-{i:04}.txt"))` with
  the same 1-based `i`.
- averages are `f64` (sum as u64, divide once); min/max stay `u64`.

### 4.4 What is deliberately absent

- **No static estimate.** `static_estimate`/`RegionArg` are a single-pass
  straight-line model — meaningless across a frame full of loops and
  interrupts. Do not call `analyze::disasm` or `cycles::estimate` here.
- **No output-tail capture** (`cap_output_tail`): the per-leg breakpoint
  output is protocol noise at frame boundaries; drop it.
- **No cleanup of previous runs' dump directories** — same policy as
  `profile`'s `profile-{seq:04}.txt` (never garbage-collected; work dir is
  session-scoped).

## 6. Algorithm — the per-frame sampling loop (step by step)

Choreography lives in `profile_frame.rs`; every helper ≤ 30 lines. `guard`
is the locked `AnySession`; `extent: Option<(Addr, Addr)>` from validation;
`leg_timeout = a.timeout_ms.unwrap_or_else(|| frames::default_timeout(1))`
(= 10040 ms default — one frame is 20 ms emulated; the run_frames budget
model already assumes armed-per-instruction slowdown, and profiling's extra
per-instruction work still leaves ~500× margin).

```
 1. extent = profile_frame_wire::validate(&a)?          (pure, §4.1 rules)
 2. seq = self.profile_seq.fetch_add(1, Relaxed) + 1    (SHARED counter with
    `profile` — one namespace of profiling artifacts per session)
 3. guard = self.session.lock().await
 4. managed::ensure_paused(&mut guard)?                 (Stopped → error here)
 5. vbl0 = frames::current_vbl(&mut guard)?
    frames::check_vbl_headroom(vbl0, a.frames + 1)?     (+1 = alignment leg)
 6. dir = proc.config().work_dir.join(format!("profile-frame-{seq:04}"))
    tokio::fs::create_dir_all(&dir)                     (map Io error via to_mcp)
 7. ALIGNMENT LEG (not measured, profiler still OFF):
    one_frame_leg(&mut guard, leg_timeout)?             — see below.
    Purpose: the session was paused at an arbitrary mid-frame PC; this leg
    parks us exactly at a VBL boundary so window 1 is a whole frame.
 8. debug::profile::profile_on(live_proc(&mut guard)?)  (issued while FROZEN
    inside the DebugUI loop — §0.3 invariant)
 9. for i in 1..=a.frames:
      a. one_frame_leg(&mut guard, leg_timeout)
         — on Err: cleanup_profile(&mut guard) then return the error,
           message prefixed "frame {i}/{frames}: ".
         (the continue inside this leg is what zeroes the counters — §1.2;
          window i therefore contains exactly frames worth of data)
      b. path_i = dir.join(format!("frame-{i:04}.txt"))
         debug::profile::profile_save(proc, &path_i)
         — on Err: cleanup_profile + return, same prefix.
      c. read path_i (tokio::fs::read_to_string), parse_profile_file,
         push sum_all(...).1 into totals;
         if extent: push sum_range(..., from, to).1 into ranges.
         (instruction counts are parsed but not reported in P25 — drop them)
10. debug::profile::profile_off(proc)?                  (hard error if this
    fails: profiling left enabled would silently slow the session)
11. build_output(...)                                   (pure, §4.2)
    Session state on success: PAUSED at the last VBL boundary (matches
    `profile`'s contract).
```

`one_frame_leg` (the only place the machine moves):

```rust
/// Run exactly one VBL frame via the managed primitive. Errors unless OUR
/// breakpoint fired AND the VBL counter advanced by exactly 1 (frame
/// isolation would otherwise be lost).
async fn one_frame_leg(guard: &mut AnySession, timeout_ms: u64) -> Result<(), McpError> {
    let cur = frames::current_vbl(guard).await?;
    let condition = frames::vbl_condition(cur, 1);   // "VBL > cur"
    match managed::run_to_breakpoint(guard, &condition, timeout_ms)
        .await
        .map_err(to_mcp)?
    {
        Fire::Fired { ours: true, .. } => {
            let after = frames::current_vbl(guard).await?;
            if after.wrapping_sub(cur) == 1 { Ok(()) } else {
                Err(McpError::internal_error(
                    format!("VBL advanced by {} (expected 1) — frame isolation lost",
                            after.wrapping_sub(cur)), None))
            }
        }
        Fire::Fired { pc, ours: false, .. } => Err(McpError::internal_error(
            format!("a foreign breakpoint fired first: pc=${pc:x}"), None)),
        Fire::TimedOut => Err(McpError::internal_error(
            format!("VBL boundary not reached within {timeout_ms} ms \
                     (machine left running, managed breakpoint disarmed)"), None)),
    }
}
```

`cleanup_profile` — best-effort `profile_off`, mirroring
`analyze_profile.rs`'s error path exactly:

```rust
/// Best-effort profiler disable on an error path; never masks the
/// original error. (After TimedOut the session is Running — the attempt
/// may fail; that is acceptable, matching `run_profile`'s precedent.)
async fn cleanup_profile(guard: &mut AnySession) {
    if let Some(proc) = guard.process_mut() {
        let _ = debug::profile::profile_off(proc).await;
    }
}
```

Reuse verbatim: `live_proc` — copy the 5-line helper from
`analyze_profile.rs` (it is private there; duplicating five lines beats
widening a visibility for it — Implementation note: if you prefer, make
`analyze_profile::live_proc` `pub(super)` and import it; either is
accepted, pick one and say which in the commit).

**Why alignment-then-enable (step 7 before step 8):** enabling before the
alignment leg would also work (the reset-on-continue discards the partial
window anyway) but would pay profiling overhead for a throwaway leg and
allocate the buffer one continue earlier. Align first, enable second.

## 7. Error cases (exhaustive)

| Case | Where | Kind | Session state after |
|---|---|---|---|
| `frames` 0 or > 200 | validate | `invalid_params` | unchanged |
| `from` xor `to` | validate | `invalid_params` | unchanged |
| bad address string | `parse_addr` | its existing error | unchanged |
| `to <= from` / `to > $400000` | validate | `invalid_params` | unchanged |
| session Stopped | `ensure_paused` | `internal_error` ("no live session", via `to_mcp`) | Stopped |
| VBL u32 overflow | `check_vbl_headroom` | `internal_error` | Paused |
| dir create fails | step 6 | `internal_error` (Io via `to_mcp`) | Paused |
| alignment leg timeout | step 7 | `internal_error`, names timeout | **Running** (managed disarmed; profiler never enabled) |
| foreign bp during any leg | `one_frame_leg` | `internal_error`, names pc + `frame i/N` prefix when in loop | Paused (at foreign bp); profiler off (best-effort) |
| leg timeout in loop | `one_frame_leg` | `internal_error`, `frame i/N` prefix | **Running**; profiler off best-effort (may fail — say nothing extra) |
| VBL delta ≠ 1 | `one_frame_leg` | `internal_error` "frame isolation lost" | Paused; profiler off (best-effort) |
| `profile save`/read/parse fails | step 9b/9c | `internal_error` (`Error::Parse`/`Io` via `to_mcp`), `frame i/N` prefix | Paused; profiler off (best-effort) |
| `profile off` fails at end | step 10 | `internal_error` | Paused, **profiler possibly still enabled** — message must say "profiler may still be enabled; stop/start to clear" |

No partial-results output: any mid-loop failure is a hard error naming the
frame index. (A short sample with an unknown contamination point is worse
than a clean retry; frames ≤ 200 keeps retries cheap.)

## 11. ADR — append to `decisions.md` (renumber NN → next-free at commit)

```markdown
## 2026-07-11 — ADR-NN: profile_frame — the measurement window is TIME (VBL frames); the PC range is demoted to an address filter

**Status:** accepted
**Context:** The `profile` tool bounds its measurement window with a PC
pair (`run to from` → `run to to`), which cannot express "one whole frame"
(natural start/end is the same loop PC and `to > from` is required) or
"routine including bsr'd callees" (the natural exit PC sits below the
entry). The effect-dev request (STEIsNotDead MCP_TODOS §1) asked for
`profile_frame`, `profile_routine`, and/or `to < from` support. Reading
the Hatari source settled the design: `profile on/off` only toggle a flag
(profile.c, Profile_Command); the per-address counters are freed and
freshly calloc'd by Profile_CpuStart (profilecpu.c:874) on EVERY debugger
exit via DebugCpu_SetDebugging (debugcpu.c:1443; debugui.c:1321/1428/1455),
and finalized by Profile_CpuStop on every entry — i.e. each
continue→break window yields exactly that window's data, and the buffer
spans all of ST RAM + cartridge + TOS (every executed address, interrupts
included).
**Decision:** One new tool, `profile_frame {frames, from?, to?}`: N managed
single-VBL legs (reusing frames.rs's vbl_condition/current_vbl primitives
and the ADR-15 lifecycle) with one `profile save` per paused frame
boundary — the reset-on-continue semantics make each dump a clean
per-frame sample with no reset command needed. `from`/`to` become a pure
address FILTER (an extent, naturally to > from): range_* = "your code",
total_* = the whole frame, both always reported because a vsync-locked
program burns ~160256 total cycles/frame by construction (total validates
the measurement; range is the cost). fits_50hz/headroom_pct are defined on
the WORST frame (a dropped frame is a visible glitch). No static estimate
(single-pass straight-line is meaningless across a frame), hence no
PROFILE_MAX_RANGE cap. Per-frame dumps go to
work_dir/profile-frame-{seq:04}/frame-{i:04}.txt; the output returns the
directory plus the worst frame's path (ADR-5).
**Alternatives considered:** (a) allow `to < from` in `profile` — patches
the symptom, still can't express whole-frame or same-PC windows;
(b) `profile_routine` with rts-depth tracking — a different mechanism
(stack tracking) whose main use ("routine incl. callees") the extent
filter already covers; deferred; (c) cumulative deltas between successive
saves (frame_i = total_i − total_{i−1}) — WRONG against this source: data
does not survive a continue (Profile_CpuStart free+calloc), which the
live test pins by asserting per-frame totals ≈160256.
**Consequences:** Frame-cost tuning becomes one call ("0.4 VBL, fits with
58% headroom"). The tool inherits the managed-lifecycle guarantees (ends
Paused, or Running on timeout with the breakpoint disarmed). Headroom is
only meaningful with an extent that excludes the vsync wait-spin — stated
in the tool description rather than hidden. The reset semantics were read
from the hrdb-modified tree at /home/matt/projects/hatari; the live test's
±frame-total assertion detects any divergent binary immediately. 50 Hz is
assumed (VBL_CYCLES = 160256); 60 Hz/mono machines measure correctly but
misstate the budget — future work if ever needed.
```
