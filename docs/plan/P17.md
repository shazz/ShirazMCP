## 1. Deliverable in one sentence

One new MCP tool, **`ym_state`** (tool count 33 → 34): from a single
non-intrusive read of Hatari's emulated YM2149 register file, report what the
PSG is playing *right now* — per channel A/B/C the tone period, frequency in
Hz, nearest note (± cents), volume (0–15) or envelope mode, and tone/noise
enables from the mixer; plus noise period, envelope period + shape, the raw
mixer byte, and the raw 14 sound registers — as a pretty text block plus
structured JSON.

## 2. Pinned live facts (verified 2026-07-10, Hatari 2.4.1, MJJ demo, machine="ste")

### 2.1 THE CRUX — reading the 14 registers without disturbing the program

Reading the YM through the bus is destructive: register N is read by first
**writing N to `$FFFF8800`** (the select port), which changes the chip's
selected register under the running player's feet. None of that is needed.

**Hatari exposes the emulated register array directly.** The debugger command
`info ym` dumps `PSGRegisters[16]` verbatim — a pure `fprintf` loop over
Hatari's internal array, no emulated bus access, no select-register write:

- `hatari/src/psg.c` — `PSG_Info(FILE*, ...)`: `for i in 0..16 { fprintf(fp,
  "Reg $%02X : $%02X\n", i, PSGRegisters[i]) }` (line ~669).
- `hatari/src/debug/debugInfo.c` line 689: `{ false, "ym", PSG_Info, NULL,
  "Show YM-2149 register contents" }` — registered as an `info` subcommand;
  the leading `false` means it does **not** require the debugger to be
  interactively entered, i.e. it works as a remote (`hatari-debug`-prefixed)
  fifo command while the machine runs.
- Confirmed present in the installed `/usr/bin/hatari` 2.4.1 (both strings
  `"Show YM-2149 register contents"` and `"Reg $%02X : $%02X"` are in the
  binary), and **verified live** (§2.2).

The wire sequence is therefore exactly one `DebugChannel::debug("info ym")`
call. While Running that becomes `hatari-debug info ym` over the cmd fifo;
while Paused it is the raw line `info ym` over stdin — the prefix is the
control plane's business (`session::fifo`, ADR-11 §2.1), invisible to this
phase's code. Output lands in the log and comes back sentinel-synced like
every other debugger command.

**Rejected alternatives** (recorded in the ADR, §13): (b) poke `$FF8800`
select + read + restore while frozen — 3+ round-trips, still a hardware-side
poke, needs the select-register's *current* value (which `info ym` does not
report and the bus read of `$FF8800` returns data, not the selection), and
strictly worse than a zero-poke path that already exists; (c) read the
player's RAM shadow — player-specific, unreliable, skip.

|---|---|---|---|

| A frequency | — | `2e6/(16·89)` | 1404.4944 Hz → **1404.49** |
| A note | — | §6.3 | **F6 +9c** (MIDI 89) |
| B tone period | R2=$EE, R3=$0E | | `$EEE` = 3822 |
| B frequency | — | `2e6/(16·3822)` | 32.7052 Hz → **32.71** |
| B note | — | | **C1 +0c** (MIDI 24) |
| C tone period | R4=$CD, R5=$02 | | `$2CD` = 717 |
| C frequency | — | `2e6/(16·717)` | 174.3375 Hz → **174.34** |
| C note | — | | **F3 −3c** (MIDI 53) |
| Noise period | R6=$07 | `R6 & $1F` | 7 → **17857.14 Hz** |
| Mixer | R7=$2A | active-low bits | tone **A,C** on / B off; noise **B** on / A,C off |
| Volumes | R8=$0B R9=$0B R10=$0E | `&$0F`; bit4=env | A=11, B=11, C=14; no channel uses envelope |
| Envelope | R11=R12=R13=$00 | | period 0 → 7812.50 Hz, shape $00 `\_` one-shot, unused |
| Audibility | — | §6.4 | A audible (tone), **B audible (noise-only!)**, C audible (tone) |

Note channel B: mixer disables its tone but enables its noise, volume 11 —
a live example of why "audible" must be `(tone_enabled || noise_enabled) &&
(volume > 0 || use_envelope)`, not "tone on".

Registers R14/R15 are the PSG I/O ports (floppy drive-select / parallel
port, R14=$25 here) — **not sound**; the tool reads all 16 (that is what
`info ym` emits) but reports only R0–R13 (§7).

## 3. The design decision — no freeze (this phase's ADR, §13)

`machine_state` (ADR-20) momentarily freezes a Running session because its
gather spans **five debugger round-trips plus a 32000-byte savebin** — the
reads could straddle VBLs. `ym_state` performs **exactly one** round-trip,
and Hatari executes a remote debugger command with the emulated CPU parked
(the fifo is polled from the main loop between emulation slices), so all 16
registers come from one coherent instant *by construction*. Freezing would
add two sentinel round-trips and ADR-20's pause/resume failure choreography
for zero coherence gain — and `pause()` parks the CPU at an *arbitrary
instruction*, potentially mid-way through a player's register-write burst,
which is no better an instant than a main-loop boundary. **Deliberate
deviation from mirroring P10's momentary freeze; the ADR records it.**

| Session state at call | Behavior | State after return |
|---|---|---|
| `Running` | one live `info ym` read | `Running` (untouched) |
| `Paused` | same read over stdin; never thaws | `Paused` |
| `Stopped` | `wrong_state(name, "running or paused")` | `Stopped` |

This is exactly the `read_memory`/`registers` session contract — copy that
access pattern (`src/tools/mem/mod.rs`: `guard.state_name()` then
`guard.process_mut().ok_or_else(|| wrong_state(..))`), not `machine_state`'s
`std::mem::replace` choreography.

Known limitation (one line in the ADR): a timer-driven player *could* in
principle be mid-update at the instant the command executes; a freeze would
not fix that either (it parks mid-instruction), so it is accepted, not
worked around.

### 5.1 `src/debug/parse/info_ym.rs` — NEW parser + `parse/mod.rs` wiring

Header comment: `//! `info ym` (PSG register dump) parsing — P17. Same
family contract as values.rs: &str in, Result out, failures are
Error::Parse, no regex.`

```rust
/// Parse Hatari's `info ym` output: 16 lines `Reg $NN : $VV` (psg.c
/// PSG_Info, pinned live 2026-07-10). Non-matching lines are skipped
/// (same tolerance as parse_memdump); all 16 indices 0..=15 must appear
/// or the result is Error::Parse { context: "info ym" }.
pub fn parse_info_ym(out: &str) -> Result<[u8; 16]>
```

Implementation contract (exact): for each line, `strip_prefix("Reg $")`;
split the remainder on `" : $"`; parse both sides with
`u8::from_str_radix(_, 16)` (trim the index side); ignore lines that fail
any step. Collect into `[Option<u8>; 16]` (indices ≥ 16 are skipped, not an
error). If any slot is `None` after the scan, return
`parse_err("info ym", out)`. Keep the fn ≤ 30 lines (split a
`fn parse_reg_line(&str) -> Option<(u8, u8)>` helper).

`parse/mod.rs`: add `mod info_ym;` and `pub use info_ym::parse_info_ym;`
(alphabetical among the existing decls).

## 6. `src/analyze/ym.rs` — pure decode (the ym2149.py math, in Rust)

Header comment: `//! Pure YM2149 register decode (P17) — the register→

### 6.1 Constants (pinned to ym2149.py)

```rust
/// Atari ST YM2149 master clock (ym2149.py CLOCK).
pub const YM_CLOCK_HZ: f64 = 2_000_000.0;

/// 16-level logarithmic volume table, normalised 0..=1 (~3 dB/step) —
/// ym2149.py's _VOL, verbatim.
pub const YM_VOLUME: [f64; 16] = [
    0.0, 0.0056, 0.0079, 0.0112, 0.0158, 0.0224, 0.0316, 0.0447,
    0.0632, 0.0892, 0.1259, 0.1778, 0.2512, 0.3548, 0.5012, 1.0,
];

/// (ascii, continuous) per envelope shape value 0..=15 (R13 & $0F).
/// One-shot shapes hold their final level; continuous shapes are the
/// "buzzer" tones. Matches ym2149.py's _ENV_SHAPE for 8/A/C/E; the
/// remaining values follow the AY/YM datasheet CONT/ATT/ALT/HOLD bits.
const ENV_SHAPES: [(&str, bool); 16] = [
    ("\\_", false), ("\\_", false), ("\\_", false), ("\\_", false), // 0-3: decay, hold 0
    ("/_", false),  ("/_", false),  ("/_", false),  ("/_", false),  // 4-7: attack, drop, hold 0
    ("\\\\", true),                                                 // 8: repeating saw down
    ("\\_", false),                                                 // 9: decay, hold 0
    ("\\/", true),                                                  // A: repeating triangle
    ("\\¯", false),                                                 // B: decay, hold 1
    ("//", true),                                                   // C: repeating saw up
    ("/¯", false),                                                  // D: attack, hold 1
    ("/\\", true),                                                  // E: repeating inverted triangle
    ("/_", false),                                                  // F: attack, drop, hold 0
];
```

(Write `ENV_SHAPES` in whatever literal layout rustfmt accepts; the sixteen
`(ascii, continuous)` values are the contract, pinned by §10.1.)

### 6.2 Types (all fields `pub`; derive `Debug, Clone, PartialEq`; `Note`
additionally `Copy`)

```rust
/// Nearest equal-tempered note to a frequency (A4 = 440 Hz = MIDI 69).
pub struct Note {
    pub midi: u8,   // 0..=127
    pub cents: i16, // offset from the exact note, −50..=50
}
impl Note {
    /// "C-1".."G9" style: NOTE_NAMES[midi % 12] + (midi/12 − 1).
    pub fn name(&self) -> String;
}

pub struct ChannelState {
    pub period: u16,        // 12-bit tone period, 0..=4095
    pub freq_hz: f64,       // YM_CLOCK_HZ / (16 · max(1, period)), unrounded
    pub note: Option<Note>, // None iff nearest MIDI outside 0..=127
    pub volume: u8,         // level register & $0F
    pub use_envelope: bool, // level register bit 4
    pub tone_enabled: bool, // mixer bit ch is 0 (active low)
    pub noise_enabled: bool,// mixer bit 3+ch is 0 (active low)
}
impl ChannelState {
    /// (tone_enabled || noise_enabled) && (volume > 0 || use_envelope).
    pub fn audible(&self) -> bool;
    /// YM_VOLUME[volume]; None when use_envelope (the envelope, not the
    /// level nibble, controls loudness then).
    pub fn amplitude(&self) -> Option<f64>;
}

pub struct EnvelopeState {
    pub period: u16,  // R11 | R12<<8
    pub freq_hz: f64, // YM_CLOCK_HZ / (256 · max(1, period)) — the envelope
                      // cycle rate (ym2149.py freq_to_ep inverse); triangle
                      // shapes sound one octave lower (32-step cycle)
    pub shape: u8,    // R13 & $0F
}
impl EnvelopeState {
    pub fn ascii(&self) -> &'static str;  // ENV_SHAPES[shape].0
    pub fn continuous(&self) -> bool;     // ENV_SHAPES[shape].1
}

pub struct YmState {
    pub channels: [ChannelState; 3], // A, B, C
    pub noise_period: u8,            // R6 & $1F
    pub noise_freq_hz: f64,          // YM_CLOCK_HZ / (16 · max(1, period))
    pub envelope: EnvelopeState,
    pub mixer: u8,                   // R7 verbatim
}
```

### 6.3 Functions

```rust
/// Decode the 16 raw PSG registers. Masks defensively (Hatari masks on
/// write — psg.c — but this fn accepts arbitrary bytes): tone coarse & $0F,
/// noise & $1F, level & $1F, shape & $0F.
pub fn decode(regs: &[u8; 16]) -> YmState;

/// YM_CLOCK_HZ / (16 · max(1, period)) — ym2149.py tp_to_freq.
pub fn tone_freq_hz(period: u16) -> f64;

/// Nearest note: midi_f = 69 + 12·log2(freq/440); nearest = midi_f.round();
/// None if nearest outside 0.0..=127.0; cents = ((midi_f − nearest)·100)
/// .round() as i16.
pub fn note_of(freq_hz: f64) -> Option<Note>;
```

`decode` internals (split for the 30-line ceiling): `fn channel(regs, ch:
usize) -> ChannelState` — `period = regs[2*ch] as u16 | ((regs[2*ch+1] &
0x0F) as u16) << 8`; level = `regs[8+ch]`; mixer bits per §6.2 comments —
and the envelope/noise assembly in `decode` itself. `NOTE_NAMES: [&str; 12]
= ["C","C#","D","D#","E","F","F#","G","G#","A","A#","B"]` (module-private
const used by `Note::name`).

### 6.4 No behavior beyond this

No LFSR, no envelope waveform sampling, no `rayon`, no allocation except
`Note::name`'s String. The whole module must be callable from a doc-less
unit test with a 16-byte array literal.

### 7.2 Building

```rust
/// Pure: analyze::ym::YmState + the raw registers → wire output.
/// `session` = AnySession::state_name() at call time.
pub(crate) fn build_output(
    session: &str,
    s: &crate::analyze::ym::YmState,
    regs: &[u8; 16],
) -> YmStateOutput
```

Rules (exact):
- channel names: `["A", "B", "C"]` zipped with `s.channels`;
- all `freq_hz` fields rounded via a module-private
  `fn round2(x: f64) -> f64 { (x * 100.0).round() / 100.0 }`;
- `amplitude`: `ch.amplitude()` rounded to 4 decimals (same pattern,
  `round4`); `note` mapped through `NoteOutput { name: n.name(), .. }`;
- `mixer_raw`/`shape_raw`/`registers_raw` entries: `format!("${:02X}", b)`;
- `registers_raw`: exactly `regs[0..14]`;
- `used_by`: names of channels with `use_envelope`, A→C order.

Split `fn channel_output(name, &ChannelState) -> ChannelOutput` to keep
`build_output` ≤ 30 lines.

### 7.3 Pretty printer — format is contractual (golden test §10.2)

```rust
pub(crate) fn pretty(o: &YmStateOutput) -> String
```

Lines, `\n`-joined, no trailing newline. Labels padded `{:<8}: ` exactly like
`machine_pretty.rs`.

```
=== ym_state — YM2149 PSG snapshot ===
session : {session}
mixer   : {mixer_raw}, tone {list}, noise {list}
A       : {note_part} ({freq_hz:.2} Hz), period ${period:03X}, vol {vol_part}, tone {on|off}, noise {on|off}
B       : …
C       : …
noise   : period ${period:02X} ({freq_hz:.2} Hz)
envelope: period ${period:04X} ({freq_hz:.2} Hz), shape {shape_raw} {shape} ({continuous|one-shot}), {env_use}
```

- `{list}` (mixer line): space-joined names of channels with the enable, or
  `none` when empty (`tone A C`, `noise B`, `tone none`).
- `{note_part}`: `"{name} {cents:+}c"` (e.g. `F6 +9c`, `C1 +0c`, `F3 -3c`)
  or `-` when `note` is `None`.
- `{vol_part}`: the decimal volume, or the literal `env` when
  `use_envelope`.
- `{env_use}`: `unused` when `used_by` is empty, else
  `used by {space-joined names}`.

```
envelope: period $0000 (7812.50 Hz), shape $00 \_ (one-shot), unused
```

Keep `pretty` ≤ 30 lines by splitting `fn channel_line` and

## 8. `src/tools/ym_state.rs` — the tool

Header comment: `//! P17 ym_state tool: one non-intrusive read of Hatari's
emulated YM2149 register file (info ym), decoded by analyze::ym — the audio
sibling of machine_state. No freeze: a single debugger round-trip is
coherent by construction (the §13 ADR).`

```rust
// `vis = "pub(crate)"`: see lifecycle.rs for the rationale (rmcp-2.2 gotcha).
#[tool_router(router = ym_router, vis = "pub(crate)")]
impl HatariServer {
    #[tool(
        name = "ym_state",
        description = "Decode what the YM2149 sound chip is playing right \
now, from one non-intrusive read of Hatari's emulated register file (the \
$FF8800 select port is never written — the running program is not \
disturbed). Per channel A/B/C: tone period, frequency in Hz, nearest note \
with cent offset, volume 0-15 or envelope mode, and tone/noise enables from \
the mixer; plus noise period, envelope period + shape, and the raw 14 sound \
registers. Works on a running or paused session. Compose with \
identify_music (which player is driving the chip) and spectrogram (what the \
output sounds like)."
    )]
    pub async fn ym_state(&self) -> Result<CallToolResult, McpError> {
        let (session, regs) = {
            let mut guard = self.session.lock().await;
            let name = guard.state_name();
            let proc = guard
                .process_mut()
                .ok_or_else(|| wrong_state(name, "running or paused"))?;
            let regs = debug::ym_registers(proc).await.map_err(to_mcp)?;
            (name, regs)
        };
        let out = ym_wire::build_output(session, &analyze::ym::decode(&regs), &regs);
        let json = serde_json::to_string(&out).map_err(|e| {
            McpError::internal_error(format!("serialize ym_state output: {e}"), None)
        })?;
        Ok(CallToolResult::success(vec![
            ContentBlock::text(ym_wire::pretty(&out)),
            ContentBlock::text(json),
        ]))
    }
}
```

That is the whole file (plus imports). Block order `[text(pretty),
text(JSON)]` is contractual — `machine_state` minus the image block. The
session lock is held only for the single read; decode/serialize happen after
the guard drops (wrap the locked section in a block exactly as shown). If
rustfmt pushes the fn over 30 lines, split the locked section into
`async fn read_regs(&self) -> Result<(&'static str, [u8; 16]), McpError>`.

## 9. Token-efficiency invariants (ADR-5 — checked in review)

- The entire output is ~1 KB of decoded facts — no waveforms, no sample
  data, no register history. The *decode* runs server-side; the agent never
  sees undigested state beyond 14 hex bytes.
- One tool, no new verbs, no arguments: nothing to progressive-disclose.
- No files written, no seq counter, no artifacts.

## 13. ADR — append to decisions.md (template; number/date at implementation)

```markdown
## 2026-07-XX — ADR-NN: ym_state — non-intrusive YM2149 readout via `info ym`, no freeze

**Status:** accepted
**Context:** "What is the sound chip playing?" previously took raw `debug`
calls plus manual math. Reading the YM through the bus is destructive:
register N is read by writing N to the $FF8800 select port — a side effect
on the running player. And machine_state's precedent (ADR-20) suggested a
momentary freeze for coherence.
**Decision:** Read Hatari's emulated register file with the debugger command
`info ym` (psg.c PSG_Info: a pure fprintf of PSGRegisters[16]; registered in
debugInfo.c as a non-interactive info subcommand). One sentinel-synced
round-trip; $FF8800 is never written; the session is never paused, resumed,
or otherwise mutated — verified live 2026-07-10 (Hatari 2.4.1, MJJ demo):
registers kept advancing between two probes and audio continued normally.
NO momentary freeze, deliberately deviating from ADR-20's pattern: a single
remote debugger command executes with the emulated CPU parked between
main-loop slices, so all 16 registers come from one instant by construction;
freezing would add two sentinel round-trips and pause/resume failure
choreography for zero coherence gain (pause parks the CPU at an arbitrary
instruction — possibly mid-way through a player's register-write burst —
which is no better an instant). Decode is pure (analyze::ym, the ym2149.py
math: freq = 2e6/(16·period), the 16-level log volume table, envelope
freq = 2e6/(256·period), active-low mixer); the tool reports R0–R13 only
(R14/R15 are I/O ports, not sound).
**Alternatives considered:** (a) poke $FF8800 select + read + restore while
frozen — 3+ round-trips, still a hardware poke, and the current selection is
not recoverable through the bus (reading $FF8800 returns data, not the
select value); (b) read the player's RAM shadow — player-specific,
unreliable; (c) momentary freeze à la ADR-20 — rejected as above.
**Consequences:** ym_state works identically on running and paused sessions
and cannot corrupt program state (nothing is written, nothing is paused).
Known accepted limitation: a timer-driven player could in principle be
mid-register-burst at the instant the command executes; a freeze would not
fix that either. The debug layer gains ym_registers/parse_info_ym (the
first `info` subcommand the codebase consumes — the same parse-family
contract as `m`/`cpureg`); analyze gains its first audio-domain decoder.
```

## 14. Explicitly out of scope for P17 (do not "helpfully" add)

- Any write to `$FF8800`/`$FF8802`, any pause/resume, any session mutation.
- Chip emulation: the LFSR, envelope waveform synthesis, sample rendering —
  `ym2149.py`'s *renderer* is deliberately not ported (that is
  `record_audio`/`spectrogram`'s job).
- Register **history** / per-frame capture (a future `ym_log` over
  `run_frames` could do this; not now).
- STE DMA sound / LMC1992 / Microwire state — different hardware, different
  phase.
- Reporting R14/R15 (PSG I/O ports — floppy/parallel, not sound).
- A `machine_state` field embedding `ym_state`'s output (composition happens
  agent-side; keep the tools orthogonal).
- Arguments/options on the tool — the output is already minimal.
