## 1. Deliverable in one sentence

One new MCP tool, **`machine_state`** (tool count 24 → 25): a
freezer-cartridge status screen returning, from a single coherent frozen
instant, the CPU registers + decoded SR flags, the video state (resolution,
50/60 Hz sync, screen base, 16-entry palette as RGB), the live 32000-byte
screen buffer rendered inline as PNG (opt-out) and/or dumped raw to disk as
a path handle (opt-in), plus a pretty-printed text status block alongside
the structured JSON.

## 2. Pinned live facts (verified 2026-07-09, MJJ demo, machine="ste")

A live probe (Hatari 2.4.1, `DISPLAY=:0`, frozen via ADR-11 `pause()`) pinned
every register format this phase reads. These are **contractual fixtures** —
the unit tests in §9 quote them verbatim.

**Raw `m` output shapes** (what `debug::read_bytes` parses; `m` rounds up to
whole 16-byte lines, `read_bytes` truncates to the requested count):

```
=== m $ff8201 13 ===
00FF8201: 03 00 22 00 00 00 00 00 00 02 00 00 00 00 0c 00   ..".............

=== m $ff8260 1 ===
00FF8260: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00   ................

=== m $ff8240 32 ===
00FF8240: 00 00 07 77 05 55 00 02 00 04 00 06 00 17 00 27   ...w.U.........'
00FF8250: 00 47 00 57 01 03 02 04 03 05 04 07 04 27 00 01   .G.W.........'..
```

**Decoded values from that instant** (all cross-checked):

| Quantity | Read | Decode | Probe value |
|---|---|---|---|
| Screen base hi | byte at `$FFFF8201` (idx 0 of the 13-byte block) | `<< 16` | `$03` |
| Screen base mid | byte at `$FFFF8203` (idx 2) | `<< 8` | `$22` |
| Screen base low (STE) | byte at `$FFFF820D` (idx 12) | `\| low` | `$00` |
| Assembled base | — | `hi<<16 \| mid<<8 \| low` | **`$032200`** |
| Sync | byte at `$FFFF820A` (idx 9) | bit 1: `1`→50 Hz, `0`→60 Hz | `$02` → 50 Hz |
| Resolution | byte at `$FFFF8260`, bits 1-0 | `ScreenRes::from_word` (0/1/2; 3 = invalid) | `$00` → low |
| Palette | 32 bytes at `$FFFF8240` | `palette_words` (16 BE words) | `[000,777,555,002,004,006,017,027,047,057,103,204,305,407,427,001]` |

One 13-byte read at `$FFFF8201` covers base hi/mid (idx 0/2), sync (idx 9),
and base low (idx 12) in a single debugger round-trip — use exactly that.

**Verified end-to-end:** `memory::acquire_range(proc, $032200, 32000)` +
`decode_planar(bytes, Low, live palette)` produced a 320×200 image with all
16 palette colors present, saved as PNG, while `screenshot` from the same
frozen instant produced the demo's title screen.

**Pinned observation (load-bearing for §9.3's assertions):** the RAM render
and the `screenshot` output shared the palette family but were **not**
pixel-identical — MJJ double-buffers, so `$FF8201/03/0D` (the *programmed*
base, latched at the next VBL) can point at the back buffer being drawn
while the Shifter still displays the front buffer. This is correct
freezer-cartridge semantics (we report what the hardware registers say), and
it is the same reason `view_screen_matches_live` (P4 §8.4) never asserted
pixel equality. **The live test asserts plausibility, never pixel equality
with `screenshot`.**

`// verify live` residue: on `machine="st"` (non-default) the STE-only
`$FF820D` low byte was *not* probed; Hatari is expected to return `0` there,
which degrades to the correct 256-byte-aligned ST base. Benign either way —
do not special-case machines. If an ST-machine live run ever shows a nonzero
low byte, flag to rust-architect.

## 3. The design decision — snapshot coherence (ADR-20)

**Problem:** with the session Running, the four debugger reads + the 32000-
byte `savebin` span many emulated VBLs; base/palette/screen can come from
different frames (the exact race behind `view_screen_matches_live`'s
historical flake, P4 §8.4).

**Decision — momentary freeze when Running.**

| Session state at call | Behavior | State after return |
|---|---|---|
| `Running` | `pause()` (ADR-11) → gather everything → `resume()` | `Running` (thaw confirmed by fifo sentinel) |
| `Paused` | gather everything; **never thaw a user's freeze** | `Paused` |
| `Stopped` | `wrong_state(name, "running or paused")` — no reads | `Stopped` |

Rejected alternative — read live with a `coherent:false` flag: cheaper (no
freeze round-trips) but produces cross-VBL soup for exactly the animated
programs this tool exists to inspect, and pushes a correctness caveat onto
every consumer. The freeze costs two sentinel round-trips (~tens of ms wall
time; the emulated machine simply doesn't advance) and reuses the proven
ADR-11 mechanism — no new session machinery.

**Failure semantics (exact, no deviation):**

- `pause()` fails → session restored `Running`, return `to_mcp(e)`. (ADR-11's
  known limitation: a retry recovers.)
- gather fails while momentarily frozen → **still attempt `resume()`**, then
  return the *gather* error (it is the primary failure). If the resume also
  fails, session is written back `Paused` (recoverable via the `resume`
  tool) and the gather error is still the one returned.
- gather succeeds but `resume()` fails → session written back `Paused`,
  return `to_mcp(resume error)`. The snapshot is discarded — a loud,
  consistent failure beats a result that lies about the session state; the
  agent calls `resume` then retries.

The output records the coherence facts: `session` (state at call time ==
state after return on success) and `momentary_freeze` (true iff the tool
froze/thawed a Running session).

### 6.3 Pure decode — `VideoRegs` + `video_from_bytes`

```rust
/// Decoded video-hardware state (pre-wire). `res == None` ⇔ $FF8260 read 3.
/// Invariant maintained by gather (§7.3): `screen` is only ever acquired
/// when `res.is_some()`.
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) struct VideoRegs {
    pub base: Addr,
    pub sync_hz: u8,
    pub res: Option<ScreenRes>,
    pub words: [u16; 16],
}

/// blk = the 13 bytes at $FFFF8201 (§2 layout: idx 0 hi, 2 mid, 9 sync,
/// 12 low); res_byte = the byte at $FFFF8260; pal = the 32 bytes at
/// $FFFF8240. Errors are Parse with the pinned contexts below.
pub(crate) fn video_from_bytes(blk: &[u8], res_byte: u8, pal: &[u8]) -> Result<VideoRegs> {
    if blk.len() < 13 {
        return Err(Error::Parse {
            context: "video base registers".to_string(),
            input: format!("{} bytes, need 13", blk.len()),
        });
    }
    let base = (u32::from(blk[0]) << 16) | (u32::from(blk[2]) << 8) | u32::from(blk[12]);
    let words = palette_words(pal).ok_or_else(|| Error::Parse {
        context: "palette registers".to_string(),
        input: format!("{} bytes, need 32", pal.len()),
    })?;
    Ok(VideoRegs {
        base: Addr::new(base),
        sync_hz: if res_sync_50hz(blk[9]) { 50 } else { 60 },
        res: ScreenRes::from_word(u16::from(res_byte & 3)),
        words,
    })
}

/// $FF820A bit 1: 1 → 50 Hz, 0 → 60 Hz (bit 0 = external sync, ignored).
fn res_sync_50hz(sync_byte: u8) -> bool { sync_byte & 0x02 != 0 }
```

### 6.4 Wire building

```rust
/// `mem` = (acquired length, png path, raw path, skip note) — passed
/// pre-digested by compose so this stays pure. None ⇔ neither screen nor
/// dump was requested.
pub(crate) fn build_output(
    session: &str,
    momentary_freeze: bool,
    regs: crate::debug::Registers,
    video: &VideoRegs,
    mem: Option<VideoMemoryOutput>,
) -> MachineStateOutput {
    MachineStateOutput {
        session: session.to_string(),
        momentary_freeze,
        cpu: super::debugger::regs_to_output(regs),
        video: video_output(video),
        video_memory: mem,
    }
}

fn video_output(v: &VideoRegs) -> VideoOutput {
    let pal = Palette::from_words(&v.words);
    VideoOutput {
        resolution: v.res.map_or("invalid", ScreenRes::name).to_string(),
        dimensions: v.res.map(|r| format!("{}x{}", r.width(), r.height())),
        sync_hz: v.sync_hz,
        screen_base: v.base.to_string(),
        palette_type: if is_ste(&v.words) { "ste" } else { "st" }.to_string(),
        palette: (0..16u8)
            .map(|i| PaletteEntry {
                raw: format!("${:04X}", v.words[i as usize]),
                rgb: rgb_hex(pal.color(i)),
            })
            .collect(),
    }
}

fn rgb_hex(c: [u8; 4]) -> String {
    format!("#{:02X}{:02X}{:02X}", c[0], c[1], c[2])
}
```

### 7.1 Constants + gather-side reads (verbatim addresses)

```rust
/// $FFFF8201: 13 bytes cover base hi/mid ($8201/$8203), sync ($820A) and
/// the STE base low byte ($820D) in one debugger round-trip (§2 pin).
const SHIFTER_BLOCK: Addr = Addr::new(0x00FF_8201);
const SHIFTER_BLOCK_LEN: usize = 13;
const RES_REG: Addr = Addr::new(0x00FF_8260);
const PALETTE_REGS: Addr = Addr::new(0x00FF_8240);
const PALETTE_LEN: usize = 32;
```

```rust
/// Video-register reads over any debug channel (testability seam — unit
/// tests drive this with a canned-response fake, §9.2).
async fn read_video(chan: &mut impl DebugChannel) -> Result<VideoRegs> {
    let blk = debug::read_bytes(chan, SHIFTER_BLOCK, SHIFTER_BLOCK_LEN).await?;
    let res = debug::read_bytes(chan, RES_REG, 1).await?;
    let pal = debug::read_bytes(chan, PALETTE_REGS, PALETTE_LEN).await?;
    machine_wire::video_from_bytes(&blk, res.first().copied().unwrap_or(3), &pal)
}
```

(`unwrap_or(3)` on an empty res read degrades to "invalid" rather than
panicking; `read_bytes` returning short is otherwise handled inside
`video_from_bytes`.)

The wire commands this emits (pinned by test `read_video_commands`, §9.2):
`m $ff8201 13`, `m $ff8260 1`, `m $ff8240 32`.

### 7.2 The frozen-state gather

```rust
/// Everything read while frozen. Invariant: `screen.is_some()` ⇒
/// `video.res.is_some()` (compose relies on it).
struct RawSnapshot {
    regs: debug::Registers,
    video: VideoRegs,
    screen: Option<MemImage>,
    /// Set iff want_mem but the buffer was not acquirable.
    note: Option<String>,
}

async fn gather(proc: &mut HatariProcess, want_mem: bool) -> Result<RawSnapshot> {
    let regs = debug::registers(proc).await?;
    let video = read_video(proc).await?;
    let (screen, note) = match (want_mem, video.res) {
        (false, _) => (None, None),
        (true, None) => (None, Some(
            "resolution register $FF8260 reads 3 (invalid) — screen skipped".to_string(),
        )),
        (true, Some(_)) => {
            let ram = proc.config().ram_len();
            if video.base.raw() as usize + SCREEN_BYTES > ram {
                (None, Some(format!(
                    "screen base {} + 32000 exceeds ST RAM ({ram} bytes) — screen skipped",
                    video.base,
                )))
            } else {
                (Some(memory::acquire_range(proc, video.base, SCREEN_BYTES).await?), None)
            }
        }
    };
    Ok(RawSnapshot { regs, video, screen, note })
}
```

An unacquirable screen is a **degradation with a note**, never an error —
the registers half of the status screen is still delivered. (The base is
machine-derived, not caller input, so `invalid_params` would be wrong; a
hard error would make the tool useless exactly when the machine is in a
weird state, which is when a freezer status screen matters most.)

### 7.3 Freeze choreography (ADR-20 §3 semantics, exactly)

Free function (not a method — it owns the session value, mirroring
`lifecycle.rs`'s transition pattern):

```rust
/// Momentary freeze: pause → gather → resume. Returns the session to write
/// back plus the gather result. Error precedence per ADR-20: a gather error
/// wins over a resume error; a failed resume leaves the session Paused
/// (recoverable via the resume tool).
async fn freeze_gather_thaw(
    sess: Session<Running>,
    want_mem: bool,
) -> (AnySession, Result<RawSnapshot, McpError>) {
    let mut paused = match sess.pause().await {
        Ok(p) => p,
        Err((s, e)) => return (AnySession::Running(s), Err(to_mcp(e))),
    };
    let snap = gather(paused.process_mut(), want_mem).await.map_err(to_mcp);
    match paused.resume().await {
        Ok(r) => (AnySession::Running(r), snap),
        Err((p, e)) => (AnySession::Paused(p), snap.and(Err(to_mcp(e)))),
    }
}
```

### 7.4 The tool fn

```rust
// `vis = "pub(crate)"`: see lifecycle.rs for the rationale (rmcp-2.2 gotcha).
#[tool_router(router = machine_router, vis = "pub(crate)")]
impl HatariServer {
    #[tool(
        name = "machine_state",
        description = "One-call status snapshot of the emulated Atari ST: \
CPU registers + SR flags, video state (resolution, 50/60 Hz, screen base \
from $FF8201/03/0D, 16-color palette as RGB), and the live 32000-byte \
screen rendered inline as PNG. A running session is momentarily frozen and \
resumed so every value comes from one coherent instant; a paused session \
is read in place (and stays paused). include_screen=false skips the render \
(cheap registers-only call); include_raw_dump=true also writes the raw \
screen bytes to a file and returns its path (never the bytes)."
    )]
    pub async fn machine_state(
        &self,
        Parameters(a): Parameters<MachineStateArgs>,
    ) -> Result<CallToolResult, McpError> {
        let include_screen = a.include_screen.unwrap_or(true);
        let include_raw = a.include_raw_dump.unwrap_or(false);
        let want_mem = include_screen || include_raw;
        let mut guard = self.session.lock().await;
        let config = guard.config().clone();
        let work_dir = config.work_dir.clone();
        let (back, session, momentary, snap) =
            match std::mem::replace(&mut *guard, AnySession::new(config)) {
                AnySession::Stopped(s) => {
                    let name = s.state_name();
                    *guard = AnySession::Stopped(s);
                    return Err(wrong_state(name, "running or paused"));
                }
                AnySession::Paused(mut s) => {
                    let snap = gather(s.process_mut(), want_mem).await.map_err(to_mcp);
                    (AnySession::Paused(s), "paused", false, snap)
                }
                AnySession::Running(s) => {
                    let (back, snap) = freeze_gather_thaw(s, want_mem).await;
                    (back, "running", true, snap)
                }
            };
        *guard = back;
        drop(guard);
        self.compose(snap?, session, momentary, include_screen, include_raw, &work_dir)
            .await
    }
}
```

*Implementation note:* if this exceeds 30 lines after rustfmt, move the
`match` body into `async fn take_snapshot(&self, want_mem: bool) ->
Result<(String, bool, RawSnapshot, PathBuf), McpError>` and keep the tool fn
as resolve-defaults → take_snapshot → compose. The semantics above do not
change.

The lock is held across pause/gather/resume (correct: no other tool may
touch the session mid-freeze — same reasoning as `grab_screen` in view.rs);
the CPU-bound render + file writes happen **after** the guard drops.

### 7.5 Compose (outside the lock)

```rust
impl HatariServer {
    /// Render/write artifacts, build wire output, assemble content blocks:
    /// [image?] + text(pretty) + text(JSON) — extract_as_png's pattern.
    async fn compose(
        &self,
        snap: RawSnapshot,
        session: &str,
        momentary: bool,
        include_screen: bool,
        include_raw: bool,
        work_dir: &Path,
    ) -> Result<CallToolResult, McpError> { .. }
}
```

Exact behavior:

1. `let n = self.machine_seq.fetch_add(1, Ordering::Relaxed) + 1;`
2. If `include_screen`, and `snap.screen` is `Some(mem)` (invariant: res is
   `Some`): `let png = super::view::render_screen(mem.bytes(), res,
   &snap.video.words)?;` — write to `work_dir.join(format!("machine-{n:04}.png"))`
   via `tokio::fs::write` (map err through `to_mcp(Error::Io(e))`), keep an
   `ContentBlock::image(b64, "image/png")` (base64 STANDARD engine, exactly
   like view.rs) and the path.
3. If `include_raw`, and `snap.screen` is `Some(mem)`: write `mem.bytes()`
   to `work_dir.join(format!("machine-{n:04}-screen.bin"))`, keep the path.
4. `video_memory`: `None` if `!include_screen && !include_raw`; else
   `Some(VideoMemoryOutput { len: snap.screen.as_ref().map_or(0, MemImage::len),
   png_path, raw_path, note: snap.note })` (paths as
   `display().to_string()`).
5. `let out = machine_wire::build_output(session, momentary, snap.regs,
   &snap.video, video_memory);`
6. Blocks, in this order: the image block **iff produced in step 2**, then
   `ContentBlock::text(machine_wire::pretty(&out))`, then
   `ContentBlock::text(serde_json::to_string(&out).map_err(..)?)` (the
   serialize-error mapping copied from extract.rs's `out_json`). Return
   `CallToolResult::success(blocks)`.

Split steps 2–3 into a helper (`async fn write_artifacts`) to respect the
30-line ceiling; the block order in step 6 is contractual.

## 8. Token-efficiency invariants (ADR-5 — checked in review)

- The 32000-byte buffer NEVER appears in any text/JSON block — only as the
  rendered PNG image block and/or an on-disk path handle.
- Default call = registers + video + one PNG; `include_screen=false` makes
  it a pure-text status probe (4 debugger round-trips, no savebin).
- One tool, no new verbs: no `machine_state_raw`, no separate palette tool.

## 12. ADR-20 — append to decisions.md (template, verbatim)

```markdown
## 2026-07-XX — ADR-20: machine_state — coherent one-call snapshot via momentary freeze

**Status:** accepted
**Context:** Agents inspecting a running program needed 4-6 tool calls
(registers, debug m ×3, view_memory_as_screen) to answer "what state is the
ST in?", and the reads spanned many emulated VBLs — resolution, palette,
screen base and screen contents could come from different frames (the
verified source of view_screen_matches_live's historical flake). The
freezer-cartridge heritage (Ultimate Ripper's status screen) suggests the
shape: one call, one frozen instant, everything on screen.
**Decision:** One `machine_state` tool that composes existing primitives
only: ADR-11 freeze/thaw, `debug::registers`, three pinned video-register
reads ($FFFF8201×13 covering base hi/mid/low + sync, $FFFF8260, $FFFF8240×32),
ranged `savebin`, and P4's `render_screen`. Coherence rule: a Running
session is **momentarily frozen** (pause → gather → resume, lock held
throughout); a Paused session is read in place and never thawed; Stopped is
a wrong-state error. Failure semantics: gather errors outrank thaw errors;
a failed thaw leaves the session Paused (recoverable via `resume`) rather
than returning a result that misreports session state. Token efficiency
(ADR-5): the 32000-byte buffer is returned only as a rendered PNG image
block (default on) and/or an on-disk path handle (`include_raw_dump`,
default off) — never as bytes in context; `include_screen=false` degrades
to a 4-round-trip text-only probe.
**Alternatives considered:** (a) read live with a `coherent:false` flag —
cheaper, but hands every consumer a cross-VBL-soup caveat on exactly the
animated programs the tool exists to inspect; (b) reuse Hatari
`--saveconfig`/state snapshots — heavyweight, file-format coupling, still
needs the register decode; (c) separate video_state/cpu_state tools — more
surface, still incoherent between the two calls.
**Consequences:** A machine_state call on a Running session halts emulation
for ~2 sentinel round-trips (invisible to the emulated program: no time
advances). The reported screen base is the *programmed* register value —
for double-buffered programs it may be the back buffer, which is correct
freezer semantics but means the render is not pixel-identical to
`screenshot` (verified live on MJJ; tests assert plausibility, never pixel
equality). The tool adds a per-call pause/resume cycle that assumes no
foreign breakpoints are armed while Running (ADR-15 already guarantees
managed runs return to a known state). SrOutput gained an additive `trace`
field; `ripper::image` gained `is_ste` as the single ST/STE detection rule.
```

## 13. Explicitly out of scope for P10 (do not "helpfully" add)

- Video **counter** ($FFFF8205/07/09) reporting — probed once, read all
  zeros while frozen; unverified semantics, not part of the tool.
- STE extras beyond the base low byte: hscroll ($FF8264/65), linewidth
  ($FF820F), DMA-sound state. Post-P10 backlog.
- MFP/PSG/Blitter state in the snapshot (the annotator + `debug` cover ad
  hoc reads).
- Any new depack/decode logic, any change to `Palette`/`decode_planar`
  semantics, any new session state or freeze mechanism.
- Pixel-equality assertions between the RAM render and `screenshot` (§2
  pinned: double-buffering makes this wrong by design).
- A `coherent:false` live-read mode (rejected in ADR-20).
- Caching/snapshot-reuse across calls; each call re-reads the machine.
