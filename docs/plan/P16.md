> where this document says something, do exactly that. If reality contradicts
> this spec, use the `Implementation note` / `// verify live` fallbacks; if

**Motivation (from `docs/live-patching.md` + `TODO.md` §"Save the patched
program"):** the Blade Runners exercise hot-patched scroller text, a raster

classic freezer-cartridge "save" (Ultimate Ripper / Multiface), scoped here
to the flavour that covers exactly what that exercise patched: static
TEXT/DATA `incbin` data in a GEMDOS program.

## 1. Deliverable in one sentence

One new MCP tool, **`save_prg(out_path, source_prg, mode="repatch")`**, valid
only on a **Paused** session: it locates the running program's load address
via the GEMDOS basepage (OSHEADER `p_run` chain, §4.3), parses the original
`.PRG` (header + segments + relocation table, §4.1/§4.2), computes the
expected in-RAM TEXT+DATA image (file bytes + relocation applied at the live
load address), acquires the actual RAM window, diffs the two, writes every
representable patched byte back to its file offset in a copy of the original
file, and reports — never persists — patches that are **not
file-representable** (bytes inside relocated longwords; BSS/runtime state is
declared out of reach), returning a compact JSON summary (paths, patch runs,
reloc warnings, divergence facts — never bytes).

## 2. The scope decision — which flavour ships (record in the ADR)

| Flavour | What it persists | Cost | P16 verdict |
|---|---|---|---|
| **1. Re-emit patched `.PRG`** (diff RAM against the file image, patch the copy) | static TEXT/DATA hacks — scroll text, palettes, tables, in-place code patches: exactly the live-patching exercise | pure byte work + 6 debugger reads + one ranged `savebin`; output is byte-for-byte the original file except the patched bytes | **ships** |
| 2. Snapshot-to-runnable `.PRG` (full RAM + regs + hardware + restore stub) | anything, including BSS/runtime/hardware state, frozen mid-frame | a 68k restore-stub code generator (supervisor entry, SR/USP/ISP restore, hardware re-programming: Shifter base/res/palette, PSG, MFP timers), degraded-machine caveats, ~a full phase of engineering (the r1pp3r model) | **deferred** to a follow-on phase; `mode="snapshot"` is reserved wire vocabulary, rejected with `invalid_params` (§7.2) |

Rationale (goes in the ADR §13): flavour 1 covers 100% of the motivating
exercise with ~0 new machinery (it composes `read_bytes`, `acquire_range`
and pure byte diffing) and produces a *clean* artifact — a faithful copy of
the original PRG, still relocatable, still TOS-loadable anywhere, symbols
and fixups intact. Flavour 2 produces a machine-state amber that only
resumes correctly when the restore stub reproduces enough hardware state —
a large, separately-testable effort that must not gate the simple save.
Reserving the `mode` value now keeps the tool contract forward-compatible.

## 4. Normative formats (pinned — do not re-derive)

### 4.1 The GEMDOS `.PRG` file layout

All header fields **big-endian**. This is `prg_wrap`'s table
(`src/ripper/extract.rs`), restated as the parse contract:

| Offset | Type | Field | Notes |
|---|---|---|---|
| `+0`  | u16 | magic | must be `0x601A` |
| `+2`  | u32 | `tlen` — TEXT segment length | |
| `+6`  | u32 | `dlen` — DATA segment length | |
| `+10` | u32 | `blen` — BSS length | not in the file; allocated at load |
| `+14` | u32 | `slen` — symbol table length | DRI/GST; opaque bytes for P16 |
| `+18` | u32 | reserved | |
| `+22` | u32 | program flags | opaque for P16 (preserved verbatim) |
| `+26` | u16 | `absflag` | **nonzero ⇒ no relocation table** |
| `+28` |     | TEXT bytes (`tlen`) | |
|       |     | DATA bytes (`dlen`) — immediately follows TEXT | |
|       |     | symbol table (`slen`) | |
|       |     | relocation table (§4.2), iff `absflag == 0` | |

`HEADER_LEN = 28`. File-offset mapping (the load-bearing formula):

```
file_offset(seg_off) = 28 + seg_off        // seg_off ∈ [0, tlen + dlen)
```

where `seg_off` is an offset into the contiguous TEXT‖DATA image. BSS has
**no file representation** — a BSS patch cannot be re-emitted, ever.

### 4.2 The relocation (fixup) table

Starts at `28 + tlen + dlen + slen`, present iff `absflag == 0` and at least
4 bytes remain. Decoding (pinned):

1. First **big-endian u32** = segment offset of the first relocated
   longword. `0` ⇒ empty table, done.
2. Then one byte at a time: `0` ⇒ **end of table**; `1` ⇒ advance the
   current offset by **254** (no fixup emitted); any other **even** value
   `2..=254` ⇒ advance by that delta and emit a fixup at the new offset.
3. Validation (each violation ⇒ `Error::Parse { context: "prg reloc
   table", input: <what> }`): the first offset and every fixup offset must
   be even and satisfy `off + 4 <= tlen + dlen`; an **odd** delta (other
   than the literal `1`) is invalid; running out of table bytes before the
   `0` terminator is invalid ("unterminated relocation table").
4. `absflag != 0`, or `absflag == 0` with zero bytes after the symbol
   table ⇒ empty fixup set (the `prg_wrap` output's 4-byte `0` table also
   decodes to empty — §9.1 pins this).

At load time TOS adds the load address (`p_tbase`) to the big-endian u32 at
every fixup offset. P16 replays exactly that (§6.2) — nothing else.

### 4.3 The GEMDOS basepage + live discovery (the wire sequence)

Basepage layout (256 bytes; the fields P16 reads, all big-endian u32):

| Offset | Field | Meaning |
|---|---|---|
| `+$00` | `p_lowtpa` | TPA start (== basepage address) |
| `+$04` | `p_hitpa`  | TPA end |
| `+$08` | `p_tbase`  | **TEXT load address** (== basepage + $100 under GEMDOS Pexec) |
| `+$0C` | `p_tlen`   | TEXT length (copied from the PRG header) |
| `+$10` | `p_dbase`  | DATA base (== `p_tbase + p_tlen`) |
| `+$14` | `p_dlen`   | DATA length |
| `+$18` | `p_bbase`  | BSS base |
| `+$1C` | `p_blen`   | BSS length |

**Discovery — exactly these six sentinel-synced reads, in order** (each via
`debug::read_bytes`, i.e. one `m $addr <n>` round-trip; the running
program's load address varies per run, so this must be read live —
authority: R1PP3R.S `FIX_CURR_BPAGE`):

| # | Read | Yields | Validation |
|---|---|---|---|
| 1 | `read_bytes($4F2, 4)` | `sysbase` (OSHEADER address) | nonzero, `< ram_len` |
| 2 | `read_bytes(sysbase + 8, 4)` | `os_beg` — the *real* OS header base (the `$4F2` pointer may reference a shadowed copy; r1pp3r dereferences `8(a1)` first — keep that step) | nonzero, `< ram_len` `// verify live` |
| 3 | `read_bytes(os_beg + 2, 2)` | `os_version` (BE u16) | if `< 0x0102` ⇒ `Error::Session("TOS < 1.02: basepage discovery unsupported")` — the r1pp3r 8x16-font heuristic is out of scope; Hatari's bundled EmuTOS and TOS 1.04 images both take the fast path `// verify live` |
| 4 | `read_bytes(os_beg + 0x28, 4)` | `p_run` — address of the TOS variable holding the current-process basepage pointer | nonzero, `< ram_len` |
| 5 | `read_bytes(p_run, 4)` | `bp_addr` — the basepage address | nonzero, even, `bp_addr + 0x100 <= ram_len`; zero ⇒ `Error::Session("no GEMDOS process is running")` |
| 6 | `read_bytes(bp_addr, 0x20)` | the 8 fields above | §5.2 sanity checks |

`// verify live` (whole sequence): `p_run` names the **current** GEMDOS
process — if the target `Pexec`'d a child, this is the child's basepage.
The §7.1 header cross-check (`tlen`/`dlen`/`blen` must match the source
PRG) converts that failure mode into a loud, explained error instead of a
corrupt save.

## 5. `src/debug/basepage.rs` — typed basepage read

### 5.0 `src/debug/mod.rs` — one line

Add `pub mod basepage;` to the module list (alphabetical: before
`pub mod breakpoint;`). Nothing else changes.

### 5.1 Public API

Module doc: "GEMDOS basepage discovery over the sentinel-synced debugger
channel (P16): `$4F2` → OSHEADER → (`os_beg+2` version gate) → `p_run` →
current basepage → TEXT/DATA/BSS geometry. The running program's load
address varies per run (ARCHITECTURE.md `debug/` contract) — this is the
only sanctioned way to obtain it. Layout authority:
refs/orionfuzion/r1pp3r/src/R1PP3R.S `FIX_CURR_BPAGE` (cited, not ported).
// verify live: p_run semantics under Hatari's bundled TOS."

```rust
use crate::error::{Error, Result};
use crate::types::Addr;

use super::{read_bytes, DebugChannel};

/// The current GEMDOS process's basepage, as read live (§4.3 fields).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Basepage {
    /// Address of the basepage itself (`p_run` dereferenced).
    pub addr: Addr,
    pub text_base: Addr,
    pub text_len: u32,
    pub data_base: Addr,
    pub data_len: u32,
    pub bss_base: Addr,
    pub bss_len: u32,
}

/// Read the current process's basepage (§4.3 wire sequence — six
/// sentinel-synced `m` reads). `ram_len` bounds every pointer hop.
pub async fn current_basepage(
    chan: &mut impl DebugChannel,
    ram_len: usize,
) -> Result<Basepage>;
```

### 5.2 Implementation (pinned)

Private helpers `be32(&[u8]) -> u32` / `be16(&[u8]) -> u16` (slices are
exact-length; `read_bytes` already errors on short reads via
`parse_memdump` + truncate — a returned vec shorter than requested is an
`Error::Parse`, add that check in a private `read_exact(chan, addr, n)`
wrapper so every hop fails loud). Pointer-hop validation is one private
`fn hop(name: &'static str, v: u32, ram_len: usize) -> Result<u32>`:
zero or `>= ram_len` ⇒ `Error::Parse { context: "basepage discovery",
input: format!("{name} = ${v:x} out of RAM") }`.

Step 5's zero check is **not** a `hop` failure — it is the distinct
`Error::Session("no GEMDOS process is running (p_run holds 0)".into())`
so the tool layer can surface a clear agent-facing message. Odd `bp_addr`
⇒ `Error::Parse` (context `"basepage discovery"`).

Sanity checks after step 6 (both `Error::Parse`, context `"basepage"`):

- `data_base == text_base + text_len` — **hard error** ("non-contiguous
  TEXT/DATA — not a standard Pexec load"); the §6.2 mapping depends on it.
- `text_base + text_len + data_len <= ram_len` — hard error.

`text_base != addr + 0x100` is **not** an error (p_tbase is authoritative);
the tool layer reports it as a warning (§7.1 step 5). `// verify live`.

`current_basepage` stays ≤ 30 lines by delegating to `read_exact`/`hop`
and a `fn decode(bp_addr: u32, raw: &[u8; 0x20]) -> Basepage`.

### 6.1 `src/ripper/prg_file.rs`

Module doc: "GEMDOS `.PRG` container parse (P16, §4.1/§4.2): 28-byte header,
TEXT/DATA/symbol segments, relocation-table decode. The header layout is
`extract::prg_wrap`'s table — `parse` round-trips `prg_wrap` output
(pinned test) so emit and parse can never drift. Path-validated file read
follows the `disk.rs` P7 precedent."

```rust
use std::path::Path;

use crate::error::{Error, Result};

pub const HEADER_LEN: usize = 28;
pub const PRG_MAGIC: u16 = 0x601A;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct PrgHeader {
    pub tlen: u32,
    pub dlen: u32,
    pub blen: u32,
    pub slen: u32,
    pub absflag: u16,
}

/// A parsed PRG. `bytes` is the whole original file (kept: the re-emit is
/// "copy + in-place byte patches", §6.2 — header, symbols and reloc table
/// are preserved verbatim by construction).
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct PrgFile {
    pub header: PrgHeader,
    pub bytes: Vec<u8>,
    /// Sorted, deduplicated segment offsets of relocated longwords (§4.2).
    pub reloc: Vec<usize>,
}

impl PrgFile {
    /// The contiguous TEXT‖DATA image (`bytes[28 .. 28 + tlen + dlen]`).
    pub fn seg_image(&self) -> &[u8];
    /// tlen + dlen as usize.
    pub fn seg_len(&self) -> usize;
}

/// Parse an in-memory PRG (§4.1 header + §4.2 reloc decode). Errors are
/// `Error::Parse` with contexts "prg header" / "prg reloc table".
pub fn parse(bytes: Vec<u8>) -> Result<PrgFile>;

/// Path-validated read + parse of a `.PRG` on disk (§6.1.1).
pub fn read_prg_file(path: &Path) -> Result<PrgFile>;
```

`parse` (≤ 30 lines by delegating to `fn parse_header(&[u8]) ->
Result<PrgHeader>` and `fn decode_reloc(&PrgHeader, &[u8]) ->
Result<Vec<usize>>`):

1. `bytes.len() >= HEADER_LEN` and magic == `PRG_MAGIC`, else
   `Error::Parse { context: "prg header", input: … }`.
2. Segment bound: `HEADER_LEN + tlen + dlen + slen <= bytes.len()` (as
   u64 math before casting — no overflow on hostile headers), else
   `Error::Parse` ("segments exceed file").
3. `tlen + dlen <= 4 * 1024 * 1024` (nothing bigger fits ST RAM), else
   `Error::Parse` ("segment image exceeds 4 MB").
4. `decode_reloc` per §4.2, exactly.

#### 6.1.1 `read_prg_file` path validation (pinned — `// SECURITY: path traversal / unexpected-file guard`)

Mirror `disk.rs` §P7 semantics:

1. `path.canonicalize()` (resolves `..`/symlinks; missing file errors as
   `Error::Io`).
2. `std::fs::symlink_metadata(&canon)` must be a regular file, else
   `Error::Parse { context: "prg file", input: "<path> is not a regular
   file" }`.
3. Extension gate (case-insensitive): accept `prg`, `tos`, `ttp`, `app`
   (the GEMDOS-executable family — identical container). Anything else ⇒
   `Error::Parse { context: "prg file", input: "not a GEMDOS executable
   (.prg/.tos/.ttp/.app)" }`.
4. Size gate before reading: `metadata.len() <= 8 * 1024 * 1024` else
   `Error::Parse` ("file too large for an ST executable") — refuses to
   slurp arbitrary huge files.
5. `std::fs::read(&canon)` → `parse(bytes)`.

### 6.2 `src/ripper/repatch.rs`

Module doc: "RAM→file back-mapping for `save_prg` (P16): reconstruct the
expected in-RAM TEXT+DATA image (file bytes + relocation at the live load
address), diff against acquired RAM, split the differences into
file-representable patch runs vs relocated-longword skips, apply the runs
to a copy of the original file. Pure — unit-tested on synthetic PRGs."

```rust
use crate::types::Addr;

use super::prg_file::{PrgFile, HEADER_LEN};

/// A maximal contiguous run of patched, file-representable bytes.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct PatchRun {
    /// Offset into the TEXT‖DATA segment image.
    pub seg_off: usize,
    pub len: usize,
}

impl PatchRun {
    pub fn file_offset(&self) -> usize { HEADER_LEN + self.seg_off }
    pub fn ram_addr(&self, text_base: Addr) -> Addr
        { Addr::new(text_base.raw() + self.seg_off as u32) }
}

/// A patched relocated longword — NOT file-representable (writing the RAM
/// value into the file would bake an absolute run-time address into a
/// relocatable image). Reported, never applied.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct RelocSkip {
    /// Segment offset of the relocated longword (== a `PrgFile::reloc` entry).
    pub seg_off: usize,
    /// The longword as stored in the file (pre-relocation).
    pub file_value: u32,
    /// file_value + text_base — what unpatched RAM should hold.
    pub expected_ram: u32,
    /// What RAM actually holds.
    pub actual_ram: u32,
}

#[derive(Debug, Clone, PartialEq, Eq, Default)]
pub struct RepatchPlan {
    pub runs: Vec<PatchRun>,
    pub reloc_skips: Vec<RelocSkip>,
    /// Total differing bytes (applied + skipped + filtered) — the honesty
    /// number behind the §7.1 divergence warning.
    pub changed_bytes: usize,
    /// Differing bytes excluded by the caller's region filter (0 when no
    /// filter). Reported, never applied.
    pub filtered_bytes: usize,
}

/// The §4.2 load replay: clone the segment image and add `text_base` to
/// the big-endian u32 at every reloc offset (wrapping add — TOS does 32-bit
/// adds too).
pub fn expected_ram(prg: &PrgFile, text_base: Addr) -> Vec<u8>;

/// Diff `actual` (the acquired RAM window, exactly seg_len bytes) against
/// `expected`; split per §6.2.1. `regions`: segment-offset ranges the
/// caller allows to be applied (None = everything).
pub fn diff(
    prg: &PrgFile,
    expected: &[u8],
    actual: &[u8],
    text_base: Addr,
    regions: Option<&[(usize, usize)]>,   // (seg_off, len), pre-validated
) -> RepatchPlan;

/// Copy of the original file with every run's bytes replaced from
/// `actual` at `file_offset()`. Header/symbols/reloc table untouched.
pub fn apply(prg: &PrgFile, plan: &RepatchPlan, actual: &[u8]) -> Vec<u8>;
```

#### 6.2.1 The diff split (pinned, per-byte, deterministic)

Precompute `in_reloc: fn(seg_off) -> Option<reloc_off>` — the byte lies in
some `[r, r+4)` for `r` in `prg.reloc` (binary search; `reloc` is sorted).
Then for each byte `i` where `expected[i] != actual[i]`, classify:

1. `in_reloc(i)` is `Some(r)` ⇒ contributes to one `RelocSkip` for `r`
   (dedupe: one skip per reloc offset, values read as BE u32 from
   `prg.seg_image()`, `expected`, `actual` at `r`).
2. Else, if `regions` is `Some` and `i` is in none of them ⇒
   `filtered_bytes += 1`.
3. Else ⇒ part of an applied run. Runs are **maximal contiguous spans of
   category-3 bytes** — a category-1 or category-2 byte (or an unchanged
   byte) terminates the current run.

Every differing byte increments `changed_bytes`. A patch that *straddles*
a relocated longword is therefore split: its outside bytes are applied,
its inside bytes produce a `RelocSkip` — the §7.2 output carries both, so
the agent sees exactly what was and wasn't persisted. Empty diff ⇒
`RepatchPlan::default()` — a valid, boring save (the tool still writes the
copy; output says `changed_bytes: 0`).

Keep `diff` ≤ 30 lines by delegating classification to a private
`fn classify(..) -> Class` and run-building to a tiny state struct.

.PRG, with your RAM patches mapped back to their file offsets. Requires a
PAUSED session (pause first) and the path of the original .PRG the program
was loaded from. Patches to loaded TEXT/DATA persist; patches inside
relocated pointers and anything in BSS/runtime state are reported but NOT
representable in the file (use the future snapshot mode for those). Returns
the patch runs applied, relocation warnings, and divergence facts — the
program's own writes to its DATA segment also count as diffs, so review
the summary (or pass regions to restrict what is applied)."

Exact behavior (split into `async fn gather_live` + `fn finish_blocking`
helpers to hold the 30-line ceiling; semantics below are contractual):

1. **Validate before touching the session** (all pure, §7.2):
   `let mode = validate_mode(a.mode.as_deref())?;` (only `Mode::Repatch`
   survives); `let (source, out) = validate_paths(&a)?;`;
   `let regions_raw = a.regions` kept for step 4.
2. **Paused gate.** `let mut guard = self.session.lock().await;` — match
   `&mut *guard`: `AnySession::Paused(s)` ⇒ proceed with
   `s.process_mut()`; `Running` ⇒ `wrong_state("running", "paused —
   pause first so the save is coherent")`; `Stopped` ⇒
   `wrong_state("stopped", "paused")`. No `mem::replace` — no state
   transition happens.
3. **Live gather (lock held — same rationale as `machine_state`):**
   `let ram_len = proc.config().ram_len();`
   `let bp = debug::basepage::current_basepage(proc, ram_len).await
   .map_err(to_mcp)?;` then
   `let ram = memory::acquire_range(proc, bp.text_base,
   (bp.text_len + bp.data_len) as usize).await.map_err(to_mcp)?;`
   Drop the guard. (Two await points; the session mutex is the only lock
   held across them — the `tools/mod.rs` locking contract.)
4. **Region parse** (needs `bp`): each `RegionArg { addr, len }` →
   `super::mem::scan::parse_addr(&r.addr)?`; require `len >= 1` and the
   whole range within `[text_base, text_base + seg_len)`, else
   `invalid_params("region $… is outside the loaded TEXT+DATA image
   ($… .. $…)")`. Convert to `(seg_off, len)` pairs.
   *Implementation note:* `parse_addr` is `pub(crate)` in
   `tools::mem::scan` and the `scan` module is `pub(crate)` — directly
   reusable; do not duplicate it.
5. **Blocking finish** (`tokio::task::spawn_blocking`, exactly the
   `extract.rs` pattern — join error ⇒
   `McpError::internal_error("save_prg task failed: {e}")`):
   1. `let prg = prg_file::read_prg_file(&source).map_err(to_mcp)?;`
   2. Cross-check (the §4.3 caveat closer): `prg.header.{tlen,dlen,blen}`
      must equal `bp.{text_len,data_len,bss_len}`, else
      `invalid_params("source PRG does not match the running program
      (text/data/bss {file} vs {live}) — wrong file, or the program is
      packed/self-relocating")`.
   3. `let expected = repatch::expected_ram(&prg, bp.text_base);`
   4. `let plan = repatch::diff(&prg, &expected, ram.bytes(),
      bp.text_base, regions.as_deref());`
   5. `let out_bytes = repatch::apply(&prg, &plan, ram.bytes());`
   6. `std::fs::write(&out, &out_bytes)` (⇒ `to_mcp(Error::Io(e))`).
   7. Warnings (in this order, each a `String` pushed to `warnings`):
      - `bp.text_base != bp.addr + 0x100` ⇒ "text base $… is not
        basepage+$100 — unusual loader `// verify live`".
      - `plan.changed_bytes * 10 > seg_len` (i.e. > 10%) ⇒
        "{changed} of {seg_len} bytes differ from the file image — the
        program self-modifies or runtime DATA writes are being persisted;
        review the runs (or pass regions)".
      - `!plan.reloc_skips.is_empty()` ⇒ "{n} patched relocated
        pointer(s) NOT persisted (not file-representable)".
      - `plan.filtered_bytes > 0` ⇒ "{n} changed byte(s) outside the
        given regions were not applied".
   8. Build `SavePrgOutput` via `save_prg_wire::summarize` (§7.2).
6. Return `Ok(Json(out))`.

pub struct SavePrgArgs {

    /// must not be the source file).

}

#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]

    /// Byte offset in the output file where the run landed.

    pub len: usize,
}

#[derive(Debug, serde::Serialize, schemars::JsonSchema)]
pub struct RelocSkipOut {
    /// RAM address of the relocated longword ("$…").
    pub addr: String,
    pub file_offset: usize,
    /// Longword in the file ("$XXXXXXXX").

}

#[derive(Debug, serde::Serialize, schemars::JsonSchema)]
pub struct SavePrgOutput {
    pub out_path: String,
    /// Output file size — always identical to the source file size (the
    /// re-emit only replaces bytes, never inserts).
    pub size: u64,
    pub basepage: BasepageOut,
    /// Total bytes differing between the file image and live RAM.
    pub changed_bytes: usize,
    /// Applied patch runs (first 32; see applied_truncated).

    pub applied_truncated: bool,
    /// Patched relocated longwords — reported, NOT persisted (first 16).
    pub skipped_reloc: Vec<RelocSkipOut>,
    pub skipped_reloc_truncated: bool,
    /// Changed bytes excluded by the regions filter (0 when no filter).

pub(crate) fn validate_mode(m: Option<&str>) -> Result<Mode, McpError>;

/// - source: must not be empty; `PathBuf::from`; the deep validation
///   (canonicalize/regular-file/extension/size) is prg_file::read_prg_file
///   — do NOT duplicate it here; but DO canonicalize here for the

///   if that path exists it must be a regular file (never a
///   directory/symlink target surprise) ⇒ else invalid_params;
///   effective out == canonical source ⇒ invalid_params("refusing to

pub(crate) fn validate_paths(a: &SavePrgArgs)

/// Pure summary builder: caps applied/skipped lists, formats addresses
/// via Addr display / "${:08X}" longwords, fixed bss_note text:
/// "BSS ($… .. $…, {blen} bytes) and runtime state are not part of the

  side) is the follow-on phase.
- Rewriting the relocation table to *re-point* a patched pointer (turning
  `actual_ram − text_base` back into a file value) — plausible but subtle
  (the new value must be a valid segment-relative pointer); reported-only
  ships first. Improvement path in the ADR.
- Packed / self-relocating / self-modifying programs (Pack-Ice'd PRGs
  etc.): the header cross-check + divergence warning make the failure loud
  and explained; depack-then-save is not attempted.
- Symbol-table rewriting, TOS < 1.02 (the 8x16-font `p_run` heuristic),
  child-process/basepage-chain walking, `.MSA`/`.DIM` sources, saving from
  a Running session (momentary freeze à la ADR-20 — rejected here: a
  persistence op should be deliberate; `pause` is one call away).
- Any change to `extract.rs`/`prg_wrap`, the plugin registry, `Finding`,
  or the session FSM.

> ## 2026-07-XX — ADR-NN: save_prg — persist a live hack by re-emitting the patched .PRG (repatch flavour; snapshot deferred)
>
> **Status:** accepted
> **Context:** The live-patch exercise (docs/live-patching.md) ends with
> nothing to keep: patches live in volatile RAM and vanish on `stop` —
> the one freezer-cartridge power the surface lacked was "save". Two
> classic flavours exist: map patched TEXT/DATA RAM back onto the
> original .PRG's file offsets (persists static-data/code hacks — exactly
> what the exercise patched), or dump full RAM+regs+hardware behind a 68k
> restore stub (the r1pp3r/Ultimate-Ripper model — persists anything,
> costs a code generator and hardware-state semantics).
> **Decision:** Ship the re-emit flavour as `save_prg(out_path,
> source_prg, mode="repatch")`; reserve `mode="snapshot"` (rejected with
> invalid_params) for a follow-on phase. Mechanics: (1) the live load
> address comes from the GEMDOS basepage via OSHEADER — `$4F2` → real OS
> base (+8) → version gate (≥ 1.02) → `p_run` (+$28) → basepage →
> p_tbase/p_tlen/p_dbase/p_dlen/p_bbase/p_blen (layout authority:
> r1pp3r's FIX_CURR_BPAGE; TOS < 1.02 font-heuristic out of scope); (2)
> the original .PRG is parsed (28-byte header per the shipped prg_wrap
> table — a parse↔prg_wrap round-trip test pins them together — plus the
> standard delta-encoded relocation table), the expected RAM image is
> reconstructed by replaying relocation at the live load address, and
> actual RAM (one ranged savebin of TEXT+DATA) is diffed against it; (3)
> diffs OUTSIDE relocated longwords are written to a byte-identical copy
> of the source file at offset 28+seg_off; diffs INSIDE relocated
> longwords and everything in BSS are NOT file-representable — reported
> (values + offsets), never persisted, with BSS declared statically
> unreachable; (4) the tool is Paused-only (a persistence op must snapshot
> a frozen machine; pause is one call away), validates both paths
> (canonicalize, regular-file, extension family, no `..`, refuse
> out==source), cross-checks header tlen/dlen/blen against the live
> basepage (catches wrong-file and packed/self-relocating programs), and
> warns when divergence exceeds 10% (the program's own DATA writes also
> diff — an optional regions allow-list restricts what is applied);
> (5) output is a compact summary — capped run/skip lists, counts, paths;
> never bytes (ADR-5).
> **Alternatives considered:** Snapshot-to-runnable first — general but a
> full phase of restore-stub engineering; it must not gate the simple
> save. Searching RAM for the PRG's byte prefix instead of reading the
> basepage — ambiguous (multiple copies; the exercise itself hit 3 copies
> of a palette). Momentary-freeze-on-Running (ADR-20 style) — rejected:
> saving is deliberate, and Paused-only keeps the tool thin. Rewriting
> the reloc table to re-point patched pointers — deferred improvement;
> report-only cannot corrupt. Emitting via prg_wrap re-serialization —
> rejected: copy+patch preserves symbols/fixups/flags byte-for-byte by
> construction.
> **Consequences:** Static TEXT/DATA hacks (scroll text, palettes,
> tables, in-place code) survive `stop` as a clean, still-relocatable
> .PRG identical in size to the original. Runtime state does not — BSS
> and patched relocated pointers are reported honestly instead of being
> silently baked in or silently dropped. The diff cannot distinguish
> agent patches from the program's own DATA-segment writes; the
> divergence warning + regions filter put that judgement where it belongs
> (the agent). Basepage discovery trusts p_run (current process) — a
> Pexec'd child fails loud via the header cross-check. `// verify live`
> residue: the discovery sequence under Hatari's bundled TOS/EmuTOS and
> p_tbase==basepage+$100 are pinned by the #[ignore]d live test. The
> reserved snapshot mode and reloc re-pointing are the improvement paths.
