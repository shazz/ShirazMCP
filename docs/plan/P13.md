## 1. Deliverable in one sentence

An `mpp` picture detector + renderer: conservative magic-anchored detection
of MPP files in RAM/depacked buffers (modes 0–3 fully sized and validated;
modes 4–7 reported header-only), and a `render_png` that performs the full
**multi-palette decode** — per scanline, reload the line-start palette
entries from the 9/12/15-bit palette bitstream, then walk the line applying
in-line palette rewrites at the mode's pinned x positions so every pixel is
looked up in the palette *as of that x* — registered with **one line** in
`default_registry()`, proven by byte-pinned synthetic fixtures whose golden
assertions include a mid-line palette change and cross-line palette
persistence.

## 4. The MPP format — normative byte spec

### 4.0 The mode question (resolves the "mode 5" credit)

The canonical container defines **exactly four modes, 0–3** (Zerkman README;
RECOIL rejects `mode > 3`). There is no public mode-4 or mode-5 layout: the
"MPP mode 5" in the Uhane credits is either a private encoder extension or a
loose credit for the mode-2 *blitter* pipeline (mode 2 is the only
blitter-based mode, and Uhane's endpart is a blitter displayer). Decision
(ADR-24): render modes 0–3 — the complete public format, superset of
anything RECOIL can decode; **detect** an otherwise-valid header with mode
4–7 as a **header-only finding** (label says "unsupported mode") so an
extended file still surfaces to the agent with its MPPH metadata; reject
mode > 7. If a real mode-5 layout is ever published, it becomes its own
follow-up phase. `// verify`: if a reachable mode-5 spec emerges, flag to
rust-architect — do not guess a layout.

### 4.1 Container layout

```
offset  size  field
0       3     magic "MPP" (4D 50 50)
3       1     mode: 0..=3 canonical (4..=7 detect-only, >7 invalid)
4       1     flags: bit0 = STE palette (12-bit entries; else 9-bit ST)
                     bit1 = extra palette bit (15-bit entries; REQUIRES bit0
                            — flags & 3 == 2 is invalid)
                     bit2 = double image (two palette+bitmap pairs, blended
                            on display)
                     bits 3..7 = reserved, always 0
5       3     reserved, always 0
8       4     extra_len (u32 BE, always even) — length of the MPPH block
12      extra_len   MPPH metadata block, present iff extra_len != 0:
                    "MPPH", 4-char tag + NUL-terminated value pairs
                    (TITL/ARTT/RIPP/CONV/YEAR), terminator "HPPM",
                    even-aligned
12+extra_len        frame 1: palette section, then bitmap section
...                 frame 2 (same sizes), present iff flags bit2
```

Per-mode geometry — **pinned from RECOIL** (the README says 200/276 lines of
*display*; the file stores 199/273 — RECOIL's exact-length validation of
real files is authoritative). `// verify` note this discrepancy in the code
comment.

| mode | width | height | method  | marketing        | stream entries/line |
|------|-------|--------|---------|------------------|---------------------|
| 0    | 320   | 199    | CPU     | 54 colors/line   | 52                  |
| 1    | 320   | 199    | CPU     | 48 colors/line   | 46                  |
| 2    | 320   | 199    | blitter | 56 colors/line   | 54                  |
| 3    | 416   | 273    | CPU     | 48+6, overscan   | 48                  |

- **Palette section size** = `(entries_per_line × height × bits_per_entry
  + 15) / 16 * 2` bytes — total bits rounded up to a 16-bit multiple, one
  continuous stream for the whole frame (NO per-line realignment — RECOIL
  reads one `BitStream` across all lines).
- **Bitmap section size** = `width × height / 2` bytes: the image is always
  4 interleaved bitplanes in the standard ST low-res word layout (`width/2`
  bytes per line: 160 for 320-wide, 208 for 416-wide), the same layout
  `image/render.rs::decode_planar` handles — MPP just swaps the palette
  underneath it while walking x.
- `bits_per_entry` = 9 (`flags&3 == 0`), 12 (`== 1`), 15 (`== 3`).
- **Total artifact length** =
  `12 + extra_len + (palette_bytes + bitmap_bytes) × frames`,
  `frames = 1 + ((flags >> 2) & 1)`.

### 4.2 Detection gates (the anti-false-positive design)

Degas' detector needs palette-plausibility heuristics because its "header"
is 2 low-entropy bytes (ADR-12/13). MPP needs none of that — the header has
enough fixed content to be a near-perfect signature. Gate set (ALL must
hold):

1. `bytes[o..o+3] == b"MPP"` (memmem-anchored, §5.2 — no alignment
   assumption, same as pack-ice, ADR-14: findings inside depacked buffers
   sit at arbitrary offsets).
2. `mode <= 7`.
3. `flags & 0xF8 == 0` and `flags & 3 != 2` (extra bit without STE is
   invalid per the README).
4. Reserved `bytes[o+5..o+8] == [0, 0, 0]`.
5. `extra_len` even and `<= 4096` (`MAX_EXTRA` — MPPH holds short text
   tags; 4 KiB is generous).
6. If `extra_len != 0`: `bytes[o+12..o+16] == b"MPPH"`.
7. Modes 0–3 additionally require `o + total_len <= bytes.len()` (the whole
   artifact fits). Modes 4–7 cannot compute a total (unknown geometry) —
   finding covers `12 + extra_len` bytes only.

That is ≥ 6 bytes of fixed/near-fixed content plus range constraints —
against ~4 MB of RAM the false-positive expectation is ≪ 1; no plausibility
scoring needed, and no ADR-13-style defer rules either ("MPP" is not a valid
Degas res word or NEO flag, and neither aliases into this header). Note:
memmem also hits the "MPP" inside a block's own "MPPH" tag (`o+12`); gate 2
kills it (`mode` byte would be `'H'` = 0x48).

### 4.3 Palette entries — bit-exact channel decode

Entries are read MSB-first from the continuous bitstream (RECOIL
`BitStream_ReadBit`: bits taken from each byte high-to-low, bytes in order).

- **9-bit (ST):** `rrrgggbbb` — r = bits 8..6, g = 5..3, b = 2..0; each is a
  linear 3-bit value (NOT a hardware word — no rotation). 8-bit output:
  `v * 255 / 7` — the **house ST scaling** (`image/mod.rs::decode_word` ST
  branch). RECOIL bit-replicates (`v<<5 | v<<2 | v>>1`) which differs by
  1/255 at v ∈ {2,4,6}; we deliberately keep the house math so an MPP and a
  Degas of the same colour decode identically (ADR-24). Golden tests use
  house math.
- **12-bit (STE):** three 4-bit **STE hardware nibbles** (bit-rotated: the
  channel LSB is stored in nibble bit 3), packed r,g,b MSB-first — r = bits
  11..8, g = 7..4, b = 3..0. Linearize `v4 = ((n & 7) << 1) | (n >> 3)`,
  output `v4 * 17` — identical to both RECOIL and `image/mod.rs`'s STE
  branch.
- **15-bit (STE + extra):** bits 14, 13, 12 are one **extra low bit** for
  r, g, b respectively; bits 11..0 are the 12-bit STE word as above.
  Per channel `v5 = (v4 << 1) | extra`, output `(v5 << 3) | (v5 >> 2)` —
  exactly RECOIL's `GetSteInterlacedColor` decomposition. On real STE
  hardware this is displayed as two alternating 12-bit palettes; the 15-bit
  entry decodes directly to the blended colour, so P13 renders it as a
  single frame (ADR-24).

### 4.4 The multi-palette change engine — THE core of this phase

Palette state is a 16-entry RGBA array that **persists across the whole
frame** (initialized to all-black once, before line 0 — mode 3 depends on
this). Per scanline `y`, in this exact order:

1. **Line-start reload:** read stream entries into palette slots
   `line_start..=15` — `line_start` = 1 for modes 0–2 (15 entries; slot 0 is
   NOT reloaded), 6 for mode 3 (10 entries; slots 0–5 persist from the
   previous line's in-line changes).
2. **Walk x from 0 to width−1.** Maintain `change_x` (next change position,
   starts at `FIRST_CHANGE_X[mode]`) and `change_color` (running change
   index, starts at 0). When `x == change_x`:
   - the palette slot rewritten is `change_color & 15` (changes cycle
     through slots 0,1,…,15,0,1,…);
   - its new value is **forced black** (no stream read) iff
     `change_color == FORCED_BLACK[mode]` — the right border must be black —
     otherwise the next stream entry;
   - then `change_x += step(mode, change_color)` and `change_color += 1`.
   The pixel at x is `palette[index]` where `index` is the standard 4-plane
   decode of this line's bitmap bytes (§4.1) — i.e. the palette **as of that
   x**, changes applied left of or at the pixel included.

Pinned per-mode tables (RECOIL `DecodeMppScreen`):

| mode | FIRST_CHANGE_X | step(cc)                                  | FORCED_BLACK | in-line changes |
|------|----------------|-------------------------------------------|--------------|-----------------|
| 0    | 33             | cc==15→88, cc==31→12, cc==37→100, else 4  | 32           | 38 (cc 0..=37)  |
| 1    | 9              | cc even→4, cc odd→16                      | 16           | 32 (cc 0..=31)  |
| 2    | 4              | always 8                                  | 32           | 40 (cc 0..=39)  |
| 3    | 69             | cc==15→112, cc==31→12, cc==37→100, else 4 | 127 (never)  | 38 (cc 0..=37)  |

Normative consistency identities (unit-tested, §6.2): per line,
`line_start_reads + in_line_changes − forced(0 or 1) == entries_per_line`:
mode 0: 15+38−1=52; mode 1: 15+32−1=46; mode 2: 15+40−1=54;
mode 3: 10+38−0=48. And the change positions for mode 2 are simply
`x = 4 + 8·cc` (cc39 at x=316 is the last; cc32's forced black lands at
x=260) — the golden fixture (§7.2) leans on these.

| 1, ST 9-bit    | 46×199=9154  | 10300 | 31840 | **42152** |

```rust
//! MPP (Multi-Palette Picture) detector — Zerkman/Sector One's format for
//! >16-colour ST(E) pictures via per-scanline palette rewrites. Container:
//! codeberg.org/zerkman/mpp README. Sizes/geometry pinned from RECOIL 6.4.5
//! recoil.c (RECOIL_DecodeMpp) — cited for semantics, not ported. The
//! renderer (change engine) lives in `mpp_decode.rs` (line budget; still
//! one registry line). Canonical modes are 0..=3; a valid header with mode
//! 4..=7 (the Uhane-credits "mode 5" case) is reported header-only, ADR-24.

use super::mpp_decode::render;
use crate::ripper::{Finding, RipKind, RipPlugin};
use crate::types::{MemImage, Offset, PluginId};

/// "MPP" + mode + flags + 3 reserved + u32 BE extra_len.
pub(crate) const HEADER_LEN: usize = 12;
/// Cap on the MPPH metadata block (short text tags; 4 KiB is generous).
const MAX_EXTRA: usize = 4096;

/// Palette-entry encoding, from flags bits 1..0 (bit 0 STE, bit 1 extra).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum PaletteKind {
    St9,
    Ste12,
    Ste15,
}

impl PaletteKind {
    fn from_flags(flags: u8) -> Option<Self> {
        match flags & 3 {
            0 => Some(Self::St9),
            1 => Some(Self::Ste12),
            3 => Some(Self::Ste15),
            _ => None, // extra palette bit without STE is invalid
        }
    }
    pub(crate) const fn bits(self) -> usize {
        match self {
            Self::St9 => 9,
            Self::Ste12 => 12,
            Self::Ste15 => 15,
        }
    }
    const fn name(self) -> &'static str {
        match self {
            Self::St9 => "ST 512",
            Self::Ste12 => "STE 4096",
            Self::Ste15 => "STE 4096+extra",
        }
    }
}

/// Parsed, size-validated header for the four canonical modes (0..=3).
#[derive(Debug, Clone, Copy)]
pub(crate) struct MppHeader {
    pub mode: u8,
    pub kind: PaletteKind,
    pub double: bool,
    pub extra_len: usize,
}

impl MppHeader {
    pub(crate) const fn width(&self) -> usize {
        if self.mode == 3 { 416 } else { 320 }
    }
    /// Stored lines. The README says 200/276 *displayed*; the file holds
    /// 199/273 — RECOIL's exact-length validation of real files wins.
    /// // verify: against RECOIL if a real MPP ever fails the length gate.
    pub(crate) const fn height(&self) -> usize {
        if self.mode == 3 { 273 } else { 199 }
    }
    /// First palette slot reloaded at each line start: modes 0-2 reload
    /// 1..=15 (slot 0 persists), mode 3 only 6..=15 (0..=5 persist).
    pub(crate) const fn line_start_color(&self) -> usize {
        if self.mode == 3 { 6 } else { 1 }
    }
    /// Stream entries consumed per scanline (RECOIL MODE_COLORS_PER_LINE).
    pub(crate) const fn entries_per_line(&self) -> usize {
        [52, 46, 54, 48][self.mode as usize]
    }
    /// Total bits rounded up to a 16-bit multiple, in bytes (§4.1).
    pub(crate) const fn palette_bytes(&self) -> usize {
        (self.entries_per_line() * self.height() * self.kind.bits() + 15) / 16 * 2
    }
    /// Always 4 interleaved planes: width/2 bytes per line.
    pub(crate) const fn bitmap_bytes(&self) -> usize {
        self.width() * self.height() / 2
    }
    pub(crate) const fn frames(&self) -> usize {
        if self.double { 2 } else { 1 }
    }
    pub(crate) const fn total_len(&self) -> usize {
        HEADER_LEN + self.extra_len + (self.palette_bytes() + self.bitmap_bytes()) * self.frames()
    }

    /// Full parse at `o`: gates + canonical mode + whole artifact in-buffer.
    /// None for modes 4..=7 — `try_mpp` reports those header-only.
    pub(crate) fn parse(bytes: &[u8], o: usize) -> Option<Self> {
        let (mode, flags, extra_len) = gates(bytes, o)?;
        if mode > 3 {
            return None;
        }
        let hdr = Self {
            mode,
            kind: PaletteKind::from_flags(flags)?,
            double: flags & 4 != 0,
            extra_len,
        };
        (o + hdr.total_len() <= bytes.len()).then_some(hdr)
    }
}

/// §4.2 gates 1-6: magic, mode <= 7, flags shape, reserved zero, even+capped
/// extra_len, "MPPH" present iff extra_len != 0. Returns (mode, flags,
/// extra_len) — mode may still be an unsupported 4..=7.
fn gates(bytes: &[u8], o: usize) -> Option<(u8, u8, usize)> {
    let h = bytes.get(o..o + HEADER_LEN)?;
    if &h[..3] != b"MPP" || h[3] > 7 || h[4] & 0xF8 != 0 || h[4] & 3 == 2 || h[5..8] != [0, 0, 0]
    {
        return None;
    }
    let extra = u32::from_be_bytes([h[8], h[9], h[10], h[11]]) as usize;
    if extra % 2 != 0 || extra > MAX_EXTRA {
        return None;
    }
    if extra != 0 && bytes.get(o + 12..o + 16)? != b"MPPH" {
        return None;
    }
    Some((h[3], h[4], extra))
}

pub struct Mpp;

impl RipPlugin for Mpp {
    fn id(&self) -> PluginId {
        PluginId::new("mpp")
    }
    fn kind(&self) -> RipKind {
        RipKind::Picture
    }
    fn describe(&self) -> &'static str {
        "MPP multi-palette pictures (per-scanline palette changes; modes 0-3 rendered)"
    }
    /// Magic-anchored scan (pack-ice precedent, ADR-14): memmem over "MPP",
    /// NO alignment assumption; offsets inside a previous hit are skipped.
    fn scan(&self, mem: &MemImage) -> Vec<Finding> {
        let bytes = mem.bytes();
        let mut out = Vec::new();
        let mut next = 0usize;
        for o in memchr::memmem::find_iter(bytes, b"MPP") {
            if o < next {
                continue;
            }
            if let Some(f) = try_mpp(bytes, o) {
                next = o + f.len;
                out.push(f);
            }
        }
        out
    }
    fn render_png(&self, bytes: &[u8]) -> Option<Vec<u8>> {
        render(&MppHeader::parse(bytes, 0)?, bytes)
    }
}

fn try_mpp(bytes: &[u8], o: usize) -> Option<Finding> {
    if let Some(hdr) = MppHeader::parse(bytes, o) {
        return Some(Finding::new(
            PluginId::new("mpp"),
            RipKind::Picture,
            Offset::new(o),
            hdr.total_len(),
            label(&hdr),
        ));
    }
    // A valid header with an unsupported mode 4..=7: report the header
    // (+ MPPH metadata) so the agent learns the picture exists even though
    // this build cannot size or decode it (§4.0, ADR-24). A canonical mode
    // that merely overruns the buffer lands here too and is dropped by the
    // mode > 3 filter — truncated canonical artifacts yield nothing.
    let (mode, _, extra_len) = gates(bytes, o)?;
    (mode > 3).then(|| {
        Finding::new(
            PluginId::new("mpp"),
            RipKind::Picture,
            Offset::new(o),
            HEADER_LEN + extra_len,
            format!("MPP mode {mode} picture (unsupported mode, header-only)"),
        )
    })
}

const MODE_DESC: [&str; 4] = [
    "54 colors/line",
    "48 colors/line",
    "56 colors/line, blitter",
    "48+6 colors/line, overscan",
];

fn label(h: &MppHeader) -> String {
    let double = if h.double { ", double-image" } else { "" };
    format!(
        "MPP mode {} {}x{} picture ({}, {}{double})",
        h.mode,
        h.width(),
        h.height(),
        MODE_DESC[h.mode as usize],
        h.kind.name(),
    )
}
```

(Example labels: `MPP mode 2 320x199 picture (56 colors/line, blitter,
STE 4096)`; `MPP mode 5 picture (unsupported mode, header-only)`.)

### 5.3 `src/ripper/plugins/mpp_decode.rs` — NEW: the multi-palette renderer

```rust
//! MPP palette bitstream + per-scanline change engine (§4.3/§4.4 of P13).
//! Semantics pinned from RECOIL 6.4.5 recoil.c (RECOIL_DecodeMppScreen,
//! MppPaletteStream_Read, BitStream_ReadBit, GetSteInterlacedColor) —
//! cited, not ported. Renders the FIRST palette+bitmap pair only; a
//! double-image file's second (blend) frame is deliberately skipped and the
//! finding label says "double-image" (ADR-24).

use image::RgbaImage;

use super::degas::warn_none;
use super::mpp::{MppHeader, PaletteKind, HEADER_LEN};
use crate::ripper::image::png_bytes;

/// Per-mode x position of the first in-line palette change (§4.4).
const FIRST_CHANGE_X: [usize; 4] = [33, 9, 4, 69];
/// Change index whose value is forced black instead of read from the
/// stream (the right border must be black); 127 = never fires (mode 3).
const FORCED_BLACK: [u32; 4] = [32, 16, 32, 127];
const BLACK: [u8; 4] = [0, 0, 0, 255];

/// MSB-first bit reader over the palette section (RECOIL BitStream
/// semantics: bits taken from each byte high-to-low, bytes in order; one
/// continuous stream for the whole frame — no per-line realignment).
struct BitReader<'a> {
    data: &'a [u8],
    pos: usize, // bit position
}

impl BitReader<'_> {
    fn read_bits(&mut self, n: u32) -> Option<u16> {
        let mut v = 0u16;
        for _ in 0..n {
            let byte = *self.data.get(self.pos >> 3)?;
            v = v << 1 | u16::from(byte >> (7 - (self.pos & 7)) & 1);
            self.pos += 1;
        }
        Some(v)
    }
}

/// Decode the first palette+bitmap pair of `bytes` (header at 0, already
/// parsed by the caller) to encoded PNG. None = corrupt input, never panic.
pub(crate) fn render(hdr: &MppHeader, bytes: &[u8]) -> Option<Vec<u8>> {
    let pal_off = HEADER_LEN + hdr.extra_len;
    let mut stream = BitReader {
        data: bytes.get(pal_off..pal_off + hdr.palette_bytes())?,
        pos: 0,
    };
    let bitmap = bytes
        .get(pal_off + hdr.palette_bytes()..)?
        .get(..hdr.bitmap_bytes())?;
    let (w, h, bpl) = (hdr.width(), hdr.height(), hdr.width() / 2);
    let mut img = RgbaImage::new(w as u32, h as u32);
    // ONE palette for the whole frame — state persists across lines
    // (mode 3's slots 0..=5 depend on it, §4.4).
    let mut palette = [BLACK; 16];
    for y in 0..h {
        for slot in hdr.line_start_color()..16 {
            palette[slot] = read_entry(&mut stream, hdr.kind)?;
        }
        render_line(&mut img, y, &bitmap[y * bpl..(y + 1) * bpl], &mut palette, &mut stream, hdr)?;
    }
    warn_none("mpp", png_bytes(&img))
}

/// One scanline: walk x, rewrite palette slots at the pinned change
/// positions, look each pixel up in the palette AS OF that x (§4.4).
fn render_line(
    img: &mut RgbaImage,
    y: usize,
    line: &[u8],
    palette: &mut [[u8; 4]; 16],
    stream: &mut BitReader<'_>,
    hdr: &MppHeader,
) -> Option<()> {
    let mode = hdr.mode as usize;
    let mut change_x = FIRST_CHANGE_X[mode];
    let mut change_color = 0u32;
    for x in 0..hdr.width() {
        if x == change_x {
            palette[(change_color & 15) as usize] = if change_color == FORCED_BLACK[mode] {
                BLACK
            } else {
                read_entry(stream, hdr.kind)?
            };
            change_x += step(hdr.mode, change_color);
            change_color += 1;
        }
        img.put_pixel(x as u32, y as u32, image::Rgba(palette[pixel_index(line, x)]));
    }
    Some(())
}

/// x-advance AFTER processing change `cc` (RECOIL DecodeMppScreen switch).
fn step(mode: u8, cc: u32) -> usize {
    match mode {
        1 => {
            if cc % 2 == 0 { 4 } else { 16 }
        }
        2 => 8,
        // modes 0 and 3 share the table, differing only at cc == 15
        _ => match cc {
            15 => {
                if mode == 0 { 88 } else { 112 }
            }
            31 => 12,
            37 => 100,
            _ => 4,
        },
    }
}

/// Standard ST 4-plane word interleave (the same layout image/render.rs
/// decodes, duplicated here for one line at a time): group x/16 is 4
/// consecutive BE words, pixel bit 15-(x%16), plane pl -> index bit pl.
/// In-bounds by construction: line.len() == width/2 == (width/16)*8.
fn pixel_index(line: &[u8], x: usize) -> usize {
    let (base, bit) = (x / 16 * 8, 15 - (x % 16));
    let mut idx = 0usize;
    for pl in 0..4 {
        let w = u16::from_be_bytes([line[base + 2 * pl], line[base + 2 * pl + 1]]);
        idx |= (((w >> bit) & 1) as usize) << pl;
    }
    idx
}

/// One palette entry -> RGBA (§4.3). 9-bit: linear rrrgggbbb, house ST
/// scaling v*255/7 (image/mod.rs decode_word ST branch; RECOIL
/// bit-replicates — <=1/255 apart at v in {2,4,6}, deliberate, ADR-24).
/// 12-bit: three rotated STE hardware nibbles, v4*17 (identical to RECOIL).
/// 15-bit: bits 14..12 are per-channel extra LSBs over the same 12-bit
/// word; (v5<<3)|(v5>>2) — exactly RECOIL GetSteInterlacedColor, already
/// blended, rendered as a single frame.
fn read_entry(s: &mut BitReader<'_>, kind: PaletteKind) -> Option<[u8; 4]> {
    Some(match kind {
        PaletteKind::St9 => {
            let v = s.read_bits(9)?;
            [st8(v >> 6 & 7), st8(v >> 3 & 7), st8(v & 7), 255]
        }
        PaletteKind::Ste12 => {
            let v = s.read_bits(12)?;
            [ste8(v >> 8 & 15), ste8(v >> 4 & 15), ste8(v & 15), 255]
        }
        PaletteKind::Ste15 => {
            let v = s.read_bits(15)?;
            [
                five8(v >> 8 & 15, v >> 14 & 1),
                five8(v >> 4 & 15, v >> 13 & 1),
                five8(v & 15, v >> 12 & 1),
                255,
            ]
        }
    })
}

/// STE hardware nibble -> linear 4-bit (the channel LSB sits in bit 3).
fn rot4(n: u16) -> u16 {
    ((n & 7) << 1) | (n >> 3)
}
fn st8(v: u16) -> u8 {
    (v * 255 / 7) as u8
}
fn ste8(n: u16) -> u8 {
    (rot4(n) * 17) as u8
}
fn five8(n: u16, extra: u16) -> u8 {
    let v5 = (rot4(n) << 1) | extra;
    ((v5 << 3) | (v5 >> 2)) as u8
}
```

### 7.1 Pinned builders

```rust
const RED: u16 = 0b111_000_000;
const GREEN: u16 = 0b000_111_000;
const BLUE: u16 = 0b000_000_111;
const WHITE: u16 = 0b111_111_111;

/// ST 3-bit -> 8-bit, the same integer math as the decoder (v*255/7).
fn st8(v: u16) -> u8 {
    (v * 255 / 7) as u8
}
fn rgba9(w: u16) -> [u8; 4] {
    [st8(w >> 6 & 7), st8(w >> 3 & 7), st8(w & 7), 255]
}

/// MSB-first bit writer — the exact mirror of mpp_decode's BitReader.
struct BitWriter {
    buf: Vec<u8>,
    bit: usize,
}
impl BitWriter {
    fn new() -> Self {
        Self { buf: Vec::new(), bit: 0 }
    }
    fn push(&mut self, v: u16, n: usize) {
        for i in (0..n).rev() {
            if self.bit == 0 {
                self.buf.push(0);
            }
            *self.buf.last_mut().unwrap() |= (((v >> i) & 1) as u8) << (7 - self.bit);
            self.bit = (self.bit + 1) % 8;
        }
    }
    /// Pad to the 16-bit boundary the palette-section size formula rounds to.
    fn finish(mut self) -> Vec<u8> {
        if self.buf.len() % 2 != 0 {
            self.buf.push(0);
        }
        self.buf
    }
}

fn mpp_header(mode: u8) -> Vec<u8> {
    let mut out = b"MPP".to_vec();
    out.extend([mode, 0, 0, 0, 0]); // flags 0 (ST 9-bit), reserved
    out.extend(0u32.to_be_bytes()); // extra_len 0
    out
}

/// Mode-2 ST file. `entry(y, k)` = 9-bit stream value for line y, stream
/// index k: k 0..=14 are the line-start reloads (slots 1..=15); k 15..=46
/// are in-line changes 0..=31; k 47..=53 are changes 33..=39 — change 32 is
/// the forced-black border and is NOT in the stream (§4.4).
fn build_mode2(entry: impl Fn(usize, usize) -> u16, bitmap_line: &[u8; 160]) -> Vec<u8> {
    let mut out = mpp_header(2);
    let mut w = BitWriter::new();
    for y in 0..199 {
        for k in 0..54 {
            w.push(entry(y, k), 9);
        }
    }
    let pal = w.finish();
    assert_eq!(pal.len(), 12090); // pinned §4.5
    out.extend(pal);
    for _ in 0..199 {
        out.extend_from_slice(bitmap_line);
    }
    assert_eq!(out.len(), 43942); // pinned §4.5
    out
}

/// Mode-3 ST file. Stream indices per line: k 0..=9 line-start (slots
/// 6..=15), k 10..=47 in-line changes 0..=37 (none forced in mode 3).
fn build_mode3(entry: impl Fn(usize, usize) -> u16, bitmap_line: &[u8; 208]) -> Vec<u8> {
    let mut out = mpp_header(3);
    let mut w = BitWriter::new();
    for y in 0..273 {
        for k in 0..48 {
            w.push(entry(y, k), 9);
        }
    }
    let pal = w.finish();
    assert_eq!(pal.len(), 14742); // pinned §4.5 (exact multiple, 0 pad bits)
    out.extend(pal);
    for _ in 0..273 {
        out.extend_from_slice(bitmap_line);
    }
    assert_eq!(out.len(), 71538); // pinned §4.5
    out
}
```

## 12. ADR-24 — append to `decisions.md` (verbatim; fill only the date)

```markdown
## 2026-07-XX — ADR-24: MPP multi-palette pictures — RECOIL-pinned change engine; unknown modes surface header-only

**Status:** accepted
**Context:** The DHS "He'e nalu Uhane" endpart displays MPP (Multi-Palette
Picture, Zerkman/Sector One) images — >16 colours via palette rewrites at
fixed x positions inside every scanline — which the single-palette P4
decoders cannot represent. The credits say "MPP mode 5", but the canonical
container (zerkman/mpp README) and its only independent decoder (RECOIL)
define modes 0–3 only; no public mode-4/5 layout exists. Two references
also disagree on stored height (README 200/276 display lines vs RECOIL
199/273 stored lines).
**Decision:** (1) One detector+renderer plugin (`mpp` + `mpp_decode`,
one registry line, ADR-2) implementing the complete public format: modes
0–3, ST 9-bit / STE 12-bit / STE 15-bit ("extra") palette entries, with the
per-line entry counts (52/46/54/48), change-position tables, and
forced-black border semantics pinned from RECOIL 6.4.5 (cited, not ported).
Heights are RECOIL's 199/273 — it length-validates real files; the README
describes displayed geometry. (2) The renderer keeps ONE 16-slot palette
that persists across the frame, reloads slots 1..=15 (mode 3: 6..=15) per
line from the continuous MSB-first bitstream, and applies in-line rewrites
while walking x, so each pixel is looked up in the palette as of its x.
(3) An otherwise-valid header with mode 4–7 becomes a header-only finding
labeled "unsupported mode" — a genuinely extended "mode 5" file still
surfaces (with its MPPH metadata extractable) instead of silently vanishing;
mode > 7 is rejected. (4) Detection is magic-anchored ("MPP" + flag/reserved
shape + MPPH-iff-extra + whole-artifact-fits) with no alignment assumption —
≥ 6 fixed bytes make Degas-style plausibility heuristics unnecessary and
false positives negligible. (5) Colour math: 12/15-bit identical to RECOIL;
9-bit uses the house v*255/7 ST scaling (RECOIL bit-replicates, ≤ 1/255
apart) so MPP and Degas render identical colours for identical palettes.
(6) Double-image files are sized fully but render frame 1 only; 15-bit
entries render as their blended colour, single frame.
**Alternatives considered:** mode 2 only (the blitter mode Uhane most
plausibly uses — rejected: the other modes share 90% of the machinery and
RECOIL parity is cheap); guessing a mode-5 layout (rejected: nothing to pin
against); rejecting unknown modes outright (rejected: hides exactly the
artifact that motivated the phase); porting RECOIL's decode verbatim
(rejected: license and style — semantics were re-derived and re-tested);
extending `decode_planar` with a palette callback (rejected: smears MPP's
change engine into the shared image layer for one consumer).
**Consequences:** `extract as=png` works for MPP with zero tool-layer
changes (ADR-12 registry lookup). A future mode-4/5 spec is a follow-up
phase touching only the plugin pair. Double-image blending and MPPH tag
parsing are recorded backlog. Fixtures are byte-pinned synthetic builders
(ADR-12 policy) whose goldens prove a mid-line palette change on the exact
pixel and cross-line palette persistence — the two behaviors that define
the format.
```
